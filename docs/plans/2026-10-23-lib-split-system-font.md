# План: библиотека `gterm` без `assets/` и бинарников; системный моноширинный шрифт

Статус: **реализовано 2026-10-23** — см. `docs/done/2026-10-23-lib-split-system-font.md`. Отклонения: `find_assets_dir` переехал в демо на шаге 1 (плюс третий источник — каталог пакета), метод `FontFamily::family()`, К4 на копии TTF с половинным advance `i`. ТЗ утверждено 2026-10-23: О1-a — workspace, О2-a — шрифт тестов из `../gterm-demo/assets`, О3-a — `fontdb` (с `memmap`, уточнение в ТЗ §3), О4-a — `assets/`, иначе системный, О5 — `gterm-demo`; К13 — минимальный пример.

- **ТЗ задачи:** `docs/spec/2026-10-23-lib-split-system-font.md`.
- **Решения:** ADR-0017 (`docs/adr/0017-library-without-assets-system-font.md`).
- **Опирается на:** ADR-0003 (семейство, подстановка начертаний по `OS/2`), ADR-0005 (размер шрифта — источник геометрии), ADR-0008 (SVG из каталога), NFR-1, NFR-3, NFR-6, NFR-7, NFR-9.

## Факты по коду (проверено 2026-10-23)

- `App::new(title, screen, rasterizer, config, options)` (`src/app/mod.rs:78`) принимает готовый `Rasterizer`; библиотека шрифт не ищет. Поиск делает `src/bin/demo/common.rs` (`load_family`, `load_rasterizer`), который `full_table` и `overlay` подключают через `#[path = "../demo/common.rs"]`.
- В `src/font.rs` к `assets/` привязаны: `FONT_FAMILY`, `ASSETS_DIR_NAME`, `FONTS_DIR_NAME`, `SEARCH_*_DEPTH`, `find_assets_dir()` (единственное использование `find_folder` в проекте), `fonts_dir()`, `FontError::AssetsDirNotFound`, `FontFamily::load(assets_dir)` (читает `assets_dir/fonts`, фильтр по `FONT_FAMILY`), `from_faces` (подставляет `FONT_FAMILY` в `NoRegularFace`). В `src/svg.rs` — `SVG_DIR_NAME`, `svg_dir()`; сама `SvgGlyphs::load(dir)` от `assets/` не зависит.
- Шрифт репозитория в тестах — `env!("CARGO_MANIFEST_DIR")/assets` в шести местах четырёх файлов: `tests/common/mod.rs:26`, `tests/events_common/mod.rs:166`, `tests/stage2_font.rs:19`, `tests/stage3_render.rs:30,61,587`. `tests/stage2_font.rs` строит временные каталоги `<tmp>/fonts/` и зовёт `FontFamily::load(<tmp>)`; тест `find_assets_dir_locates_repo_assets_from_test_cwd` проверяет `find_assets_dir()`.
- `Config::parse` отвергает неизвестные аргументы (`ConfigError::UnknownArgument`, `src/config.rs:162`) — флаги демо снимаются до разбора через `common::take_flag` (`src/bin/demo/main.rs:33`).
- `Cargo.toml`: `default-run = "demo"`, `[profile.release]` §10.2, четыре `[[test]] harness = false`. Профиль у не-корневого члена workspace Cargo игнорирует — профиль переезжает в корень.
- `fontdb 0.24.0` (исходники из реестра): `Database::new()` ставит `monospace = "Courier New"` на всех платформах; `load_system_fonts()` обходит `%WINDIR%\Fonts`, `%LOCALAPPDATA%\Microsoft\Windows\Fonts`, `%APPDATA%\Microsoft\Windows\Fonts`; на Linux с фичей `fontconfig` читает `/etc/fonts/fonts.conf` (и `local.conf`, `$XDG_CONFIG_HOME/fontconfig/fonts.conf`) и переопределяет `monospace` по алиасам, без неё — `/usr/share/fonts`, `/usr/local/share/fonts`, `~/.fonts`, `~/.local/share/fonts`. Без `memmap` каждый файл читается `std::fs::read` целиком, с `memmap` — отображается (`unsafe` внутри крейта). `FaceInfo { families: Vec<(String, Language)>, source: Source::File(path), index, style, weight, monospaced (по `post.isFixedPitch`) }`; `query(&Query { families: &[Family::Monospace | Family::Name(..)], .. })` возвращает один `ID`; `faces()` — обход всех лиц.

## Проектные решения (зафиксированы в ADR-0017)

1. **Workspace** из двух пакетов в одном репозитории: `crates/gterm` (библиотека, тесты, пример `minimal`) и `crates/gterm-demo` (бинарники, `assets/`, `find_folder`). Корневой `Cargo.toml` — виртуальный: `[workspace] members`, `resolver = "3"`, `[profile.release]`. `default-members` не задаётся: `cargo test` в корне гоняет оба пакета, запуск — `cargo run --bin demo|full_table|overlay`.
2. **Общий код демо** — библиотечная цель пакета `gterm-demo` (`src/lib.rs` с модулями `common` и `assets`) вместо `#[path]`; бинарники пишут `use gterm_demo::common`.
3. **API шрифта**: `FontFamily::load(fonts_dir, family)` — каталог с файлами (без неявного `fonts/`), `FontFamily::from_files(paths, family)`, `from_faces(faces, family, found)`; `NoRegularFace { family: String, found }`; проверка моноширинности в `from_faces` по advance набора `M i . W 0 ␠` на `FONT_SIZE_PX` (метрики `skrifa`, как в `cell_metrics`) → `NotMonospace { family, glyph, advance, expected }`.
4. **Системный шрифт** — модуль `src/font/system.rs` (`mod system` внутри `src/font.rs`, non-mod-rs схема, без переноса файла): `FontFamily::system(family)` и `FontFamily::system_monospace()`. База `fontdb` строится при вызове и отбрасывается; файлы семейства — `faces()` с `families`, содержащим имя, `Source::File` → `fs::read` → `Face` (как при каталоге). Кандидаты `system_monospace()`: Windows — `Cascadia Mono`, `Consolas`, `Lucida Console`, `Courier New`; Linux — сначала `Family::Monospace` (алиас fontconfig), затем `DejaVu Sans Mono`, `Liberation Mono`, `Noto Sans Mono`, `FreeMono`. Семейство принимается, если есть Regular и пройдена проверка п.3; иначе — следующее; все отказы копятся в `NoSystemMonospace { tried }`.
5. **Демо**: `assets.rs` в `gterm-demo` — `FONT_FAMILY`, `find_assets_dir`, `fonts_dir`, `svg_dir`; цепочка `common::load_family`: `--system-font` → `system_monospace()`; иначе `find_assets_dir()` → `load(fonts_dir, FONT_FAMILY)`; каталога нет → `system_monospace()`. Источник пишется в stderr (`gterm: font source: assets <dir> | system`). SVG грузятся только при источнике `assets`.
6. **Минимальный пример** `crates/gterm/examples/minimal.rs`: `AppHandler` с одной сценой (несколько строк текста, рамка U+2500), `FontFamily::system_monospace()` → `Rasterizer::new` → `App::new(...).run`; аргументы — `Config::parse` библиотеки (`--backend=…` работает).

## Шаги

0. **Базовая линия (QG-08).** `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (ожидание: 151 тест + 4 бинарника), `cargo build --release` и размеры `demo.exe`/`full_table.exe`/`overlay.exe` — в отчёт.
1. **Workspace без смены поведения.** `git mv`: `src/{cell,buffer,…,app,renderer}` → `crates/gterm/src/`, `tests/` → `crates/gterm/tests/`, `src/bin/*` → `crates/gterm-demo/src/bin/*`, `src/bin/demo/common.rs` → `crates/gterm-demo/src/common.rs`, `assets/` → `crates/gterm-demo/assets/`. Манифесты: корень (`workspace`, `resolver = "3"`, профиль), `crates/gterm/Cargo.toml` (зависимости библиотеки без `find_folder`, четыре `[[test]]`), `crates/gterm-demo/Cargo.toml` (`gterm = { path = "../gterm" }`, `winit`, `find_folder`, `default-run = "demo"`). Шесть путей к шрифту в тестах → `tests/common::repo_assets_dir()` = `CARGO_MANIFEST_DIR/../gterm-demo/assets` (в `events_common`, `stage2_font`, `stage3_render` — через тот же помощник или ту же формулу). Проверка: гейты, golden без изменений (`git status` чист в `tests/golden/`), `cargo run --bin demo` из корня.
2. **API шрифта (п.3).** Правка `src/font.rs`, перенос констант и `find_assets_dir`/`fonts_dir`/`svg_dir` в `gterm-demo/src/assets.rs` (тест `find_assets_dir_locates_…` — туда же юнит-тестом); `stage2_font` на новую сигнатуру (`load(<tmp>/fonts, FAMILY)`); новые тесты К3 (идентичность старому `load`: файлы по начертаниям, метрики, растр `A`/`Я` бит в бит с результатом `from_files`) и К4 (`NotMonospace`: пропорциональный системный TTF недетерминирован, поэтому тест строится на шрифте репозитория — проверка выделяется в функцию над метриками advance, которую тест кормит подменёнными значениями; если при реализации без внешнего пропорционального файла не обойтись — тест помечается как зависящий от окружения с печатью причины пропуска). Проверка: гейты, golden.
3. **Системный шрифт (п.4).** Зависимость `fontdb = { version = "0.24", default-features = false, features = ["fs", "memmap", "fontconfig"] }`, `Cargo.lock`; `src/font/system.rs`; stderr-лог файлов начертаний; тесты К6/К7 (зависят от окружения: нет семейства — печать причины и `return`, как `stage4_gl` без GL); замер `load_system_fonts()` + отбор на машине владельца (в отчёт, К5).
4. **Демо и пример (п.5–6).** `--system-font` через `take_flag`, цепочка источников, справка `--help`; `examples/minimal.rs`; `cargo clippy --all-targets` покрывает пример. Проверка К5/К8/К13 на машине владельца: `cargo run --bin demo -- --system-font` (три бэкенда), копия `demo.exe` в пустой каталог, `cargo run -p gterm --example minimal`.
5. **Замеры и документы.** Размеры release до/после (К11); `AGENTS.md` (команды, структура), `PROJECT_MAP.md`, `TODO.md`, ТЗ → 1.14 (§1, FR-8, FR-8.1, FR-8.5, NFR-3, §5.1, §10.1); ADR-0017 — дополнить «Последствия» замерами; отчёты `docs/done|test|verify/2026-10-23-lib-split-system-font.md`.

## Риски

- Старт с обходом системных каталогов: сотни файлов на Windows. С `memmap` читаются только заголовки, но каждый файл открывается; порог ≈ 100 мс — по замеру К5, иначе О3-b отдельным решением.
- `git mv` ста с лишним файлов: история сохраняется (`git log --follow`), но diff шага 1 большой — шаг делается отдельным коммитом по запросу владельца, без правок содержимого.
- Семейство с иконками шире ячейки проходит проверку по контрольному набору, но отдельные глифы шире — рендерер обрезает их по ячейке (FR-13), как и сейчас у иконок без суффикса Mono.
- `fontdb` на Linux без fontconfig оставляет `monospace = "Courier New"` — его обычно нет, тогда работает список кандидатов п.4.
