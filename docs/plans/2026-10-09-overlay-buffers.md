# План: наложение клиентских буферов поверх экрана

Статус: **реализовано 2026-10-09** — см. `docs/done/2026-10-09-overlay-buffers.md`. Решения: О1–О4 — а. Отклонения: (а) по замеру шага 7 добавлены `#[inline(always)]` у попиксельных функций и `Atlas::pixel`, `div255` вместо деления и два быстрых пути — формула та же; (б) Software с наложением на весь экран — 23,6 FPS, ниже NFR-5 — ⚠ и отдельная задача, как предусмотрено рисками; (в) `--bench --overlay` — флаг демо, а не отдельный режим.

- **ТЗ задачи:** `docs/spec/2026-10-09-overlay-buffers.md` — утверждено 2026-10-09 (Н1 — ping-pong, по проходу на буфер; Н2 — отдельный бинарник `overlay`).
- **Опирается на:** ADR-0013 — `blend`, `fade`, `Color` `0xAARRGGBB`, фон буфера.
- **Основное ТЗ:** FR-12, FR-25 (+FR-25.1), §5.2, §5.3, §7, §8 → версия 1.12.

## Факты по коду (проверено 2026-10-09)

- **Кадр в `App`.** `RedrawRequested` → `App::redraw` → `render_frame` (`src/app/frame.rs`) → `Renderer::render(&mut screen)`. После успешного кадра вызывается `on_frame`. Обратного вызова «до кадра» нет. Обработчик лежит в `App::handler: Option<Box<dyn AppHandler>>` и на время вызова вынимается (`notify`, `src/app/events.rs`).
- **GL** (`src/renderer/gl_backend.rs`):
  - одна программа (`init`, строки 400–477), VAO без буферов, текстуры атласа `RGBA8UI` и данных `RGBA32UI`;
  - FBO для `render_to_frame` создаётся по требованию (`ensure_offscreen`, `RGBA8`);
  - `draw` (611) — один `draw_arrays`;
  - данные загружаются построчно (`upload_data`, буфер строки переиспользуется);
  - глифы готовятся в `prepare_glyphs(screen, full)`, при сбросе страницы — повтор для всего экрана.
- **Software** (`src/renderer/soft_backend.rs`):
  - кадр окна `0x00RRGGBB`;
  - `rows_to_draw` — отмеченные строки;
  - `prepare_glyphs` идёт по отмеченным строкам, сброс страницы → полный кадр;
  - `draw_cell` смешивает фон ячейки с фоном буфера раз на ячейку;
  - `collect_damage` строит полосы по `rows_to_draw`.
- **Пустые ячейки клиентского буфера непрозрачны.** `ScreenBuffer::new` заполняет пустые места непрозрачными `DEFAULT_FG`/`DEFAULT_BG`. Клиентский буфер, созданный через `new`, закроет экран чёрным. Прозрачный буфер сейчас делается только через `with_default_colors(c, r, Color::TRANSPARENT, Color::TRANSPARENT)` (см. О4).

## Проектные решения (уйдут в ADR-0014)

1. **`Overlay`** — публичный тип библиотеки, хранит записанные буферы кадра.
   - `push(&ScreenBuffer, col: i32, row: i32)` **копирует** ячейки во внутренний массив (переиспользуется между кадрами — NFR-6 после первого кадра) и запоминает позицию и размер.
   - `clear()`, `is_empty()`, итерация по записям.
   - Копия решает вопрос времени жизни: буфер принадлежит клиенту и одолжен только на время `on_redraw`, а рисуем мы после возврата из него.
2. **API приложения.**
   - `AppHandler::on_redraw(&mut self, ctx: &mut DrawCtx<'_>)` с пустым телом по умолчанию.
   - `DrawCtx { overlay: &mut Overlay, grid: Grid }`: методы `draw_buffer(&ScreenBuffer, col, row)` (то есть `overlay.push`) и `grid()`.
   - `App::redraw`: `overlay.clear()` → `on_redraw` → `render_frame` (`render_overlaid`). Повтор кадра после ошибки идёт новым `RedrawRequested` — `on_redraw` вызывается снова.
3. **Формулы** (при О2 — а). Обозначения: `mul(x, a) = (x·a + 127) / 255`; `T = (t_rgb, t_a)` — пиксель текстуры, RGB предумножен на альфу.
   - **Слой поверх `T`** — пиксель с цветом `c` и альфой `α`:

     ```
     t_rgb' = mul(c, α) + mul(t_rgb, 255 − α)
     t_a'   = α + mul(t_a, 255 − α)
     ```

   - **Ячейка клиентского буфера** — два слоя подряд: сначала фон (`bg.rgb`, `bg.a`), затем символ (`fg'`, `fade(cov, fg.a)`). `fg'` — RGB с осветлением `BOLD`; `UNDERLINE` даёт `cov = 255` на нижней строке ячейки.
   - **Наложение на кадр** (пиксель основного кадра `F`):

     ```
     out = t_rgb + mul(F, 255 − t_a)
     ```

   - **Свойства** (проверяются тестами):
     - `α = 255` даёт ровно `c`;
     - `α = 0` не меняет `T`;
     - пустая текстура (`0`) не меняет кадр;
     - переполнения нет: `mul(c, α) ≤ α` и `t_rgb ≤ t_a`, поэтому `out ≤ 255`.
   - В Software это публичные функции рядом с `blend`/`fade` (`over`, `composite`); в шейдере — те же операции в том же порядке.
4. **Software.**
   - Текстура наложения — `Vec<u32>` размером с сетку в пикселях, в формате `0xAARRGGBB` с предумноженным RGB. Выделяется заранее, растёт только при росте сетки.
   - **Строки кадра:** отмечаются dirty-строки основного буфера, строки, покрытые наложением в этом кадре, и строки, покрытые в прошлом (`prev_overlay_rows`, переиспользуемый `Vec<bool>`).
   - **Порядок:**
     1. очистить в текстуре строки прошлого кадра;
     2. нарисовать в текстуру записи по порядку, с обрезкой по сетке;
     3. нарисовать отмеченные строки основного буфера как сейчас;
     4. для отмеченных строк, покрытых наложением, — `composite`.
   - Полосы перерисованного (ADR-0010) строятся по тем же отмеченным строкам.
   - Без записей путь прежний: golden и замер без наложения не меняются.
5. **Атлас.**
   - Глифы готовятся одним проходом: отмеченные строки основного буфера плюс все ячейки всех записей.
   - Если страница сбрасывается, второй проход идёт по всему основному буферу и всем записям.
   - Если и он сбрасывает страницу — `RenderError`, как сейчас.
   - То же в GL (`prepare_glyphs`).
6. **GL** (при Н1 и О3 — а).
   - **Ресурсы:**
     - две текстуры `RGBA8UI` размером с сетку в пикселях с FBO к каждой — ping-pong;
     - текстура данных клиентского буфера `RGBA32UI`, растёт до наибольшего буфера кадра и не больше `GL_MAX_TEXTURE_SIZE` (иначе `RenderError`);
     - программа наложения `overlay.frag`.
   - **Кадр с записями:**
     1. `glClearBufferuiv` первой текстуры;
     2. на каждую запись — загрузка её ячеек и проход в другую текстуру: шейдер читает пиксель предыдущей (`texelFetch`), считает ячейку записи по формулам п.3, вне записи копирует пиксель как есть;
     3. основной проход с `u_overlay` (последняя текстура) и `u_has_overlay = 1` — последним шагом `composite`.
   - **Без записей** `u_has_overlay = 0`: проходов наложения нет, один draw call.
   - Аппаратное смешивание выключено, как сейчас.
   - `render_to_frame_overlaid(screen, &Overlay)` — для тестов.
7. **Ресурсы при откате** (FR-21) не переносятся: наложение очищается каждый кадр, клиент нарисует его заново в следующем `on_redraw`.

## Не входит

Пиксельные смещения; наложение на поле вокруг сетки; наложение, живущее дольше кадра; масштаб и поворот буфера; прозрачность окна.

## Риски

- **Цена Software.** Строки под наложением перерисовываются каждый кадр — и основной слой, и наложение. Для наложения на весь экран это полная перерисовка плюс смешивание. Оценка — по замеру шага 7. Возможна просадка ниже 60 FPS на сетке 120×40; тогда — ⚠ и отдельная задача, не обход формулы.
- **Копирование буферов в `push`:** 16 Б на ячейку за кадр. Для 120×40 это 77 КБ — дёшево, но растёт с числом и размером буферов.
- **Ёмкость атласа.** Разных глифов на экране может стать больше; переполнение страницы обрабатывается сбросом (п.5), предел — прежний.
- **Расхождение GL ↔ Software в двух проходах.** Смягчение: одни целочисленные формулы, сцена в `stage4_gl` и мутационная проверка (шаг 4).
- **Ping-pong на слабых GLES-драйверах** (FBO с `RGBA8UI`). Неполный FBO → `RenderError` → откат на Software (FR-18). Проверено будет только на NVIDIA; другие конфигурации — этап 8.
