## Проектные решения этапа (в ADR-0006 после утверждения)

- **Фаза мигания в `Ctx`** (`ctx.blink_phase: bool` — фаза, с которой будет отрисован следующий кадр). Сейчас демо переключает курсор на каждый `on_tick`, стартуя с «видим», — это синфазно с `BLINK`, а после `Blinker::catch_up` (пропущено несколько переключений за одно пробуждение) чётность может уехать. Противофаза по факту: курсор рисуется при `!ctx.blink_phase`. Закрывает риск, названный в ADR-0004 («у приложения нет способа узнать фазу изнутри `Ctx`»).
- **Статистика кадра `FrameStats { frames, cpu, total }`** считается в `App` вокруг `render` (без аллокаций, два `Instant::now()` на кадр): `total` — весь кадр, включая `swap_buffers`/`present`; `cpu` — для GL время `render_into` (сборка данных + `glTexSubImage2D` + draw call, без ожидания VSync — именно это меряет NFR-4), для Software — время `render` без `present`. GL-бэкенд запоминает длительность `render_into` в поле и отдаёт методом; трейт `Renderer` не меняется.
- **`AppHandler::on_frame(&mut self, stats: FrameStats, ctx)`** с пустым телом по умолчанию — вызывается после каждого успешного кадра. Единственный способ для приложения гнать кадры непрерывно (`--bench`); обычное демо его не реализует, поэтому стоимость для прочих приложений — ноль. `Ctx.stats` доступен во всех обработчиках — демо обновляет строку статуса по `on_tick` (2 Гц при периоде 500 мс), чтобы запись в экран не порождала бесконечный цикл перерисовки.
- **`--bench`** (флаг демо, как `--no-blink`): `FixedGrid`, сетка по активному бэкенду — 200×60 для GL/GLES (NFR-4), 120×40 для Software (NFR-5); каждый кадр перезаписываются все ячейки (все строки dirty) символами из набора ASCII, растеризованного на прогреве; 30 кадров прогрева не считаются, затем 300 измеряемых; в stderr — бэкенд, `glyph_px`, сетка, размер окна (и пометка, если сетка обрезана окном — тогда замер Software неполный), `cpu` среднее/медиана/p95/макс, `total` среднее, FPS; выход с кодом 0. Переключение `1/2/3` в `--bench` не используется — замер одного бэкенда за запуск: `demo --bench`, `demo --bench --backend=gles`, `demo --bench --backend=soft`.
- **Разбиение демо** на `src/bin/demo/main.rs` (аргументы, `Demo: AppHandler`, клавиши, курсор), `scene.rs` (статическая сцена, палитра, таблица глифов) и `bench.rs` (`Bench: AppHandler`): `demo.rs` сейчас 429 строк, после этапа превысил бы порог QG-06; у трёх частей разные обязанности.

## Риски этапа

- **Окно под сетку 200×60 не помещается на экран** при высоком DPI (ячейка 17×36 при `glyph_px = 28` → 3400×2160 px): `FixedGrid` обрежет сетку, GL-часть замера (`render_into`) от этого не зависит, а Software рисует только видимые пиксели — замер NFR-5 окажется завышенным. `--bench` печатает размер окна и пометку «сетка обрезана»; честный замер Software — при 100 % DPI либо на экране ≥ 2040×1440.
- **VSync и `cpu` на GL** — первый замер (Windows, NVIDIA 581) показал `cpu` = 16,1 мс при 60 Гц: драйвер ждёт кадр монитора не в `swap_buffers`, а в первом GL-вызове следующего кадра, и CPU-часть неотличима от периода. Поэтому добавлена `AppOptions::vsync` (по умолчанию `true`), `--bench` выключает VSync (`SwapInterval::DontWait`); в обычном режиме ничего не меняется (ADR-0006, уточнение).
- **`on_frame` — петля перерисовки**, если приложение запросит `redraw` из него безусловно; документируется в трейте; демо делает это только в `--bench` с ограничением по числу кадров.
- **`panic = "abort"` в release** уже стоит: `cargo test --release` не работает, гейты — в debug (AGENTS.md).
- **Размер release на Windows** после полного профиля меняется (`lto = "fat"`, `codegen-units = 1`, `strip`) — замер фиксируется как справка, лимита больше нет.
