## Формула и константы (ADR-0005)

```
glyph_px = clamp(round(FONT_SIZE_PX · FONT_SCALE · scale_factor), 8, 48)
```

`FONT_SIZE_PX = 16` (логический размер), `FONT_SCALE = 1.0` (множитель пользователя, константа до появления файла настроек), `scale_factor` — из окна. Всё остальное выводится из метрик растеризации: ячейка = `glyph_w × glyph_h`, сетка = окно ÷ ячейка.

## Риски этапа

- **Пауза при смене DPI**: пересборка хинтеров + сброс страницы + 0,25–0,9 с растеризации видимых глифов. При старте не видна (окно скрыто, FR-22); при переносе окна между мониторами — замирание. Бюджет растеризации отклонён сознательно (ADR-0005 п.8).
- **Переполнение атласа при крупном шрифте**: при `glyph_px = 48` и странице 1024 ёмкость 441 слот; на драйверах с `GL_MAX_TEXTURE_SIZE = 1024` сцена «таблица всех глифов шрифта» (FR-27) не помещается → `RenderError` → откат на Software (страница 2048, 1764 слота). Отслеживать, не превращается ли это в регулярные откаты.
- **`ScaleFactorChanged` на X11/Wayland** может приходить без предложенного размера окна — принимать размер только если `inner_size_writer` его дал, иначе пересчитать сетку по текущему `inner_size`.
- **`ScreenBuffer::resize` при каждом `Resized`** — в `AutoGrid` мышь у края окна даёт серию resize; сохранять содержимое только при реальном изменении `cols/rows`.
- **Хинтер авто пересобирается при смене размера** — при >100 мс первый кадр показывать со старым атласом и дособирать новый лениво (сейчас пересборка синхронна).
- **Публичный API привязан к `winit` 0.30** (ADR-0004) — при апгрейде `winit` ломается API; изоляция в `app.rs` (ТЗ §14).
