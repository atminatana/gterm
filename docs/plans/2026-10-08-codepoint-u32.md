# План: кодовая точка во всём диапазоне Unicode (`u16` → 32 бита)

Статус: **решения приняты владельцем 2026-10-08** (ADR-0009): A — `char`, B — плоский массив, C — `to_packed`/`from_packed` сохраняются (R = `ch`, A = флаги). Задача выполняется **до** SVG-глифов. **Реализовано 2026-10-08** — см. `docs/done/2026-10-08-codepoint-u32.md`. Отклонение: функция записи строки — `write_row` (в плане ошибочно `write_str`).

- **Цель:** `Cell::ch` и ключ атласа охватывают весь Unicode U+0000–U+10FFFF. Это открывает 6 896 глифов шрифта вне BMP (Material Design Icons, U+F0001–U+F1AF0) и даёт SVG-глифам имена в 4–6 HEX-цифр, с плоскостью U+100000–U+10FFFD под тайлы.
- **ТЗ:** FR-2 (`ch: u16`), FR-4 (API записи), FR-8.4 («все кодовые точки BMP»), FR-9 (таблица «кодовая точка → слот» на 65 536), §6.1 (данные GPU — **не меняются**), §13 (пункт «Unicode вне BMP» — выполняется частично: без второго шрифта и LRU). ADR-0001 п.6 и ADR-0003 (область — BMP) уточняются новым ADR.
- **Факты по коду (проверено 2026-10-08):**
  - GPU получает **номер слота**, а не кодовую точку: `gl_backend.rs:587` (`slot | flags << 16`), `soft_backend.rs:163`. Слот остаётся `u16`, поэтому шейдер, текстура данных, атлас-страница и golden-эталоны не меняются.
  - Кодовая точка как `u16`:
    - `cell.rs:119` — поле `ch`, `cell.rs:150-167` — `to_packed`/`from_packed`: `ch` в битах 0–15, флаги в 16–31; используется только тестом `stage1_buffer.rs:164`;
    - `buffer.rs:89,104,127` — `set_cell`, `write_str`, `fill_rect`;
    - `atlas.rs:42,44,173,190,240,269` — `slot_by_codepoint`, `codepoint_of_slot`, `slot_of`, `ensure`, `glyph`, `fill_channel`;
    - `rasterizer.rs:149,164` — `has_glyph`, `rasterize`;
    - `box_drawing.rs:6,8,56,61,339,366`;
    - бинарники: `demo/{main,scene,bench}.rs`, `full_table/main.rs:43,124,148,157,231`;
    - тесты: `common`, `events_common`, `stage1_buffer`, `stage2_font`, `stage3_render`, `stage6_app` — около 80 мест вида `'A' as u16`.
  - **Дефект:** `buffer.rs:104` — `write_str` делает `c as u16`: символ вне BMP молча обрезается до младших 16 бит (U+F0001 → U+0001). Исправляется самим переходом.
  - `full_table` перебирает `0x20..=u16::MAX` через `has_glyph` (`full_table/main.rs:124`). На всём диапазоне это 1,1 млн вызовов — нужен перебор по `cmap` (шаг 5).

## Решения (AR-04) — закрыты 2026-10-08: A(а), B(а), C(а)

A. **Тип кодовой точки.**
   - (а) **`char`** — `ch: char`, API `set_cell(…, ch: char, …)`, `ensure(ch: char, …)`. Компилятор гарантирует допустимое значение (≤ U+10FFFF, без суррогатов), литералы `'A'` без приведений (уходят ~80 `as u16` в тестах), `write_str` пишет `char` как есть, `0` — `'\0'`. В памяти те же 4 байта, что `u32`. *Рекомендую.*
   - (б) **`u32`** — буквально, но допускает недопустимые значения (> U+10FFFF, суррогаты); нужна проверка в `Atlas::ensure` (недопустимое → слот 0) и `as u32` во всех литералах.
B. **Таблица «кодовая точка → слот» в атласе.**
   - (а) **плоский массив** на 0x110000 записей `u16` — 2,2 МБ (страница атласа 16 МБ). Код меняется в одной строке, доступ O(1) как сейчас. Сброс страницы (переполнение, смена DPI) заливает 2,2 МБ вместо 128 КБ — доли миллисекунды, редко. *Рекомендую — минимальный дифф.*
   - (б) двухуровневая таблица по плоскостям Unicode (17 × 64 К, плоскость выделяется при первом обращении): 128 КБ на занятую плоскость, на одно обращение к памяти больше; выделение на промахе вне горячего пути. Больше кода.
   - (в) `HashMap` — хэширование на каждую ячейку каждого кадра (`slot_of` в горячем пути GL), отклоняю.
C. **`Cell::to_packed`/`from_packed`** (раскладка `ch | flags << 16` больше не помещается; в рендерерах не используется):
   - (а) **R = `ch` целиком, A = флаги** (A сейчас резерв). Тест `stage1_buffer` обновляется. *Рекомендую — API сохраняется.*
   - (б) удалить оба метода как неиспользуемые — меньше кода, но меняет публичный API без просьбы (BP-07.2).

## Не входит

Второй шрифт (fallback-цепочка шрифтов), LRU и вторая страница атласа, комбинируемые символы и широкие (East Asian Wide) символы на 2 ячейки, SVG-глифы (следующая задача).

## Риски

- **Ломающее изменение публичного API** (`Cell::ch`, `set_cell`, `fill_rect`, `Atlas`, `Rasterizer`): внешних потребителей у крейта пока нет, внутри — все места перечислены выше.
- **Ячейка 12 → 16 байт** (при `char`/`u32` поле 4 байта, выравнивание по `Color`): буфер 200×60 вырастет с 144 до 192 КБ — несущественно.
- **Ёмкость страницы.** 6 896 иконок MDI плюс 5 020 глифов BMP = ~11,9 тыс. Страница 2048² при ячейке 10×21 вмещает ~19 тыс. слотов (ADR-0003), при 26 px (~16×34) — около 7,7 тыс. **`full_table` целиком не поместится, но он листает постранично** — сброс атласа на переходе страницы уже предусмотрен (FR-9). Экран всегда помещается.
- **Число глифов шрифта:** в ТЗ FR-8.4 и ADR-0003 записано 3 371 BMP, разбор `cmap` даёт 5 020 BMP + 6 896 вне BMP. Сверить подсчётом `full_table` на шаге 5 и исправить ТЗ.
- **Не проверено, к задаче не относится:** при `glyph_px = 8` ёмкость страницы может превысить 65 535 слотов, тогда `slot as u16` (`atlas.rs:205`) переполнится. Проверить отдельно расчётом ёмкости при минимальной ячейке.
