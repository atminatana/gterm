# План: многопоточная отрисовка Software-рендерера

Статус: **реализовано 2026-10-10** — см. `docs/done/2026-10-10-soft-threads.md`. ТЗ утверждено 2026-10-10 (О1 — `rayon`, О2 — ≤ 4 потоков, О3 — сейчас). Отклонение: в раздачу полос передаётся число строк сетки (`grid_rows`), а не выводится из длины среза.

- **ТЗ задачи:** `docs/spec/2026-10-10-soft-threads.md`.
- **Опирается на:** ADR-0010 (частичный кадр), ADR-0014/0015 (наложение, кэш текстуры), NFR-6, NFR-9.

## Факты по коду (проверено 2026-10-10)

- `SoftBackend::render_overlaid` (`src/renderer/soft_backend.rs`): подготовка глифов (меняет атлас) → `draw_row` для отмеченных строк → `draw_overlay` (сборка текстуры при необходимости + `composite_row`) → `collect_damage`.
- Строка сетки `r` в кадре — пиксельные строки `origin_y + r·cell_h …` шириной окна; в текстуре — `r·cell_h …` шириной сетки. Полосы строк не пересекаются → `chunks_mut` без `unsafe`.
- `Atlas: Sync` (проверено компиляцией), `ScreenBuffer` и `Overlay` только читаются.
- Владелец решения об отказе от своего пула: свой пул на `std` требует `unsafe` для одолженных данных (NFR-9), `thread::scope` — 13 выделений на кадр (NFR-6).

## Проектные решения (уйдут в ADR-0016)

1. **Пул** — `rayon::ThreadPool` в `SoftBackend` (`Option`: ошибка создания → однопоточно). Потоки создаются в конструкторе, не в кадре.
2. **Полоса** — непрерывный диапазон строк сетки; полос столько, сколько потоков; `par_chunks_mut` по кадру и по текстуре.
3. **Одна реализация.** Отрисовка полосы — свободные функции над срезом полосы и неизменяемым контекстом кадра (атлас, экран, геометрия, отметки строк, текстура). Однопоточный путь — та же функция для всего кадра. Методы `draw_row`/`draw_cell`/`fill_pixel`/`composite_row`/`draw_overlay_cell` переходят в эти функции.
4. **Порог.** Если строк к перерисовке меньше `PARALLEL_MIN_ROWS` (8) — в текущем потоке; сборка текстуры — по числу строк под наложением.
5. **Порядок кадра.** Текстура собирается до основного слоя (она от кадра не зависит), затем одним проходом по полосам: строки основного слоя и наложение на них.

## Шаги

1. Зависимость `rayon = { version = "1.12", default-features = false }`; `Cargo.lock`.
2. Перенос отрисовки в функции полосы, однопоточно (модуль `src/renderer/soft_band.rs`). Проверка: все тесты рендера без изменений эталонов (характеризация — golden, `stage4_gl`, `tests/overlay.rs`, `soft_partial_redraw`).
3. Пул и параллельный проход по полосам кадра и текстуры; `with_threads`; порог. Проверка: тест К1, тесты рендера.
4. Тест К2 (счётчик выделений) — отдельный тест-бинарник.
5. Замеры К3–К5, размер бинарника.
6. Документы: ADR-0016 и индекс, `PROJECT_MAP.md`, `AGENTS.md`, `TODO.md`, отчёты `done`/`test`/`verify`.

## Риски

- Однопоточный путь при `opt-level = "z"` компилируется хуже, чем тело задачи потока (в прототипе 16,0 против 12,9 мс). Защита — К5; при регрессии — разбор кода по замеру.
- Потоки `rayon` спят между кадрами; лишняя нагрузка на CPU в простое — проверить по диспетчеру задач на машине владельца.
