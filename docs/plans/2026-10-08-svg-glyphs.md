# План: SVG-глифы — изображения как дополнение к шрифту (и карта из тайлов)

Статус: **реализовано 2026-10-08** (ADR-0008) — см. `docs/done/2026-10-08-svg-glyphs.md`. Отклонения от плана: (а) правки ТЗ — версия 1.7 (1.6 заняла задача `codepoint-u32`); (б) отдельного golden-файла SVG нет — растр SVG проверяется точными пикселями в `tests/svg_glyphs.rs` и сравнением GL ↔ Software в `stage4_gl`; (в) обводки с `stroke-dasharray` поддержаны (штрихи `tiny-skia-path`) — дешевле, чем отбрасывать; (г) подключение к растеризатору — `Rasterizer::set_svg_glyphs`.

- **Постановка владельца (2026-10-08):** поддержка SVG-изображений, которые дополняют набор глифов шрифта; кодовая точка Unicode — в имени файла в HEX; цвета фигуры считаются чёрными, на экран выводятся как у глифов шрифта; в бинарниках увеличить шрифт; вопрос, можно ли собрать карту из SVG.
- **ТЗ:** FR-2 (`ch: u16`), FR-8, FR-8.4, FR-8.5, FR-9, FR-10, §5.2 (`AppOptions`), §6.3, §7.3, NFR-1, NFR-6, NFR-7, §13.
- **Факты по коду и шрифту (проверено 2026-10-08):**
  - SVG встраивается по образцу процедурной псевдографики: `Rasterizer::rasterize` → `scratch` → `Atlas::fill_channel` (все 4 канала). Рендереры и шейдер не меняются.
  - `FONT_SIZE_PX` читается в `app.rs:445`, `app.rs:483`, `app.rs:698`.
  - Стартовые сетки: `demo` 80×25 (`scene.rs:11-12`), `full_table` 80×45 (`full_table/main.rs:34-35`), `--bench` — `FixedGrid` 200×60 / 120×40.
  - `cmap` шрифта `RobotoMonoNerdFontMono-Regular.ttf` (разбор скриптом): 5 020 кодовых точек BMP и **6 896 вне BMP (U+F0001–U+F1AF0, Material Design Icons)**. Вторые сейчас недоступны из-за `ch: u16`. В ТЗ FR-8.4 и ADR-0003 записано «3371 BMP» — расхождение с подсчётом, причина не выяснялась.
  - Свободные блоки PUA (≥ 64 подряд): U+E00B–E09F (149), U+E0D8–E1FF (296), U+E2AA–E2FF (86), U+E3E4–E5F9 (534), U+E6BC–E6FF (68), U+E959–EA5F (263), U+EC85–ECFF (123), U+F386–F3FF (122), U+F534–F6C2 (399), **U+F6C4–F8FF (572)**. Для тайлов рекомендуется U+F6C4–U+F8FF либо U+E3E4–U+E5F9. Новые версии Nerd Fonts могут занять эти блоки.

## Решения владельца (2026-10-08) — ADR-0008

1. Разбор — `usvg`, растеризация — `zeno`.
2. Приоритет: **SVG > псевдографика > шрифт**.
3. Вписывание **с сохранением пропорций**, по центру ячейки.
4. Логический размер шрифта в бинарниках — **26** (поле `AppOptions::font_size_px`).
5. Каталог `assets/svg/`, имя — **только HEX-код и `.svg`** (4–6 цифр после решения 6), без префиксов и суффиксов.

**Допущение агента (локальное, обратимое — BP-02.3):** `demo --bench` оставляет размер 16. Иначе 200×60 при 26 px не поместится ни на один экран, и замеры NFR-4/NFR-5 перестанут сравниваться с этапом 7. Если нужно и в `--bench` 26 — одна строка в `bench.rs`.

## Решение 6 — закрыто 2026-10-08

6. **(б)** Сначала отдельной задачей — переход кодовой точки на 32 бита (`docs/plans/2026-10-08-codepoint-u32.md`), затем эта задача. Имя SVG — **4–6 HEX-цифр** (ADR-0008 п.2), под тайлы рекомендуется плоскость U+100000–U+10FFFD.

## Проектные решения

Подробно — ADR-0008. Ключевое для реализации:

- **`src/svg.rs`:** `SvgGlyphs::load(assets_dir)`:
  - перечисляет `assets/svg/`, имя проверяет по `^[0-9A-Fa-f]{4,6}\.svg$`, значение ≤ U+10FFFF и не суррогат;
  - разбирает файл через `usvg`, переводит обводки в заливку;
  - хранит контур в координатах `viewBox` как `Vec<zeno::Command>` и размер `viewBox`;
  - печатает итог в stderr: `gterm: svg: N glyphs from <dir> (M override)`.
- **`Rasterizer`:** владеет `SvgGlyphs`.
  - `has_glyph` → SVG, затем псевдографика, затем шрифт.
  - `rasterize` → SVG первым: равномерный масштаб `s = min(w / vb_w, h / vb_h)`, центрирование, `zeno::Mask` в `out` без хинтинга. Затем псевдографика, затем шрифт.
- **`Atlas::fill_channel`:** все 4 канала для SVG (признак «процедурный» обобщается до «одинаков во всех начертаниях»).
- **`AppOptions::font_size_px`:** три чтения `FONT_SIZE_PX` в `app.rs` заменяются полем. `common::demo_options` ставит 26, лог `load_family` печатает фактический размер.

## Не входит

Цвета из файла, градиенты, прозрачность, `<image>`/`<text>`, широкие тайлы на 2 ячейки, горячая перезагрузка, SVG из памяти.

## Риски

- **Квадратные тайлы в ячейке 1 : 2** при сохранении пропорций занимают около половины высоты: карта из квадратных картинок будет «полосатой». Для карты рисовать тайлы в пропорции ячейки. Точную пропорцию при 26 px покажет stderr (`cell WxH`).
- **Окно `full_table` при 26 px:** ячейка вырастает примерно в 26/16 ≈ 1,6 раза. Стартовая сетка 80×45 даёт высоту около 1,5 тыс. логических px — больше экрана 1080p. Сетка `AutoGrid` подстроится под окно, которое ограничит система, но если окно окажется за краем экрана — уменьшить стартовую сетку (согласовать).
- **Потолок `glyph_px = 48`** при DPI ≥ 1,85: на 200 % шрифт будет 48, а не 52.
- **SVG на U+2500–U+259F** ломает стыковку линий; **SVG на занятой иконке** Nerd Font молча её заменяет — оба случая видны в логе перекрытий.
- **Размер бинарника** растёт на `usvg` (замеряется); **дрейф версий `usvg`** — фиксируется `Cargo.lock`.
