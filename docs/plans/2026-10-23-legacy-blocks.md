## Проектные решения (зафиксированы в ADR-0022)

1. `procedural.rs`: `pub(crate) Canvas` (перенесён из `box_drawing`), `is_procedural`, `draw` — диспетчер по трём модулям, `ranges()` — объединённые диапазоны для примеров.
2. `block_mosaic.rs`: сетки через `edge(len, k, n) = (len·k + n/2) / n` — та же формула, что у восьмушек и квадрантов, поэтому октанты 2×4 совпадают с квадрантами 2×2 по границам; секстанты и октанты по таблицам; Centered и ■ — сетка 4×4; восьмушки U+1FB82–8B — сетка 8; U+1CEA0/A3/A8/AB и U+1FBE6/E7 — как октанты.
3. `shapes.rs`: `fill_region(inside)` — доля из 4×4 точек пикселя внутри области; выпуклые многоугольники — по знаку векторных произведений; эллипсы — по уравнению; части кругов — эллипсы радиусов `(w/2,h/2)` (◖◗ и ●), `(w, h/2)` / `(w/2, h)` (половины U+1FBE8–EB), `(w, h)` (четверти U+1FBEC–EF) с центром на стороне/в углу; диагонали — сторона прямой A–B, где лежит угол.
4. Растеризатор: `is_procedural`/`procedural::draw` вместо `is_box_drawing`/`box_drawing::draw` — новые наборы в `Font`/`Combined` ведут себя как рамки.
5. Пример: строки-образцы наборов (секстанты, октанты, Centered, восьмушки, круги с композициями 2×1/1×2/2×2, треугольники, диагонали), случайное заполнение из `procedural::ranges()`.

## Риски

- Трактовка ■ как центрального блока 2×2 сетки 4×4 (ряд «Centered» автора) — отличается от шрифтового ■, который крупнее; при возражении — одна константа.
- Общие рёбра областей при сглаживании считаются обеими сторонами (по 1/16 покрытия) — сумма дополнений может превышать 255 на 16; тесты с допуском.
