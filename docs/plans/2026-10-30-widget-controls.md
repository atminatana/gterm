# План: контролы с фокусом, маршрутизацией ввода и сообщениями в `gterm-widgets`

Статус: **выполнен 2026-10-30** — см. `docs/done/2026-10-30-widget-controls.md`. Отклонения от плана: `Element` получил время жизни описания (`Element<'a, M>`) ради привязок-замыканий; мышь внутри модального слоя мимо контролов поглощается (уточнение контракта, не было в ТЗ); захват снимается отпусканием любой кнопки (кнопка захвата не хранится); оконный тест проверяет `cell_px` и пустые модификаторы, инжекции ввода нет.

- **ТЗ задачи:** `docs/spec/2026-10-30-widget-controls.md` (утверждено владельцем 2026-10-30; решения О1–О5 в §6 ТЗ).
- **Решения:** ADR-0026 (`docs/adr/0026-widget-controls.md`).
- **Опирается на:** ADR-0004 (контракт `AppHandler`, типы `winit`), ADR-0013/0014 (альфа, наложение `DrawCtx::draw_buffer`), ADR-0023 (немедленный режим, `Widget`/`StatefulWidget`, `Layout`, `Popup`).
- **Исследование:** `docs/research/2026-10-30-controls-interview.md`.

## Факты по коду (проверено 2026-10-30)

- `app/events.rs`: `KeyboardInput` → `on_key` только для `Pressed` (стр. 38); `CursorMoved` хранит положение в `App.pointer: PhysicalPosition<f64>` (`mod.rs:56`) и считает дельту; `MouseInput`/`MouseWheel`/`CursorLeft` → `PointerEvent::{Input, Wheel, Left}` без координат; `WindowEvent::ModifiersChanged` не обрабатывается. `notify` собирает `Ctx { screen, request, stats }`.
- `app/window.rs:17`: `pub(super) fn cell_px(&self) -> (usize, usize)` — метрики атласа активного бэкенда, `(1, 1)` до бэкенда.
- `api.rs`: `PointerEvent<'a>` — `Copy`, варианты `Moved { position, delta }`, `Input { state, button }`, `Wheel { delta: &MouseScrollDelta }`, `Left`; `Ctx<'a>` — `screen`, `request`, `stats`; `DrawCtx` — `draw_buffer`, `grid()`.
- `gterm-widgets`: `Widget::render(self, area, buf)`, `StatefulWidget::render(self, area, buf, state)` (`widgets/mod.rs:21-28`); `ListState { offset, selected }` с `select_next/previous/first/last`; `List::visible_range` и `Table::first_visible` уже вычисляют первую видимую строку по высоте пунктов — место для карты строк; `Block::inner(area)`, `Block::border_style`; `Layout::split(area) -> Vec<Rect>`; `Popup { area, style }` с `centered`, `local_area`, `buffer`, `draw`. `winit` только в `dev-dependencies`.
- `examples/widgets.rs`: `Demo { backend, focus: Focus, list, table, popup: bool }`, `draw` раскладывает вручную, `on_key` — `match` по `Focus`, `on_redraw` рисует `Popup`.
- Оконные тесты (`stage6_events`, `events_common/mod.rs`) не инжектируют ввод: проверяют уведомления, `Request`, статистику. Клавиши и мышь с окна в тестах недоступны.
- Образцы `PointerEvent::` вне библиотеки (grep 2026-10-30): `crates/gterm-demo/src/bin/demo/main.rs:219` — `Moved { position, .. }` (уже с `..`), `:223` — `Input { state, button }` без `..`, `crates/gterm-demo/src/bin/full_table/main.rs:334` — `Wheel { delta: LineDelta(_, lines) }` без `..`; в примерах и тестах `gterm` и в `gterm-widgets` совпадений нет. Два образца правятся в шаге 1.

## Проектные решения (зафиксированы в ADR-0026)

1. **Контрол — трейт `Control<M>` на состоянии.** `fn node(&self) -> &NodeState`, `fn node_mut(&mut self) -> &mut NodeState` (общий блок `NodeState { focused: bool, area: Rect, captured: bool }`, `Default`), `fn focusable(&self) -> bool` (по умолчанию `false`), `fn key(&mut self, &KeyMsg, &mut Messages<M>) -> Handled` и `fn mouse(&mut self, &MouseMsg, &mut Messages<M>) -> Handled` (по умолчанию `Handled::No`). Встроенные состояния `ListState`, `TableState`, `ButtonState` получают поле `pub node: NodeState` и `impl<M> Control<M>`; свой контрол приложения — одно поле `node` плюс реализация. Флаги фокуса и области живут в состоянии: исчезновение контрола из описания обнаруживается (цепочка `focused` пуста → фокус первому кандидату), идентификаторов и индексов не нужно.
2. **Сообщения ввода** (`input.rs`): `KeyMsg<'a> { key: &'a Key, text: Option<&'a str>, modifiers: ModifiersState }` — строится из `&KeyEvent` и `Ctx::modifiers` (сам `KeyEvent` не хранится: в тестах без окна его не сконструировать, `Key`/`ModifiersState` — можно); `MouseMsg { kind: MouseKind, button: Option<MouseButton>, col: i32, row: i32, modifiers }`, `MouseKind::{Down, Up, Move, Wheel { lines: f32 }, Cancel}`; `MouseMsg::from_pointer(&PointerEvent, &Ctx) -> Option<MouseMsg>` (ячейка — из события, `Wheel.lines` — `LineDelta.y` как есть, `PixelDelta.y / cell_px.1`, `Left` → `Cancel`); `Handled::{Yes, No}`; `Messages<M>` — обёртка над `Vec<M>` с `push`, передаётся обработчикам `&mut` (О1); результат маршрутизации `Routed<M> { handled: Handled, messages: Vec<M> }` → `IntoIterator` по сообщениям.
3. **Описание экрана `Ui<'a, M>`** (`ui/`): временное дерево; узлы в `Vec` в порядке объявления в глубину с индексом родителя; элементы — `Box<dyn Element<M> + 'a>` только в этом векторе (в состояниях приложения `Box` нет). Конструкторы: `Ui::split(Layout, Vec<Ui>)` — прозрачный контейнер; `Ui::group(Block<'a>, Layout, Vec<Ui>).focus_style(Style)` — контейнер с рамкой, стиль накладывается на `border_style`, когда фокус внутри; `Ui::control(&'a mut C)` при `C: Control<M>` — свой контрол (сам рисует: `C: Control<M>` дополнительно требует `fn render(&mut self, area, buf)`; для разделения вида и поведения у встроенных см. следующий пункт); `Ui::stateful(widget: W, state: &'a mut S)` при `W: StatefulWidget<State = S>, S: Control<M>` с привязками `.on_select(fn(usize) -> M)` (список/таблица), `.on_activate(M)` (кнопка); `Ui::widget(W: Widget)` — лист без состояния. Методы: `layout(area)` пишет `node.area`; `render(self, area, &mut ScreenBuffer)` — раскладка и отрисовка; `key(&mut self, &KeyEvent, &Ctx) -> Routed<M>`; `pointer(&mut self, &PointerEvent, &Ctx) -> Routed<M>`; `focus_first()`; `draw_modal(self, &mut DrawCtx)` — отрисовка модального слоя через `Popup`.
4. **Фокус:** кандидаты — узлы `Control` с `focusable()`; порядок — обход дерева в глубину; `Tab`/`Shift+Tab` (по `modifiers.shift_key()`) перехватываются до контролов, кольцо; установка фокуса снимает `focused` у всех узлов дерева и ставит целевому; нет ни одного `focused` среди кандидатов (старт, исчезновение) — `focus_first` перед доставкой клавиши; `Ui::group` подсвечивает рамку, если `focused` у любого потомка.
5. **Маршрутизация:** клавиша — контролу с `focused`, иначе приложению (`Handled::No`, без сообщений); без фокуса — приложению. Мышь: при `captured` у какого-то узла `Move`/`Up`/`Cancel` идут ему, `Up` той же кнопки и `Cancel` снимают захват; иначе адресат — последний в порядке обхода узел-контрол, чья `area` содержит `(col, row)`; левый `Down` на `focusable` ставит фокус до `mouse`; узел, ответивший `Yes` на `Down`, получает `captured`. `Ui::widget`-листы не адресуются (мышь по ним — «не обработано»).
6. **Модальный слой `Modal<'a, M>`** (`ui/modal.rs`): `Modal::centered(width, height).style(Style).on_escape(M).content(Ui)`; область — центрирование по сетке в момент маршрутизации/отрисовки (из `Ctx::screen` или `DrawCtx::grid()`); маршрутизация: при наличии слоя все клавиши и мышь идут ему; мышь переводится в локальные ячейки (`col - area.x`), вне области — `Handled::Yes` без сообщений (О2); `Esc`, не взятый контролом слоя, → `on_escape` или `Handled::No` (О5); отрисовка — `Popup::new(area).style(style)` → `buffer()` → `content.render(local_area, &mut buffer)` → `popup.draw(ctx, &buffer)` (О3; `Popup` не меняется).
7. **Встроенные контролы.** `Button<'a>` (`widgets/button.rs`): `label: Line<'a>`, `style`, `focus_style`, `pressed_style`, `disabled_style`; `ButtonState { node, enabled, pressed }`: `focusable = enabled`; `Enter`/пробел → сообщение привязки; левый `Down` в области → `pressed = true`, `Handled::Yes` (захват); `Up` внутри области → сообщение, `Up` снаружи/`Cancel` → сброс (О4). `ListState`/`TableState`: `↑`/`↓`/`Home`/`End`/`PgUp`/`PgDn`; `Down` по строке → выделение; `Wheel` → выделение на `round(lines)`; сообщение привязки `on_select` — только при изменении выделения. Для попадания клика `List::render`/`Table::render` пишут в состояние `rows: Vec<Option<usize>>` (строка области → индекс пункта; вектор переиспользуется) и `len`. `List`/`Table` получают `focus_style(Style)` — накладывается на рамку при `state.node.focused`. Привязки встроенных живут в элементе дерева (`Ui::stateful(...).on_select(..)`), а не в состоянии: состояние лишь сообщает дереву «выделение изменилось на i» через возвращаемое значение внутреннего хука (`Control::key`/`mouse` возвращает `Handled`, а изменение выделения элемент дерева читает из `state.selected` до/после вызова — без новых типов).
8. **Изменения `gterm`:** `PointerEvent::Moved/Input/Wheel` получают `cell: (i32, i32)` (= `floor(pointer / cell_px)`, чистая функция `cell_of(position, cell_px)` в `app/mod.rs`); `Ctx` получает `modifiers: ModifiersState` (поле `App.modifiers`, `WindowEvent::ModifiersChanged` → `self.modifiers = m.state()`) и `cell_px: (u32, u32)`; `Request`, рендереры не меняются.
9. **Зависимость:** `winit` переезжает в `[dependencies]` `gterm-widgets` с теми же фичами, что у `gterm` (`rwh_06`, `x11`, `wayland`, `wayland-dlopen`); новых транзитивных зависимостей нет.

## Шаги

1. **`gterm`: ячейка и модификаторы.** `api.rs` — поля `cell` в `PointerEvent`, `modifiers`/`cell_px` в `Ctx`; `mod.rs` — `App.modifiers`, `cell_of`; `events.rs` — `ModifiersChanged`, передача `cell` и `modifiers`; `notify` заполняет `Ctx`. Поправить образцы `PointerEvent::` в демо/примерах/тестах. Тесты: единичный `cell_of` (границы, отрицательные, `(1,1)` до бэкенда) в `stage6_app`; `events_common::Probe` пишет `ctx.modifiers` и `ctx.cell_px` в `Log`, `stage6_events` проверяет `modifiers == empty()` и `cell_px` равен метрикам шрифта (ввод с окна недоступен — ограничение в отчёте тестов). Проверка: `cargo test -p gterm`, `cargo run --bin demo` собирается.
2. **`gterm-widgets`: ввод и контрол.** `Cargo.toml` — `winit` в `[dependencies]`; `input.rs` (`KeyMsg`, `MouseMsg`, `MouseKind`, `Handled`, `Messages`, `Routed`), `control.rs` (`NodeState`, `Control<M>`); `lib.rs` — экспорт. Тесты: `MouseMsg::from_pointer` (ячейка, колесо построчно/попиксельно, `Left` → `Cancel`) в `tests/input.rs`. Проверка: `cargo test -p gterm-widgets`.
3. **Дерево: раскладка, отрисовка, фокус.** `ui/mod.rs` (`Ui`, узлы, `split`/`group`/`control`/`stateful`/`widget`, `layout`, `render`), `ui/focus.rs` (`focus_first/next/prev`, сброс флагов, подсветка группы). Тесты: `tests/tree_render.rs` (кадр дерева = ручной рендер; области в `node.area`; лишние дети пусты; `focus_style` группы и листа только при `focused`), `tests/focus.rs` (таблица деревьев из контролов-заглушек: порядок, кольцо, обратный, пропуск нефокусируемых и `widget`-листов, без кандидатов, исчезновение фокуса). Проверка: `cargo test -p gterm-widgets`.
4. **Маршрутизация клавиатуры и мыши.** `ui/route.rs`: `key` (Tab-перехват, доставка фокусу, «не обработано»), `pointer` (адресат по области, фокус по левому `Down`, захват до `Up`/`Cancel`), сбор сообщений в `Routed`. Тесты: `tests/route.rs` с заглушками, пишущими журнал вызовов (К2, К3, К4: доставка, `Tab`, без фокуса, верхний узел, фокус до доставки, нефокусируемый, захват вне области и снятие, вне всех областей, публикация из заглушки через `Messages`). Проверка: `cargo test -p gterm-widgets`.
5. **Модальный слой.** `ui/modal.rs` (`Modal`, `Ui::modal`, перевод ячеек, поглощение вне области, `on_escape`, `draw_modal` через `Popup`). Тесты: `tests/modal.rs` — ввод только слою, фокус экрана не тронут, локальные ячейки, клик вне поглощён, `Esc` → `on_escape`/«не обработано», кадр слоя через `SoftBackend` как в `tests/popup.rs` (пиксель под окном — фон слоя); `tests/popup.rs` без изменений. Проверка: `cargo test -p gterm-widgets`.
6. **Встроенные контролы.** `widgets/button.rs` (`Button`, `ButtonState`); `ListState`/`TableState`: `node`, `rows`, `len`, `impl Control`, `focus_style`; привязки `on_select`/`on_activate` в элементе дерева. Тесты: `tests/widgets.rs` дополняется (кнопка в четырёх состояниях, активация клавишей, `Down`+`Up` внутри, `Up` снаружи и `Cancel` — отмена, неактивная не реагирует; список/таблица: клавиши, `on_select` только при изменении, `PgUp`/`PgDn` по карте, клик по строке многострочного пункта, колесо); старые ожидания не меняются. Проверка: `cargo test -p gterm-widgets`.

## Риски

- Обобщение `M` через `Element<M>`, `Ui<'a, M>`, `Modal<'a, M>` — компилируемость проверить в шаге 3 на минимальном дереве до написания маршрутизации; при проблемах с выводом типов у `Ui::widget` (без `M`) — явный `Ui::<M>::widget` или `PhantomData`.
- Привязка `on_select` читает `state.selected` до и после вызова — работает для `ListState`/`TableState`, где выделение публично; для своих контролов привязок нет (они публикуют сами), так что общего хука не требуется.
- Образцы `PointerEvent::Moved { position, delta }` в чужом коде перестанут собираться — проверка `grep` до шага 1, правка на `..`.
- `ModifiersChanged` на окне не проверяется без инжекции ввода — отчёт тестов фиксирует ограничение; глазами — владелец (К8).
- Карта строк `rows` и `len` в состояниях списка/таблицы заполняются только при `render` — клик до первого кадра не сопоставляется (как и `area`); документировать в rustdoc.
