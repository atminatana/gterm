# План: основа, тона и вывод недостающих областей темы; темы sniffnet

Статус: **выполнен 2026-11-23** — см. `docs/done/2026-11-23-theme-roles.md`. Отклонения от плана: шаг 6 — коэффициенты по снимкам менять не пришлось; код виджетов не правился (как и предполагалось в «Фактах по коду»).

- **ТЗ задачи:** `docs/spec/2026-11-23-theme-roles.md` (утверждено 2026-11-23: О6 — (c) `ui.control*`, О1–О5 — (a)).
- **Решения:** ADR-0038 (`docs/adr/0038-theme-derivation.md`).
- **Опирается на:** ADR-0037 (области, запасные цепочки, `Theme::list`), ADR-0013 (альфа цвета), ADR-0003 (`BOLD` осветляет цвет).

## Факты по коду (проверено 2026-11-23)

- Каждый виджет ищет сначала свою область: `theme.first(&["ui.button", scope::MENU])` (`button.rs:170`), так же флажок, поле, список, таблица, вкладки, полоса, индикаторы (`grep theme.first|find|inactive` по `src/widgets/`). Значит, если вывод записывает недостающие области в саму тему под их именами, код виджетов не меняется, а прежние цепочки продолжают работать для темы без основы.
- Тесты `tests/theme_widgets.rs` собирают темы через `Theme::new` + `set` и вывода не зовут: запасные цепочки helix в них остаются проверенными без правок.
- `Theme::default()`, `gterm_dark`, `gterm_light` не задают `ui.checkbox.pressed|disabled`, `ui.input.selection`, `ui.combo*`, `ui.tabs.focus`, `ui.gauge.unfilled` (встроенная — ещё `ui.checkbox.focus`, `ui.input.placeholder`): сейчас они берутся по цепочкам ADR-0037 — ссылки уровня 3 для них повторяют эти цепочки (уточнение в ТЗ).
- `load.rs`: тема собирается в `build()` — единственная точка для вызова вывода при загрузке.
- Темы sniffnet: 10 файлов `resources/themes/*.toml` и 12 палитр в `src/gui/styles/custom_themes/*.rs` (`color!(0x…)`), коммит `247b75b`, лицензия `MIT OR Apache-2.0`.
- Базовый прогон (коммит `4920525`, тот же код): 348 тестов, 0 падений.
