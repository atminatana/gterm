# План: комбинации клавиш — модуль `gterm::hotkey`, запись и разбор, трекер, пример `hotkeys`

Статус: **выполнен 2026-10-30** — см. `docs/done/2026-10-30-hotkeys.md`. Уточнения при реализации: правило скобок в записи — без скобок продолжение ряда модификаторов (`Ctrl+Shift+[K,U]`) и линейная цепочка (`Ctrl+K+U`), иначе группа в скобках (`Space+[Ctrl+[K,U]]`, как в постановке); разбор принимает и псевдоним, и имя варианта `KeyCode` (`1`/`Digit1`, `Esc`/`Escape`); имена сканируются как любые буквы и цифры Unicode — кириллица даёт «неизвестная клавиша», а не «лишний символ».

- **ТЗ задачи:** `docs/spec/2026-10-30-hotkeys.md` (утверждено 2026-10-30; О1–О3 — рекомендованные варианты).
- **Решения:** ADR-0028 (`docs/adr/0028-hotkeys.md`).
- **Опирается на:** ADR-0004 (библиотека ввод не интерпретирует — трекер кормит приложение), ADR-0026/0027 (`Ui::key` в `gterm-widgets`).

## Факты по коду (проверено 2026-10-30)

- `app/events.rs:38` — `KeyboardInput … if event.state == ElementState::Pressed` → `on_key`; `api.rs:137` — документация «нажатие или отпускание». Обработчики `on_key` в `demo`, `full_table`, `overlay`, `pseudographica`, `widgets`, `widget_edit` проверяют `state == Pressed` сами; `minimal` клавиш не обрабатывает.
- `winit 0.30.13`: `KeyEvent { physical_key: PhysicalKey::Code(KeyCode) | Unidentified, repeat, state, … }`; `KeyCode` — `#[non_exhaustive]`, 194 варианта (список снят из `keyboard.rs`): `Key*`, `Digit*`, `Arrow*`, `F1`–`F35`, `Numpad*`, знаки (`Backquote`, `Backslash`, `BracketLeft/Right`, `Comma`, `Equal`, `IntlBackslash`, `IntlRo`, `IntlYen`, `Minus`, `Period`, `Quote`, `Semicolon`, `Slash`), модификаторы `Control/Alt/Shift/Super{Left,Right}`, прочие (`Escape`, `Space`, медиа-клавиши …).
- `gterm-widgets/src/ui/route.rs`: `Ui::key(&KeyEvent, &Ctx)` строит `KeyMsg` и зовёт `route_key` без проверки состояния.
- `examples/minimal.rs` — образец примера на системном шрифте без `assets/`.

## Проектные решения (зафиксированы в ADR-0028)

1. **`Key`** — `enum { Ctrl, Alt, Shift, Super, Code(KeyCode) }`; `from_event` по `physical_key` (`Unidentified` → `None`), `from_code` сводит левый/правый модификатор к одному; `name()`/`parse_name()` по таблице всех вариантов `KeyCode` (макрос `key_names!` — одна таблица на оба направления; псевдонимы: `KeyA` → `A`, `Digit1` → `1`, `ArrowUp` → `Up`, `Escape` → `Esc`; остальные — имя варианта); регистр при разборе не важен; неизвестный вариант будущего `winit` печатается `?` и не разбирается.
2. **`Hotkey`** — `alts: Vec<Seq>`, `Seq = Vec<Node>`, `Node { key, inner: Hotkey }`; записанная комбинация — один `alt`, образец — несколько (`|`); пустая — без `alt`. `Display`: `alts` через `|`, узлы через `,`, узел — `K`, `K+inner` (один вложенный узел без альтернатив) или `K+[…]`. Разбор — рекурсивный спуск по грамматике `expr := seq ('|' seq)* ; seq := item (',' item)* ; item := NAME ('+' (item | '[' expr ']'))?`, ошибки с позицией (`ParseError { position, kind }`). **Канонизация модификаторов:** подряд идущие модификаторы в цепочке одиночных вложений сортируются (`Ctrl`, `Alt`, `Shift`, `Super`); `FromStr`, `chain`, `full()`/`current()` и сигналы отдают канонический вид; `PartialEq` — структурное на канонических значениях. `matches(&self, pattern)` — рекурсивно: записанная последовательность совпадает с любой альтернативой образца той же длины поузлово.
3. **`HotkeyTracker`** — `full: Hotkey` (не канонизирован внутри — по нему ходят пути), `held: Vec<Held { key, path: Vec<usize> }>` в порядке нажатия; `feed(&KeyEvent)` → `feed_key(key, state, repeat)`: автоповтор, повторное нажатие удержанной, отпускание неизвестной — `None`; нажатие при пустом `held` очищает `full`; новый узел — в последовательность узла последней удержанной клавиши (или на верхний уровень); отпускание — `hotkey = current()` до удаления (цепочка удержанных по порядку нажатия), после удаления `held` пуст → `hotkey = full` канонический, `complete = true`, `full` очищен. `current()`, `full()`, `is_active()`, `reset()`.
4. **`gterm`:** `events.rs` — убрать фильтр `Pressed`; `gterm-widgets/src/ui/route.rs` — `Ui::key`: `Released` → `Routed::ignored()`.
5. **Пример** `crates/gterm/examples/hotkeys.rs`: `FixedGrid` 70×14, системный шрифт; `on_key` → `tracker.feed`; строки «сейчас», «полная», «последняя завершённая», журнал пяти последних сигналов, образцы `Ctrl+S`, `Ctrl+[K,U]`, `K|U`, `Space+[Ctrl+[K,U]]`, `Ctrl+Shift+Z` с отметкой совпавших; `Esc` при пустом трекере — выход.

## Риски

- `KeyCode` `#[non_exhaustive]`: `match` с `_ => "?"`; новая клавиша будущего `winit` не разбирается — зафиксировано в ТЗ.
- Пути `held` указывают в неканонизированный `full`; канонизация — только на выдаче (клон).
- После снятия фильтра `Pressed` любой обработчик без проверки состояния получит двойные события — в репозитории таких нет (grep), потребители вне репозитория предупреждены ADR-0028.
