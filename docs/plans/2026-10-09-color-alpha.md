# План: альфа-канал цветов ячейки и фон буфера

Статус: **реализовано 2026-10-09** — см. `docs/done/2026-10-09-color-alpha.md`. Отклонения: (а) вместо одной `compose` — `blend` + `fade`, фон ячейки раз на ячейку; (б) отдельная ветка для непрозрачного символа (решение 4) отклонена по замеру — 67 против 77 FPS; (в) Software медленнее ≈ 14 % при выполненном NFR-5; (г) в GL снята полная загрузка данных при смене фона.

- **ТЗ задачи:** `docs/spec/2026-10-09-color-alpha.md` — утверждено 2026-10-09, Р1 — а (тип `ViewParams` удаляется), Р2 — а (строка демо с альфой).
- **Следующая задача:** `docs/spec/2026-10-09-overlay-buffers.md` (утверждено). Формула ячейки пишется так, чтобы наложение клиентских буферов взяло её без переделки (шаг 3).
- **Основное ТЗ:** FR-2, FR-14, §5.2, §6.1, §7.2–7.3, §8, §13 → версия 1.11.

## Факты по коду (проверено 2026-10-09)

- `Color(pub u32)` хранит `0x00RRGGBB`. `from_rgba` отбрасывает альфу, константы собраны через `Self(0x00……)` (`src/cell.rs:1-41`). `Color::default()` = `Color(0)`.
- Альфу срезают три маски `& 0x00FF_FFFF`:
  - `encode_color` в `soft_backend.rs:319`;
  - `encode_color` в `gl_backend.rs:875`;
  - тестовый помощник `rgb()` в `tests/stage3_render.rs:35` — он сравнивает с кадром, а кадр остаётся `0x00RRGGBB`, поэтому его не трогаем.

  `from_packed` передаёт `u32` целиком (`cell.rs:162-163`). Других мест, где `Color(0x…)` собирается напрямую, в `src/` и `tests/` нет.
- В текстуре данных GPU каналы G и B — это `encode_color(fg)` и `encode_color(bg)` (`gl_backend.rs:586-591`). Канал A всегда 0. Шейдер распаковывает только RGB: `unpack`, `cell.frag:25`.
- Поле вокруг сетки:
  - GL — `uniform vec4 u_border`, `o_color = u_border` (`cell.frag:9,28,33`), значение передаётся как `c/255.0` (`gl_backend.rs:655-661`);
  - Software — `frame.fill(encode_color(view.border_color))` при полном кадре (`soft_backend.rs:302`).
- `ViewParams { border_color }` — единственное поле (`renderer/mod.rs:60-63`). Его используют:
  - `Renderer::render(screen, view)`;
  - `GlBackend::render_to_frame(screen, view)`;
  - `SoftBackend::last_view` — смена вида означает полный кадр;
  - `App::new(…, view, …)` и поле `App::view` (`app/mod.rs`, `app/frame.rs`);
  - `common::demo_view()` (`demo`, `bench`, `full_table`);
  - тесты: `common`, `events_common`, `stage3`, `stage4_gl`, `stage6_app`, `soft_partial_redraw`.

  Всего по поиску 126 вхождений в 15 файлах.
- Смешивание `blend(bg, fg, a)` целочисленное, с быстрыми путями `a = 0` и `a = 255` (`soft_backend.rs:325-340`); в шейдере та же формула (`cell.frag:68`). `blend(x, y, 255) = y` и `(cov·255 + 127)/255 = cov`. Значит, при непрозрачных цветах новая формула даёт тот же кадр бит в бит — на это опирается критерий 1.
- Базовая скорость Software в `--bench`: 97,9 FPS на сетке 120×40 (этап 7, `PROJECT_MAP.md`).

## Проектные решения (уйдут в ADR-0013)

1. **`Color`.**
   - Значение `0xAARRGGBB`.
   - `from_rgb` → `A = 0xFF`; `from_rgba` хранит `a`; добавляется `a()`.
   - Константы перечисляются как `0xFF……`.
   - Добавляется `Color::TRANSPARENT = Color(0)`, равный `default()`.
2. **Фон буфера.**
   - `ScreenBuffer { background: Color }`, по умолчанию `Color::BLACK`.
   - `background()` и `set_background(c)`.
   - `set_background` dirty-строки **не трогает**. Полный кадр после смены фона определяет рендерер: он сравнивает фон с прошлым кадром, как сейчас сравнивает `last_view`. Причины: у GL фон — uniform, данные перегружать не нужно; признак «вид изменился» уже живёт в рендерере.
3. **Формула ячейки — одна функция «шаг слоя»** (Software, `soft_backend.rs`):

   ```
   fn compose(under: u32 /*RGB*/, bg: Color, fg_rgb: u32, a_fg: u8, cov: u8) -> u32
       let cell_bg = blend(under, bg.rgb, bg.a)
       blend(cell_bg, fg_rgb, (cov·a_fg + 127)/255)
   ```

   - `under` — RGB фона буфера; в задаче про наложение сюда придёт содержимое под слоем.
   - Осветление `BOLD` применяется к `fg_rgb` до вызова; альфа fg не меняется.
   - Подчёркивание: `cov = 255` на нижней строке ячейки, как сейчас.
   - В шейдере то же самое теми же целыми операциями, в том же порядке.
4. **Скорость Software.** `bg' = blend(under, bg, bg.a)` считается **один раз на ячейку**, а не на пиксель. Это возможно, потому что `under` в этой задаче однотонный. На пиксель остаётся одно `blend`, как сейчас, плюс умножение покрытия на `a_fg`. Это умножение пропускается при `a_fg = 255`: одна ветка на ячейку.
5. **Данные GPU.**
   - G и B — `Color` целиком, без маски.
   - `unpack` в шейдере возвращает `uvec4` (RGB и A).
   - Канал A текстуры остаётся резервом.
6. **Фон в шейдере.**
   - `uniform ivec3 u_background` в целых 0…255 вместо `vec4 u_border` — оба шага смешивания целочисленные.
   - Поле вокруг сетки: `o_color = vec4(vec3(B)/255.0, 1.0)` — то же точное преобразование, что у ячеек.
7. **Удаление `ViewParams` (Р1 — а).**
   - `Renderer::render(&mut self, screen)`, `GlBackend::render_to_frame(screen)`.
   - `App::new(title, screen, rasterizer, config, options)`.
   - Поле `App::view` и `demo_view()` удаляются.
   - Цвет поля задаётся `screen.set_background(…)`. У `demo`, `full_table` и `bench` это прежний `Color::BLACK`, по умолчанию.
   - `SoftBackend::last_view` превращается в `last_background: Option<Color>`.
8. **Строка демо (Р2 — а).** В свободных строках сцены 6 и 8 (освободились после ADR-0012):
   - строка 6 — `fg.a` = 0, 64, 128, 192, 255: белый текст на тёмно-синем фоне ячейки;
   - строка 8 — `bg.a` = 0, 64, 128, 192, 255: красный фон ячейки над фоном буфера (чёрным), текст непрозрачный.

   Подписи — прямо в строке.

## Не входит

Прозрачность окна; картинка под сеткой; наложение клиентских буферов (следующая задача); альфа и цвета из SVG-файлов.

## Риски

- **Расхождение GL ↔ Software в двухшаговом смешивании.** Смягчение: одна последовательность целочисленных операций и сцена с альфой в `stage4_gl` (шаг 5).
- **Регрессия скорости Software.** Смягчение: фон ячейки считается один раз на ячейку, для непрозрачного fg — отдельная ветка (решение 4). Оценка — только по замеру шагов 1 и 7, без ожиданий (CQ-10.4).
- **Внешний код, собирающий `Color(0x00RRGGBB)` напрямую,** после правки получит прозрачный цвет. Внутри проекта таких мест нет (поиск выше). Для приложений это ломающее изменение API; фиксируется в ADR-0013.
- **Удаление `ViewParams`** — ломающее изменение `Renderer` и `App::new`; фиксируется в ADR-0013.
