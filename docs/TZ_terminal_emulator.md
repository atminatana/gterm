## 1. Цель и область применения

Разработать компактное кроссплатформенное (Windows, Linux) приложение на Rust, которое отображает в окне текстовую сетку («экран консоли»). Состояние экрана хранится в буфере ячеек; каждая ячейка содержит код символа, цвет символа и цвет фона. Отрисовка выполняется шейдером на GPU по текстуре-атласу глифов. При невозможности создать OpenGL-контекст приложение автоматически переключается на программную отрисовку на CPU с идентичным результатом.

Проект оформляется как **библиотека (crate) + демонстрационный бинарник**, чтобы модуль отображения можно было встроить в другие продукты (например, киоски и билетные терминалы). С версии 1.14 (ADR-0017) это workspace: библиотека `crates/gterm` не содержит ресурсов и кода поиска каталогов — шрифт задаёт приложение (`FontFamily::load`/`from_files`/`system`/`system_monospace`, FR-8); демо-бинарники, их общий код и `assets/` — пакет `crates/gterm-demo`; минимальный потребитель без ресурсов — `crates/gterm/examples/minimal.rs`. Прикладной слой интерфейса — отдельный крейт `crates/gterm-widgets` (ADR-0023): виджеты в немедленном режиме по образцу ratatui, рисующие в `ScreenBuffer`; библиотека `gterm` о нём не знает.

### 1.1. Что входит в задачу
- буфер экрана и API для записи в него;
- атлас глифов (динамический, из TTF-семейства в `assets/`, четыре начертания) и SVG-глифы из `assets/svg/` (FR-8.6);
- OpenGL-рендерер (шейдер);
- программный рендерер (fallback);
- окно, события, изменение размера, DPI и размер шрифта;
- демо-приложение и тесты.

### 1.2. Что не входит (вне рамок версии 1.0)
- разбор escape-последовательностей (VT100/ANSI) и запуск shell/PTY (закладывается как расширение, см. раздел 13);
- Vulkan-бэкенд (стек `glow` его не даёт; архитектура допускает добавление, см. раздел 13);
- субпиксельное (LCD) сглаживание, лигатуры, сложная вёрстка Unicode (RTL, комбинируемые символы); *градационное сглаживание глифов входит — FR-8.4, ADR-0002*;
- macOS и мобильные платформы (не запрещены, но не тестируются).

## 2. Термины

| Термин | Значение |
|---|---|
| Ячейка (cell) | Одна позиция сетки: символ + цвета + флаги |
| Сетка (grid) | `cols × rows` ячеек |
| Глиф | Растровое изображение символа `glyph_w × glyph_h` пикселей |
| Атлас | Текстура со всеми глифами, 16×16 глифов для 256 кодов |
| Dirty-область | Набор строк (или ячеек), изменённых с прошлого кадра |
| Рендерер | Реализация трейта `Renderer` (GL или Software) |

## 3. Функциональные требования

### 3.1. Буфер экрана
- **FR-1.** Буфер хранит `cols × rows` ячеек в линейном массиве (row-major).
- **FR-2.** Ячейка содержит: код символа (`char` — любая кодовая точка Unicode U+0000–U+10FFFF; `'\0'` — пустая ячейка; ADR-0009), цвет символа и цвет фона (`Color`, `0xAARRGGBB`; `A = 255` — непрозрачный, `A = 0` — прозрачный; `from_rgb` даёт `A = 255`), флаги (`u16`). **Альфа участвует в смешивании** (§7.3, ADR-0013): фон ячейки ложится на фон буфера (FR-2.1) по своей альфе, символ — на фон ячейки по покрытию, умноженному на альфу символа. Прозрачность окна (рабочий стол сквозь окно) — расширение, §13. Сглаживание *глифов* — отдельный механизм, см. FR-8.4.
- **FR-2.1.** У буфера есть **фон** (`ScreenBuffer::background()` / `set_background`, по умолчанию чёрный) — непрозрачная подложка под всеми ячейками; им же заливается поле вокруг сетки (FR-14). Альфа фона не учитывается. Смена фона перерисовывает кадр целиком (ADR-0013).
- **FR-3.** Флаги (ADR-0012): `BOLD` = бит 0 (**жирный глиф + осветление цвета**), `ITALIC` = бит 1 (курсивный глиф), `UNDERLINE` = бит 2; других флагов нет — обмен fg/bg приложение делает само при записи ячейки. Пара (`BOLD`, `ITALIC`) задаёт начертание — канал атласа (FR-9); при отсутствии файла начертания действует подстановка FR-8.3. Курсор не является флагом ячейки и не входит в обязанности библиотеки (§13).
- **FR-4.** API записи: установка ячейки, заливка области, запись строки текста с заданными цветами, очистка, прокрутка (scroll up/down на N строк), копирование области.
- **FR-5.** Буфер ведёт учёт изменений (dirty-строки), чтобы в GPU передавались только изменившиеся данные.
- **FR-6.** Изменение размера сетки (`resize(cols, rows)`) с сохранением содержимого в пересекающейся области.
- **FR-7.** *(Удалено в 1.10, ADR-0012.)* Мигания символов нет: флага `BLINK`, периода и фазы мигания в библиотеке нет. Курсор (позиция, видимость, форма, мигание) — **не обязанность библиотеки**: реализуется приложением, см. §13.

### 3.2. Шрифт и атлас
- **FR-8.** Глифы растеризуются программой из TTF-файлов **семейства** (ADR-0003); семейство задаёт приложение (ADR-0017): `FontFamily::load(fonts_dir, family)` — каталог, `from_files(paths, family)` — явные файлы, `system(family)` — установленные в системе, `system_monospace()` — системный моноширинный по умолчанию. Начертание Regular проверяется на моноширинность: advance глифов `i . W 0 ␠` (тех, что есть в шрифте) равен advance `M` с точностью до пикселя при `FONT_SIZE_PX`, иначе `FontError::NotMonospace`. Константы в коде: `FONT_FAMILY = "RobotoMono Nerd Font Mono"` — в пакете демо (`gterm_demo::assets`; сравнивается с `name` ID 1 файла; именно вариант **Mono** — в нём иконки ужаты в один advance, тогда как в сборке без суффикса они шире ячейки и обрезались бы рендерером, который рисует каждый глиф строго в своей ячейке — FR-9, FR-13), `FONT_SIZE_PX` (по умолчанию 16) — **логический** размер шрифта, то есть физический при `scale_factor = 1`, и `FONT_SCALE` — множитель размера, задаваемый пользователем (в 1.0 константа `1.0`; точка подключения будущего файла настроек). Приложение может задать свой логический размер полем `AppOptions::font_size_px` (по умолчанию `FONT_SIZE_PX`; `demo` и `full_table` — 22, `demo --bench` — 16, ADR-0008). Физический размер растеризации — `glyph_px = clamp(round(FONT_SIZE_PX · FONT_SCALE · scale_factor), 8, 48)` (FR-24). Размер ячейки `glyph_w × glyph_h` выводится из метрик начертания Regular (advance `M` × (ascent − descent)); базовая линия — `ascent`. 8 бит покрытия на пиксель (ADR-0002).
- **FR-8.1.** Каталог `assets/` — ресурс **пакета демо** (`gterm_demo::assets::find_assets_dir`, ADR-0017), библиотека его не ищет. Поиск крейтом `find_folder`: сначала от каталога исполняемого файла (потомки на 1 уровень, затем родители до 4 уровней), затем так же от рабочего каталога, затем каталог пакета на момент сборки (`cargo run` из корня workspace; у установленного exe этого пути нет). Шрифты лежат в подкаталоге **`assets/fonts/`**: `FontFamily::load` загружает все `*.ttf`/`*.otf`, у которых имя семейства (`name` ID 1) равно запрошенному (для демо — `FONT_FAMILY`); файлы других семейств и не-шрифты пропускаются. Нет каталога или задан флаг `--system-font` — демо берёт `FontFamily::system_monospace()`: на Windows кандидаты `Cascadia Mono`, `Consolas`, `Lucida Console`, `Courier New`, затем умолчание `fontdb`; на Linux — алиас fontconfig `monospace`, затем `DejaVu Sans Mono`, `Liberation Mono`, `Noto Sans Mono`, `FreeMono`; берётся первое семейство с Regular, прошедшее проверку моноширинности; источник шрифта и время его выбора пишутся в stderr. На системном шрифте иконок Nerd Font и SVG-тайлов нет — пустые ячейки.
- **FR-8.2.** Начертание каждого файла определяется по таблицам шрифта (`OS/2.usWeightClass ≥ 600` → Bold, `OS/2.fsSelection` ITALIC → Italic), **не по имени файла**. Файлов-кэшей на диске нет: глиф растеризуется при первом показе и живёт в атласе до сброса страницы (FR-9).
- **FR-8.3.** Подстановка недостающих начертаний: Bold Italic → Italic → Bold → Regular; Bold → Regular; Italic → Regular. Подстановка не копирует данные: рендерер читает канал начертания-источника. Нет Regular → ошибка FR-8.5. Какой файл за какое начертание отвечает — пишется в stderr при старте.
- **FR-8.4.** Растеризация: контуры `skrifa` с хинтингом, покрытие `zeno` 0…255 без порога (градационное сглаживание); результат детерминирован, что требуется golden-тестам. Движок хинтинга — по шрифту (ADR-0025): глифы с родными инструкциями (`maxp.maxSizeOfInstructions > 0`, `font::has_glyph_instructions`) → интерпретатор с целью `Mono` (ADR-0002); без инструкций (CFF, неинструктированные TTF, Nerd-сборки) → автохинтер с целью `Smooth { Normal }` — в `Mono` автохинтер привязывает стойки по обеим осям и расширяет их до 2 px, сжимая буквы. Тем же признаком среди файлов одного начертания семейства (каталог, список, система — FR-8.1, ADR-0017) предпочитается файл с инструкциями; среди равных — прежний порядок. **Псевдографика U+2500–U+257F и U+2580–U+259F рисуется процедурно** на сетке ячейки (толщины `light = max(1, h/16)`, `heavy = 2·light + 1`, двойная — две `light` с зазором `light`; в тройнике на двойной линии (╤ ╧ ╟ ╢) одиночная рука упирается в ближний штрих, зазор пуст, а в крестах ╪ ╫ и углах ╒ ╓ проходит сквозь зазор — как в шрифтах (сверено 2026-10-23 с RobotoMono Nerd Font и Cascadia Mono); тени ░▒▓ — покрытие 64/128/192) и **перекрывает** глифы шрифта — линии стыкуются между ячейками без зазоров (ADR-0002). В растр попадают **все кодовые точки Unicode (U+0001–U+10FFFF), для которых у шрифта есть глиф** (RobotoMono Nerd Font Mono, разбор `cmap`: 5 020 в BMP и 6 896 вне BMP — U+F0001–U+F1AF0; ADR-0009); никакой кодовой страницы нет, `Cell::ch` — сама кодовая точка. Кодовая точка без глифа (и 0) отображается в **слот 0 — пустой глиф** (рисуется только фон ячейки). См. ADR-0001. **Режим псевдографики** (ADR-0018, `rasterizer::BoxDrawingMode`): `Procedural` — описанное выше умолчание; `Font` — рамки и блоки берутся из глифов шрифта (нет глифа — пустая ячейка); `Combined` — глиф шрифта, если он есть, иначе формула. SVG-глифы главнее в любом режиме. В `Font`/`Combined` псевдографика зависит от начертания (каналы атласа заполняются по `BOLD`/`ITALIC`). Смена режима на лету — `Request::box_drawing`: страница атласа сбрасывается, кадр перерисовывается целиком на любом бэкенде; GL и Software остаются бит-идентичны. В режимах `Font` и `Combined` контур глифа U+2500–U+259F берётся **без хинтинга** и **вписывается в ячейку** (ADR-0020): `x' = x · w / advance`, `y' = (baseline − h) + (y − descent) · h / (ascent − descent)`; так рамки соседних ячеек смыкаются по ширине и высоте у шрифтов, рисующих их на advance и `descent…ascent`. Негодные метрики — контур не трогается. Затем контур выравнивается по пиксельной сетке ячейки (ADR-0021): различимые координаты точек по каждой оси монотонно отображаются в целые с шагом не меньше 1 px — линии чёткие, целой толщины, штрихи не схлопываются; дуги при этом огрубляются. **Мозаики и фигуры** (ADR-0022, тот же приоритет и режимы, что у рамок): секстанты U+1FB00–U+1FB3B, октанты U+1CD00–U+1CDE5 и половины четвертей U+1CEA0/A3/A8/AB, «Centered» ■ и U+1FBE4–U+1FBE7, восьмушки U+1FB82–U+1FB8B — заливка клеток сетки ячейки по формуле восьмушек (`(len·k + n/2) / n`), покрытие 0/255; части кругов ● ◖ ◗ U+1FBE8–U+1FBEF, треугольники ▲▶▼◀ ◆ ◢◣◤◥ U+1FB68–U+1FB6F U+1FB9A–U+1FB9B и диагонали U+1FB3C–U+1FB67 — выпуклые области с покрытием по 4×4 точкам на пиксель; части кругов прижаты к стороне или углу и складываются в круги 2×1, 1×2, 2×2 ячейки. Брайль и разделённые мозаики не рисуются.
- **FR-8.5.** Regular-файл семейства не найден (в каталоге, среди файлов или в системе — ни один кандидат `system_monospace()` не подошёл), шрифт не моноширинный, либо хинтер не построился → приложение завершается с понятным сообщением в stderr и кодом возврата ≠ 0 (аналогично отказу `softbuffer`, раздел 8). Глиф, который не нарисовался (нет контура, ошибка интерпретатора) → пустая ячейка, без остановки.
- **FR-8.6.** **SVG-глифы** (ADR-0008) дополняют набор глифов шрифта. Каталог задаёт приложение (`SvgGlyphs::load(dir)`); демо — `assets/svg/` (тот же `assets/`, что FR-8.1, только при шрифте из `assets/`; нет каталога — SVG нет, это не ошибка). Имя файла — **только** HEX-код кодовой точки и `.svg`: 4–6 цифр, регистр не важен (`E000.svg`, `F0001.svg`, `100000.svg`), значение ≤ U+10FFFF и не суррогат; иное имя, повтор кодовой точки (побеждает первое имя по сортировке) или ошибка разбора → строка в stderr и пропуск файла. Разбор — `usvg` (без текста, системных шрифтов и svgz) один раз при старте: `transform`, `use`, фигуры применены, обводки (в т.ч. `stroke-dasharray`) переведены в заливку; растеризация — `zeno`, как у шрифта, без хинтинга. **Приоритет: SVG > процедурная псевдографика > шрифт** — файл перекрывает любой глиф с той же кодовой точкой. Холст SVG вписывается в ячейку **с сохранением пропорций** и центрируется. **Цвета и прозрачность файла игнорируются**: всё закрашенное или обведённое — покрытие (`fill="none"`/`stroke="none"` учитываются), на экране глиф окрашивается как глиф шрифта — `fg` по покрытию поверх `bg` (§7.3); `BOLD`-осветление и `UNDERLINE` действуют. Растровые `<image>`, текст, маски, обрезка и фильтры не поддерживаются. Начертаний у SVG нет — атлас заполняет все 4 канала сразу (FR-9). Под тайлы рекомендуется плоскость U+100000–U+10FFFD — в шрифте она пуста.
- **FR-9.** Атлас — **динамическая страница** `RGBA8` размером `page × page`, `page = min(GL_MAX_TEXTURE_SIZE, 2048)`, не меньше 1024 (запрос лимита не удался → 1024). Каналы текселя — начертания: R Regular, G Bold, B Italic, A Bold Italic; один слот на кодовую точку для всех начертаний, каналы заполняются **лениво** при первом показе в данном начертании; у SVG-глифов и процедурной псевдографики растр от начертания не зависит — заполняются все 4 канала сразу. Слот `s` занимает клетку `(s % cols, s / cols)`, `cols = page / glyph_w`; слот 0 — пустой. Кодовая точка → слот: плоский массив на 0x110000 записей `u16` (не загружено / пусто / слот), O(1); слот — `u16` (ADR-0009). Переполнение страницы — **сброс**: атлас очищается, экран перерисовывается целиком; страница ≥ 1024 вмещает все глифы BMP-шрифта, поэтому экран всегда помещается после сброса, иначе — `RenderError` (NFR-7). Рендереры работают со слотами; в GL-текстуру данных CPU упаковывает номер слота (§6.1), начертание — из флагов ячейки.
- **FR-10.** Размер ячейки берётся из метрик семейства (`CellMetrics { glyph_w, glyph_h, baseline }`); рендереры не содержат ни констант 8/16, ни масштаба ячейки (ADR-0005). Смена `FONT_SIZE_PX`, `FONT_SCALE`, `FONT_FAMILY` или `scale_factor` меняет размер ячейки и ёмкость страницы без изменения рендереров.
- **FR-11.** Растеризатор — `skrifa` + `zeno`, обязательные зависимости (не feature). Фича `ttf` из ранних версий документа упразднена.

### 3.3. Отрисовка
- **FR-12.** Кадр без наложения рисуется одним draw call (один полноэкранный треугольник), вся логика ячеек — во фрагментном шейдере. Кадр с наложением (FR-25.1) — по одному проходу на каждый записанный буфер в текстуру наложения и тот же основной draw call, который последним шагом накладывает текстуру на кадр (ADR-0014).
- **FR-13.** Результат: пиксель-в-пиксель точное отображение (фильтрация `NEAREST`, без интерполяции). **Один пиксель глифа = один пиксель кадра**: увеличения блока нет, размер ячейки задаётся размером шрифта (ADR-0005).
- **FR-14.** Область окна, не заполненная сеткой (остаток при нецелом делении), заливается фоном буфера (FR-2.1; до 1.11 — `ViewParams::border_color`, упразднён ADR-0013).
- **FR-15.** *(Удалено в 1.10, ADR-0012: мигания символов нет, uniform фазы в шейдере нет.)*
- **FR-16.** Подчёркивание рисуется в шейдере по координатам внутри ячейки.

### 3.4. Выбор бэкенда и fallback
- **FR-17.** Порядок инициализации:
  1. OpenGL 3.3 Core;
  2. OpenGL ES 3.0 (через EGL/ANGLE-совместимые драйверы, Mesa);
  3. программный рендерер (`softbuffer`).
- **FR-18.** Переход на следующий уровень происходит автоматически при любой ошибке: не найдена конфигурация, не создан контекст, не скомпилирован шейдер, не поддерживается нужный формат текстуры, ошибка `glGetError` при первом кадре.
- **FR-19.** Принудительный выбор бэкенда через аргумент командной строки `--backend=gl|gles|soft` и переменную окружения `TERM_BACKEND`. Значение `auto` — по умолчанию; аргумент имеет приоритет над переменной. Значение задаёт **стартовый уровень** цепочки FR-17, ниже него откат продолжается (`gl` → GL 3.3 → Software; `gles` → GLES 3.0 → Software; `soft` → только Software) — так `--backend=gl` без GL завершается на Software (§11.2). Прочие аргументы: `--fail-gl` (§11.4 п.4), `--allow-sw-gl=true|false` (§9 п.6), `--debug` (FR-20), `--fail-frames=N` и `--lose-context` (инжекция ошибок кадра для проверки §5.3 п.5 и FR-21, ADR-0007: первые `N` попыток кадра завершаются ошибкой рендера; первая попытка кадра — потерей контекста), `--help`. Неизвестный аргумент или значение → сообщение, справка, код ≠ 0. Разбор — `src/config.rs`.
- **FR-20.** Текущий бэкенд и причина отката пишутся в лог (stderr) и доступны через API (`Renderer::name()`), а также в заголовке окна в режиме `--debug`.
- **FR-21.** Потеря GL-контекста во время работы (смена драйвера, RDP-сессия, `GL_CONTEXT_LOST`) обрабатывается переключением на программный рендерер без завершения приложения. Признаки: `glGetError() == GL_CONTEXT_LOST` (0x0507) после кадра либо ошибка обмена буферов → `RenderError::ContextLost`; приложение забирает атлас у GL-бэкенда и создаёт Software на том же окне, кадр перерисовывается целиком.

### 3.5. Окно и ввод
- **FR-22.** Создание окна через `winit`: заголовок, начальный размер по числу ячеек в **логических** единицах (`LogicalSize` — чтобы размер не зависел от DPI монитора), изменяемый размер (можно отключить), полноэкранный режим (F11). Окно создаётся **скрытым**, первый кадр рисуется до показа — иначе на Windows видна вспышка белого фона класса окна до первого `RedrawRequested`.
- **FR-23.** При изменении размера окна количество столбцов/строк пересчитывается автоматически (режим `AutoGrid`, по умолчанию) либо сетка остаётся фиксированной (режим `FixedGrid`). Размер шрифта ни в одном режиме не подбирается под окно: в `FixedGrid` сетка, не помещающаяся в окно, центрируется и обрезается по границе окна. Режим задаётся при создании. Запрос сетки от приложения (FR-25) действует только в `FixedGrid`: в `AutoGrid` сетка всегда выводится из окна, иначе следующая же перерисовка по размеру окна вернула бы заданное значение обратно.
- **FR-24.** Поддержка изменения DPI. Физический размер растеризации вычисляется как `glyph_px = clamp(round(FONT_SIZE_PX · FONT_SCALE · scale_factor), 8, 48)` (FR-8); из него через метрики выводятся ячейка, сетка и размер окна — это единственный источник геометрии (ADR-0005). Значение `scale_factor` берётся у созданного окна; при его изменении (`ScaleFactorChanged`) новый физический размер применяется, предложенный системой размер окна принимается (`InnerSizeWriter`), иначе окно «прыгает» при переносе между мониторами. Значения, не являющиеся конечным положительным числом, трактуются как `1.0`. Нижняя и верхняя границы ограничены: меньше 8 px ячейка нечитаема, больше 48 px страница атласа перестаёт вмещать глифы BMP-шрифта (FR-9, ADR-0003 п.5).
- **FR-25.** События ввода и уведомления передаются приложению через трейт `AppHandler` (ADR-0004): клавиатура (`KeyboardInput`), текстовый ввод (`Ime::Commit`), мышь (`CursorMoved`, `MouseInput`, `MouseWheel`), изменения сетки и бэкенда, фокус окна (`Focused` → `on_focus`, ADR-0029). События пробрасываются **без интерпретации**, типами `winit`; перевод в собственные типы не делается. Библиотека не перехватывает `Esc`: решение принимает приложение. `Request::box_drawing` (ADR-0018) — смена источника псевдографики, см. FR-8.4. Нажатия кнопок мыши подряд считает окно (ADR-0035): `PointerEvent::Input::click_count` — 2 у второго нажатия левой кнопки в той же ячейке не позже 500 мс после предыдущего (двойной клик), иначе 1; после двойного счёт начинается заново. Привязка двойного клика к контролу — в `gterm-widgets` (`Ui::on_double_click`).
- **FR-25.1.** Наложение клиентских буферов (ADR-0014). Буферы создаёт и хранит приложение. На каждом `RedrawRequested` библиотека очищает наложение и вызывает `AppHandler::on_redraw(&mut DrawCtx)`; в нём `ctx.draw_buffer(&buffer, col, row)` кладёт буфер поверх основного экрана и ранее нарисованных — позже нарисованный лежит выше. `(col, row)` — ячейка основной сетки под левым верхним углом буфера (может быть отрицательной), всё за пределами сетки обрезается, на поле вокруг сетки наложение не попадает. Буфер копируется при вызове. Пустые ячейки `ScreenBuffer::transparent` прозрачны, у `ScreenBuffer::new` — непрозрачны. Наложение живёт один кадр.
- **FR-26.** Перерисовка только по запросу (`request_redraw`): события окна, ввод, запрос приложения через `Ctx`. Мигания и таймеров ячеек в библиотеке нет (ADR-0012). Периодический тик приложения (ADR-0033): при заданном периоде (`AppOptions::tick_period`, смена — `Request::tick_period`) библиотека зовёт `AppHandler::on_tick` не раньше срока, пропущенные тики не догоняет и кадр сама не запрашивает. Без периода цикл всегда ждёт событий (`ControlFlow::Wait`), в простое приложение не потребляет CPU.

### 3.6. Демо-приложение
- **FR-27.** Бинарник `demo` показывает: текст с флагами и начертаниями, псевдографику, палитру, фрагмент таблицы глифов, строку статуса с названием бэкенда, счётчиком FPS и временем CPU на кадр (обновляется по событиям — вводу, смене сетки и бэкенда). Курсор демо рисует сам, средствами приложения (§13), — это и есть пример реализации курсора поверх `ScreenBuffer`: обмен fg/bg своей ячейки, без мигания (ADR-0012). Прокрутка из демо исключена решением владельца (2026-10-02). Флаг демо `--bench` — замер NFR-4/NFR-5: непрерывные кадры с полной перезаписью сетки 200×60 (GL/GLES) или 120×40 (Software), статистика в stderr, выход с кодом 0.
- **FR-27.1.** Второй бинарник `full_table` показывает таблицу **всех** глифов шрифта постранично (`PgUp`/`PgDn`/`Home`/`End`, колесо); клавиши FR-28 действуют и в нём. Глиф занимает блок 2×2 ячейки (цветная ячейка глифа и чёрный зазор в ячейку справа и снизу); у соседних блоков разные фон и цвет символа — пары консольной палитры. *(1.7, решение владельца 2026-10-08: отдельный блок 16 фонов × 16 цветов символа убран — цвета проверяются в самой таблице.)*
- **FR-28.** Клавиши демо: `1/2/3` — переключение бэкенда на лету (пересоздание рендерера), `F11` — полный экран, `Esc` — выход. Изменение размера шрифта пользователем в 1.0 не предусмотрено (FR-8, `FONT_SCALE = 1.0`).

## 4. Нефункциональные требования

### 4.1. Платформы
| Платформа | Требования |
|---|---|
| Windows 10/11 x64 | WGL (OpenGL 3.3), fallback — GDI через `softbuffer` |
| Linux x64 | X11 (GLX/EGL) и Wayland (EGL); fallback — `softbuffer` (X11 / Wayland `wl_shm`) |

Сборка под `x86_64-pc-windows-msvc`, `x86_64-pc-windows-gnu`, `x86_64-unknown-linux-gnu`. Допустима сборка под `aarch64-unknown-linux-gnu`.

### 4.2. Размер
- **NFR-1.** Размер release-бинарника демо **замеряется на каждом этапе и фиксируется в отчёте** (§15 п.5; без учёта внешних библиотек ОС). Жёсткого лимита нет: прежние пределы (1,5 МБ Windows / 2 МБ Linux) служили оценкой стека на старте и сняты решением владельца на этапе 7 (2026-10-02) — измеренные 1 051 КБ (Windows) и 2 323 КБ (Linux, из них ≈ 450 КБ — поддержка X11 и Wayland одновременно) признаны приемлемыми.
- **NFR-2.** Достигается настройками профиля (см. раздел 10), отключением лишних features зависимостей и отсутствием форматирования с тяжёлыми зависимостями. Растеризатор `skrifa` + `zeno` входит в бюджет размера (≈ 550 КБ в release, замер в ADR-0002); контроль `cargo bloat` на этапах 4 и 7.
- **NFR-3.** Нет обязательных динамических зависимостей помимо системных (`libc`, `libX11`/`libwayland-client`/`libxkbcommon`, `libEGL`/`libGL` — загружаются динамически через `dlopen`, `opengl32.dll` на Windows). Обязательных внешних ресурсов нет (ADR-0017): библиотека берёт шрифт из каталога, файлов или установленных в системе; демо предпочитает каталог `assets/` рядом с exe (FR-8.1), без него — системный моноширинный.

### 4.3. Производительность
- **NFR-4.** Сетка 200×60 (12 000 ячеек) обновляется целиком на GL-бэкенде не более чем за **1 мс** CPU-времени на кадр (сборка данных + `glTexSubImage2D`), 60 FPS на интегрированной графике.
- **NFR-5.** Программный рендерер: сетка 120×40 при `scale_factor = 1` — не менее 60 FPS на одном ядре современного CPU при полной перерисовке; при частичных изменениях перерисовываются только dirty-строки, а в окно выводятся только перерисованные полосы (ADR-0010).
- **NFR-6.** Нет выделений памяти в горячем пути отрисовки кадра (буферы предвыделены и переиспользуются). Промах кэша глифов (первый показ символа) — отдельный путь: растеризация в переиспользуемые буферы контура и маски; аллокации возможны только при росте буфера контура (ADR-0003 п.7).

### 4.4. Надёжность
- **NFR-7.** Приложение не паникует при ошибках графики: все ошибки инициализации и рендера обрабатываются через `Result` и приводят к откату на следующий бэкенд.
- **NFR-8.** `panic = "abort"` в release; в debug — стандартное поведение. Обработчик паники выводит сообщение в stderr.
- **NFR-9.** Нет `unsafe` вне слоя создания контекста/дисплея и вызовов `glow` (последние обёрнуты в `unsafe` самой библиотекой, в проекте изолируются в модуле `gl_backend`).

### 4.5. Качество кода
- Rust edition 2021+, MSRV фиксируется в `Cargo.toml` (`rust-version`).
- `cargo fmt`, `cargo clippy -- -D warnings` без замечаний.
- Документация публичного API (`///`), примеры в `examples/`.

### 5.3. Жизненный цикл
1. `main` разбирает конфигурацию.
2. `App::new` создаёт `EventLoop` и окно (для GL — через `glutin_winit::DisplayBuilder`, подбирающий конфиг и окно совместно).
3. Последовательно вызывается `try_init_renderer(kind)` по цепочке GL → GLES → Soft.
4. Цикл событий: `Resized`/`ScaleFactorChanged` → пересчёт сетки и `renderer.resize`, `RedrawRequested` → очистка наложения, `on_redraw`, `renderer.render_overlaid`, ввод и уведомления → трейт `AppHandler` (ADR-0004); `ControlFlow::Wait`, а при заданном периоде тика — `WaitUntil` до срока и `on_tick` из `about_to_wait` (FR-26, ADR-0033).
5. При `Err(ContextLost)` — откат на Soft; при остальных ошибках `render` — повторная попытка один раз, затем откат. Ошибка на Software (откатываться некуда) — завершение с сообщением и кодом ≠ 0.

## 6. Модель данных и передача на GPU

### 6.1. Формат данных на GPU
Одна **целочисленная текстура данных** `RGBA32UI` размером `cols × rows` (1 тексель = 1 ячейка):

| Канал | Содержимое |
|---|---|
| R | **слот атласа** (биты 0–15; `atlas.slot_of(ch)`, 0 — пустой), флаги (биты 16–31: `BOLD` — 16, `ITALIC` — 17, `UNDERLINE` — 18; начертание шейдер берёт из `BOLD`/`ITALIC`) |
| G | цвет символа, `Color` целиком (`0xAARRGGBB`) |
| B | цвет фона, `Color` целиком (`0xAARRGGBB`) |
| A | зарезервировано (например, индекс альтернативного глифа/атрибуты) |

Плюсы: одна текстура, один `texelFetch`, точное значение без фильтрации, нет ограничений на количество цветов. Требуются OpenGL 3.0+/GLES 3.0+, что соответствует выбранной цепочке бэкендов.

### 6.2. Обновление данных
- Для каждой dirty-строки формируется непрерывный участок памяти `[u32; 4 * cols]` и передаётся `glTexSubImage2D` (либо одним вызовом на группу смежных строк).
- Промежуточный CPU-буфер `Vec<u32>` хранится в рендерере и переиспользуется.
- После успешной передачи dirty-флаги сбрасываются.
- При `resize(cols, rows)` текстура пересоздаётся, передаётся полное содержимое.
- Ограничение: `cols`, `rows` ≤ `GL_MAX_TEXTURE_SIZE` (проверяется при инициализации; иначе — откат на Soft).

### 6.3. Атлас
- Формат **`RGBA8UI`** (`GL_RGBA8UI`, `GL_RGBA_INTEGER`, `usampler2D`), фильтры `NEAREST`, wrap `CLAMP_TO_EDGE` — `texelFetch` возвращает точное целое покрытие; каналы — начертания (FR-9), канал выбирается по `u_style_channel[начертание]` (подстановка FR-8.3 учтена на CPU).
- Значение — покрытие пикселя 0…255 (0 — фон, 255 — символ целиком); смешивание — целочисленное, одинаковое для GL и Software (§7.3).
- Загрузка: страница целиком при создании и после сброса атласа; иначе только слоты из `Atlas::take_dirty_slots` через `glTexSubImage2D` (ADR-0003).
- Выравнивание строк: `glPixelStorei(GL_UNPACK_ALIGNMENT, 1)` перед загрузкой.

## 7. Шейдеры

### 7.1. Общие положения
- Один исходник, две версии заголовка: `#version 330 core` и `#version 300 es` + `precision highp float; precision highp int; precision highp usampler2D;`. Заголовок подставляется программой в зависимости от выбранного бэкенда.
- Вершинный шейдер: полноэкранный треугольник по `gl_VertexID`, без vertex buffer (для GL 3.3 core потребуется пустой VAO). Исходники — `src/renderer/shaders/cell.{vert,frag}` и `overlay.frag` (проход наложения, ADR-0014), включаются `include_str!`.

### 7.2. Uniform-переменные

| Имя | Тип | Назначение |
|---|---|---|
| `u_data` | `usampler2D` | текстура ячеек |
| `u_atlas` | `sampler2D` | атлас глифов |
| `u_grid` | `ivec2` | размер сетки (cols, rows) |
| `u_glyph` | `ivec2` | размер ячейки в пикселях (FR-10, ADR-0005) |
| `u_origin` | `ivec2` | смещение сетки в окне (для центрирования) |
| `u_background` | `ivec3` | фон буфера RGB 0…255: подложка ячеек и поле вокруг сетки (ADR-0013) |
| `u_viewport_h` | `int` | высота окна в пикселях (перевод `gl_FragCoord` в координаты «верх слева») |
| `u_atlas_cols` | `int` | слотов в строке атласа (`page / glyph_w`) |
| `u_style_channel` | `ivec4` | канал атласа для начертаний Regular/Bold/Italic/BoldItalic |
| `u_overlay` | `usampler2D` | текстура наложения `RGBA8UI` размером с сетку, RGB предумножен (ADR-0014) |
| `u_has_overlay` | `int` | 1 — в кадре есть наложение: последним шагом `c = t.rgb + mul(c, 255 − t.a)` |

### 7.3. Алгоритм фрагментного шейдера (псевдокод)

```glsl
ivec2 p = ivec2(gl_FragCoord.x, u_viewport_h - 1.0 - gl_FragCoord.y) - u_origin; // верх слева
uvec3 B = uvec3(u_background);                          // фон буфера, непрозрачный
if (p.x < 0 || p.y < 0) { out = B; return; }
ivec2 cell_px = u_glyph;
ivec2 cell    = p / cell_px;
if (cell.x >= u_grid.x || cell.y >= u_grid.y) { out = B; return; }

ivec2 in_cell = p - cell * cell_px;                     // пиксель внутри ячейки
uvec4 d  = texelFetch(u_data, cell, 0);
uint slot = d.r & 0xFFFFu;                              // слот атласа, не кодовая точка (§6.1)
uint fl  = d.r >> 16;
uvec3 fg = rgb(d.g);                                    // 0…255
uvec3 bg = blend(B, rgb(d.b), alpha(d.b));              // фон ячейки поверх фона буфера (ADR-0013)

if ((fl & F_BOLD) != 0u) fg = min(fg + 0x55u, 255u);    // только RGB, альфа символа не меняется

ivec2 g = ivec2(int(slot) % 16, int(slot) / 16) * u_glyph + in_cell;
uint a = texelFetch(u_atlas, g, 0).r;                  // покрытие 0…255 (R8UI)

if ((fl & F_UNDERLINE) != 0u && in_cell.y == u_glyph.y - 1) a = 255u;
a = (a * alpha(d.g) + 127u) / 255u;                     // покрытие × альфа символа (`fade`)

// Целочисленное смешивание по каналам (ADR-0002): blend(x, y, a) = (x·(255 − a) + y·a + 127) / 255
out = vec4(vec3(blend(bg, fg, a)) / 255.0, 1.0);
```

Зафиксированные детали (контракт бит-идентичности GL ↔ Software, см. `soft_backend.rs`):
- `u_origin` — сетка **центрируется**: `origin = (размер_окна − размер_сетки) / 2` целочисленно, не меньше 0.
- BOLD — осветление, не второй глиф: `c' = min(c + 0x55, 255)` по каналам.
- Кадр — `0x00RRGGBB`. Смешивание в два шага, оба целочисленные `(x·(255−a) + y·a + 127)/255`: фон ячейки поверх фона буфера по `α_bg`, затем символ поверх фона ячейки по `(покрытие·α_fg + 127)/255` (ADR-0013). При `α = 255` формула совпадает с прежней бит в бит.

Использовать `texelFetch` (без фильтрации и нормализованных координат) — это гарантирует пиксельную точность и совпадение с CPU-версией.

## 8. Программный рендерер (fallback)

- Формат кадра — `u32` (0x00RRGGBB), совместимый с `softbuffer`.
- Реализует ту же логику, что и шейдер (раздел 7.3), но по строкам: для каждой dirty-строки ячеек перерисовываются `glyph_h` строк пикселей окна по высоте, в каждой — отрезок шириной `glyph_w`, заливаемый одним `slice::fill`.
- Сохраняется собственный кадровый буфер `Vec<u32>` размера окна; при `resize` пересоздаётся и перерисовывается целиком.
- Перерисовываются только dirty-строки; смена фона буфера — весь кадр (ADR-0010, ADR-0013). Фон ячейки смешивается с фоном буфера один раз на ячейку.
- Наложение (ADR-0014): записи рисуются в текстуру размером с сетку (`0xAARRGGBB`, RGB предумножен): `t' = mul(c, α) + mul(t, 255 − α)`, `t_a' = α + mul(t_a, 255 − α)` — сначала фон ячейки записи, затем символ с долей `fade(покрытие, α_fg)`; затем `out = t + mul(кадр, 255 − t_a)`. `mul(x, a) = (x·a + 127)/255`. Перерисовываются ещё строки, покрытые наложением в этом или прошлом кадре.
- Вывод в окно (ADR-0010): рендерер отдаёт полосы перерисованных строк; если буфер окна хранит прошлый кадр (`softbuffer` `age() == 1`) и кадр запрошен приложением, копируются только эти полосы и выводятся `present_with_damage`; буфер без прошлого кадра (`age ≠ 1`) или перерисовка по запросу системы — весь кадр, `present()`; ни одна строка не перерисована — вывода нет.
- Потоки (ADR-0016): кадр и текстура наложения рисуются непересекающимися полосами строк сетки в постоянном пуле `rayon` (`min(ядра, 4)` потоков); меньше 8 строк к отрисовке — в текущем потоке. Подготовка глифов и вывод в окно — в текущем потоке. Кадр от числа потоков не зависит; выделений памяти в кадре нет (NFR-6), `unsafe` не нужен (NFR-9).
- Оптимизации (по необходимости): развёртка глифа в маску 8 бит на строку, отдельный быстрый путь для однотонных строк.
- Требование к соответствию: результат Software и GL **побитово совпадает** на демо-сцене (допускается расхождение до 0 в каждом канале при отсутствии альфа-смешивания).
- Если `softbuffer` не смог создать поверхность (крайний случай), приложение завершается с понятным сообщением и кодом возврата ≠ 0.

## 9. Инициализация OpenGL (детали)

1. Через `glutin_winit::DisplayBuilder` подобрать конфигурацию: 8 бит на канал, без depth/stencil, без multisampling, по возможности аппаратное ускорение (`prefer_hardware_accelerated(Some(true))`).
2. Попытаться создать контекст `ContextApi::OpenGl(Some(Version::new(3, 3)))` с профилем Core; при ошибке — `ContextApi::Gles(Some(Version::new(3, 0)))`.
3. Создать оконную поверхность и сделать контекст текущим; VSync через `set_swap_interval` (при ошибке — игнорировать).
4. Создать `glow::Context` через `glutin::display::GlDisplay::get_proc_address`.
5. Проверить: версию, `GL_MAX_TEXTURE_SIZE`, успешную компиляцию и линковку шейдеров, отсутствие `glGetError` после создания текстур.
6. Обнаружение программных драйверов (`GL_RENDERER` содержит `llvmpipe`, `softpipe`, `GDI Generic`): вести себя согласно настройке `--allow-sw-gl` (по умолчанию GL разрешён, но `GDI Generic` (OpenGL 1.1 Microsoft) считается отказом и приводит к откату на Software). `GL_MAX_TEXTURE_SIZE < 1024` — тоже отказ.
7. Логировать: `GL_VENDOR`, `GL_RENDERER`, `GL_VERSION`, выбранный уровень.

## 11. Тестирование и критерии приёмки

### 11.1. Модульные тесты
- Буфер: запись/чтение ячеек, заливка, прокрутка, `resize`, корректность dirty-флагов.
- Шрифт: загрузка четырёх начертаний по признакам шрифта; подстановка при отсутствии файлов (временный каталог с подмножеством); ошибка без Regular; метрики ячейки; растеризация детерминирована; начертания различаются, подставленное совпадает с источником; псевдографика процедурная во всех начертаниях.
- Атлас: промах выделяет слот, попадание переиспользует; каналы заполняются лениво в одном слоте; отсутствующий символ → слот 0 без выделения; переполнение → сброс и продолжение работы; список «грязных» слотов; геометрия слотов на странице.
- Упаковка ячеек в `[u32; 4]` и обратно.

### 11.2. Интеграционные и визуальные тесты
- **Golden-тест:** Software-рендер демо-сцены сравнивается с эталонным PNG/сырой дампом (хранится в репозитории).
- **Сравнение GL и Software:** на машине с GL рендер в FBO (`RGBA8`) и чтение `glReadPixels` сравниваются с Software-кадром (допуск — 0) на нескольких сценах и двух кадрах подряд (полный и dirty-путь). GL недоступен → тест печатает причину и завершается успешно («пропуск»); ошибка после создания контекста — падение. `tests/stage4_gl.rs`.
- **Fallback-тест:** запуск с `--backend=gl` в окружении без GL (виртуальная машина без 3D, `LIBGL_ALWAYS_SOFTWARE`/`GALLIUM_DRIVER` недоступны, RDP) должен завершаться переходом на `soft`, а не падением. На машине с GL тот же путь проверяется флагом `--fail-gl`: stderr содержит причину и `backend Software`, окно работает.
- **Тест ошибок кадра (§5.3 п.5, FR-21, ADR-0007):** ошибки инжектируются флагами `--fail-frames=N` и `--lose-context` на настоящем окне. Сценарии: одна ошибка → повтор кадра, бэкенд прежний; ошибка и после повтора → откат GL → Software, работа продолжается; потеря контекста → откат сразу, без повтора; ошибки на Software → `App::run` возвращает ошибку (демо — код ≠ 0); ошибки, пережившие откат → остановка. Проверяются последовательность бэкендов, счётчик кадров и сообщения stderr. Нет окна или GL — сценарий печатает причину и завершается успешно («пропуск»). `tests/stage8_faults.rs`.

### 11.3. Ручная проверка (чек-лист)
- Windows 10/11 с дискретной и интегрированной графикой, в RDP-сессии, в виртуальной машине без 3D-ускорения.
- Linux: X11 и Wayland (GNOME/KDE), Mesa (Intel/AMD), NVIDIA proprietary, `llvmpipe`.
- Смена размера окна, DPI 100 % / 150 % / 200 %, полный экран, сворачивание/разворачивание.
- Работа при отсутствии `libEGL`/`libGL` (Linux): переход на Software.

### 11.4. Критерии приёмки
1. Сборка без ошибок и предупреждений clippy на Windows и Linux.
2. Размер бинарника замерен и записан в отчёт этапа (NFR-1; лимита нет).
3. Демо запускается и корректно отображает сцену на GL и Soft бэкендах; кадры совпадают.
4. При принудительной ошибке GL-инициализации (флаг `--fail-gl` для тестов) приложение работает на Software.
5. Нет утечек и роста памяти при 10 минутах непрерывной работы (проверка по диспетчеру задач / `top`).
6. Нагрузка на CPU в простое < 1 %.

## 13. Расширяемость (закладывается в архитектуру, но не реализуется в 1.0)

- **Vulkan/DX12/Metal:** добавляется новой реализацией трейта `Renderer` (например, на `wgpu`) за отдельной feature; цепочка выбора расширяется без изменения остальной части кода.
- **Несколько шрифтов:** *(Unicode вне BMP выполнен в 1.6 — ADR-0009)* расширение динамического атласа (FR-9) ключом «кодовая точка + шрифт», LRU вместо сброса, вторая страница как слой `TEXTURE_2D_ARRAY`; интерфейс рендереров (слот + начертание) сохраняется.
- **VT/ANSI-парсер и PTY:** отдельный модуль поверх `ScreenBuffer` (например, на базе `vte`), с библиотекой `portable-pty` либо собственным слоем ConPTY/`forkpty`.
- **Курсор:** вне 1.0 — реализуется приложением поверх `ScreenBuffer` (блочный — обменом fg/bg при записи ячейки, подчёркивание/черта — символом или флагом `UNDERLINE`) и, при необходимости, вторым проходом или слоем поверх кадра. Библиотека не рисует курсор и не держит его состояние (FR-3, FR-7). Мигание курсора требует периодического пробуждения цикла, а таймеров в библиотеке нет (FR-26) — это расширение.
- **Ввод приложения и контролы:** *(выполнено в 1.21 — ADR-0026)* библиотека по-прежнему не интерпретирует ввод (ADR-0004), но дополняет события: `PointerEvent::{Moved, Input, Wheel}` несут ячейку сетки под указателем (`cell`, с учётом центрирования сетки в окне, §7.2 `u_origin`), `Ctx` — состояние модификаторов (`WindowEvent::ModifiersChanged`) и размер ячейки в пикселях. Фокус, маршрутизация клавиш, мыши и текста (`KeyEvent.text` непринятой клавиши и `on_text` → `Ui::text`, 1.22 — ADR-0027), сообщения приложения и модальные слои — в крейте `gterm-widgets` (`Ui`, `Control`, `Modal`), не в библиотеке; курсор поля ввода рисует виджет обменом fg/bg (`TextInput`, ADR-0027) — библиотека по-прежнему курсора не знает.
- **Комбинации клавиш:** *(выполнено в 1.23 — ADR-0028)* `on_key` отдаёт нажатия и отпускания (FR-25); модуль `hotkey` вне цикла событий — приложение кормит трекер: `Key` по `physical_key` (одна физическая клавиша — одно имя в любой раскладке), дерево удержаний `Hotkey` с записью `K`/`K+inner`/`K+[a,b]`/`a,b` и образцами `|`, сигнал на каждое отпускание, при последнем — полная комбинация. Карта «сочетание → сообщение» *(выполнено в 1.24 — ADR-0029)*: в `gterm-widgets` — `HotkeyMap` в состоянии приложения, `Ui::hotkeys`/`Modal::hotkeys`; привязка срабатывает на нажатие, не принятое контролом под фокусом (сначала полная история комбинации, затем цепочка удержанных клавиш); при модальном слое действует только его карта; запись — имена физических клавиш, акселераторов `Alt+буква` нет; потерю фокуса окна сообщает `on_focus`, трекер сбрасывает приложение.
- **Выделение и буфер обмена в поле ввода:** *(выполнено в 1.25 — ADR-0030)* `gterm-widgets`: выделение — промежуток между якорем и курсором (`Shift` с клавишами движения, протяжка мышью, `Ctrl+A`), набор и удаление заменяют выделенное; копирование, вырезание и вставка — команды правки, которые дерево распознаёт по физическим клавишам (`Ctrl+C/X/V`, `Ctrl+Insert`, `Shift+Delete`, `Shift+Insert`) и передаёт контролу под фокусом до обычной доставки клавиши; поле их поглощает; буфер — трейт `Clipboard` в состоянии приложения, системная реализация — `arboard` за фичей `system-clipboard`; `gterm` буфера обмена не знает.
- **Флажок и группы:** *(выполнено в 1.26 — ADR-0031)* `gterm-widgets`: `Checkbox` — метка и подпись, переключение пробелом, `Enter` и отпусканием мыши внутри области, новое значение — сообщением привязки `on_toggle`; группа — контейнер `Ui::group` с рамкой и заголовком; переключателей «один из многих» и третьего состояния нет.
- **Виджеты, часть 2:** *(выполнено в 1.27 — ADR-0032)* `Clear`, `Gauge` (доля с точностью до 1/8 ячейки), `LineGauge`; `Tabs` — контрол с фокусом, клавишами и мышью (отклонение от ТЗ виджетов 2026-10-23 в сторону ADR-0026); `Scrollbar` — только отображение, значения даёт приложение. Индикатор уровня `Meter` (ADR-0034, `docs/spec/2026-11-13-tick-meter.md`): зоны «порог → стиль» с цветом ячейки по её месту на шкале, заполнение с точностью до половины ячейки, отметка пика; значения даёт приложение. Ползунок `Slider` (1.29 — ADR-0036, `docs/spec/2026-11-16-double-click-slider.md`): контрол с целым значением в границах и шагом — клавиши `←`/`→`/`Home`/`End`, клик и протяжка по дорожке под захватом, колесо; новое значение — сообщением привязки `on_value` только при изменении пользователем.
- **Темы оформления:** *(выполнено в 1.30 — ADR-0037)* `gterm-widgets`: `Theme` — области «имя → стиль» и палитра в формате тем редактора helix (TOML: цвет или `{ fg, bg, modifiers, underline }`, `[palette]`, `inherits`; расширение — `#RRGGBBAA`), значение в состоянии приложения; хранит все области файла, приложение читает свои по имени (`style` с наследованием по точке, `first`, `color`). Подключение — `Ui::theme(&theme)`: базовый стиль области, рамки, модальный слой и все контролы; области своей раскраски знает сам виджет, стиль, заданный явно, сильнее темы. Чего ячейка не умеет (FR-3): `reversed` заменяется обменом цветов при загрузке, остальное пропускается с предупреждением. Встроенная тема — в коде; разбор TOML — крейт `toml` за фичей `theme-toml`. Библиотека `gterm` о темах не знает.
- **Вывод недостающих областей темы:** *(выполнено в 1.31 — ADR-0038)* тема читается в три уровня, у каждого элемента — имя области: основа (`ui.background`, `ui.text`, `ui.accent`, `error`), тона (`ui.control`, `ui.control.focus|pressed|disabled`, `ui.selection`, `ui.popup`, `ui.window`, `ui.window.focus`, `ui.text.focus`, `ui.text.inactive`), области виджетов — ссылки на тона. Заданное в теме берётся как есть; недостающее выводится целочисленными формулами (`Theme::derive`, при загрузке — само) и помечается (`Theme::is_derived`). Тема без `ui.background` или `ui.text` красится по прежним цепочкам ADR-0037.
- **SVG-глифы, расширения FR-8.6:** цвета из файла (многоцветные тайлы — вторая текстура или слой), прозрачность и маски, «широкие» тайлы на 2 ячейки (квадратная клетка карты при ячейке ~1 : 2), загрузка SVG из памяти и горячая перезагрузка каталога.
- **Отдельные текстуры цвета:** палитра из 256 индексов вместо TrueColor для экономии передачи.
- **Эффекты в шейдере:** CRT-скан-линии, свечение, кривизна экрана — как необязательный второй проход.

## 14. Риски и их снижение

| Риск | Вероятность | Митигация |
|---|---|---|
| Окно, созданное под GL-конфигурацию, несовместимо с `softbuffer` при откате (различия визуала/формата пикселей на X11, `SetPixelFormat` на Windows) | Средняя | При откате пересоздавать окно; проверить на всех целевых платформах на этапе 5 |
| `GDI Generic` (OpenGL 1.1) на Windows в виртуальных машинах формально «создаёт контекст», но не поддерживает GL 3.3 | Высокая | Проверка версии и `GL_RENDERER`, при отказе — Software |
| Различия `glutin`/`winit` между версиями (частые breaking changes API) | Высокая | Зафиксировать версии в `Cargo.lock`, изолировать вызовы в модулях `app/` и `gl_backend.rs` |
| Размер бинарника превысит лимит из-за features `winit`/`glutin` | Средняя | Отключить features по умолчанию, замерять размер на каждом этапе (`cargo bloat`) |
| Невозможность использовать `RGBA32UI` на старых GLES-драйверах | Низкая | Запасной формат — две текстуры `RGBA8` (код+флаги, цвета) под флагом; либо откат на Software |
| Wayland: отсутствие серверных декораций окна | Средняя | Использовать клиентские декорации `winit` (feature `wayland-csd-adwaita` при необходимости — с учётом размера) |
| Разница поведения VSync/`swap_interval` на разных драйверах | Низкая | Не считать ошибку `set_swap_interval` критической; ограничение частоты по таймеру |
