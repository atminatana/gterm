# Тесты: кодовая точка — `char` во всём Unicode

## Состав

Новые тесты (4) и расширенные:

| Тест | Проверяет |
|---|---|
| `stage1_buffer::write_row_keeps_codepoints_outside_bmp` | `write_row("a\u{F0001}\u{10FFFD}")` сохраняет кодовые точки целиком (регрессия обрезки до u16) |
| `stage1_buffer::unpack_of_invalid_codepoint_gives_blank_char` | `from_packed` с суррогатом U+D800 и 0x110000 → `'\0'` |
| `stage1_buffer::cell_pack_and_unpack_are_round_trip_exact` (изменён) | раскладка ADR-0009 п.4 на U+F0001: `packed[0] == 0xF0001`, флаги в `packed[3]`, обратная распаковка точна |
| `stage2_font::rasterization::glyph_outside_bmp_is_rasterized` | `has_glyph(U+F0041)`, растр с покрытием, отличается от `A` |
| `stage2_font::atlas::codepoint_outside_bmp_gets_its_own_slot` | U+F0041 получает свой слот ≠ слоту `A`, `slot_of` его находит, растры различны; `char::MAX` → слот 0 без выхода за таблицу |
| `stage4_gl` (сцена `outside BMP 16px`) | GL 3.3 и GLES 3.0 ≡ Software, допуск 0, 2 кадра: U+F0001, U+F0041, U+F1AF0 (иконки MDI) и U+10FFFD (нет глифа → слот 0) |

Остальные тесты изменены только в местах вызова (литералы `char` вместо `as u16`); утверждения не ослаблялись, golden-эталоны не перезаписывались.

## Результат прогона

`cargo test` (debug, Windows 10, NVIDIA GTX 1060, драйвер 581.57): 106 тестов harness'а ok + 4 оконных бинарника ok; `stage4_gl`: `GL ↔ Software identical, 5 scenes` на OpenGL 3.3 и OpenGL ES 3.0.

## Ограничения

- `stage4_gl` на машине без GL печатает причину и проходит (§11.2) — на этой машине GL есть, сравнение выполнено.
- Отображение иконок в `full_table` проверяется глазами на машине владельца (§11.3).
