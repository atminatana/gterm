# ADR-0038. Тема в три уровня: основа, тона, области виджетов — недостающее выводится, у всего есть имя

- **Дата:** 2026-11-23
- **Статус:** Accepted (ТЗ `docs/spec/2026-11-23-theme-roles.md` утверждено владельцем 2026-11-23: формат helix остаётся базой; недостающее создаётся из основных цветов; у выводимых элементов есть имена — для корректировки и полного ручного описания; О6 — имена `ui.control*`; О1–О5 — рекомендованные варианты).
- **Тема:** ADR-0037 (дополняет: порядок поиска стиля), ADR-0013, ADR-0003. План — `docs/plans/2026-11-23-theme-roles.md`.

## Контекст

Областей элементов форм в темах helix нет, и запасные цепочки ADR-0037 (`ui.button` → `ui.menu` и т. п.) дают на чужих темах неразличимые и малоконтрастные состояния — это показал пример `theme`. В sniffnet тема — шесть цветов, остальное выводится формулами в коде; контраст задан конструкцией, но поправить отдельный выведенный цвет нельзя: у него нет имени.

## Решение

1. **Формат темы не меняется** — области helix. Тема читается на трёх уровнях; каждый элемент каждого уровня — область с именем. Заданное в файле (или через `Theme::set`) берётся как есть, недостающее выводится из уровня выше и записывается в тему под тем же именем с пометкой (`Theme::is_derived`).
2. **Основа:** `ui.background` (`bg`) и `ui.text` (`fg`) — обязательны; без любой из них вывода нет, тема ведёт себя по ADR-0037. `ui.accent` = `{ fg, bg }` (новая область: акцент и текст на нём); не задана — `bg` ← `fg` из `ui.text.focus` → `bg` из `ui.selection` → цвет текста, `fg` ← фон. `error` (`fg`) ← `diagnostic.error` → красный по светлоте темы.
3. **Тона** (имена helix там, где смысл совпадает; новые — `ui.control*`). Арифметика целочисленная: тема тёмная, если сумма каналов фона ≤ 382; `сдвиг` — каналы фона на 38 вверх (тёмная) или вниз (светлая) с насыщением; `смесь(a, b, k/n)` — поканально с округлением, альфа смешивается так же.

| Тон | Вывод |
|---|---|
| `ui.text.inactive` | `fg` из `ui.virtual`, иначе `смесь(текст, фон, 1/2)` |
| `ui.text.focus`, `ui.window.focus` | `fg` = акцент |
| `ui.window` | `fg` = цвет тона `ui.text.inactive` |
| `ui.popup` | `bg` = `смесь(фон, сдвиг, 1/2)` |
| `ui.selection` | `fg` = текст, `bg` = `смесь(фон, акцент, 1/3)` |
| `ui.control` | `fg` = текст, `bg` = `сдвиг` |
| `ui.control.focus` | `fg` = текст тона, `bg` = `смесь(фон тона ui.control, акцент, 1/4)` |
| `ui.control.pressed` | `fg` = текст тона, `bg` = `смесь(фон тона ui.control, акцент, 1/2)` |
| `ui.control.disabled` | `fg` = цвет тона `ui.text.inactive`, `bg` = `смесь(фон, фон тона ui.control, 1/2)` |

   Состояния `ui.control.*` считаются от тона `ui.control` — заданного или выведенного: поправка одного тона доходит до его состояний.
4. **Области виджетов** — только ссылки, без формул: `ui.button` ← `ui.control`; `ui.button.focus` ← `ui.accent`; `ui.button.pressed` / `.disabled` ← `ui.control.pressed` / `.disabled`; `ui.input` / `.focus` ← `ui.control` / `.focus`; `ui.input.selection`, `ui.checkbox.pressed`, `ui.list.selected`, `ui.table.selected` ← `ui.selection`; `ui.input.placeholder`, `ui.checkbox.disabled` ← `ui.text.inactive`; `ui.checkbox.focus`, `ui.tabs.focus` ← `ui.text.focus`; `ui.combo` / `.focus` / `.selected` ← `ui.input` / `ui.input.focus` / `ui.list.selected`; `ui.table.header`, `ui.tabs.selected`, `ui.scrollbar.thumb` ← `fg` из `ui.text.focus`; `ui.scrollbar`, `ui.gauge.unfilled` ← `fg` из `ui.window`; `ui.gauge.filled` ← `fg` акцент, `bg` из `ui.control`.
5. **Порядок поиска стиля:** явный стиль виджета → область темы (заданная или выведенная) → прежняя запасная цепочка ADR-0037. Вывод записывает области под их собственными именами, поэтому цепочка обрывается на первом звене, а код виджетов не меняется; до остальных звеньев дело доходит только в теме без основы.
6. **Когда выводится:** при загрузке (`Theme::load`, `Theme::from_toml_str`), во встроенной теме и по вызову `Theme::derive()` для темы, собранной в коде. `derive()` повторяем: прежние выведенные области отбрасываются и считаются заново, заданные не трогаются; `set` снимает с области пометку «выведена».
7. **Жирное начертание в выводимых стилях не используется** — `BOLD` осветляет цвет (ADR-0003).
8. **Темы sniffnet** — 22 файла `examples/themes/sniffnet_*.toml` (10 файлов и 12 встроенных палитр sniffnet 1.6.0): палитра из шести цветов и три области основы; тона и области виджетов выводятся. Источник и лицензия — `examples/themes/README.md`.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Только роли, как в sniffnet, без областей | решение владельца: формат helix — база, которую приложение дорабатывает; терялись бы точечная настройка и свои области приложения |
| Формулы прямо в строках областей виджетов (первая редакция ТЗ) | замечание владельца: выведенный цвет без имени нельзя поправить, не переписав все области, где он встречается |
| Роли по именам палитры (`[palette] accent = …`) | палитры тем helix уже используют произвольные имена — совпадение дало бы чужой цвет |
| Вывод в момент обращения, внутри виджетов | правила разошлись бы по файлам виджетов; просмотрщик и свои виджеты приложения выведенного не видели бы |
| Прежние цепочки helix сильнее вывода | найденная проблема осталась бы для большинства тем helix |
| Свой префикс (`gterm.control*`) или слово `surface` | решение владельца: `ui.control*` в общем пространстве `ui.` |
| Ссылки уровня 3 строго по первой редакции ТЗ (`ui.tabs.focus` ← `ui.accent`, `ui.input.selection` ← `ui.accent`) | `gterm_dark`, `gterm_light` и встроенная тема этих областей не задают, их вид изменился бы; взяты действующие цепочки ADR-0037 |
| Переписать свои темы на одну основу | решение владельца: оставить образцами точечной настройки |

## Последствия

**Плюсы:** тема из трёх строк основы даёт полный вид всех контролов; одна строка тона меняет все ссылающиеся виджеты; тема, описанная вручную целиком, не получает выведенных цветов; код виджетов и прежние тесты цепочек не тронуты; приложение читает тона и выведенные области по имени для своих виджетов.

**Минусы / риски:** тема helix меняет вид в примерах (цель задачи); тон с именем helix, заданный в чужой теме неудачно (`ui.selection`, `ui.window`), берётся как есть; в теме helix, где `ui.text.focus` совпадает с `ui.text`, акцент равен цвету текста — лечится строкой `ui.accent`; контраст выведенных пар не проверяется; правка основы или тона через `set` выведенное не пересчитывает до вызова `derive()`; `scopes()` загруженной темы теперь включает выведенные области.

## Поправка 2026-11-23: полная запись темы — `Theme::to_toml_string`

**Контекст.** Выведенные области видны в просмотрщике, но в файле их нет: чтобы поправить тон или взять тему за основу, автору приходилось переписывать значения с экрана. Владелец поручил сохранение текущей темы целиком, включая вычисленные цвета, — в файл, который можно править или доработать.

**Решение.** `Theme::to_toml_string() -> String` (`theme/save.rs`, без зависимости от разборщика — доступна и без фичи `theme-toml`): текст формата helix, где каждая область — заданная и выведенная — записана явно, одной строкой. Разделы идут по уровням: «Основа», «Тона», «Области виджетов», «Остальные области», затем `[palette]`; выведенные области помечены комментарием `# выведено`. Цвет пишется именем палитры, если он в ней есть (при нескольких именах одного цвета — первое по алфавиту), иначе `#RRGGBB` / `#RRGGBBAA`; область только с цветом символа — строкой, прочие — таблицей `{ fg, bg, modifiers }`. Загрузка записи даёт те же области и палитру, и все они уже заданы; строка, удалённая из тонов или областей виджетов, при загрузке выводится заново. Запись в файл — дело приложения (в библиотеке только текст): пример `theme` по `F6` предлагает путь `<имя>_full.toml` в первом каталоге перечня и не заменяет существующий файл.

**Альтернативы.** Записывать только заданные области — файл не содержал бы того, что автор хочет поправить. Писать все цвета числами — палитра темы перестала бы работать как место правки, а запись темы sniffnet потеряла бы связь областей с её шестью цветами. `Theme::save(path)` в библиотеке — политика перезаписи и выбор каталога принадлежат приложению. Сохранять `inherits` и исходный текст файла — тема хранит разрешённые стили, а не текст; запись всегда плоская.

**Последствия.** Запись плоская: `inherits`, комментарии исходного файла и то, что загрузка пропустила с предупреждением, в неё не попадают; `reversed` записан уже обменянными цветами. Снятие флагов (`Style::remove`) в формате helix не выражается и не записывается — у тем из файлов его нет. В записанном файле правка основы уже не меняет тона и области виджетов: они заданы; чтобы вернуть вывод, строку удаляют.
