# ADR-0012. Флаги ячейки — только `BOLD`, `ITALIC`, `UNDERLINE`; мигания, `INVERSE`, `CURSOR` и таймера в библиотеке нет

- **Дата:** 2026-10-09
- **Статус:** Accepted (частично заменяет 0004, 0006, 0010)
- **Тема:** состав и порядок битов `CellFlags`; отход от ТЗ FR-3, FR-7, FR-15, FR-26; отчёт — `docs/done/2026-10-09-cell-flags-trim.md`

## Контекст

`CellFlags` содержал `INVERSE`, `UNDERLINE`, `BLINK`, `BOLD`, `CURSOR`, `ITALIC` (биты 0–5). `CURSOR` не читал никто: курсор убран из библиотеки ещё в ADR-0004. `INVERSE` меняет местами fg и bg, а это приложение может сделать само при записи ячейки. `BLINK` тянул за собой таймер `Blinker`, счётчик мигающих ячеек в `ScreenBuffer`, `ViewParams::blink_phase` и uniform `u_blink`, `Ctx::blink_phase`, `AppOptions`/`Request::blink_period`, `AppHandler::on_tick`, `WaitUntil` в цикле и частичную перерисовку строк с `BLINK` в Software (ADR-0010 п.1). Владелец решил (2026-10-09) оставить три флага и убрать мигание вместе со всей связанной логикой, включая таймер и `on_tick`.

## Решение

1. `CellFlags`: `BOLD = 1 << 0`, `ITALIC = 1 << 1`, `UNDERLINE = 1 << 2`. В шейдере `cell.frag` те же значения: `F_BOLD = 1u`, `F_ITALIC = 2u`, `F_UNDERLINE = 4u`. Совпадение проверяет тест `flag_bits_are_bold_italic_underline_from_zero`.
2. Алгоритм §7.3 в обоих рендерерах: цвета ячейки, затем осветление при `BOLD`, затем глиф начертания по `BOLD`/`ITALIC`, затем подчёркивание. Обмена цветов и гашения глифа нет.
3. Таймера в библиотеке нет: `src/blink.rs` удалён, `on_tick` и `Ctx::blink_phase` тоже, `ViewParams` содержит только `border_color`. Цикл всегда ждёт событий (`ControlFlow::Wait`). Приложение будит только ввод, окно и запрос кадра.
4. Software перерисовывает только dirty-строки. При `resize`, смене `ViewParams` или сбросе атласа рисуется полный кадр. Полосы и вывод `present_with_damage` (ADR-0010 п.2–7) не меняются.
5. Курсор демо рисует приложение: меняет fg и bg своей ячейки и не мигает. Строка статуса `demo` и `full_table` обновляется по событиям (ввод, смена страницы, смена сетки или бэкенда).
6. Оконные автотесты ведёт `on_frame`. `Probe` просит следующий кадр, как замер `--bench`, и выходит после N кадров. Вместо прежнего сторожа на тиках стоит поток-сторож с тайм-аутом 60 с.

## Альтернативы и обоснование

| Вариант | Почему не выбран |
|---|---|
| Оставить общий периодический тик для приложений (`tick_period`, `on_tick` без фазы) | владелец выбрал удалить всё; периодический таймер приложение заведёт само, если понадобится |
| Сохранить старые номера битов (`UNDERLINE = 1 << 1`, `BOLD = 1 << 3`, `ITALIC = 1 << 5`) | порядок задал владелец; с непрерывными битами 0–2 флаги проще сверять с шейдером |
| Оставить `INVERSE` только для курсора демо | обмен цветами при записи даёт тот же результат без ветки в обоих рендерерах |

## Последствия

- **Плюсы:** алгоритм §7.3 короче на две ветки в шейдере и в Software; в простое цикл не просыпается вообще (FR-26 выполняется тривиально); меньше состояния в `App`, `ScreenBuffer` и `ViewParams`.
- **Минусы / риски:** ТЗ приведено к решению в версии 1.10 (FR-3, FR-7, FR-15, FR-26 и др.). FPS в строке статуса демо в простое не обновляется, его видно только после событий. Golden-эталоны 16 и 32 px перезаписаны: сцена содержит другие флаги. Оконные тесты теперь гоняют кадры подряд вместо 20-мс тиков. Проверено глазами владельцем 2026-10-09 (§11.3).
