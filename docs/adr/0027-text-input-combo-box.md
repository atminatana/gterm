# ADR-0027. Поле ввода и выпадающий список: текст как вход контрола, курсор в виджете, раскрытие слоем с `on_click_outside`

- **Дата:** 2026-10-30
- **Статус:** Accepted (ТЗ `docs/spec/2026-10-30-widget-edit.md` утверждено владельцем 2026-10-30; решения владельца по четырём вопросам — в постановке ТЗ).
- **Тема:** ТЗ §13; ADR-0004, ADR-0023, ADR-0026. План — `docs/plans/2026-10-30-widget-edit.md`.

## Контекст

Механизм контролов ADR-0026 доставляет клавиши и мышь, но текст приложение получает отдельным событием `on_text` (`Ime::Commit`, IME в `gterm` включён), а контролы не умеют его принимать. Для форм нужны поле ввода и выпадающий список; курсор библиотека не рисует (ADR-0004), а раскрытому списку нужно закрываться по клику мимо, который модальный слой ADR-0026 поглощает молча.

## Решение

1. **Текст — третий вход контрола:** `Control::text(&str, &mut Messages<M>) -> Handled`. Два источника, исключающие друг друга для одного нажатия (проверено по исходникам `winit 0.30.13`: Windows `event_loop.rs:1527-1598` — `Ime::Commit` только внутри `WM_IME_COMPOSITION`/`WM_IME_ENDCOMPOSITION`, обычный набор идёт в `KeyEvent.text` из `WM_CHAR`; X11 `event_processor.rs:968-1010` — либо `KeyboardInput` с текстом, либо `Ime::Commit`): (а) обычный набор — `KeyEvent.text`: клавишу, не принятую контролом под фокусом, дерево доставляет ему как текст (`KeyMsg::typed_text` — без `Ctrl`/`Alt`/`Super` и с хотя бы одним печатным символом, чтобы `Esc` и `Enter` не глотались); (б) IME-композиция — `AppHandler::on_text` → `Ui::text(&str)`. `gterm` не меняется; символьные клавиши поле в `key` не обрабатывает — текст приходит через `text` обоими путями, двойного ввода нет.
2. **События с данными:** `WidgetEvent::Changed(String)` и `Submitted(String)`, привязки `on_change`/`on_submit` у встроенных контролов — по образцу `on_select`.
3. **`TextInput` — базовый однострочный редактор** (вставка в курсор, `Backspace`/`Delete`, стрелки, `Home`/`End`, `Enter`, клик ставит курсор, прокрутка держит курсор видимым); курсор рисует виджет обменом fg/bg только под фокусом, без мигания (ТЗ §13, ADR-0012). `Tab` переводит фокус — опции `wants_tab` нет.
4. **`ComboBox` раскрывается слоем** в том же описании, и поле, и слой строит один вызов `Ui::combo_box(widget, &mut state, on_select)`: пока список закрыт — обычный встроенный контрол; пока раскрыт — поле рисуется снимком состояния (ввод ему не нужен, его берёт слой), а `&mut` состояние держит содержимое слоя (`Ui::owned` — контрол, которым владеет описание, с узлом в состоянии приложения). Слой — `Modal::below(anchor, height)` под полем (над — при нехватке места), поднимается из дочернего описания к корню; выбор (`Enter`, клик по строке) закрывает список и публикует `on_select` при изменении; `Esc` список закрывает сам, клик мимо — через `Modal::dismiss_on_click_outside` → `Control::dismiss`. Сообщения приложению для закрытия не нужны. В закрытом поле стрелки значения не листают.
5. **Слой:** `Modal::at`, `Modal::below`, `Modal::on_click_outside(M)` — сообщение при левом нажатии вне области (нажатие по-прежнему поглощается), `Modal::on_close(M)` (`M: Clone`) — одно сообщение на `Esc` и клик мимо, `Modal::dismiss_on_click_outside()` — закрытие силами контролов содержимого; без привязок поведение ADR-0026. Программные `TextInputState::set_value`/`clear` событий не дают — события отражают ввод пользователя.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Только `Ime::Commit` → `on_text` (первая редакция) | на Windows и X11 обычный набор приходит в `KeyEvent.text`, `Ime::Commit` — только при композиции: поле не получало набранный текст (обнаружено владельцем глазами 2026-10-30) |
| Символьные клавиши в `key()` поля | поле знало бы о `Key::Character`, а текст из IME — отдельно; единый вход `text` с подачей из обоих источников проще и не удваивает ввод |
| Выделение и буфер обмена в первом шаге | владелец выбрал базовый объём; буфер обмена — внешняя зависимость и риски Wayland |
| `wants_tab` у поля | владелец выбрал перевод фокуса; автодополнение — не в этой задаче |
| Список раскрывается внутри раскладки, сдвигая соседей | непривычно; слой уже есть |
| Без раскрытия (значения листаются стрелками) | владелец выбрал раскрытие списком |
| Закрытие списка сообщением приложения (`on_close`, вариант ТЗ п. 3) | при реализации выяснилось, что поле и слой не могут оба держать `&mut` на состояние, поэтому слой строит сам крейт (`Ui::combo_box`) и владеет состоянием — закрыть список он может сам; сообщение приложению стало бы лишней веткой `update` на каждый список. `Modal::on_close` оставлен для слоёв приложения |
| Закрытие списка через `MouseKind::Cancel` | `Cancel` означает уход указателя из окна — список закрывался бы при каждом выходе мыши; введён отдельный `Control::dismiss` |

## Последствия

**Плюсы:** формы собираются из встроенных контролов с привязками; `gterm` не тронут; слой получил два общих расширения (`at`, `on_click_outside`), полезные меню.

**Минусы / риски:** копия строки в каждом `Changed`; пока список раскрыт, поле — снимок, и его область в состоянии не обновляется (слой строится по области последней закрытой раскладки — при смене размера окна с раскрытым списком он остаётся на старом месте до закрытия); `Ui::owned` требует от контрола хранить узел в состоянии приложения; `on_close` требует `M: Clone`; курсор без мигания виден только контрастом fg/bg. Размеры release — в `docs/done/2026-10-30-widget-edit.md`.
