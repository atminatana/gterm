# ADR-0030. Выделение и буфер обмена в поле ввода: команды правки — вход контрола по физическим клавишам, трейт `Clipboard`, системный буфер на `arboard` за фичей по умолчанию

- **Дата:** 2026-11-12
- **Статус:** Accepted (ТЗ `docs/spec/2026-11-12-text-input-clipboard.md` утверждено владельцем 2026-11-12; О1–О4 — варианты (a)).
- **Тема:** ТЗ §13; ADR-0004, ADR-0026, ADR-0027, ADR-0029. План — `docs/plans/2026-11-12-text-input-clipboard.md`.

## Контекст

`TextInput` (ADR-0027) не умел выделять текст и работать с буфером обмена. Владелец: поле само обрабатывает стандартные сочетания (`Ctrl+V`, `Ctrl+X`) и поглощает их; запись сочетаний — физические клавиши. Контрол получает только логическую клавишу (`KeyMsg`), физическую видит дерево (`Ui::route_key_event`, ADR-0029). `winit` буфера обмена не даёт; описание экрана живёт одно событие, а владелец системного буфера на X11 обязан жить всё время работы программы.

## Решение

1. **Выделение — якорь в `TextInputState`:** выделение — промежуток между якорем и курсором. `Shift` + стрелки/`Home`/`End` расширяют, движение без `Shift` снимает (`←` — в начало, `→` — в конец выделения), набор, вставка, `Backspace`, `Delete` заменяют выделенное одним `Changed`. Мышь: нажатие ставит якорь, протяжка под захватом расширяет и прокручивает за краем, `Shift` + нажатие расширяет. Рисуется только под фокусом стилем `selection_style` (по умолчанию обмен fg/bg); при непустом выделении ячейка курсора не рисуется.
2. **Команды правки — вход контрола:** `Control::edit(command, &mut dyn Clipboard, out) -> Handled` (по умолчанию `No`), `EditCommand::{Copy, Cut, Paste, SelectAll}`. Дерево распознаёт сочетание по физической клавише и модификаторам (`EditCommand::from_key`) и вызывает метод у контрола под фокусом **до** обычной доставки клавиши; `No` — клавиша идёт прежним путём (контрол → текст → карта сочетаний). Сочетания: `Ctrl+C`/`Ctrl+Insert`, `Ctrl+X`/`Shift+Delete`, `Ctrl+V`/`Shift+Insert`, `Ctrl+A`.
3. **Буфер — трейт `Clipboard`** (`get`/`set`/`is_available`: вырезание при недоступном буфере текст не удаляет — иначе он пропал бы) в состоянии приложения, подключается `Ui::clipboard(&mut …)` на корне; слой пользуется им же. `MemoryClipboard` — в памяти. Без подключённого буфера поле команды всё равно поглощает, операции с буфером — без действия.
4. **`SystemClipboard` на `arboard 3.7`** (`default-features = false` — только текст) за фичей `system-clipboard`, включённой по умолчанию. Ошибки не паникуют: `get` → `None`, `set` — без действия, причина один раз в stderr.
5. **Вставка в однострочное поле:** перевод строки и табуляция → пробел, прочие управляющие символы отбрасываются.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Сочетания в `Control::key` по логической клавише | `Ctrl+C` в русской раскладке — «с» кириллическая; владелец: всегда латиница |
| Физическая клавиша полем в `KeyMsg` | меняет конструктор сообщения во всех тестах и контролах ради четырёх сочетаний; дерево уже получает её отдельным аргументом |
| Только трейт, системную реализацию пишет приложение (О1-b) | каждое приложение повторяло бы обёртку; владелец выбрал готовую реализацию |
| Буфер в `gterm` через `Ctx` (О1-c) | библиотека ввод не интерпретирует (ADR-0004), зависимость попала бы во все бинарники |
| Только `Ctrl+C/X/V` (О2-b) | классические `Ctrl+Insert`/`Shift+Delete`/`Shift+Insert` привычны и стоят трёх строк |
| При вставке отбрасывать переводы строк или брать первую строку (О3-b, c) | склейка слов либо потеря текста |
| Поле без буфера пропускает сочетания в карту (О4-b) | `Ctrl+C` из поля запускал бы постороннюю привязку; поведение поля зависело бы от подключения |
| `ClipboardOp` без «выделить всё» (формулировка ТЗ) | `Ctrl+A` тоже должен распознаваться по физической клавише — тем же путём; перечисление названо `EditCommand` |
| Фича `arboard/wayland-data-control` | тянет `wl-clipboard-rs`; на Wayland буфер работает через XWayland; проверить на машине владельца и при необходимости включить отдельной задачей |

## Последствия

**Плюсы:** стандартная правка в поле, раскладко-независимые сочетания, контролы не знают об ОС, приложение может подменить буфер (`MemoryClipboard`, свой трейт-объект).

**Минусы / риски:** новая зависимость `arboard` (Windows: `clipboard-win`, `error-code`; Linux: `x11rb` — уже в сборке, `parking_lot` и четыре мелких крейта); на Wayland без XWayland системный буфер недоступен (ошибка в stderr, поле работает без буфера); системный буфер автотестом не проверяется; при фокусе в поле `Ctrl+A/C/X/V` до карты сочетаний не доходят. Размеры release — в `docs/done/2026-11-12-text-input-clipboard.md`.
