# ADR-0011. `app.rs` → каталог `src/app/` по обязанностям, внешний API через реэкспорт

- **Дата:** 2026-10-08
- **Статус:** Accepted
- **Тема:** размер и связность `src/app.rs` (QG-06, CQ-01/CQ-02); план — `docs/plans/2026-10-08-app-module-split.md`

## Контекст

`src/app.rs` вырос до 1173 строк (порог QG-06 для логики — 500) и совмещает семь обязанностей: контракт для приложений (`AppHandler`, `Ctx`, `Request`, `PointerEvent`, `FrameStats`), параметры и ошибки (`AppOptions`, `Grid`, `GridMode`, `AppError`, `auto_grid`, `centered_origin`), состояние бэкенда (`Backend`, `SoftState` с выводом в окно), цепочку уровней GL → GLES → Software с откатами и переключением, геометрию окна и DPI, кадр и цикл (`render_frame`, повтор, таймер мигания), разбор событий `winit`. Разные задачи (ADR-0005, -0007, -0010) правят разные части одного файла.

## Решение

1. `src/app.rs` становится каталогом `src/app/`:
   - `mod.rs` — структура `App`, `new`, `run`, геттеры, реэкспорты;
   - `api.rs` — `AppHandler`, `Ctx`, `Request`, `PointerEvent`, `FrameStats`;
   - `options.rs` — `AppOptions`, `Grid`, `GridMode`, `AppError`, `auto_grid`, `centered_origin`;
   - `backend.rs` — `Backend`, `SoftState` (вывод Software в окно);
   - `chain.rs` — создание окна и уровней, откат, переключение бэкенда;
   - `window.rs` — атрибуты окна, подгонка растеризатора, `resize_window`, `apply_scale_factor`, заголовок;
   - `frame.rs` — `render_frame`, инжекция ошибок, `redraw`, `request_redraw`, `stop_with`, таймер мигания;
   - `events.rs` — `impl ApplicationHandler`, `notify`, `apply_request`.
2. Методы `App` остаются в блоках `impl App` дочерних модулей: дочерний модуль видит приватные поля `App`. Методы, вызываемые из соседних модулей, получают `pub(super)` — видимость вне `app` не меняется.
3. Внешний путь `gterm::app::…` для всех публичных имён сохраняется реэкспортом в `mod.rs`; файлы вне `src/app/` не меняются.
4. Перенос — отдельный набор изменений, только перемещение кода (CQ-02.1): логика, сигнатуры и тексты не меняются, кроме объявлений видимости и `use`.

## Альтернативы и обоснование

| Вариант | Почему не выбран |
|---|---|
| Четыре файла (`mod`, `api`, `backend` с цепочкой, `events`) | `backend.rs` ~420 строк снова у порога и смешивает состояние бэкенда с логикой откатов |
| Оставить файл как есть | порог QG-06 превышен вдвое; правки разных задач сходятся в одном файле |
| Вынести части в отдельные типы (`BackendChain`, `FramePresenter`) с собственным состоянием | меняет логику и владение полями — уже не механический перенос; без нужды (CS-1.2) |

## Последствия

- **Плюсы:** каждый файл описывается одной фразой и ниже порога; цепочка откатов, DPI и кадр — в разных файлах; внешний API и тесты не меняются.
- **Минусы / риски:** `pub(super)` на методах раскрывает их соседним модулям `app` (не крейту); `apply_scale_factor` (перенос окна между мониторами с разным DPI) оконным автотестом не покрыт — проверка глазами у владельца.
