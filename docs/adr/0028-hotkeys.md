# ADR-0028. Комбинации клавиш: раскладко-независимая `Key`, дерево удержаний `Hotkey` с записью и разбором, трекер с сигналом на отпускание, `on_key` получает отпускания

- **Дата:** 2026-10-30
- **Статус:** Accepted (ТЗ `docs/spec/2026-10-30-hotkeys.md` утверждено владельцем 2026-10-30; О1–О3 — рекомендованные варианты).
- **Тема:** ТЗ §13, FR-25; ADR-0004, ADR-0026/0027. План — `docs/plans/2026-10-30-hotkeys.md`.

## Контекст

Приложениям (файл-менеджер) нужны горячие клавиши и аккорды, не зависящие от раскладки: `Ctrl+K` обязан срабатывать и на кириллической «Л». `on_key` отдаёт `KeyEvent` `winit` только для нажатий, без удобной структуры сочетания и без текстовой записи для карт «сочетание → действие». Библиотека ввод не интерпретирует (ADR-0004), поэтому структура должна быть автономной и кормиться приложением.

## Решение

1. **`Key` строится из `physical_key`** (`KeyCode`, имена позиций US-раскладки), левый и правый модификаторы сведены к `Ctrl`/`Alt`/`Shift`/`Super`. Одна физическая клавиша — одно имя в любой раскладке.
2. **`Hotkey` — дерево удержаний:** узел — клавиша и последовательность того, что нажималось при её удержании. Запись: `K`, `K+inner`, `K+[a,b]`, верхний уровень `a,b`; образцы — альтернативы `|` на любом уровне. Подряд удержанные модификаторы — множество в каноническом порядке `Ctrl`, `Alt`, `Shift`, `Super`; порядок прочих клавиш значим. `Display`/`FromStr` круговые, ошибки разбора — с позицией. Скобки в записи: без скобок пишется продолжение ряда модификаторов (`Ctrl+Shift+[K,U]`) и линейная цепочка (`Ctrl+K+U`), иначе группа берётся в скобки (`Space+[Ctrl+[K,U]]`). Имена знаков — по вариантам `KeyCode` (`Comma`, `BracketLeft` …), без экранирования; буквы, цифры, стрелки и `Esc` — короткими псевдонимами, разбор принимает и псевдоним, и имя варианта (`1`/`Digit1`), регистр не важен.
3. **`HotkeyTracker`** живёт от первого нажатия до отпускания всех: `full` — история, `current()` — цепочка удержанных; сигнал `HotkeyEvent { hotkey, complete }` на каждое отпускание — цепочка удержанных на момент перед отпусканием, включая отпускаемую; при отпускании последней — `full` и `complete`. Автоповтор, повторные нажатия и чужие отпускания игнорируются; повторное нажатие той же клавиши в одной жизни записывается как есть (`Ctrl+[K,K]`).
4. **Модуль `gterm::hotkey`** без окна и `unsafe`; приложение кормит трекер из `on_key`. **`on_key` получает и отпускания** — фильтр `Pressed` в цикле событий снят, как и обещала документация; `Ui::key` в `gterm-widgets` отбрасывает `Released` сам.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Запись по логической клавише (`Key::Character`) | зависит от раскладки — `Ctrl+K` не сработал бы на «Л» |
| Сигнал только при отпускании всех (первая постановка) | владелец уточнил: сигнал на каждое отпускание, при последнем — полная комбинация |
| Структура в `gterm-widgets` или отдельном крейте | нужна и демо без виджетов; модуль библиотеки без интерпретации ввода не нарушает ADR-0004 |
| Отдельный `on_key_released` | два метода на одно событие; документация `on_key` уже обещала оба состояния, все обработчики репозитория проверяют состояние |
| Знаки в записи самими символами с экранированием | `+ , [ ] |` заняты грамматикой; имена кодов читаются однозначно |
| Различение левого/правого модификатора | не нужно постановке; усложнило бы канонизацию |

## Последствия

**Плюсы:** раскладко-независимые сочетания и аккорды, текстовые карты в настройках, одно дерево для записи и образцов; `gterm` без новых зависимостей.

**Минусы / риски:** приложения вне репозитория, не проверяющие `state`, получат отпускания в `on_key`; `KeyCode` `#[non_exhaustive]` — неизвестные будущие клавиши печатаются `?`; потерю фокуса окна библиотека не сообщает — «зависшую» клавишу снимает `reset()`; сигнал `Ctrl+U` при отпускании Ctrl и при отпускании U одинаков, различие — в `full`. Размеры release — в `docs/done/2026-10-30-hotkeys.md`.
