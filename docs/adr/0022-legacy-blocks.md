# ADR-0022. Процедурные мозаики и фигуры: секстанты, октанты, Centered, восьмушки, круги, треугольники, диагонали

- **Дата:** 2026-10-23
- **Статус:** Accepted (решения владельца 2026-10-23: без Брайля и разделённых мозаик — О1; восьмушки U+1FB82–U+1FB8B целиком — О2; три модуля — О3). Расширяет ADR-0002.
- **Тема:** ТЗ FR-8.4, FR-9, FR-13. ТЗ задачи — `docs/spec/2026-10-23-legacy-blocks.md`, план — `docs/plans/2026-10-23-legacy-blocks.md`.

## Контекст

Процедурно рисовались только рамки и блоки U+2500–U+259F (ADR-0002). Владелец хочет так же рисовать наборы из таблиц PhMajerus «Blocks tables»: секстанты, октанты, «Centered», круги, треугольники, диагонали — мозаики «Symbols for Legacy Computing» (Unicode 13 и 16) и части геометрических фигур, которые складываются в картинки и крупные фигуры через границы ячеек. В шрифтах они есть редко (Unicode 16 — почти нигде), и даже при наличии стыкуются хуже, чем формулы по сетке ячейки.

## Решение

1. **Три модуля вместо роста `box_drawing.rs`** (406 строк): `procedural.rs` — диспетчер (`is_procedural`, `draw`, `ranges()`) и общий холст `Canvas`; `block_mosaic.rs` — мозаики; `shapes.rs` — фигуры. Публичные `box_drawing::{BOX_FIRST, BOX_LAST, is_box_drawing, draw}` сохраняются.
2. **Мозаики — заливка клеток ровной сетки** по формуле `edge(len, k, n) = (len·k + n/2) / n`, той же, что у восьмушек и квадрантов: границы одинаковы у всех знаков набора и у наборов между собой (октанты 2×4 ложатся на квадранты 2×2), соседние ячейки смыкаются, покрытие только 0/255. Узоры секстантов (60), октантов (230) и диагоналей (44) — таблицы, сгенерированные из имён Unicode 16 (`unicodedata`, Python 3.14), как `BOX_SIDES`. «Centered» (■, U+1FBE4–E7) — сетка 4×4; U+1FBE6/E7 и U+1CEA0/A3/A8/AB — клетки сетки 2×4.
3. **Фигуры — выпуклые области со сглаживанием** по 4×4 точкам на пиксель (как дуги ADR-0002): многоугольники по знаку векторных произведений, эллипсы по уравнению. Части кругов — эллипсы, прижатые к стороне или углу так, что ◖+◗ дают ● в одной ячейке, U+1FBE9+EB — круг 2×1, U+1FBEA+E8 — 1×2, U+1FBEC–EF — 2×2 (трактовка таблиц автора, не рисунок конкретного шрифта). Диагонали — угол ячейки по ту сторону прямой между точками сетки 3×3 из имени знака.
4. **Единый контракт с рамками:** растеризатор пользуется `procedural::is_procedural`/`draw`; в `Procedural` наборы перекрывают шрифт и не зависят от начертания, в `Font`/`Combined` — глиф шрифта с вписыванием и выравниванием (ADR-0020/0021), `Combined` без глифа — формула.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Всё в `box_drawing.rs` | файл за 1000 строк с тремя разными механиками (QG-06) |
| Таблицы руками | 334 узора, ошибки неизбежны; имена Unicode — машинно-читаемый эталон |
| Отдельный растеризатор на фигуру (круг — Брезенхем и т.п.) | один сэмплер «точка внутри?» покрывает круги, треугольники, ромб и диагонали, и тот же, что у дуг |
| Брайль и разделённые мозаики | не нужны владельцу (О1); при необходимости — те же сетки, те же таблицы из имён |
| Части кругов «как в шрифте» (половина круга в центре ячейки) | не складываются в круги 2×1/2×2, ради которых набор и существует |

## Последствия

**Плюсы:** все наборы таблицы автора (кроме исключённых О1) рисуются без шрифта, ровно по сетке, стыкуются между ячейками; GL ↔ Software бит-идентичны; работа — на промахе атласа; таблицы ~0,5 КБ.

**Минусы / риски:** общие рёбра соседних областей при сглаживании считаются обеими сторонами (до 1/16 покрытия); ■ трактуется как центральный блок 2×2 сетки 4×4 (ряд «Centered»), крупнее шрифтового он не будет; размер release 2026-10-23: `demo.exe` 1 540 608 Б (+9 728 к 1 530 880), `pseudographica.exe` 1 168 384 Б (`docs/done/2026-10-23-legacy-blocks.md`).
