# ADR-0002. Сглаживание глифов: 8-битное покрытие, хинтинг `skrifa` (`Target::Mono`), целочисленное смешивание, процедурная псевдографика

- **Дата:** 2026-10-01
- **Статус:** Accepted
- **Тема:** качество отрисовки глифов (ТЗ §1.2, FR-8, §6.3, §7.3, §8); исследование — `docs/research/2026-10-01-glyph-alpha.md`

## Контекст

Растр 1 бит/пиксель с порогом 50 % выбрасывает при 16 px **73 %** пикселей с чернилами (частичное покрытие) — текст «грубый»: рваные `W`/`m`, слипшиеся точки `ё`. Вторая причина — отсутствие хинтинга в `fontdue`: штрихи не прибиты к сетке, `─` ложится между рядами. У PT Mono есть нативные TrueType-инструкции (`fpgm`/`prep`/`cvt`, все 462 простых глифа). Спайк показал: `skrifa` с `Target::Mono` + растеризация `zeno` даёт штрихи 1 px и чёткую псевдографику; цена — +548 КБ (проект ≈ 900 КБ при лимите 1,5 МБ).

## Решение

1. **Растр — 8 бит покрытия на пиксель** (0…255). Формат `.fnt` → версия 2 (`FNT_FORMAT_VERSION = 2`), кэш пересоздаётся автоматически. Атлас в памяти остаётся R8; в GL — текстура `R8UI`, `texelFetch` даёт точное целое `a`.
2. **Растеризатор — `skrifa` + `zeno`** (чистый Rust, без SIMD-ветвлений), хинтинг по нативным инструкциям, `HintingOptions { engine: AutoFallback, target: Mono }`. `fontdue` удаляется.
3. **Смешивание целочисленное и одинаковое** на CPU и в шейдере: `c = (bg·(255 − a) + fg·a + 127) / 255` по каналам, в sRGB-пространстве. Бит-идентичность GL↔Software не зависит от float.
4. **Псевдографика процедурная**: U+2500–U+257F (рамки) и U+2580–U+259F (блоки, тени) рисуются по формулам на сетке ячейки при сборке растра и **перекрывают** глифы шрифта: линии толщиной `light = max(1, h/16)`, `heavy = 2·light + 1`, двойные — две `light` с зазором `light`; стыкуются между ячейками без зазоров; тени ░▒▓ — равномерное покрытие 64/128/192 (подтверждено владельцем 2026-10-04: узор из точек рвался бы на стыке ячеек нечётного размера и зависел бы от DPI). Штриховые линии (дополнение 2026-10-04) — 2/3/4 периода «штрих + зазор» с целыми границами, зазор в конце периода; дуги `╭╮╯╰` — четверть окружности общего радиуса с прямыми хвостами, покрытие сглажено (4×4 точки на пиксель, целочисленно — как и текст, дуга не должна быть «лесенкой», а результат не должен зависеть от платформы); диагонали `╱╲╳` — полоса из угла в угол толщиной `light` с тем же сглаживанием (раньше — 1 px без сглаживания при любом размере).
5. UNDERLINE, курсор — `a = 255`; BLINK в фазе off — `a = 0`; BOLD — осветление, как раньше.
6. LUT контраста не вводится — хинтинг `Mono` даёт достаточную чёткость; вернуться, если понадобится.
7. Альфа-канал **цветов** ячейки в 1.0 игнорируется (FR-2, уточнено).

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Оставить 1bpp | теряется 73 % формы при целевом размере 16 px |
| `fontdue` + 8 бит + LUT контраста | без хинтинга штрихи 1,5 px серым, `─` двойной серой линией; LUT маскирует, не лечит |
| `swash` | внутри тот же `skrifa`, но режим `Smooth + LCD horizontal` — визуально = fontdue; +617 КБ, больше skrifa |
| `skrifa Target::Smooth` | выигрыш мал (65 % частичных против 73 %) при той же цене |
| FreeType | C-зависимость, динамическая библиотека — против NFR-3 и NFR-1 |
| Субпиксельное (LCD) сглаживание | зависит от панели, три канала покрытия, бессмысленно при scale ≥ 2 |
| Растр под масштаб (`px·scale`) | совместимо, отложено до этапа 6 (меняет смысл FR-13) |
| float `mix()` в шейдере и `f32` на CPU | риск расхождения в младшем бите между GPU и CPU — противоречит §8 (допуск 0) |

## Последствия

**Плюсы:** читаемый текст при 16 px; чёткие рамки/блоки, стыкующиеся между ячейками; алгоритм §7.3 не меняется структурно — только `a` стало 0…255 и смешивание целочисленное; детерминизм сохранён.

**Минусы / риски:** бинарник ≈ 900 КБ (запас ≈ 600 КБ на `glutin`/`glow`; замерять `cargo bloat` на этапе 4 и 7); `.fnt` ×8 по объёму (≈ 150 КБ); `Target::Mono` слегка «угловатит» форму букв; `skrifa` — молодой API (0.47), версии фиксируются в `Cargo.lock`.
