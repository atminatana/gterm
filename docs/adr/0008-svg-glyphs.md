# ADR-0008. SVG-глифы из `assets/svg/` как источник глифов поверх псевдографики и шрифта; логический размер шрифта — параметр `AppOptions`

- **Дата:** 2026-10-08
- **Статус:** Accepted
- **Тема:** изображения как дополнение к набору глифов (карта из тайлов), увеличение шрифта в бинарниках (ТЗ FR-8, FR-8.4, FR-9, FR-10, §13); план — `docs/plans/2026-10-08-svg-glyphs.md`

## Контекст

Владелец хочет дополнять набор глифов шрифта SVG-изображениями — в том числе собирать из них карту (тайл = ячейка). Атлас (ADR-0003) уже умеет второй, не шрифтовой источник растра: процедурная псевдографика U+2500–U+259F рисуется в `Rasterizer::rasterize` в тот же буфер покрытия и заполняет все 4 канала-начертания. Рендереры читают только страницу атласа, поэтому новый источник глифов их не затрагивает.

Логический размер шрифта — константа библиотеки `FONT_SIZE_PX = 16` (ADR-0005), её читает `App`. Увеличить шрифт только в бинарниках без нового параметра нельзя.

## Решение

1. **Разбор** — крейт `usvg` без фич текста и системных шрифтов: дерево с применёнными `transform`, `use` и базовыми фигурами. Обводки при загрузке переводятся в заливку (`tiny-skia-path`, зависимость `usvg`). **Растеризация — `zeno`**, как у шрифта; второго растеризатора нет.
2. **Каталог и имя.** `assets/svg/`, имя файла — **только** HEX-код кодовой точки и `.svg`: `E000.svg`, `F0001.svg`, `100000.svg` — **4–6 HEX-цифр** (регистр не важен), значение ≤ U+10FFFF, не суррогат. Без префиксов (`U+`, `uni`) и суффиксов. Остальные файлы — строка в stderr и пропуск. Каталога нет — SVG нет, это не ошибка. Весь диапазон Unicode доступен после перехода ключа атласа на 32 бита (решение владельца 2026-10-08, выполняется **до** SVG — `docs/plans/2026-10-08-codepoint-u32.md`). Под тайлы рекомендуется плоскость U+100000–U+10FFFD — в шрифте она пуста.
3. **Приоритет источников: SVG > процедурная псевдографика > шрифт.** Файл SVG перекрывает любой глиф с той же кодовой точкой, в том числе U+2500–U+259F. Перекрытия печатаются в stderr при старте.
4. **Вписывание — с сохранением пропорций:** `viewBox` масштабируется равномерно до вписывания в `glyph_w × glyph_h` и центрируется. Остаток ячейки — фон.
5. **Цвет.** Цвета файла игнорируются: всё закрашенное или обведённое даёт покрытие по маске `zeno` (сглаженные края, как у шрифта). `fill="none"` и `stroke="none"` учитываются, `opacity` в этой версии — нет. На экране SVG-глиф окрашивается как глиф шрифта: `fg` по покрытию поверх `bg` (§7.3). `INVERSE`, `BLINK` и `BOLD` (осветление цвета) действуют как у шрифта. `<image>` и `<text>` не поддерживаются.
6. **Атлас.** SVG-глиф пишется во все 4 канала (у изображения нет начертаний) — как псевдографика. Рендереры, шейдер и формат текстуры не меняются, так что бит-идентичность GL ↔ Software сохраняется.
7. **Загрузка и владение.** Файлы разбираются один раз при старте в контуры в нормированных координатах `viewBox`, при промахе атласа контур только масштабируется. Набор живёт в `Rasterizer` рядом с `FontFamily` и переживает смену DPI и откат бэкенда. Битый файл — строка в stderr и пропуск, без паники (NFR-7).
8. **Размер шрифта приложения** — новое поле `AppOptions::font_size_px` (по умолчанию `FONT_SIZE_PX = 16`), которое `App` использует вместо константы. Бинарники `demo` и `full_table` ставят **22** (сначала было 26 — ячейка 16×34; уменьшено владельцем 2026-10-08 после проверки окна `full_table`: ячейка 13×29). `FONT_SCALE` и ограничение `glyph_px ∈ [8, 48]` не меняются. Это уточнение ADR-0005: логический размер — параметр приложения, а не только библиотеки.

## Альтернативы и обоснование

| Вариант | Почему не выбран |
|---|---|
| `resvg` целиком (`usvg` + `tiny-skia`) | второй растеризатор рядом с `zeno` и больший бинарник ради градиентов, масок и фильтров, которые не нужны, раз цвета файла игнорируются |
| Свой разбор только `<path d>` (`svgtypes`) | файлы из редакторов почти всегда содержат `transform`, `rect`, `circle`, `stroke` — рисовались бы неверно |
| Псевдографика > SVG, или SVG только для кодовых точек без глифа | владелец выбрал полный приоритет SVG: явный файл означает явное намерение |
| Растягивать `viewBox` на всю ячейку | выбрано сохранение пропорций: изображение не искажается |
| Поменять `FONT_SIZE_PX` для всех | меняет поведение библиотеки и тестов; владелец просил увеличить шрифт только в бинарниках |

## Последствия

- **Плюсы:** новый источник глифов не трогает рендереры и шейдер; бит-идентичность и golden-путь детерминированы (целочисленное покрытие `zeno`); тайлы карты перекрашиваются через `fg`/`bg` без перерастеризации; SVG переживает смену DPI вместе со шрифтом.
- **Минусы / риски:**
  - Ячейка примерно 1 : 2, поэтому квадратное изображение при вписывании занимает около половины высоты, и между тайлами карты видны полосы фона. Тайлы под карту нужно рисовать в пропорции ячейки.
  - Без хинтинга тонкие линии на малом размере размываются.
  - Файл SVG в U+2500–U+259F ломает стыковку линий псевдографики.
  - Файл на занятой кодовой точке молча меняет иконку Nerd Font (смягчено логом).
  - Бинарник растёт на разбор XML/SVG (замеряется, NFR-1).
  - При `font_size_px = 22` и DPI ≥ 2,2 срабатывает потолок `glyph_px = 48`.
  - Зависит от перехода на 32-битную кодовую точку: SVG реализуется после него.
