# ADR-0004. События приложения через трейт `AppHandler`, курсор на стороне приложения

- **Дата:** 2026-10-02
- **Статус:** Accepted (частично заменён 0012: мигание, `INVERSE` и таймер удалены)
- **Тема:** публичный API событий ввода и уведомлений; место курсора (ТЗ FR-3, FR-7, FR-25, FR-27, §1, §5.2)

## Контекст

ТЗ §1 требует поставлять модуль как библиотеку + демо-бинарник, «чтобы модуль отображения можно было встроить в другие продукты (например, киоски и билетные терминалы)». Значит форма обмена с приложением — часть контракта, а не внутренняя деталь.

Состояние кода до решения:

1. `App` сам реализует `winit::ApplicationHandler` и обрабатывает четыре события (`CloseRequested`, `Esc`, `Resized`, `RedrawRequested`), остальные отбрасывая (`_ => {}` в `app.rs`). FR-25 не выполнено.
2. `Esc` перехватывается библиотекой: приложение не может решить, что с ним делать.
3. Единственный обратный вызов — `on_backend(Box<dyn FnMut(&mut ScreenBuffer, &'static str)>)`. Один хук на весь API; следующие события потребовали бы новых полей и новых методов билдера.
4. `App::new` **забирает владение** `ScreenBuffer`, и приложение получает его обратно только внутри этого хука. Между вызовами хука у приложения нет доступа к экрану — оно не может отреагировать на нажатие клавиши.
5. `CellFlags::CURSOR` и `ViewParams::cursor` описывают курсор, который не реализует ни одно приложение: демо рисует слово «cursor», но настоящего курсора нет ни в одном сценарии, а `CursorState`/`CursorShape` только занимают место в шейдере, в CPU-рендерере и в golden-сценах.

Владелец проекта постановил: курсор из описания убрать, при необходимости он реализуется на стороне приложения.

## Решение

1. **Трейт `AppHandler`**, реализуемый приложением; `App::run` принимает его. Методы: `on_key`, `on_text`, `on_pointer`, `on_grid_resized`, `on_backend_changed`, `on_tick`. У всех — тело по умолчанию, реализовывать нужно только нужное.
2. **Типы `winit` не переводятся**: `&KeyEvent`, `&str` (для `Ime::Commit`), `&PointerEvent` передаются как есть (FR-25 «без интерпретации»). Собственного слоя событий в `gterm` не появляется.
3. **`Ctx`** — то, что передаётся вместе с событием: `&mut ScreenBuffer`, изменение размера сетки, выход из цикла (`ctx.exit()`), прочие команды приложения. Это деталь реализации; публичная поверхность — трейт.
4. **Буфер остаётся у `App`** и отдаётся в обработчик как `&mut`: dirty-учёт и загрузка в GPU — внутреннее состояние `App`. Владение буфером приложением потребовало бы `App<'a>` либо `Rc<RefCell<_>>`; для 1.0 это лишняя сложность, а когда появится VT-парсер (§13), можно добавить отдельный способ подключения, не ломая текущий API.
5. **`on_backend` заменяется на метод трейта** `on_backend_changed` — сущность одна, форма билдера исчезает.
6. **`Esc` больше не перехватывается**: приходит в `on_key`, решение принимает приложение (иначе киоск не может использовать клавишу).
7. **Курсор убран из библиотеки**: нет `CellFlags::CURSOR`, нет `ViewParams::cursor`, нет uniform `u_cursor`, нет трёх форм в CPU-рендерере; `cursor.rs` заменён файлом `blink.rs` с таймером мигания символов `BLINK`. Демо показывает, как курсор делается приложением: перекраской ячейки через `INVERSE` (FR-27).
8. **Мигание остаётся в библиотеке** — это свойство ячейки (`BLINK`), а не приложения: таймер один, период настраивается, `0` — выключено (FR-7).

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Набор замыканий-хуков, как `on_backend` | каждое новое событие — новое поле и новый метод билдера; состояние приложения всё равно приходится куда-то класть; шесть хуков читаются хуже одного трейта |
| `enum AppEvent` + канал/очередь | **новый вариант `enum` ломает все `match`** у интеграторов при каждом расширении; событие, которому нужен доступ к экрану, неудобно выражать элементом очереди; приложение всё равно достаётся из цикла через `Rc<RefCell<_>>` |
| Собственные типы событий вместо типов `winit` | дублирование слоя перевода и его поддержка; выигрыш — только независимость от `winit`, которая нужна лишь при смене вендора окна (риск в ТЗ §14, изолируется модулем `app.rs`) |
| Оставить курсор в библиотеке | владелец решил, что курсор не нужен: единственный сценарий — демо/киоск, где достаточно перекраски ячейки; неиспользуемое состояние в шейдере и в обоих рендерерах — цена без выгоды |
| Экран принадлежит приложению (`ScreenBuffer` в `Rc<RefCell<_>>`) | владение буфером — типичная потребность будущего VT-парсера, но для 1.0 даёт либо параметр времени жизни у `App`, либо паники на рантайме при пересечении вложенных вызовов |
| `ctx.exit()` как отдельный хук/событие | выход — это команда приложения «закончить цикл», а не ввод; хук на каждое действие раздувает трейт |

## Последствия

**Плюсы:** один объект состояния приложения без `Rc`/`RefCell` и без параметров времени жизни; расширение событий не ломает интеграторов (метод по умолчанию); состояние `winit` пробрасывается без перевода; `Esc` в распоряжении приложения; API событий документирован в ТЗ §5.2 как норма, а не как деталь демо.

**Минусы / риски:** публичный API привязан к версии `winit` (0.30) — при апгрейде `winit` ломается API; удаление курсора требует перегенерации golden-эталонов (в сценах исчезает прямоугольник курсора) — гейт проверяется точечно, а не сравнением всего кадра; у приложения нет отдельного способа узнать фазу мигания изнутри `Ctx` (при необходимости — `on_tick`).
