# ADR-0014. Наложение клиентских буферов: `on_redraw` + `DrawCtx::draw_buffer`, предумноженная альфа, проход на запись

- **Дата:** 2026-10-09
- **Статус:** Accepted; п.5 и п.7 дополнены ADR-0015 (2026-10-10: кэш текстуры, пары каналов)
- **Тема:** FR-12, FR-25.1, §5.2–5.3, §7, §8. ТЗ задачи — `docs/spec/2026-10-09-overlay-buffers.md`, план — `docs/plans/2026-10-09-overlay-buffers.md`.

## Контекст

Владелец хочет собирать многоцветный символ из нескольких буферов. Решения владельца (2026-10-09):
- буфер хранится у клиента;
- контекст при `RedrawRequested` даёт функцию отрисовки буфера в текстуру, текстура ложится поверх основного экрана;
- наложение очищается каждый кадр;
- координаты в ячейках сетки, обрезка по сетке;
- в GL — отдельный проход на буфер (Н1);
- пример — отдельный бинарник (Н2);
- по плану: О1–О4 — а.

Опора — формула ячейки ADR-0013 (`blend`, `fade`, `0xAARRGGBB`).

## Решение

1. **API.**
   - `AppHandler::on_redraw(&mut self, &mut DrawCtx)` вызывается на каждом `RedrawRequested` до кадра, наложение к этому моменту пусто.
   - `DrawCtx::draw_buffer(&ScreenBuffer, col: i32, row: i32)` и `DrawCtx::grid()`.
   - `DrawCtx` существует только внутри `on_redraw`.
   - `ScreenBuffer::transparent(cols, rows)` — буфер с прозрачными пустыми ячейками (О4).
2. **`Overlay`** (`src/overlay.rs`) — записи кадра.
   - `push` **копирует** ячейки во внутренний массив, который переиспользуется между кадрами: буфер клиента одолжен только на время `on_redraw`, а рисует библиотека после него.
   - `Layer::grid_rows` / `grid_cols` — обрезка по сетке.
3. **Рендерер (О1 — а).**
   - `Renderer::render_overlaid(screen, &Overlay)`.
   - `render(screen)` — метод по умолчанию с пустым наложением.
   - GL: `render_to_frame_overlaid`.
4. **Формулы (О2 — а, предумноженная альфа).** `mul(x, a) = (x·a + 127)/255`, текстура `T = (t_rgb предумножен, t_a)`:
   - слой: `t' = mul(c, α) + mul(t, 255 − α)`, `t_a' = α + mul(t_a, 255 − α)`;
   - ячейка записи — фон (`bg`, `α_bg`), затем символ (`fg'`, `fade(cov, α_fg)`);
   - на кадр: `out = t + mul(F, 255 − t_a)`.

   Свойства: непрозрачный слой даёт ровно свой цвет, прозрачный ничего не меняет, переполнения нет. Проверено перебором.
5. **Software.**
   - Текстура `Vec<u32>` размером с сетку.
   - Перерисовываются dirty-строки и строки под наложением в этом или прошлом кадре.
   - Записи рисуются в текстуру, затем она накладывается на эти строки.
   - Глифы основного экрана и всех записей готовятся одним проходом; при сбросе страницы — повтор для всего.
6. **GL (Н1, О3 — а).**
   - Две текстуры `RGBA8UI` размером с сетку с FBO к каждой, программа `overlay.frag`, текстура данных записи `RGBA32UI`. Создаются при первом кадре с наложением.
   - Кадр с наложением: очистка первой текстуры, затем на каждую запись — проход в другую текстуру (ping-pong), затем основной проход, который последним шагом накладывает итоговую текстуру (`u_overlay`, `u_has_overlay`).
   - Без наложения — один draw call, как раньше.
7. **Горячий путь Software.** Попиксельные функции (`Atlas::pixel`, `slot_origin`, `blend`, `fade`, `mul`, `over`, `composite`) встраиваются принудительно (`#[inline(always)]`).
   - Деление на 255 заменено точным тождеством `div255(y) = (y + 1 + (y >> 8)) >> 8` для `y ≤ 65534`; проверено перебором, результат тот же бит в бит. Шейдер делит как есть.
   - Быстрые пути без изменения формулы: фон ячейки поверх пустого пикселя — константа на ячейку; нулевая доля символа пропускает второй `over`.

## Альтернативы и обоснование

| Вариант | Почему не выбран |
|---|---|
| Прямая альфа в текстуре наложения (так в ТЗ задачи §3.3) | деление на итоговую альфу и особый случай `α = 0` в обоих бэкендах — больше мест для расхождения GL ↔ Software (О2) |
| Отдельный проход наложения на кадр в GL (ТЗ §3.4) | основной кадр пришлось бы рисовать в промежуточный FBO; на проход больше (О3) |
| `render(screen, &Overlay)` у всех | вторая подряд ломка API трейта; тесты и бенчмарк без наложения не меняются (О1) |
| Все записи одним проходом с пределом N | предел на число буферов и массивы uniform-переменных (Н1) |
| Хранить ссылки на буферы клиента | они одолжены только на время `on_redraw`; копия решает время жизни без `Rc`/`RefCell` |

## Последствия

- **Плюсы:**
  - многоцветные символы и слои поверх экрана без изменения основного буфера;
  - GL ↔ Software бит-идентичны (8 сцен, допуск 0);
  - golden-эталоны не менялись;
  - Software без наложения после принудительного встраивания и `div255` быстрее, чем до задачи: 102–104 FPS против 81–85 (сетка 120×40).
- **Минусы / риски:**
  - Software с полупрозрачным наложением на весь экран — 23,6 FPS при NFR-5 ≥ 60. С `opt-level = 3` (справочная сборка) — 47,3 FPS. Профиль `opt-level = "z"` (§10.2) стоит Software в 2–3 раза. Ускорение — отдельная задача.
  - GL с наложением на весь экран: CPU-часть кадра 0,66 → 1,24 мс (упаковка и загрузка 12 000 ячеек записи).
  - Копия буфера на кадр — 16 Б на ячейку.
  - Наложение не переживает кадр, клиент рисует его в каждом `on_redraw`.
