# ADR-0031. Флажок `Checkbox`: переключение пробелом, `Enter` и отпусканием мыши, событие `Toggled` с привязкой `on_toggle`, метки `[x]`/`[ ]`; группа — существующий `Ui::group`

- **Дата:** 2026-11-12
- **Статус:** Accepted (ТЗ `docs/spec/2026-11-12-checkbox.md` утверждено владельцем 2026-11-12; О1–О5 — рекомендованные варианты (a); О2 изменён владельцем 2026-11-12 после реализации: `Enter` переключает так же, как пробел).
- **Тема:** ТЗ §13; ADR-0023, ADR-0026. План — `docs/plans/2026-11-12-checkbox.md`.

## Контекст

Постановка владельца 2026-10-27 — элементы форм: кнопки, чекбоксы, группы. Кнопка (`Button`) и группа с рамкой, заголовком и подсветкой под фокусом (`Ui::group`) сделаны в ADR-0026; не было флажка.

## Решение

1. **`Checkbox` / `CheckboxState`** по образцу кнопки: вид — виджет-значение, поведение — состояние с `Control<M>` (ADR-0023, ADR-0026). Состояние: `checked`, `enabled`, `pressed`.
2. **Переключение:** пробел, `Enter` и мышь — отпускание левой кнопки внутри области после нажатия в ней (захват, как у кнопки); кликабельна вся область с подписью. `Enter` действует как у кнопки (решение владельца 2026-11-12, изменившее первоначальное «только пробел»): флажок под фокусом принимает его, до формы и карты сочетаний он не доходит.
3. **Событие `WidgetEvent::Toggled(bool)`** с новым значением → привязка `Ui::on_toggle(Fn(bool) -> M)`. Программная смена (`set_checked`, `toggle`) события не даёт — события отражают ввод пользователя, как у `TextInputState::set_value`.
4. **Вид:** метка и подпись слева в одну строку, метки по умолчанию `[x]` / `[ ]`, свои — `Checkbox::marks`; стили `style` / `focus_style` / `pressed_style` / `disabled_style` с порядком наложения кнопки.
5. **Группа — `Ui::group`** без новых типов. Переключателей «один из многих» и третьего состояния нет.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Только пробел (О2-a, первоначальное решение) | изменено владельцем: `Enter` должен переключать флажок так же, как пробел — единообразно с кнопкой |
| Метки `☑`/`☐` по умолчанию (О3-b) | зависят от шрифта; `[x]`/`[ ]` рисуются любым, свои метки задаются `marks` |
| Переключатели radio в этой задаче (О1-b) | в постановке их нет; тот же механизм, отдельной задачей при необходимости |
| Третье состояние (О4-b) | не нужно постановке, усложняет событие и вид |
| Отдельный тип группы (О5-b) | `Ui::group` уже даёт рамку `Block`, заголовок и подсветку под фокусом |
| Переиспользовать `Activated` вместо `Toggled` | приложению нужно новое значение, а не факт нажатия; чтение состояния в `update` связало бы сообщение с конкретным полем |

## Последствия

**Плюсы:** флажок с тем же поведением мыши и стилями, что у кнопки; формы собираются из готового (`Ui::group`, `Checkbox`, `Button`, `TextInput`, `ComboBox`).

**Минусы / риски:** `Enter` при фокусе на флажке переключает его и не подтверждает форму (привязка `Enter` в карте сочетаний не сработает); новый вариант публичного `WidgetEvent` — внешний исчерпывающий `match` перестанет собираться (в репозитории он один, в `ui/element.rs`); метки шире одной ячейки занимают место подписи. Размеры release — в `docs/done/2026-11-12-checkbox.md`.
