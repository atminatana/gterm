# ADR-0001. Растр шрифта создаётся программой из TTF и кэшируется в `assets/*.fnt`

- **Дата:** 2026-10-01
- **Статус:** Accepted; **частично заменён ADR-0003** (2026-10-01): предрастеризация всех глифов и файл `assets/*.fnt` упразднены, остаются выбор шрифта из `assets/` рядом с exe и все глифы BMP как область покрытия; область расширена на весь Unicode ADR-0009 (2026-10-08)
- **Тема:** источник глифов для атласа (ТЗ §3.2, FR-8…FR-11; затрагивает NFR-1…NFR-3, этап 2)

## Контекст

ТЗ 1.0 требовало bitmap-шрифт 8×16, вшитый в бинарник через `include_bytes!` (4 КБ, без внешних ресурсов). Проверка `assets/font_8x16.bin` показала, что файл битый: это 8×8-шрифт, прочитанный как 8×16 (глиф `A` = «A» над «F»). Готового корректного 1bpp-шрифта с кириллицей в проекте нет, а поддерживать бинарный растр вручную нельзя: любая смена размера ячейки или шрифта требует внешнего инструмента.

Владелец проекта поставил требование: файл растра создаёт **сама программа** из шрифта и размера, заданных константами в коде; пересоздаёт, если файла нет или шрифт/размер изменились. В репозиторий добавлен `assets/pt-mono_regular.ttf` (PT Mono, моноширинный, с кириллицей).

## Решение

1. Константы в `font.rs`: `FONT_FILE = "pt-mono_regular.ttf"`, `FONT_SIZE_PX = 16`. Размер глифа выводится из метрик шрифта.
2. При старте программа ищет `assets/<шрифт>_<FONT_SIZE_PX>px.fnt` в каталоге `assets/` **рядом с exe** (затем — `./assets/` относительно cwd, для `cargo run`).
3. Файл **пересоздаётся**, если его нет, или в заголовке не совпали: версия формата, имя шрифта, `FONT_SIZE_PX`, хеш содержимого TTF (FNV-1a 64). Иначе используется как есть.
4. Растеризация — `fontdue` (обязательная зависимость), без сглаживания, порог покрытия 50 %, результат детерминирован.
5. Формат `.fnt` — заголовок `GFNT` + таблица слотов + 1bpp растр (`ceil(w/8)` байт на строку, MSB слева); описан в FR-8.3.
6. **В растр входят все глифы шрифта из BMP** (PT Mono — 788); `Cell::ch` — кодовая точка Unicode, переводится в слот атласа таблицей O(1). Кодовой страницы нет. Нет глифа → слот 0, пустая ячейка (рисуется только фон). *(Уточнение владельца 2026-10-01, заменяет первоначальный вариант «256 кодов по CP1251».)*
7. TTF не найден / растеризация не удалась → выход с сообщением и кодом ≠ 0. Кэш не записывается (read-only каталог) → предупреждение, работа из памяти.
8. `.fnt` в `.gitignore`; в репозитории — только TTF.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| **Оставить вшитый bitmap** (ТЗ 1.0) | Нет корректного файла; ручная поддержка растра при каждой смене шрифта/размера; нет кириллицы. |
| **Генерация на сборке (`build.rs` → `include_bytes!`)** | Сохраняет NFR-2/NFR-3 (без внешних ресурсов и растеризатора в бинарнике), но не удовлетворяет требованию владельца: файл должна создавать программа, пересоздание — по факту изменения, а не по пересборке. Рекомендовался агентом, отклонён владельцем. |
| **Системный шрифт по имени (GDI / fontconfig)** | Платформенный код; растр различается между машинами → golden-тесты и бит-идентичность GL↔Soft (§8) нестабильны. |
| **Кэш рядом с exe (не в `assets/`)** | Владелец выбрал `assets/` — единое место для исходного TTF и производного растра. |
| **Только константы в заголовке, без хеша TTF** | Замена файла шрифта при тех же константах оставила бы устаревший кэш; хеш FNV-1a дёшев и без зависимостей. |
| **256 кодов по кодовой странице (CP1251 / CP437)** | Теряются глифы вне страницы (псевдографика U+25xx, расширенная кириллица, стрелки), нужна таблица перекодировки и выбор между кириллицей и псевдографикой. Атлас на все 788 глифов стоит 100 КБ R8 и снимает вопрос целиком. |
| **Глиф `.notdef` для отсутствующих символов** | Владелец выбрал пустую ячейку: меньше шума на экране; отсутствие символа видно по пустому месту. |

## Последствия

**Плюсы**
- Смена шрифта/размера — правка констант, растр пересоздаётся автоматически.
- Кириллица, псевдографика и всё остальное содержимое шрифта из коробки, `write_row` принимает любой текст; детерминированный растр → golden-тесты и сравнение GL↔Soft остаются осмысленными.
- Атлас перестаёт быть фиксированным 16×16: число строк зависит от шрифта; в GL-текстуру данных уходит слот, а не кодовая точка (§6.1) — таблица поиска живёт только на CPU.
- Рендереры не содержат констант 8/16 (FR-10 реально выполняется).

**Минусы / риски**
- `fontdue` в бинарнике — давление на NFR-1 (≤ 1,5 МБ). Замер `cargo bloat` на этапе 2 обязателен; при превышении — обсуждать `opt-level="z"` / урезание features, а не откат решения.
- Появился внешний ресурс (`assets/` рядом с exe) — NFR-3 ослаблен; поставка должна копировать каталог.
- Первый запуск медленнее (растеризация 256 глифов) — однократно, далее кэш.
- Поиск `assets/` по двум путям — потенциальная путаница при запуске из нестандартного cwd; путь выводится в stderr при `--debug`.
