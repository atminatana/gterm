# ADR-0019. Целая ширина ячейки подбором эффективного размера шрифта — опция растеризатора

- **Дата:** 2026-10-23
- **Статус:** Rejected — отклонено владельцем 2026-10-23 после проверки глазами (`pseudographica -- --snap-cell`, `Cascadia Mono` 14 px → 13,65 px): видимого улучшения стыков рамок из шрифта нет. Код опции откачен в тот же день (файлы восстановлены из `HEAD` коммита 7f3d6b2), в репозитории остались только документы эксперимента. Следующий шаг — вариант Б (ADR-0020). Было: Accepted (вариант А как опция, выключенная по умолчанию; флаг только в примере). Уточняет ADR-0005: номинальный размер остаётся целым и единственным источником геометрии для `App`; эффективный размер — внутреннее дело растеризатора.
- **Тема:** ТЗ FR-8, FR-13, FR-24; ADR-0018 (артефакты рамок из шрифта, пункт «обрезка глифа по ячейке при дробном advance»). ТЗ задачи — `docs/spec/2026-10-23-cell-width-snap.md`, план — `docs/plans/2026-10-23-cell-width-snap.md`.

## Контекст

Размер растеризации целый (`glyph_px`), advance `M` при нём дробный, ширина ячейки — его округление. Глиф рамки из шрифта рисуется до advance и либо обрезается ячейкой (FR-13), либо не доходит до её края: на стыке — зазор или серая колонка. Это одна из причин артефактов в режимах `Font`/`Combined` (ADR-0018). Владелец хочет увидеть эффект устранения этой причины глазами, не меняя поведения по умолчанию.

## Решение

1. **Эффективный размер.** `FontFamily::snapped_size(nominal)`: `a = advance_M(1 px)`, `w = max(1, round(nominal · a))`, `size = w / a` — при нём advance `M` целый и равен ширине ячейки. Метрики и хинтеры строятся при дробном `Size::new(size)`.
2. **Опция, а не умолчание.** `Rasterizer::set_snap_cell_width(bool)`; по умолчанию выключена — golden, `stage4_gl`, замеры прежние. `set_size(nominal)` и смена DPI уважают флаг.
3. **Номинал — публичный контракт.** `size_px()` возвращает номинальный целый размер; `App`, `Atlas`, бэкенды не знают о дробном. `effective_size_px()` — только для лога.
4. **Демонстрация** — флаг `--snap-cell` примера `pseudographica`, сравнение глазами двух запусков в режиме рамок из шрифта.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Дробный размер по всему пути (`glyph_px: f32`, `set_size(f32)`) | ломает контракт ADR-0005, формулу DPI и десятки тестов ради эффекта, который нужно сначала увидеть |
| Включить подбор по умолчанию | меняет golden и `--bench`; хинтинг при дробном ppem не проверен глазами |
| Растягивать контур рамки под ячейку (вариант Б) | другая задача: лечит стыки рамок, не трогая размер текста; делается следующей и сравнивается с А |
| Опция в `AppOptions` с переключением на лету | смена ширины ячейки требует перестройки окна (путь DPI) — лишнее для сравнения глазами; при положительном вердикте — отдельная задача |

## Последствия

**Плюсы:** при включённой опции глиф рамки из шрифта ровно вписывается в ячейку по ширине; текст не искажается, меняется только эффективный размер (до половины ширины ячейки); по умолчанию ничего не меняется.

**Минусы / риски:** дробный ppem у TrueType-интерпретатора — инструкции работают по округлённому ppem, контур масштабируется дробно, буквы могут стать менее резкими; эффективный размер отклоняется от заказанного (11 px → 10,24 px у `Cascadia Mono`); высота ячейки и вертикали `│` не затронуты (вариант Б); размер release 2026-10-23: `pseudographica.exe` 1 149 440 Б (было 1 147 392), `demo.exe` 1 523 712 Б (`docs/done/2026-10-23-cell-width-snap.md`).
