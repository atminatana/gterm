# ADR-0003. Динамический атлас глифов, начертания в каналах `RGBA8`, без файла кэша

- **Дата:** 2026-10-01
- **Статус:** Accepted. Заменяет ADR-0001 в части «растр всех глифов создаётся заранее и кэшируется в `assets/*.fnt`»; выбор шрифта из `assets/` рядом с exe и хеширование источника сохраняются как основа правила «кэш в памяти действителен для данного TTF». Ключ атласа расширен с BMP на весь Unicode — ADR-0009 (2026-10-08).
- **Тема:** хранение глифов, начертания Bold/Italic, лимит текстуры (ТЗ FR-3, FR-8, FR-9, §6.3, §13)

## Контекст

Шрифт заменён на RobotoMono Nerd Font: 3371 кодовая точка BMP, ячейка 10×21, четыре файла начертаний (Regular/Bold/Italic/Bold Italic, помечены в `OS/2.fsSelection`). Предрастеризация всех глифов (ADR-0001) даёт атлас 160×4431 px — выше типичного `GL_MAX_TEXTURE_SIZE` 4096 уже для одного начертания; четыре начертания «плоскостями» — ещё ×4. Первый запуск растеризует всё за ≈ 2,4 с × число стилей, хотя экран использует 100–300 глифов. Владелец предложил: спрашивать лимит у драйвера, заполнять атлас по требованию, начертания — в каналах одной текстуры.

## Решение

1. **Атлас динамический**: глиф растеризуется при первом показе (кэш-промах) и занимает слот; таблица «(кодовая точка) → слот» в памяти. Файл `.fnt` **упраздняется** — холодный старт стоит ≈ 0,7 мс на новый глиф (измерено: 3371 глиф за 2,4 с с автохинтером).
2. **Начертания — каналы одного текселя** `RGBA8` (`RGBA8UI` в GL): R = Regular, G = Bold, B = Italic, A = Bold Italic; один слот на кодовую точку для всех стилей. Каналы заполняются **лениво**: битовая маска готовых стилей на слот; промах по стилю растеризует только этот стиль.
3. **Подстановка начертаний** при отсутствии файла: Bold Italic → Italic → Bold → Regular; Bold → Regular; Italic → Regular; нет Regular → ошибка и выход (FR-8.5). Реализуется таблицей `style_source[4]`, без копирования и без повторной растеризации. Файлы выбираются по `fsSelection` (биты ITALIC/BOLD), не по именам.
4. **`BOLD` в ячейке = жирный глиф + осветление цвета** (`min(c + 0x55, 255)`); новый флаг **`ITALIC`** (бит 5). Стиль ячейки = `(BOLD, ITALIC)` → канал.
5. **Размер страницы**: `min(GL_MAX_TEXTURE_SIZE, 2048)²`; если запрос лимита не удался — 1024. 2048² RGBA = 16 МБ, ≈ 19 000 слотов при 10×21 — больше покрытия любого BMP-шрифта. Software-рендерер использует тот же размер страницы ради идентичного поведения кэша.
6. **Переполнение страницы** — сброс: атлас очищается, все строки экрана помечаются dirty, видимые глифы растеризуются заново. LRU и вторая страница (`TEXTURE_2D_ARRAY`) не делаются — на BMP-шрифтах недостижимо; архитектура их не исключает.
7. **Горячий путь** (NFR-6): отрисовка из атласа — без аллокаций; промах кэша — отдельный путь с переиспользуемыми буферами растеризации (контур, маска). Это явно вписывается в ТЗ как оговорка к NFR-6.
8. Псевдографика U+2500–U+259F — по-прежнему процедурно (ADR-0002), одинаково во всех каналах.
9. Бит-идентичность GL↔Software не зависит от порядка заполнения атласа: пиксели глифа одинаковы в любом слоте; golden сравнивает кадры.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Предрастеризация всех глифов (ADR-0001) | атлас выше лимита текстуры, 2,4 с × стили на первом запуске, 2,8 МБ `.fnt` |
| Четыре плоскости слотов (стили рядом) | высота атласа ×4; таблица слотов на стиль; никаких преимуществ перед каналами при той же памяти |
| Персистентный кэш глифов на диске | потолок размера есть (покрытие шрифта), но нужна атомарная перезапись при выходе и формат частичного набора; выигрыш — только тёплый старт (~0,1–0,2 с). Отложено; формат и правило пересоздания при необходимости вернутся |
| Дедупликация «стиль похож на Regular» | при каналах память не экономится вовсе; сравнение дёшево, но совпадений у настоящих Bold/Italic нет; случай «нет файла» закрыт подстановкой |
| 7 бит покрытия + 1 бит «контур» | покрытие и есть альфа; отдельный бит ничего не кодирует (подчёркивание/курсор — из флагов ячейки), а точность смешивания теряется |
| Синтетический наклон/жирность при отсутствии файла | не нужно при полном комплекте файлов; оставлено как возможная опция |
| LRU-вытеснение | сложнее сброса, а переполнение на практике недостижимо |

## Последствия

**Плюсы:** атлас всегда помещается в текстуру; мгновенный старт; ленивые стили; один слот на глиф; нет внешнего кэш-файла и его инвалидации.

**Минусы / риски:** первый показ глифа — ≈ 0,7 мс (худший случай экрана из 2000 разных символов ≈ 1,4 с — нереалистичен для терминала); промах кэша аллоцирует (оговорка к NFR-6); 16 МБ на страницу атласа в памяти (Software) и в VRAM (GL); `.fnt`-формат, тесты кэша и `font_gen::load_or_generate` удаляются — ADR-0001 частично устаревает.
