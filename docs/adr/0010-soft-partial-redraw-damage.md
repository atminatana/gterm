# ADR-0010. Software: смена фазы мигания перерисовывает только строки с `BLINK`; в окно копируются и выводятся только перерисованные полосы

- **Дата:** 2026-10-08
- **Статус:** Accepted (частично заменён 0012: мигание, `INVERSE` и таймер удалены)
- **Тема:** CPU в простое с миганием и цена вывода кадра в Software (ТЗ NFR-5, NFR-6, §8, §11.4 п.6); план — `docs/plans/2026-10-08-soft-partial-redraw.md`

## Контекст

`SoftBackend` рисует только dirty-строки, но любое изменение `ViewParams` (в том числе `blink_phase`, дважды в секунду) запускает полную перерисовку окна — на этапе 6 это 2,60 % CPU в простое с миганием против 0,20 % у GL (`docs/test/2026-10-02-stage6-blink-dpi-events.md`). Вывод кадра (`App::render_frame`) всегда копирует весь кадр в буфер `softbuffer` и выводит его целиком, даже если перерисована одна строка или ничего. `softbuffer 0.4.8` умеет выводить только прямоугольники (`present_with_damage`) и сообщает, хранит ли буфер прошлый кадр (`age()`: 1 — да; 0 — содержимое не определено; Wayland — бывает 2).

## Решение

1. **Строки с `BLINK` находит рендерер.** Если от прошлого кадра изменилась только `blink_phase` (та же `border_color`, нет иных причин полного кадра), `SoftBackend` проходит по ячейкам и перерисовывает строки, где есть `BLINK`, вместе с обычными dirty-строками. `ScreenBuffer` не меняется. Смена `border_color` — по-прежнему полный кадр.
2. **Единица изменения — полоса строк сетки.** После `render` рендерер отдаёт полосы перерисовки кадра (`y`, высота в пикселях), соседние строки слиты; полный кадр — одна полоса на всю высоту. Буфер полос предвыделен (NFR-6). Полоса переводится в прямоугольник вывода шириной сетки с обрезкой по окну — чистой функцией.
3. **Буфер окна без прошлого кадра** (`age() ≠ 1`: первый кадр, после `resize`, Wayland с `age = 2`) — копируется весь кадр, вывод `present()` целиком.
4. **Системные перерисовки** (`RedrawRequested`, не запрошенный приложением, таймером мигания или самой `App`) — полный вывод: на X11 без композитора открытая заново часть окна иначе осталась бы мусорной.
5. **Нечего выводить** (свой запрос кадра, ни одна строка не перерисована) — буфер окна не трогается, `present` не вызывается.
6. Иначе (`age() == 1`, свой запрос, есть полосы) — в буфер окна копируются только строки полос, вывод `present_with_damage`.
7. Инвариант: кадр рендерера после любой последовательности частичных перерисовок бит-идентичен кадру, нарисованному с нуля; GL-бэкенд не меняется.

## Альтернативы и обоснование

| Вариант | Почему не выбран |
|---|---|
| Построчные счётчики `BLINK` в `ScreenBuffer` | больше инвариантов в буфере и правка его API; проход по ~2000 ячейкам дважды в секунду ничтожен против перерисовки 2,2 Мпикс |
| Точные прямоугольники изменённых ячеек | буфер ведёт учёт по строкам, не по ячейкам; выигрыш редкий |
| При `age = 2` копировать объединение полос двух кадров | выигрыш на Wayland ценой хранения истории и лишних случаев; при `age ≠ 1` полный вывод всегда корректен |
| Всегда полный `present()`, частичное только копирование | без разделения системных и своих перерисовок проще, но на Win32 теряется часть выигрыша вывода |
| Выводить кадр и тогда, когда ничего не перерисовано | лишнее копирование и вывод всего окна на тиках без изменений |

## Последствия

- **Плюсы:** смена фазы мигания стоит пропорционально числу строк с `BLINK`, а не площади окна; вывод — пропорционально перерисованному; GL, шейдер и формат данных не меняются; инвариант «частичный кадр = кадр с нуля» проверяется тестами и сравнением GL ↔ Software.
- **Минусы / риски:** ошибка учёта полос даёт мусор в окне, невидимый тестам кадра рендерера — смягчено чистой функцией перевода полос под тестами и полным выводом на системных перерисовках; на Wayland (`age = 2`) выигрыш только от п.1; `App` ведёт признак «свой запрос кадра»; проверка глазами на Windows и Linux X11/Wayland — у владельца (§11.3).
