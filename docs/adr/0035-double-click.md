# ADR-0035. Двойной клик: число нажатий считает окно (`PointerEvent::Input::click_count`), привязка `Ui::on_double_click` у любого контрола, отказ контрола по месту нажатия

- **Дата:** 2026-11-16
- **Статус:** Accepted (G-4 ТЗ `sfplayer` `docs/spec/2026-11-16-dialogs-and-keys.md`, утверждено владельцем 2026-11-16, решение по ОР-1; ТЗ задачи — `docs/spec/2026-11-16-double-click-slider.md`).
- **Тема:** FR-25; ADR-0004, ADR-0026, ADR-0032. План — `docs/plans/2026-11-16-double-click-slider.md`.

## Контекст

Приложению (`sfplayer`: выбор банка и файла в списках диалогов) нужен двойной клик по пункту списка. Решение владельца: двойной клик делается в `gterm` для любого контрола, приложение обрабатывает его привязкой сообщения — так же, как обычный клик у кнопки (`on_activate`). У контролов нет часов (ADR-0026, поправка ADR-0032: «таймеров у виджетов нет»), `winit` числа нажатий не сообщает.

## Решение

1. **Считает окно.** `App` держит счётчик (`app/clicks.rs`, время — аргументом, как у тика ADR-0033) и кладёт номер нажатия подряд в новое поле `PointerEvent::Input::click_count: u8`. Двойной клик — второе нажатие **левой** кнопки в **той же ячейке** (`PointerEvent::Input::cell`, допуск — ноль ячеек) не позже **500 мс** после предыдущего; ровно 500 мс — ещё двойной. После двойного счёт начинается заново (третье нажатие — 1, четвёртое в пределах интервала — снова 2). Нажатие другой кнопки — всегда 1 и прерывает серию левой. У отпускания — номер нажатия, которое оно завершает.
2. **`gterm-widgets`.** `MouseMsg::click_count` переносит число (у движения, колеса и отмены — 0), `MouseMsg::is_double_click()` — второе нажатие левой кнопки.
3. **Привязка у узла дерева.** `Ui::on_double_click(message: M)` хранится в узле `Ui` (а не в элементе `Stateful`), поэтому действует у любого контрола: встроенного (`Ui::stateful`), своего (`Ui::control`) и принадлежащего описанию (`Ui::owned`); у контейнеров и листов без состояния не действует. Модальный слой маршрутизирует своё содержимое тем же `route_mouse` — привязка работает и там.
4. **Порядок.** Второе нажатие доставляется контролу как обычное (первое тоже было обычным кликом: в списке оно выделило строку), затем дерево публикует сообщение привязки — к этому моменту выделена строка под указателем. Сообщение переносится, а не клонируется (описание живёт одно событие, как у `on_activate`). Если сообщение опубликовано, результат — `Handled::Yes`; захват по-прежнему определяется только ответом контрола на нажатие.
5. **Отказ по месту.** `Control::accepts_double_click(&self, &MouseMsg) -> bool`, по умолчанию `true`; дерево спрашивает **до** доставки нажатия — по виду, который видел пользователь, — и только у контрола с привязкой. `ListState` и `TableState` отказывают на своей полосе прокрутки (`BarState::contains`) и мимо строк (заголовок, строки ниже последнего пункта); неактивные `ButtonState` и `CheckboxState` — всегда.
6. **Проверка без окна.** Счётчик — unit-тестами в самом модуле (`#[cfg(test)]`), он `pub(super)` и наружу не выходит; дерево — через `Ui::route_mouse` с `MouseMsg { click_count: 2, .. }`.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Часы в контролах или в дереве `Ui` (`Instant` в состоянии списка) | противоречит G-4 («часы в контролах не нужны») и ADR-0026; тесты зависели бы от времени |
| Допуск по месту в пикселях (как в ОС) | контролы и тесты работают в ячейках; две ячейки — два разных пункта, а внутри ячейки дрожание руки не меняет адресата |
| Интервал из настроек ОС (`GetDoubleClickTime`) | платформенный код без пользы для терминальной сетки; G-4 фиксирует 500 мс; при надобности — отдельной задачей |
| Привязка только у встроенных контролов (`Stateful::bind_double_click`, как `on_activate`) | G-4 требует «любой контрол дерева»; свой контрол приложения привязок `Stateful` не имеет |
| Публиковать на отпускании второго клика | первое нажатие уже обычный клик, а нажатие — тот же момент, когда реагирует выделение; отпускание за пределами контрола пришлось бы отменять отдельно |
| Отдельный `MouseKind::DoubleClick` вместо поля | второе нажатие перестало бы быть `Down` — контролы без поддержки двойного клика (кнопка, флажок, поле ввода) потеряли бы обычный клик |
| Отказ контрола после доставки нажатия | нажатие на стрелку полосы прокручивает список; суждение по уже изменённому состоянию зависело бы от того, что сделал контрол |
| Публичный счётчик в `gterm::app` для тестов из `tests/` | лишний публичный API ради тестов; в `src/` юнит-тестов прежде не было, это первый — осознанное отклонение от привычки репозитория |

## Последствия

**Плюсы:** двойной клик по любому контролу одной строкой описания; контролы и тесты без часов; без привязки маршрутизация прежняя (те же вызовы, захват и сообщения — проверено тестом).

**Минусы / риски:** новые поля публичных типов — внешний код, создающий `PointerEvent::Input` или `MouseMsg` литералом, перестанет собираться (в `sfplayer` — литералы `MouseMsg` в тестовых помощниках, дополняются `click_count`); интервал 500 мс не совпадает с настройкой ОС у пользователя, изменившего её; контрол, отвечающий `Handled::No` на нажатие (свой контрол без мыши), с привязкой всё равно даёт сообщение — так задумано: двойной клик пришёлся на его область. Размеры release — в `docs/done/2026-11-16-double-click-slider.md`.
