# ADR-0013. Альфа цветов ячейки `0xAARRGGBB` и фон буфера вместо `ViewParams`

- **Дата:** 2026-10-09
- **Статус:** Accepted
- **Тема:** FR-2, FR-2.1, FR-14, §6.1, §7.3, §8. ТЗ задачи — `docs/spec/2026-10-09-color-alpha.md`, план — `docs/plans/2026-10-09-color-alpha.md`.

## Контекст

`Color` хранил `0x00RRGGBB`, альфу отбрасывал `from_rgba` и маски `& 0x00FF_FFFF` в обоих рендерерах (FR-2: «альфа игнорируется»). Поле вокруг сетки задавал `ViewParams::border_color` — единственное поле параметров вида. Владелец решил (2026-10-09):
- альфа fg — прозрачность символа над фоном ячейки;
- альфа bg — прозрачность фона ячейки над подложкой;
- подложка — фон буфера, он же заменяет `border_color`;
- `ViewParams` удаляется (Р1 — а).

Следующая задача — наложение клиентских буферов (`docs/spec/2026-10-09-overlay-buffers.md`); она опирается на ту же формулу ячейки.

## Решение

1. **`Color` — `0xAARRGGBB`.**
   - `A = 255` — непрозрачный цвет, `A = 0` — прозрачный.
   - `from_rgb` даёт `A = 255`, `from_rgba` хранит `a`; добавлен аксессор `a()`.
   - Константы `BLACK`, `WHITE` и прочие непрозрачные; добавлена `TRANSPARENT`, равная `default()`.
   - Кадр рендерера по-прежнему `0x00RRGGBB`.
2. **Фон буфера.** `ScreenBuffer::background()` / `set_background()`, по умолчанию `BLACK`.
   - Это непрозрачная подложка под ячейками и заливка поля вокруг сетки; альфа фона не учитывается.
   - `set_background` не трогает dirty-строки. Смену замечает Software-рендерер (`last_background`) и рисует кадр целиком. GL перерисовывает кадр всегда, фон ему передаётся uniform-переменной.
3. **Формула ячейки** — целочисленная, одинаковая в шейдере и в Software:

   ```
   bg' = blend(B, bg.rgb, bg.a)          // B — фон буфера
   fg' = BOLD ? min(fg.rgb + 0x55, 255) : fg.rgb
   a   = fade(cov, fg.a) = (cov·fg.a + 127)/255   // UNDERLINE: cov = 255 на нижней строке
   out = blend(bg', fg', a)
   ```

   - При `α = 255` формула совпадает с прежней бит в бит: golden-эталоны не менялись.
   - В Software `bg'` считается один раз на ячейку, потому что подложка однотонная. Функции `blend` и `fade` — публичные в `soft_backend`.
4. **Данные GPU.**
   - Каналы G и B текстуры данных несут `Color` целиком.
   - Фон передаётся `uniform ivec3 u_background` в целых 0…255 вместо `vec4 u_border`.
   - Полная загрузка данных GL при смене вида упразднена: данные ячеек от фона не зависят.
5. **`ViewParams` удалён.**
   - Сигнатуры: `Renderer::render(&mut self, screen)`, `GlBackend::render_to_frame(screen)`, `App::new(title, screen, rasterizer, config, options)`.
   - Цвет поля задаётся `screen.set_background(…)`.

## Альтернативы и обоснование

| Вариант | Почему не выбран |
|---|---|
| Хранить прозрачность (`255 − α`), чтобы старые `0x00RRGGBB` остались непрозрачными | нестандартно и легко перепутать при чтении и записи; внутри проекта прямых `Color(0x00…)` не было (проверено поиском) |
| Фон буфера отдельно от `border_color` | два почти одинаковых цвета; владелец выбрал замену |
| Оставить пустой `ViewParams` как точку расширения | YAGNI; смена пустой структуры ничего не значит (Р1 — а) |
| Смена фона помечает все строки dirty | у GL фон — uniform, данные перегружать незачем; признак «вид изменился» и так жил в рендерере |
| Отдельный цикл пикселей для непрозрачного символа (`draw_glyph::<FADED>`) | замер дал 67 FPS против 77 у простого варианта: при `opt-level = "z"` цена определяется раскладкой кода, а не арифметикой (отчёт задачи) |

## Последствия

- **Плюсы:**
  - полупрозрачные символы и фоны при сохранении бит-идентичности GL ↔ Software (7 сцен, допуск 0);
  - golden-эталоны не менялись;
  - формула ячейки готова для наложения клиентских буферов.
- **Минусы / риски:**
  - ломающее изменение API: `Color(0x00RRGGBB)`, собранный напрямую, теперь прозрачный; у `Renderer::render` и `App::new` больше нет параметра вида;
  - Software при полной перерисовке медленнее примерно на 14 %: 88,6–93,9 → 75,9–78,4 FPS на сетке 120×40 при попеременных запусках. NFR-5 (≥ 60 FPS) выполняется. Причина не локализована, дальнейшая оптимизация — отдельная задача.
