# ADR-0007. Инжекция ошибок рендера флагами `Config`: `--fail-frames=N`, `--lose-context`

- **Дата:** 2026-10-04
- **Статус:** Accepted
- **Тема:** автотест политики ошибок кадра (ТЗ §5.3 п.5, FR-21, §11.2, §12 этап 8); план — `docs/plans/2026-10-04-render-fault-injection.md`

## Контекст

Политика §5.3 п.5 (`ContextLost` → откат сразу; иная ошибка → один повтор кадра, затем откат; ошибка на Software → завершение с кодом ≠ 0) реализована в `App::redraw` на этапе 5 и с тех пор подтверждена только чтением кода (`docs/verify/2026-10-01-stage5-fallback-cli.md`, `docs/verify/2026-10-02-stage6-blink-dpi-events.md`). Автотестом покрыт лишь откат по запросу приложения (`tests/stage6_fallback.rs`). Настоящую ошибку кадра и потерю контекста на рабочей машине воспроизвести нечем.

`App` держит конкретный `enum Backend { Gl, Soft }`, а не `dyn Renderer`: уровни различаются поверхностью вывода и передачей атласа при откате. Подставить в окно произвольный тестовый `Renderer` без перестройки `App` нельзя.

## Решение

1. Ошибки кадра инжектируются **флагами `Config`**, по образцу `--fail-gl` (§11.4 п.4):
   - `--fail-frames=N` (`Config::fail_frames: u32`) — первые `N` попыток кадра завершаются `RenderError::Other`; счётчик общий на весь запуск: повторы и кадры после отката тоже считаются;
   - `--lose-context` (`Config::lose_context: bool`) — первая попытка кадра завершается `RenderError::ContextLost`, один раз.
2. Точка инжекции — `App::render_frame`, **после** настоящего рендера и вывода кадра, до обновления статистики: так же приходит настоящая ошибка GL (`glGetError` после кадра, ошибка обмена буферов). Дальше ошибка идёт обычным путём через `App::redraw` — отдельной ветки для инжектированных ошибок нет.
3. Проверка — оконный тест-бинарник (`harness = false`), проходящий весь путь на настоящем окне: повтор, откат GL → Software, остановка на Software с ошибкой из `App::run`.

## Альтернативы и обоснование

| Вариант | Почему не выбран |
|---|---|
| Чистая функция «что делать после кадра» + обёртка `FaultyRenderer<R: Renderer>` в `tests/` | работает без окна и не трогает `Config`, но проверяет только решение (повтор/откат/стоп), а не проводку в `App`: откат на том же окне и код возврата остались бы «по коду» |
| Оба варианта сразу | максимальное покрытие ценой самого большого объёма правок; чистая функция из десятка строк даёт мало сверх оконного теста |
| Третий вариант `Backend` с произвольным `dyn Renderer` | перестройка `App` ради теста; тестовый рендерер всё равно не имел бы поверхности и атласа настоящих уровней |

Флаги выбраны владельцем: они проверяют настоящий путь целиком и пригодятся в ручных прогонах этапа 8 (RDP, ВМ без 3D, другие драйверы) — откат можно вызвать на любой машине, не дожидаясь настоящего сбоя.

## Последствия

- **Плюсы:** §5.3 п.5 и FR-21 получают автотест на настоящем окне; ручная проверка отката на целевых конфигурациях — одной командой; путь обработки ошибок один и тот же для настоящих и инжектированных ошибок.
- **Минусы / риски:** в публичном `Config` и в справке появляются отладочные флаги (как уже есть `--fail-gl`); без окна тест пропускается с причиной, как остальные оконные тесты; инжекция имитирует ошибку после успешного кадра и не воспроизводит сбой внутри драйвера — настоящая потеря контекста остаётся ручной проверкой этапа 8.
