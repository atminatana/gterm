# ADR-0036. Ползунок `Slider`: целое значение в границах, дорожка на ширину области, событие `ValueChanged(i64)` с привязкой `on_value`, протяжка под захватом

- **Дата:** 2026-11-16
- **Статус:** Accepted (G-3 ТЗ `sfplayer` `docs/spec/2026-11-16-dialogs-and-keys.md`, утверждено владельцем 2026-11-16, решение по ОР-3; ТЗ задачи — `docs/spec/2026-11-16-double-click-slider.md`).
- **Тема:** ТЗ §13; ADR-0023, ADR-0026, ADR-0031, ADR-0034. План — `docs/plans/2026-11-16-double-click-slider.md`.

## Контекст

В `sfplayer` уровни эффектов (реверб, хорус) меняются ползунком (решение владельца по ОР-3). В `gterm-widgets` есть индикаторы (`Gauge`, `LineGauge`, `Meter`), но они только показывают долю; контрола, меняющего число мышью и клавишами, нет.

## Решение

1. **`Slider` / `SliderState`** (`src/widgets/slider.rs`) по образцу флажка (ADR-0031): вид — виджет-значение, поведение — состояние с `Control<M>` и `WidgetEvents`.
2. **Значение — `i64`** в границах `min..=max`, шаг `step ≥ 1`. `SliderState::new(min, max)` (при `max < min` верхняя граница поднимается до нижней; значение — `min`, шаг — 1), `with_value`, `with_step`; чтение `value`/`min`/`max`/`step`; программная смена `set_value`, `set_range` (значение зажимается в новые границы), `set_step` — без события. `Default` — 0…100, шаг 1: чтобы состояние приложения могло выводить `Default`.
3. **Клавиши под фокусом:** `←`/`→` — на шаг, `Home`/`End` — к границам; шаг за границу останавливается на ней. В границе клавиша принимается (`Handled::Yes`, до формы и карты сочетаний не доходит — как навигация списка), но значение и событие не меняются. Прочие клавиши — приложению.
4. **Мышь.** Дорожка — вся область узла (`NodeState::area`), значение по колонке: левая ячейка — `min`, правая — `max`, между — пропорционально с округлением к ближайшему; указатель за краями — граница; у дорожки в одну ячейку положения нет — значение прежнее. Левое нажатие ставит значение и берёт захват (`Handled::Yes` на `Down`); движение под захватом ведёт значение; отпускание и уход указателя (`Cancel`) снимают захват, достигнутое значение остаётся. Колесо — на `round(lines)` шагов, вверх — больше. Неактивный ползунок не фокусируется и ни ввода, ни двойного клика (ADR-0035) не принимает.
5. **Событие `WidgetEvent::ValueChanged(i64)`** — только при изменении пользователем и только если значение стало другим → привязка `Ui::on_value(Fn(i64) -> M)` (имена — по образцу `Toggled`/`on_toggle`).
6. **Вид:** в средней строке области — заполненная часть левее ползунка (`━`), ползунок в колонке значения (`█`), незаполненная часть правее (`─`); все три знака процедурные (ADR-0022), свои — `filled_symbol`/`thumb_symbol`/`unfilled_symbol`. Стили `style`, `filled_style`, `thumb_style`, `unfilled_style`; стиль состояния — `focus_style` под фокусом либо `disabled_style` у неактивного — накладывается поверх стиля части и на всю область. Колонка ползунка — обратное к отображению «колонка → значение», поэтому клик ставит ползунок под указатель.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Значение `f64` или доля 0…1 (как у `Gauge`) | G-3 — «целое значение в заданных границах»; шаг клавиш и равенство «то же значение — нет события» с дробями неоднозначны |
| Заполнение до половины ячейки (`▌`, как у `Meter`) без ползунка | у контрола нужна точка, за которую тянут и куда ставит клик; без неё у краёв не видно, достигнута ли граница |
| Подпись и значение внутри виджета | раскладку подписи приложение уже делает строкой формы; число рядом — `Paragraph` (так в примере `widget_edit`) |
| Рамка (`block`) у ползунка | геометрия дорожки разошлась бы с областью узла, по которой считается мышь; рамку даёт `Ui::group` |
| В границе отвечать `Handled::No` | `←` у левой границы уходил бы в карту сочетаний или приложению — поведение контрола зависело бы от значения |
| Отдельный флаг протяжки в состоянии | захват уже хранит `NodeState::captured`; дерево снимает его на `Up`/`Cancel` |
| Вертикальный ползунок | не нужен постановке; при надобности — отдельной задачей |

## Последствия

**Плюсы:** универсальный контрол для числовых параметров; то же поведение мыши с захватом, что у полосы прокрутки, и тот же порядок стилей, что у флажка; событие только от пользователя — программная установка из конфига не порождает лишних сообщений.

**Минусы / риски:** новый вариант публичного `WidgetEvent` — внешний исчерпывающий `match` перестанет собираться (в репозитории он один, в `ui/element.rs`); при диапазоне шире дорожки клик и протяжка дают только значения, попадающие в колонки, точная настройка — клавишами и колесом; колесо с попиксельной прокруткой меньше половины строки шага не делает. Размеры release — в `docs/done/2026-11-16-double-click-slider.md`.
