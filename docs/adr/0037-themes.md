# ADR-0037. Темы оформления: `Theme` формата helix в `gterm-widgets`, неявная доставка через `Ui`, области раскраски знает сам виджет

- **Дата:** 2026-11-18
- **Статус:** Accepted (ТЗ `docs/spec/2026-11-18-themes.md` утверждено владельцем 2026-11-18: О1 — неявный способ, «контрол знает, какой стиль брать из темы»; О3 — крейт `toml`; О4 — `reversed` реализуется; О5 — все контролы крейта; О2, О6, О7 — рекомендованные варианты (a)).
- **Тема:** ТЗ §13; ADR-0023, ADR-0026, ADR-0012, ADR-0013, ADR-0017. План — `docs/plans/2026-11-18-themes.md`.

## Контекст

Цветов по умолчанию у виджетов нет: каждый стиль каждого состояния приложение задаёт построителями, примеры держат свои константы. Владелец поставил задачу тем по образцу редактора helix: раскраска общих элементов и доступ приложения к специфическим элементам темы. Формат helix — TOML: область (`"ui.menu.selected"`) → цвет или таблица `{ fg, bg, modifiers, underline }`, таблица `[palette]`, `inherits`. Областей для кнопок, полей и прочих элементов форм в helix нет; модификатор `reversed` используется часто, а флага инверсии в ячейке нет (ADR-0012).

## Решение

1. **`Theme` — значение в состоянии приложения** (`gterm-widgets/src/theme/`; `gterm` о темах не знает, глобального состояния нет). Хранит все области файла — и неизвестные библиотеке — и палитру. Доступ: `get` (точно), `style` (наследование по точке: `a.b.c` → `a.b` → `a`), `first` (первая существующая из перечня точных имён), `color` (палитра), `scopes`, `base`; правка — `set`, `set_color`. Свои области приложение кладёт в файл темы и читает теми же вызовами.
2. **Встроенная тема** `Theme::default()` задана в коде: библиотека остаётся без файлов (ADR-0017).
3. **Формат helix, разбор — крейт `toml`** (`std` + `parse`, без `serde`) за фичей `theme-toml`, включённой по умолчанию. Цвета: `#RRGGBB`, `#RRGGBBAA` (расширение — альфа ADR-0013), имена палитры, 16 имён ANSI helix (`default` — «не задан»). `inherits` — цепочка файлов в каталогах, заданных приложением; таблицы объединяются до разрешения цветов, поэтому области родителя берут палитру потомка (как в helix). `Theme::load(dirs, name)`, `Theme::from_toml_str(text)`.
4. **Чего ячейка не умеет** (ADR-0012): `bold`, `italic`, `underlined` и любой `underline.style` → флаги ячейки; `reversed` — обмен `fg` и `bg` при загрузке, недостающий цвет берётся из `ui.text` / `ui.background`; `dim`, `crossed_out`, мигание, `hidden`, цвет и вид подчёркивания пропускаются. Всё пропущенное и негодные области (неизвестный цвет, чужой тип) — в `Theme::warnings()`; ошибкой `ThemeError` считаются только отсутствие файла, синтаксис TOML (с позицией) и цикл либо глубина `inherits`.
5. **Доставка — неявная, через описание экрана.** `Ui::theme(&theme)` поднимается к корню. `Ui::render` с темой накладывает на свою область базовый стиль (`fg` — `ui.text`, `bg` — `ui.background`) и передаёт тему каждому узлу; модальный слой заливается стилем `ui.popup` поверх базового и передаёт тему содержимому.
6. **Области своей раскраски знает виджет.** У трейтов `Widget`, `StatefulWidget`, `Drawable` — метод по умолчанию `apply_theme(&mut self, &Theme)`; дерево зовёт его перед отрисовкой. Встроенный виджет подставляет стили темы **под** явные (`тема.patch(явный)`): заданное приложением сильнее. То же действие явно — `.themed(&theme)` для виджетов вне дерева. Текст своей области не имеет: `Paragraph` и подписи берут цвета области, на которой лежат.
7. **Области и запасные цепочки** (слева направо — первая существующая; имена точные):

| Элемент | Цепочка |
|---|---|
| фон экрана | `bg` из `ui.background` |
| текст | `fg` из `ui.text` |
| рамка (`Block`) | `fg` из `ui.window` (фон этой области в темах helix — полоса разделителя окон, на рамке из линий он дал бы бруски) |
| рамка под фокусом (группа, список, таблица) | `ui.window.focus` → `fg` из `ui.text.focus` |
| модальный слой | `ui.popup` поверх базового стиля |
| кнопка | `ui.button` → `ui.menu` |
| кнопка: фокус / нажата / неактивна | `ui.button.focus` → `ui.menu.selected` / `ui.button.pressed` → `ui.selection` / `ui.button.disabled` → `ui.text.inactive` → `ui.virtual` |
| флажок | `ui.checkbox` |
| флажок: фокус / нажат / неактивен | `ui.checkbox.focus` → `ui.text.focus` / `ui.checkbox.pressed` → `ui.selection` / `ui.checkbox.disabled` → `ui.text.inactive` → `ui.virtual` |
| поле ввода | `ui.input` → `ui.menu` |
| поле: фокус / выделение / подсказка | `ui.input.focus` → `ui.text.focus` / `ui.input.selection` → `ui.selection` / `ui.input.placeholder` → `ui.text.inactive` → `ui.virtual` |
| выпадающий список: поле / фокус / пункт | `ui.combo` → `ui.input` → `ui.menu` / `ui.combo.focus` → `ui.input.focus` → `ui.text.focus` / `ui.combo.selected` → `ui.list.selected` → `ui.menu.selected` |
| список: область / выделенный пункт | `ui.list` / `ui.list.selected` → `ui.menu.selected` |
| таблица: область / заголовок / выделенная строка | `ui.table` / `ui.table.header` / `ui.table.selected` → `ui.menu.selected` |
| вкладки: область / выбранная / фокус | `ui.tabs` → `ui.bufferline` / `ui.tabs.selected` → `ui.bufferline.active` → `ui.menu.selected` / `ui.tabs.focus` → `ui.text.focus` |
| полоса прокрутки: дорожка / ползунок | `ui.scrollbar` → `fg` из `ui.window` / `ui.scrollbar.thumb` → `fg` из `ui.menu.scroll` |
| индикаторы: область / заливка / незаполненная линия | `ui.gauge` / `ui.gauge.filled` → `ui.menu.scroll` (у `LineGauge` — только `fg`) / `fg` из `ui.gauge.unfilled` → `ui.window` |

8. **Файлы тем:** темы helix в репозиторий не копируются; две свои (`gterm_dark`, `gterm_light`) лежат в `crates/gterm-widgets/examples/themes/` и служат образцом своих областей.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Явный способ — только `.themed(&theme)` у каждого виджета (О1-a) | решение владельца: основной способ — неявный; явный вызов оставлен для виджетов вне дерева |
| Дерево само знает области каждого виджета | решение владельца: области знает контрол; иначе свой виджет приложения не мог бы краситься темой |
| Отдельный трейт `Themed` как супертрейт `Widget` | ломает свои виджеты приложений; метод по умолчанию у существующих трейтов — нет |
| Различать «стиль не задан» и «задан пустым» (`Option<Style>` в каждом поле) | `Style` уже частичная заплатка: пустой стиль ничего не задаёт, правило «тема под явным» выражается одним `patch` |
| Наследование по точке внутри запасных цепочек | `ui.window.focus` находил бы `ui.window`, и рамка под фокусом не отличалась бы от обычной; в цепочках имена точные |
| Свой разборщик подмножества TOML (О3-b) | решение владельца: крейт; свой код разошёлся бы с чужими файлами |
| Пропускать `reversed` (О4-b) | решение владельца: реализовать; иначе `ui.cursor`, `ui.menu.selected` многих тем теряют выделение |
| Флаг `INVERSE` в ячейке | изменение `gterm`, шейдера и обоих рендереров (ADR-0012) ради частного случая, решаемого при загрузке |
| Только названные в постановке элементы (О5-a) | решение владельца: все контролы, реализованные на текущий момент |
| Копировать темы helix в репозиторий (О6-b) | у тем свои лицензии; каталог helix подключается ключом примера |

## Последствия

**Плюсы:** одна строка `Ui::theme(&theme)` красит экран и слой целиком; файлы helix загружаются как есть; приложение читает и свои области; смена темы на лету — замена значения; существующие приложения без темы рисуют то же, что раньше.

**Минусы / риски:** новая зависимость `toml` (отключается фичей); `Ui::render` с темой перекрашивает свою область базовым стилем — фон, который приложение красило само, заменяется цветами темы; темы helix подобраны под редактор, и по запасным цепочкам часть тем даёт малоконтрастные кнопки и рамки — лечится своими областями в файле; `reversed` разрешён при загрузке, поэтому правка `ui.text` / `ui.background` через `set` уже разрешённые области не пересчитывает; неотображаемые модификаторы видны только в `warnings()`. Размеры release — в `docs/done/2026-11-18-themes.md`.

## Поправка 2026-11-23: перечень тем каталогов — `Theme::list`

**Контекст.** Каталоги тем приложение передаёт в `Theme::load(dirs, name)`, но узнать, какие темы в них есть, библиотека не позволяла: пример `widget_edit` перебирал `*.toml` сам. Владелец поручил пример просмотра тем (`theme`) с указанием каталогов и перечнем тем и выбрал место перечня — библиотека, а не код примера (решение 2026-11-23).

**Решение.** `Theme::list(dirs) -> Result<Vec<String>, ThemeError>` (`theme/load.rs`, за фичей `theme-toml`): имена файлов `*.toml` всех каталогов перечня без расширения, по алфавиту и без повторов — ровно то, что принимает `Theme::load` с теми же каталогами. Файлы не читаются: годность темы выясняет загрузка. Каталог, который не удалось прочитать (в том числе отсутствующий), — ошибка `ThemeError::Io` с его путём; вариант `Io` теперь означает «файл или каталог не прочитан», текст ошибки — `theme path …`.

**Альтернативы.** Перебор файлов в каждом приложении — правило «что считается темой» (расширение, имя в UTF-8, файл, а не каталог) разошлось бы с `load`. Молча пропускать непрочитанный каталог, как `load` пропускает каталог без нужного файла, — опечатка в пути выглядела бы как пустой перечень. Возвращать загруженные темы — перечень из сотни файлов читал и разбирал бы все ради списка имён.

**Последствия.** Приложение строит выбор темы двумя вызовами — `list` и `load`. При нескольких каталогах один непрочитанный лишает перечня целиком: приложение, которому нужен частичный перечень, зовёт `list` по каталогу. `widget_edit` остался на своём переборе (вне границ задачи).
