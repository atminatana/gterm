# ADR-0017. Библиотека без ресурсов: workspace `gterm` + `gterm-demo`, шрифт — параметр API, системный моноширинный через `fontdb`

- **Дата:** 2026-10-23
- **Статус:** Accepted (решения владельца 2026-10-23: О1-a, О2-a, О3-a с `memmap`, О4-a, О5). Дополняет ADR-0003 (семейство из `assets/` → семейство из каталога/файлов/системы), ADR-0008 (`svg_dir` уходит в демо).
- **Тема:** ТЗ §1, FR-8, FR-8.1, FR-8.5, NFR-1, NFR-3, NFR-9, §5.1. ТЗ задачи — `docs/spec/2026-10-23-lib-split-system-font.md`, план — `docs/plans/2026-10-23-lib-split-system-font.md`.

## Контекст

ТЗ §1 требует «библиотека + демо-бинарник, чтобы модуль отображения можно было встроить в другие продукты». Фактически один крейт содержит библиотеку, три бинарника и `assets/` (10,3 МБ TTF Nerd Font + SVG-тайлы демо), а `src/font.rs` знает имя шрифта (`FONT_FAMILY`), каталог `assets/` и ищет его относительно exe (`find_folder`). Потребитель библиотеки обязан везти `assets/` с именно этим шрифтом. Владелец заявил потребность использовать библиотеку **без** ресурсов рядом с exe.

Ограничения: golden-эталоны и `stage4_gl` — растр конкретного шрифта репозитория, системные шрифты от машины к машине разные; NFR-6/NFR-9 — ничего в кадре, `unsafe` только в `gl_backend.rs`; NFR-1 — размер замеряется.

## Решение

1. **Workspace в одном репозитории**: `crates/gterm` — библиотека, её интеграционные тесты, пример `examples/minimal.rs`; `crates/gterm-demo` — бинарники `demo`/`full_table`/`overlay`, общий код демо библиотечной целью (`common`, `assets`), каталог `assets/`, зависимость `find_folder`. Корневой манифест виртуальный (`resolver = "3"`, `[profile.release]` §10.2). Имя библиотеки `gterm` не меняется.
2. **Шрифт тестов библиотеки** — `crates/gterm-demo/assets/fonts/` через единый помощник тестов (`../gterm-demo/assets`): без дублирования 10 МБ, golden не меняется.
3. **Библиотека не знает ни имени шрифта, ни каталогов**: `FontFamily::load(fonts_dir, family)`, `from_files(paths, family)`, `from_faces(faces, family, found)`; `FONT_FAMILY`, `ASSETS_DIR_NAME`, `FONTS_DIR_NAME`, `find_assets_dir`, `fonts_dir`, `svg_dir`, `FontError::AssetsDirNotFound` переезжают в `gterm-demo`. Правила отбора начертаний по `OS/2` и подстановки (ADR-0003) сохраняются. Добавляется проверка моноширинности Regular по advance контрольного набора → `FontError::NotMonospace`.
4. **Системный моноширинный шрифт** — модуль `font::system` на `fontdb 0.24` (`default-features = false`, фичи `fs`, `memmap`, `fontconfig`): `FontFamily::system(family)` и `FontFamily::system_monospace()` с фиксированным порядком кандидатов (Windows: Cascadia Mono, Consolas, Lucida Console, Courier New; Linux: алиас fontconfig `monospace`, затем DejaVu Sans Mono, Liberation Mono, Noto Sans Mono, FreeMono); первое семейство с Regular, прошедшее проверку п.3. База `fontdb` живёт только на время вызова. `unsafe` отображения файлов — внутри зависимости, как у `winit`/`softbuffer`; в коде проекта `unsafe` не появляется.
5. **Умолчание демо**: `assets/fonts/` рядом с exe или в репозитории, если найден (иконки Nerd Font, SVG-тайлы, сопоставимость `--bench`), иначе системный; `--system-font` — принудительно системный. Пример `minimal` использует только `system_monospace()`.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Бинарники в `examples/` того же крейта, `assets/` в корне | `assets/` и демо-код остаются внутри пакета библиотеки — цель §1 достигается лишь формально |
| Два репозитория (библиотека, демо) | ломает единые гейты одной командой, golden-тесты библиотеки теряют шрифт, двойная история |
| Копия TTF в `tests/data/` библиотеки | +10,3 МБ дублирования ради автономности тестов, которая нужна только при публикации (не в объёме) |
| `assets/` в корне workspace вне крейтов | ресурсы ничьи; по формулировке владельца ресурсы идут вместе с демо |
| Собственный обход системных каталогов на `skrifa` | нет fontconfig на Linux, список каталогов поддерживается вручную; оставлен как запасной путь, если старт с `fontdb` окажется дольше ≈ 100 мс |
| `font-kit` (DirectWrite/fontconfig/CoreText) | внешние C-зависимости и `unsafe`-обёртки — против NFR-3/NFR-9 |
| `fontdb` без `memmap` | читает каждый системный шрифт целиком (`std::fs::read`) — сотни МБ на старте |
| Демо всегда на системном шрифте | теряет иконки Nerd Font и сопоставимость `--bench` с прежними замерами |

## Последствия

**Плюсы:** потребитель подключает `gterm` без ресурсов рядом с exe (К13 — пример `minimal`); имя шрифта и каталоги — дело приложения; golden и бит-идентичность GL ↔ Software не затронуты; системный шрифт выбирается детерминированно и логируется.

**Минусы / риски:** несовместимое изменение API `FontFamily` (библиотека 0.x, внешних потребителей нет); новая зависимость `fontdb` — +40 448 Б к `demo.exe` (1 482 240 → 1 522 688 Б, 2026-10-23); выбор системного шрифта на машине владельца (1 709 файлов шрифтов, 2,4 ГБ) — 150–158 мс в release при тёплом кэше ОС и ≈ 12 с в debug при холодном (первый запуск после загрузки; release при холодном кэше не замерялся) — выше порога ≈ 100 мс из плана, запасной путь (собственный обход, реестр шрифтов Windows, кэш выбора) — решение владельца (`docs/done/2026-10-23-lib-split-system-font.md`); коллекции `.ttc` — только первое лицо файла; тесты библиотеки читают шрифт из соседнего пакета; на системном шрифте иконки Nerd Font и глифы вне BMP — пустые ячейки (§13 «несколько шрифтов» не делается); команды запуска меняются на `cargo run --bin <имя>`.
