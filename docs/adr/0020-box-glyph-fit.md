# ADR-0020. Рамки из шрифта вписываются в ячейку: advance → ширина, `descent…ascent` → высота

- **Дата:** 2026-10-23
- **Статус:** Accepted (постановка владельца 2026-10-23: вариант Б после отклонения варианта А — ADR-0019). Дополняет ADR-0018: касается только режимов `Font`/`Combined`.
- **Тема:** ТЗ FR-8.4, FR-9, FR-13. ТЗ задачи — `docs/spec/2026-10-23-box-glyph-fit.md`, план — `docs/plans/2026-10-23-box-glyph-fit.md`.

## Контекст

Глиф рамки из шрифта рисуется в своих метриках: по ширине до дробного advance, по высоте так, как задумал автор шрифта. Ячейка же — `round(advance) × round(ascent − descent)`. Поэтому `─` соседних ячеек либо обрезается, либо не доходит до края, а `│` соседних строк не смыкается по высоте. Подбор размера шрифта под целую ширину ячейки (вариант А, ADR-0019) видимого эффекта не дал и отклонён.

## Решение

1. В режимах `Font`/`Combined` контур глифа U+2500–U+259F (без хинтинга, п.3) **вписывается в ячейку** аффинным преобразованием команд пера: `x' = x · w / advance`, `y' = (baseline − h) + (y − descent) · h / (ascent − descent)` — в координатах пера (пиксели, y вверх, базовая линия в 0). Негодные метрики (advance ≤ 0, `ascent ≤ descent`) — контур не трогается.
2. Масштаб — по **метрикам строки**, не по габаритам глифа: иначе `─` растянулся бы в блок, а стыки `├` сместились бы.
3. **Вписываемый контур берётся без хинтинга** (`DrawSettings::unhinted`). Факт при реализации: с хинтингом нижняя строка `│` получала 177 единиц краски против 267 у остальных — хинтер округляет конец штриха к пиксельной сетке номинального размера, и после пересчёта под ячейку он не доходит до низа; без хинтинга краска равномерна по всей длине (`─` — 378 в каждой колонке, `│` — 329 в каждой строке). Цена — дробная толщина линий (378/255 ≈ 1,5 px на две строки, то есть сероватые линии); решение владельца — глазами (вариант В из разбора вошёл сюда).
4. Буквы, SVG и режим `Procedural` не затронуты.

## Альтернативы и обоснование

| Вариант | Почему отклонён |
|---|---|
| Подбор размера шрифта под целый advance (вариант А, ADR-0019) | проверен глазами — эффекта нет; не лечит вертикали |
| Масштаб по габаритам глифа | `─` стал бы блоком, стыки `├`/`┬` сместились бы относительно соседей |
| Растягивать хинтованный контур (первоначальное допущение ТЗ) | проверено тестом: вертикальный стык не смыкается (177 против 267), хинтер и растяжение противоречат друг другу |
| Отдельный режим `FontFitted` рядом с `Font` | режим «как в шрифте, но с зазорами» никому не нужен: `Font` без вписывания был бы заведомо хуже |

## Последствия

**Плюсы:** стыки рамок из шрифта смыкаются по ширине и высоте у шрифтов, рисующих рамки на advance и `descent…ascent`; процедурный путь и текст не меняются; GL ↔ Software бит-идентичны (атлас); работа — только на промахе атласа.

**Минусы / риски:** линии рамок без хинтинга имеют дробную толщину — сероватые при малых размерах (в отличие от целых толщин процедурного пути); шрифты, намеренно рисующие `│` короче строки, получают меньший, но не нулевой зазор; размер release 2026-10-23: `demo.exe` 1 524 224 Б (+1 536 к 1 522 688), `pseudographica.exe` 1 148 928 Б (`docs/done/2026-10-23-box-glyph-fit.md`).
