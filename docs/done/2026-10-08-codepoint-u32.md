# Выполнение: кодовая точка — `char` во всём Unicode

- План: `docs/plans/2026-10-08-codepoint-u32.md`; ТЗ 1.6 (FR-2, FR-8.4, FR-9, §5.2, §13); ПОЧЕМУ — `docs/adr/0009-codepoint-char-full-unicode.md`.

## WHAT

| Файл | Изменение |
|---|---|
| `src/cell.rs` | `Cell::ch: char`, `Cell::new(ch: char, …)`; `to_packed`: R = `ch` целиком, A = флаги; `from_packed`: недопустимая кодовая точка → `'\0'` |
| `src/buffer.rs` | `set_cell`/`fill_rect` принимают `char`; `write_row` пишет `char` без приведения (раньше `c as u16` обрезал символы вне BMP); пустая ячейка — `'\0'` |
| `src/atlas.rs` | таблица «кодовая точка → слот» на `char::MAX + 1` = 0x110000 записей (`CODEPOINT_COUNT`); `codepoint_of_slot: Vec<char>`; `slot_of`/`ensure`/`glyph`/`fill_channel` принимают `char` |
| `src/rasterizer.rs` | `has_glyph`/`rasterize` принимают `char`; лишнее `char::from_u32` убрано |
| `src/box_drawing.rs` | `BOX_FIRST`/`BOX_LAST: char`, `is_box_drawing`/`draw` принимают `char`; внутренние формулы — на `u32` |
| `src/bin/full_table/main.rs` | перечень глифов — по `cmap` начертания Regular (`skrifa` `charmap().mappings()`) плюс псевдографика, отбор `has_glyph`; `Vec<char>`; HEX в заголовке через `u32::from` |
| `src/bin/demo/{main,scene,bench}.rs` | места вызова: литералы `char`, числовые циклы по кодам — `u32` → `char::from_u32` |
| `tests/*` | места вызова изменённых сигнатур (`'A' as u16` → `'A'` и т.п.); новые тесты — см. `docs/test/2026-10-08-codepoint-u32.md` |
| ТЗ 1.6, ADR-0009 (+ пометки в ADR-0001/0003, индекс), `PROJECT_MAP.md`, `TODO.md` | обновлены; ТЗ и ADR закоммичены владельцем ранее (`e89cbfd`) |

Шейдер, `gl_backend.rs`, `soft_backend.rs`, `app.rs`, golden-эталоны — **не менялись** (на GPU уходит слот, а не кодовая точка, §6.1).

## CORRECTNESS

Golden-эталоны Software не перезаписывались и совпали — набор пикселей для прежних сцен не изменился. Новая сцена `stage4_gl` использует U+F0041, у которого младшие 16 бит равны `A`: при обрезке до `u16` тест бы упал на совпадении слотов/растров, а не прошёл случайно.
