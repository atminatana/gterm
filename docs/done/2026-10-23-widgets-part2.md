## Исправления по замечаниям владельца (2026-11-12, после коммита `1b45e27`)

Замечания: при листании списка клавишей `End` ползунок полосы не обновлялся; полоса не реагировала на мышь. Причина и решение — поправка в ADR-0032.

| Что | Результат |
|---|---|
| Полоса у списка | `widgets/list.rs`: `List::scrollbar(Scrollbar)` — полоса в последней колонке с точными значениями кадра; `ListState` — разметка полосы, состояние протяжки, ключ подгонки смещения; `scroll_by`, `scroll_to`; мышь: стрелки, дорожка, ползунок под захватом |
| Разметка полосы | `widgets/scrollbar.rs`: `BarLayout`, `BarPart`, `part_at`, `position_for_drag`; отрисовка возвращает разметку |
| Тесты | `tests/list_scrollbar.rs` (5) |
| Пример | `widgets`: полоса задаётся у списка, отдельный лист и раскладка до отрисовки убраны |
| Инструмент | `tools/shot.ps1`: изменение размера окна, клик и протяжка мышью |

- Мутации (исходники восстановлены побайтно): полоса берёт смещение до пересчёта; подгонка под выделение на каждом кадре; нажатие на полосе выделяет строку; состояние протяжки не сбрасывается отпусканием; отрисовка не подрезает смещение; протяжка не учитывает взятую ячейку; стрелки перепутаны — 7 из 7 пойманы. Первый прогон мутаций поймал 4 из 7: две проверки дописаны (нажатие на стрелку после протяжки; смещение, заданное мимо методов), одна мутация заменена на содержательную.
- Два падения при написании тестов — ошибки ожиданий теста (смещение сверялось до отрисовки; ползунок при высоте 2 — одна ячейка), код не менялся.
- После последнего изменения кода: `cargo fmt --check` и `cargo clippy --all-targets -- -D warnings` чисто; `cargo test` — **303 теста, 0 падений** в 44 бинарниках; `gterm-widgets` — 108.
- Проверено на живом окне (OpenGL 3.3, окно уменьшено до 740×300, чтобы список не помещался): `Tab`, `End` — ползунок внизу в том же кадре; клик по стрелке вверх — список на пункт выше; протяжка ползунка вверх — список в начале; клик по дорожке ниже ползунка — последняя страница; выделение не менялось.
- Размер release: `widgets.exe` 1 251 840 Б (+2 048).
- LOC: `list.rs` 445, `scrollbar.rs` 307, `tests/list_scrollbar.rs` 260, `tools/shot.ps1` 143.
- Не сделано: полоса у `Table`; автоповтор при удержании кнопки на стрелке; колесо двигает выделение, а не смещение.

## Доработка полосы прокрутки (2026-11-12, после коммита `ddefd2e`)

Поручение владельца: «Доработай полосу прокрутки». Сделаны три пункта, остававшиеся после исправлений; решения — вторая поправка в ADR-0032.

| Что | Результат |
|---|---|
| Общая логика | `widgets/scrollbar.rs`: `BarState` — нажатие, протяжка, удержание, колесо, правило подгонки; `Scrollbar::REPEAT_DELAY`, `REPEAT_INTERVAL`; `ListState` переведён на него |
| Полоса таблицы | `widgets/table.rs`: `Table::scrollbar`, `TableState::scroll_by`/`scroll_to`, предел смещения и число видимых строк, мышь и колесо |
| Колесо | с полосой прокручивает содержимое, без полосы — выделение, как раньше |
| Повтор при удержании | `Control::tick`, `Element::tick`, `Ui::tick`, `Modal::route_tick`; список и таблица листают по тактам |
| Тесты | `tests/scrollbar_owner.rs` (4) |
| Пример | `widgets`: полоса у таблицы, `on_frame` с `Ui::tick` |
| Инструмент | `tools/shot.ps1`: `-Hold`, `-Wheel`, подъём окна на передний план, признак `hit=` |

- Мутации (исходники восстановлены побайтно): нет начальной задержки; повтор без промежутка; листание по дорожке не останавливается у указателя; отпускание не снимает удержание; колесо в обратную сторону; колесо прокручивает и без полосы; полоса таблицы на строке заголовка; таблица всегда подгоняет смещение под выделение — 8 из 8 пойманы. С первого захода — 7 из 8: дописан случай с указателем посередине дорожки.
- Одно падение при написании тестов — порядок действий в тесте (программная прокрутка сразу после смены выделения кликом), код не менялся.
- После последнего изменения кода: `cargo fmt --check` и `cargo clippy --all-targets -- -D warnings` чисто; `cargo test` — **307 тестов, 0 падений** в 45 бинарниках; `gterm-widgets` — 112.
- Проверено на живом окне (OpenGL 3.3, окно 740×300): удержание кнопки на стрелке списка 1 с — список долистал до конца, выделение осталось на первом пункте; колесо над таблицей на два щелчка вниз — строки 03–10; удержание на стрелке таблицы 1,5 с — строки 05–12, ползунок внизу.
- Первая попытка живой проверки не дошла до окна (три действия без эффекта, фокус не перешёл): окно не было на переднем плане либо под точкой лежало другое окно. Скрипт доработан (подъём окна, признак `hit=`), повтор прошёл.
- Размер release: `widgets.exe` 1 253 376 Б (+1 536), `widget_edit.exe` 1 252 864 Б (+1 024), `demo.exe` без изменений.
- LOC: `scrollbar.rs` 446, `table.rs` 474, `list.rs` 445, `ui/route.rs` 259, `ui/element.rs` 346, `tests/scrollbar_owner.rs` 333, `tools/shot.ps1` 207.
- Замечено по снимку, не исправлялось: числа в последней колонке таблицы стоят вплотную к полосе («37▲») — отступа между колонками и полосой нет.
- Допущение исполнителя: колесо меняет поведение только у контролов с полосой; у остальных оставлено прежнее (ADR-0026).

## CORRECTNESS
- Мутации (исходники восстановлены побайтно, полный прогон после восстановления зелёный): `gauge.rs` — подпись над заливкой не обращается, сдвиг ряда восьмушек, доля не обрезается, отступ линии после подписи — 4 из 4 пойманы; `tabs.rs` — событие без смены, клик без проверки строки, стиль фокуса не накладывается — 3 пойманы, «`→` без ограничения у края» — эквивалентная мутация (выход за последнюю вкладку отсекает проверка индекса); `scrollbar.rs` — позиция ползунка не подрезается, стрелки на полосе в две ячейки, ползунок нулевой длины — 3 из 3 пойманы.
- Первый прогон тестов части 2: 1 падение — ошибка в тесте (снимок из одной строки для экрана в две), исправлено ожидание, код не менялся.
- Найдено компиляцией тестов и исправлено: `Scrollbar` с двумя трейтами (`Widget` и `StatefulWidget`) делал вызов `.render` неоднозначным — оставлен `Widget`.

## ⚠ WARNINGS
- Вид примера проверен исполнителем 2026-11-12 по снимкам окна на OpenGL 3.3 (Windows; запуск exe, снимок и клавиши через PowerShell): первая вкладка, вторая вкладка после `→`, модальное окно по `P`, список после `Tab` и `End`. Мышь на вкладках и изменение размера окна на окне не проверялись. Проверка по бэкендам для виджетов не требуется (решение владельца 2026-11-12): они пишут только в `ScreenBuffer`, равенство бэкендов держит `tests/stage4_gl.rs`.
- В примере первый фокус теперь на вкладках (они первые в порядке обхода), а не на списке: стрелки `↑`/`↓` двигают список после `Tab`.
- Найдено по первому снимку и исправлено в примере: на первом кадре ползунок полосы был в две ячейки, хотя список помещался целиком (высота списка ещё не была записана в состояние) — `Demo::draw` теперь вызывает раскладку до отрисовки; повторный снимок первого кадра — ползунок во всю дорожку. Найдено владельцем по снимку и исправлено: модальное окно шириной 60 обрезало строку в 60 знаков («поглощаетс») — ширина 64, проверено снимком.
- Отклонение от ТЗ 2026-10-23 (решение владельца, ADR-0032): `Tabs` принимает ввод; `Scrollbar` — без `StatefulWidget`; в примере `Gauge` не внизу экрана, а на второй вкладке (внизу — `LineGauge`).
- Вкладки, не поместившиеся по ширине, обрезаются; прокрутки ряда вкладок нет.
- `←`/`→`/`Home`/`End` при фокусе на вкладках до карты сочетаний не доходят.
- Коммиты `1b45e27` (часть 2) и следующий (исправления полосы прокрутки, `tools/shot.ps1`) сделаны и запушены по запросу владельца 2026-11-12.
