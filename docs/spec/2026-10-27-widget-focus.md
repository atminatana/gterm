# ТЗ: фокус, маршрутизация ввода и фреймы в `gterm-widgets` (модель В2+)

- **Идентификатор:** `2026-10-27-widget-focus`
- **Дата:** 2026-10-27; редакция 2 от 2026-10-28 — переписано под модель В2+ (первая редакция описывала В4 — арену с `NodeId`, отклонена владельцем)
- **Статус:** отклонено 2026-10-30 — владелец решил начать вопрос с чистого листа; документ оставлен как история, решения и варианты из него в новом обсуждении не используются. До этого: черновик, ждал утверждения (открытые решения О1–О4 в §6)
- **Постановка владельца (2026-10-27):** фрейм как основа всплывающих окон (`Popup` становится `Frame`), модальные диалоги — фреймы; свойства виджета `focusable` и `focused` (второе — сам виджет или любой вложенный); клавиатура — контролу под фокусом, необработанное сообщение поднимается к родителю вплоть до корня; мышь — самому верхнему контролу под указателем, левая кнопка на `focusable` даёт ему фокус, координаты — в ячейках; `Tab`/`Shift+Tab` по циклу, у вложенных `focusable` фокус уходит с родителя после последнего дочернего; фон фрейма в примере непрозрачный, полупрозрачность показывает тень под окном.
- **Решения владельца по интервью 2026-10-27** (`docs/research/2026-10-27-focus-interview.md`, варианты — `docs/research/2026-10-27-focus-models.md` §4 В2+): (1) модель В2+ — фокус и область в состояниях виджетов, структура экрана один раз методом `tree()`, то же дерево раскладывает, рисует и маршрутизирует; без `Id`, без `Box<dyn>` в хранении, без пересборки состояния; (2) общий `enum Event` крейта с адресацией путём индексов; (3) диалог закрывается событием `Close`; (4) объём — механизм плюс простейшая кнопка; (5) фрейм диалога — буфер наложения с непрозрачным фоном и полупрозрачной тенью, `Popup` заменяется `Frame`; (6) мышь вне модального диалога поглощается; (7) `Tab`/`Shift+Tab` по циклу, координаты мыши в ячейках.
- **Основа:** ADR-0023 (немедленный режим, `Widget`/`StatefulWidget`, `Popup` через наложение), ADR-0004 (`AppHandler`/`Ctx`, типы `winit` не переводятся, `Esc` не перехватывается), ADR-0013/0014 (альфа, `DrawCtx::draw_buffer`), ТЗ §13 (ввод и курсор — на стороне приложения); код `crates/gterm-widgets/src/widgets/{mod,list,table,block,popup}.rs`, `layout.rs`, `examples/widgets.rs` (фокус сейчас — `enum Focus` и `match` в приложении), `crates/gterm/src/app/api.rs` (`PointerEvent::Moved` — физические пиксели, `Input` — без координат, `Ctx` без размера ячейки и модификаторов), `app/events.rs` (`ModifiersChanged` не обрабатывается; `on_key` получает только `Pressed`); `winit 0.30.13` `event.rs:523–640` — у `KeyEvent` есть поле `pub(crate) platform_specific`, сконструировать его вне `winit` нельзя.

## 1. Цель

Приложение на `gterm-widgets` описывает экран один раз — методом `tree()`, возвращающим временное дерево ссылок на свои состояния вместе с виджетами-значениями и раскладкой, — и получает из него отрисовку, обход фокуса по `Tab`, попадание мыши и подъём необработанных сообщений к родителю. Ручной `match focus { … }` из `examples/widgets.rs` исчезает; на этом механизме строятся формы (чекбокс, поле ввода, выпадающий список — отдельные задачи `TODO.md`) и модальные диалоги. Это `view()` из iced без `Id` и без `diff`: дерево держит прямые `&mut` на состояния, сопоставлять нечего, виджеты по-прежнему значения, потребляемые один раз (ADR-0023).

## 2. Границы

**Входит — `crates/gterm-widgets`:**

1. **Сообщения ввода** (новый модуль `input`). `KeyMsg<'a> { key: &'a Key, text: Option<&'a str>, modifiers: ModifiersState }` — строится `KeyMsg::from_event(&KeyEvent, ModifiersState)`; `&KeyEvent` в сообщении не хранится намеренно: его нельзя сконструировать в тестах без окна (см. «Основа»), а `Key`/`NamedKey`/`ModifiersState` — можно. Приходят только нажатия (`events.rs` фильтрует `Pressed`), `repeat` не различается. `MouseMsg { kind: MouseKind, button: MouseButton, col: i32, row: i32, modifiers: ModifiersState }`, `MouseKind::{Down, Up, Move, Wheel { lines: f32 }, Cancel}` — координаты **в ячейках** системы координат дерева (главный экран — сетка; диалог — локальные ячейки фрейма; отрицательные и за краем — вне); `Wheel.lines` — `LineDelta(_, y)` как есть, `PixelDelta` — `y / cell_h`, положительное — вверх (соглашение `winit`); `Cancel` — указатель покинул окно (`PointerEvent::Left`): снимает захват, узлу под захватом приходит как «отпущено без действия». Типы `winit` (`Key`, `ModifiersState`, `MouseButton`) — как у `gterm` (ADR-0004); крейт получает обычную зависимость `winit` с тем же набором фич, что у `gterm` (новых транзитивных зависимостей нет; сейчас она только в `dev-dependencies`). Результат обработки: `Handled::{Yes, No}`; `Event` — одно перечисление крейта, `#[non_exhaustive]`: `Selected(usize)` (выделение в списке/таблице изменилось), `Activated` (кнопка), `Close` (закрыть окно); будущие элементы форм добавляют свои варианты (`Changed` и т. п.). `Response { handled: Handled, event: Option<Event> }`; результат маршрутизации — `Routed { response: Response, path: Path }`, где `Path` — путь индексов детей от корня дерева до узла, который принял сообщение (`[1, 0]` — первый ребёнок второго ребёнка корня; пустой — никто/корень). Путь действителен только для дерева, в котором получен; приложение сверяет его с порядком своего `tree()` либо после сброса дерева читает флаги состояний (`self.ok.node.focused`).
2. **Узел — трейт на состоянии, не на виджете.** Общий блок полей `NodeState { focused: bool, area: Rect, captured: bool }` встраивается полем `pub node: NodeState` в `ListState`, `TableState`, новые `ButtonState` и `GroupState`; трейт `Node` на этих типах: `node()`/`node_mut()` (доступ к блоку), `focusable() -> bool` (по умолчанию `false`), `enabled() -> bool` (по умолчанию `true`; неактивный узел и всё его поддерево фокус и ввод не получают), `wants_tab() -> bool` (по умолчанию `false`; `true` — будущее поле ввода), `on_key(&mut self, &KeyMsg) -> Response` и `on_mouse(&mut self, &MouseMsg) -> Response` (по умолчанию `Handled::No`). Семантика `focused`: у листа — фокус на нём; у группы — фокус на ней самой **или** внутри (свойство `focused` владельца, `Descendant` первой редакции); `area` — область последней раскладки (пишет `Tree::layout`, читает попадание мыши — поэтому мышь маршрутизируется по областям прошлого кадра ещё до новой раскладки); `captured` — захват мыши между `Down` и `Up`.
   - `ListState: Node` — `focusable`; `on_key`: `↑`/`↓`/`Home`/`End`/`PgUp`/`PgDn` меняют выделение (`Handled::Yes` для этих клавиш всегда, `Event::Selected(i)` — только если выделение изменилось); `on_mouse`: левый `Down` по строке пункта — выделение этого пункта (`Selected`), `Wheel` — выделение на `round(lines)` пунктов. Для этого `List::render` записывает в состояние, как сегодня `offset`, число пунктов (`len`) и карту видимых строк `rows: Vec<Option<usize>>` (строка области → индекс пункта; пункты многострочные, иначе клик по строке не сопоставить; вектор переиспользуется между кадрами); `PgUp`/`PgDn` — на высоту карты.
   - `TableState: Node` — то же по строкам таблицы (строка заголовка не выделяется).
   - `ButtonState: Node` — новый; `focusable`; `enabled: bool`; `pressed: bool` (нажата мышью, до `Up`/`Cancel`); `role: ButtonRole::{Plain, Close}` — роль «закрывает окно» (О4): `Enter`/пробел/левый `Down`+`Up` внутри области → `Event::Activated` (`Plain`) или `Event::Close` (`Close`). Виджет `Button<'a>` — `label: Line<'a>` по центру области, `style`, `focus_style`, `pressed_style`, `disabled_style`; `StatefulWidget<State = ButtonState>`.
   - `GroupState: Node` — новый; `focusable: bool` (по умолчанию `false`), `enabled: bool`; `on_key`/`on_mouse` — `Handled::No` (О2); контейнер с собственной обработкой — свой тип состояния с `impl Node`.
   - `Paragraph` и `Block` остаются `Widget` без состояния — в дереве это листы без узла: не фокусируются, ввод не обрабатывают, сообщение мыши по ним уходит родителю.
   - `List`, `Table` и `Block` получают строитель `focus_style(Style)` — стиль, накладываемый на `border_style` рамки, когда узел под фокусом: `List`/`Table` читают `state.node.focused` в `StatefulWidget::render`; у `Block` стиль применяет группа дерева (п. 3), сам `Block::render` не меняется и о фокусе не знает. Без фокуса картинка виджетов не меняется (тесты К2 ADR-0023 остаются).
3. **Дерево `Tree<'a>`** — временная структура, которую приложение строит методом `fn tree(&mut self) -> Tree<'_>` на каждое событие и на каждый кадр; состояния и данные приложения не пересобираются. Конструкторы: `Tree::leaf(state: &'a mut S, widget: W)` при `W: StatefulWidget<State = S>, S: Node`; `Tree::widget(widget: W)` при `W: Widget` — лист без состояния; `Tree::group(state: &'a mut GroupState, layout: Layout, children)` с необязательным `.block(Block<'a>)` — рамка вокруг детей (groupbox из `TODO.md`), дети раскладываются внутри `block.inner(area)`; `Tree::split(layout: Layout, children)` — контейнер без состояния (только раскладка; для фокуса и подъёма прозрачен). Узлы хранятся вектором с индексом родителя в порядке объявления (обход в глубину, родитель раньше детей); элементы — `Box<dyn …>` **только в этом временном векторе** (О1), в состояниях приложения `Box` нет. Методы: `layout(&mut self, area: Rect) -> &mut Self` — раздаёт области (`Layout::split` по ограничениям группы; детей больше, чем ограничений — лишним пустая область: не рисуются, мышь не ловят) и пишет их в `node.area`; `render(self, buf: &mut ScreenBuffer)` — потребляет дерево: группа рисует свой `Block` (со `focus_style`, если `state.node.focused`), затем детей по порядку; лист — `StatefulWidget::render(widget, area, buf, state)`; пустая область пропускается; `focus_first/focus_next/focus_prev/focus_clear`, `focused_path() -> Option<Path>`, `route_key(&mut self, &KeyMsg) -> Routed`, `route_mouse(&mut self, &MouseMsg) -> Routed`. Порядок обхода фокуса, отрисовки и попадания мыши — один по построению. Пока дерево живёт, состояния заняты `&mut`, поэтому порядок в обработчике: `let r = self.tree().route_key(&msg);` (дерево сброшено в конце оператора) → разбор `r` с изменением `self` → `self.tree().layout(area).render(ctx.screen)`. Два построения на событие — норма; стоимость — вектор из десятка узлов.
4. **Обход фокуса.** Кандидаты — узлы с `focusable() && enabled()`, все предки которых `enabled()`; порядок — порядок обхода дерева в глубину: фокусируемая группа раньше своих детей, после последнего дочернего — следующий брат группы (правило владельца «фокус уходит с родителя после последнего дочернего»); `Tab` по циклу, `Shift+Tab` — строго обратный порядок; без кандидатов фокуса нет, `Tab` ничего не делает. Установка фокуса: снять `focused` со всех узлов дерева, поставить на цель и всех её предков. Адресат ввода — самый глубокий узел на цепочке `focused` от корня (спуск в первого ребёнка с `focused`); узлы с `focused` вне этой цепочки (устаревшие флаги) при любом `route_*`/`focus_*` сбрасываются. Состояние с `focused == true`, которого нет в `tree()` (условный виджет), крейт не видит: дерево ведёт себя как без фокуса, флаг у состояния остаётся — задокументировать, тест. Область узла при обходе не учитывается (до первой раскладки все области пусты, а `focus_first` нужен уже в `on_backend_changed`); скрытый раскладкой узел исключается из `tree()` или получает `enabled = false`.
5. **Маршрутизация клавиатуры.** `route_key`: `Tab`/`Shift+Tab` (по `modifiers.shift_key()`) перехватывается деревом до узлов — `focus_next`/`focus_prev` (без фокуса — `focus_first`), `Handled::Yes`, путь — новый фокус; исключение — адресат с `wants_tab()`, ему `Tab` доставляется как обычная клавиша. Остальное — адресату; `Handled::No` — родителю, и так до корня; непринятое корнем возвращается приложению (`Handled::No`, пустой путь). Без фокуса обычные клавиши идут корню (группа — `No`). `Esc` для дерева не особенный (ADR-0004); превращение в `Close` — у `Frame` (п. 7).
6. **Маршрутизация мыши.** `route_mouse`: при захвате (`captured` у какого-то узла) `Move`/`Up`/`Cancel` идут ему, `Up` той же кнопки и `Cancel` снимают захват; иначе адресат — последний в порядке обхода узел, чья `area` содержит `(col, row)` (= верхний при отрисовке; листы без состояния не адресуются — сообщение уходит их родителю); никого — `Handled::No`, пустой путь. Левый `Down` на `focusable && enabled` переводит фокус на узел **до** `on_mouse`; на не фокусируемом — фокус не меняется. `on_mouse` → `Handled::No` → родителю до корня, как клавиатура (О3; нужно для будущих «клик по заголовку группы»). Узел, ответивший `Yes` на `Down`, получает `captured` до `Up` той же кнопки или `Cancel`. Положение указателя между `Moved` и `Input` помнит помощник крейта `Pointer`: `Pointer::translate(&PointerEvent, cell_px, modifiers) -> Option<MouseMsg>` — `Moved` обновляет `(col, row) = (floor(x / cell_w), floor(y / cell_h))` и даёт `Move`, `Input` — `Down`/`Up` в запомненной точке, `Wheel` — `Wheel`, `Left` — `Cancel`.
7. **Фрейм.** `Frame` заменяет `Popup` с тем же API (`new`, `centered`, `style`, `local_area`, `buffer`, `draw`; `tests/popup.rs` переводится на `Frame` без изменения ожидаемых пикселей) плюс: `shadow(Shadow { dx: u16, dy: u16, color: Color })` — буфер наложения больше `area` на `dx × dy`; прямоугольник тени — `(dx, dy, width, height)` в буфере; ячейки тени, не накрытые окном, — `'\0'` с `bg = color` (чёрный с альфой в примере → экран под ними темнеет, ADR-0013/0014); ячейки ни окна, ни тени (угол `[width, width+dx) × [0, dy)` и `[0, dx) × [height, height+dy)`) — прозрачные; тень не входит в `area`, мышь не ловит; `to_local(col, row) -> (i32, i32)` — из ячеек сетки в ячейки буфера; `route_key(&self, tree: &mut Tree, &KeyMsg) -> Routed` — `tree.route_key`, а непринятый деревом `Esc` → `Handled::Yes`, `Event::Close`, пустой путь; `route_mouse(&self, tree: &mut Tree, msg_in_grid_cells) -> Routed` — перевод в локальные ячейки и `tree.route_mouse`; вне окна — `Handled::No` (решение 6: приложение главному дереву ничего не передаёт, диалог остаётся). Главное окно фреймом не является: его дерево рисует прямо в `ctx.screen` в области `Rect::of_screen`. Диалог: дерево диалога строится в `on_redraw` (раскладка в `frame.local_area()`, `render` в `frame.buffer()`, `frame.draw(ctx, &buffer)`) и в `on_key`/`on_pointer` для маршрутизации; фокус главного дерева лежит во флагах его состояний и не трогается, пока диалог открыт — восстанавливать нечего. Выбор дерева — `if let Some(dialog) = &mut self.dialog { … } else { … }` в приложении, отдельный помощник крейта не нужен.
8. **Изменения `gterm`** (минимальные, ADR-0004 соблюдается — типы `winit` не переводятся): `Ctx` получает `modifiers: ModifiersState` (цикл событий обрабатывает `WindowEvent::ModifiersChanged`, хранит состояние в `App`) и `cell_px: (u32, u32)` — размер ячейки в физических пикселях (= `glyph_w × glyph_h` атласа). `PointerEvent`, `Request`, рендереры не меняются.
9. **Пример** `examples/widgets.rs` переводится на `tree()`: `Tree::split` на две колонки; слева `Tree::group(&mut self.left, …).block(Block::bordered().title(" Возможности gterm ").focus_style(…))` со списком (рамка группы подсвечивается, пока фокус внутри); справа `Tree::split` — таблица (`Table::…block(…).focus_style(…)` — подсветка на уровне листа), абзац (`Tree::widget(Paragraph)`), кнопка «Открыть окно» (`Activated` → диалог); строка подсказки. `Tab`/`Shift+Tab` по циклу список → таблица → кнопка; стрелки/`Home`/`End`/`PgUp`/`PgDn`, колесо и клик — в узле под указателем/фокусом; `Esc` на главном экране — выход (непринятый деревом, обрабатывает приложение). `p` и кнопка открывают модальный `Frame` с **непрозрачным** фоном и полупрозрачной тенью (`dx = 2`, `dy = 1`, чёрный с альфой — демонстрация альфы переезжает с фона окна на тень): внутри абзац «Выбрано в списке: …» и кнопка «OK» с ролью `Close`; `Tab` ходит внутри диалога; `Esc`/`OK` дают `Event::Close` — приложение убирает диалог; пока он открыт, главное дерево ввода не получает, клик вне окна поглощается.
10. **Тесты** без окна (чистые функции над деревом из состояний-заглушек, пишущих журнал вызовов, и из настоящих состояний): `tests/focus.rs` — порядок обхода таблицей деревьев, цикл, обратный обход, пропуск не фокусируемых/неактивных поддеревьев, без кандидатов, сброс устаревших флагов, фокус на отсутствующем узле; `tests/route.rs` — подъём клавиши до первого `Yes` и до корня, `Tab` и `wants_tab`, путь; мышь — верхний узел, фокус по левому `Down` до `on_mouse`, не фокусируемый не меняет фокус, захват до `Up`/`Cancel`, подъём, вне всех областей, `Pointer::translate` (пиксели → ячейки, `Left` → `Cancel`); `tests/tree_render.rs` — кадр дерева совпадает с ручным рендером тех же виджетов (узлы ничего не добавляют к картинке), области записаны в состояния, лишние дети пусты, `focus_style` группы и листа только при `focused`; `tests/frame.rs` — `tests/popup.rs` на `Frame` без изменения ожиданий плюс тень (пиксель под тенью — смесь экрана и цвета тени, под окном — цвет фона, углы прозрачны), `to_local`, `Esc` → `Close`, мышь вне окна → `No`; `tests/widgets.rs` — `Button` в трёх состояниях, `ListState`/`TableState`: клавиши, `Selected` только при изменении, `PgUp`/`PgDn` по карте строк, клик по строке многострочного пункта, колесо. `gterm`: `Ctx::modifiers` — сценарий в оконном тесте `stage6_events` (один цикл событий на процесс — только расширением существующего бинарника); `cell_px` — единичный тест.
11. **Документы:** ADR на модель В2+ (после утверждения ТЗ, AR-04), ТЗ 1.21 (§13), `AGENTS.md`, `PROJECT_MAP.md`, `TODO.md` (пункты «мышь» и «комбинации клавиш» закрываются в части маршрутизации и модификаторов; формы, поле ввода и выпадающий список остаются), отчёты `docs/done|test|verify/`; размер release-примера `widgets.exe` — замерить и записать (NFR-1).

**Не входит:**

- элементы форм, кроме кнопки (чекбокс, поле ввода, выпадающий список) — отдельные задачи `TODO.md` на этом механизме;
- карта «сочетание клавиш → действие», акселераторы (`Alt+буква`), `Enter` в группе как «кнопка по умолчанию» (О2) — здесь только модификаторы в сообщении;
- двойной клик, перетаскивание как жест, автоповтор, курсор ввода, IME (`on_text` остаётся приложению);
- перекрывающиеся немодальные окна с переключением по клику, стек из более чем одного диалога (второй диалог — ещё одно дерево и `if let`, механизм тот же, не демонстрируется);
- типизированные по контролу события (В3) и `Id` (В4/В5) — отклонены владельцем;
- изменение рендереров и формата кадра; новые зависимости помимо `winit` в `gterm-widgets`.

## 3. Контракты

- Виджет рисует только внутри своей области (ADR-0023); узел считает попадание только по `node.area`; `focus_*`/`route_*` никогда не ставят фокус на узел с `focusable() == false` или `enabled() == false` (включая неактивного предка); без кандидатов фокуса нет.
- В дереве не более одной цепочки `focused` от корня к адресату; после любого `focus_*`/`route_*` флаги вне цепочки сброшены. Порядок обхода детерминирован и равен порядку объявления в `tree()` в глубину; `focus_prev` — строго обратный `focus_next`; `focus_next` после последнего — первый.
- Сообщение клавиатуры доставляется ровно одному пути «адресат → … → корень» и останавливается на первом `Handled::Yes`; `Tab`/`Shift+Tab` перехватываются деревом, кроме адресата с `wants_tab()`.
- Сообщение мыши доставляется по пути от верхнего узла под указателем (или от узла под захватом); левый `Down` меняет фокус до доставки; захват — у узла, принявшего `Down`, до `Up` той же кнопки или `Cancel`.
- Координаты в `MouseMsg` — ячейки системы координат дерева; перевод из пикселей — `Pointer` по `Ctx::cell_px`, деление с округлением вниз; `Frame::route_mouse` вычитает `area.x`/`area.y`.
- `Tree::render` даёт те же ячейки, что ручной вызов `render` тех же виджетов в тех же областях, плюс `focus_style` на рамках узлов с `focused`; `Tree::layout` даёт те же области, что `Layout::split` группы по `block.inner(area)`.
- `Frame` без тени даёт тот же буфер, что `Popup` сегодня (прозрачная подложка, фон стиля, `'\0'`); с тенью — буфер больше на `dx × dy` с ячейками тени и прозрачными углами по п. 7.
- `gterm` меняется только добавлением `Ctx::modifiers`, `Ctx::cell_px` и обработкой `ModifiersChanged`; рендереры, `PointerEvent`, `Request` не трогаются; NFR-6 не затрагивается — дерево строится в обработчиках событий и в `on_redraw`, не в кадре рендерера.
- Крейт без `unsafe`; MSRV 1.85; `winit` в `gterm-widgets` с теми же фичами, что в `gterm`.

## 5. Риски

- Пока дерево живёт, все состояния заняты `&mut`: приложение не может читать `self.list.selected()` «во время». Смягчение: порядок «route → сбросить дерево → разобрать → tree().layout().render()» закреплён в п. 3 и показан в примере.
- `GroupState` — новое состояние для `Block`, который был `Widget` без состояния. Смягчение: `Block::render` не меняется, рамку группы рисует дерево, передавая стиль фокуса.
- Дерево строится на каждое событие и кадр с `Vec` узлов и `Box` на узел (О1) — выделения в обработчиках; NFR-6 (рендерер) не затронут; размер `widgets.exe` записать (NFR-1).
- `winit` как обычная зависимость `gterm-widgets` — те же фичи, что у `gterm`, новых транзитивных зависимостей нет; замерить размер.
- Карта строк `rows` в `ListState`/`TableState` — состояние растёт на вектор; переиспользуется, после первого кадра выделений нет; клик сопоставляется только с последним кадром (как и области — осознанно).
- `ModifiersState` на Wayland/X11 приходит отдельным событием до клавиши — порядок гарантирует `winit`; при расхождении на платформе владельца — проверка глазами (К9).
- Два стиля в одном крейте — немедленные виджеты (ADR-0023) и дерево узлов — расходятся меньше, чем в первой редакции: виджеты те же, дерево лишь вызывает их `render`; приложение может не использовать дерево вовсе.

## 6. Открытые решения

- **О1. Хранение узлов временного дерева.** (a) **Рекомендуется:** `Vec<Box<dyn Element + 'a>>` — по короткому выделению на узел при построении, зато любой тип состояния приложения с `impl Node` и любой виджет; решение владельца «без `Box<dyn>` в хранении» соблюдено — в состояниях приложения `Box` нет; (b) `enum` вариантов встроенных виджетов (`List`, `Table`, `Button`, `Paragraph`, группа) плюс `Custom(&'a mut dyn Node, …)` — без `Box`, но закрытый набор: новый виджет требует правки крейта; (c) вложенные обобщённые типы/кортежи — это В3, отклонено.
- **О2. Клавиши у группы.** (a) **Рекомендуется:** `GroupState::on_key` — `Handled::No`, своя обработка — свой тип состояния с `impl Node` (допущение интервью); (b) уже в этой задаче `Enter` в группе активирует кнопку по умолчанию — нужно понятие «кнопка по умолчанию», переносится в задачу про формы.
- **О3. Мышь без обработчика.** (a) **Рекомендуется:** подъём к родителю, как у клавиатуры (колесо над абзацем доходит до группы; нужно будущим «клик по заголовку группы», меню); (b) мышь — только верхнему узлу, без подъёма. Сюда же — колесо в списке: (a) **рекомендуется** двигать выделение (смещение и так подгоняется под выделение при `render`), (b) двигать смещение, не трогая выделение — потребует отменить подгонку смещения в `List::render`.
- **О4. Закрытие диалога кнопкой.** (a) **Рекомендуется:** роль `ButtonRole::Close` у состояния кнопки — она сама порождает `Event::Close` (с путём, по которому приложение отличает «OK» от «Отмена»), фрейм добавляет только `Esc` → `Close`; (b) фрейм превращает любой `Activated` в `Close` — любая кнопка диалога закрывает его, не годится для диалогов с действиями; (c) крейт ничего не превращает, приложение само сопоставляет `Activated` и путь — формулировка владельца «фрейм превращает в `Close`» не выполняется.
