# ТЗ: набор виджетов `gterm-widgets` по образцу ratatui

- **Идентификатор:** `2026-10-23-widgets`
- **Дата:** 2026-10-23
- **Статус:** утверждено владельцем 2026-10-23 (О1 — рисовать прямо в `ScreenBuffer`; О2 — жадная раскладка; О3 — сначала `Block`, `Paragraph`, `List`, `Table`, `Popup`, остальное (`Tabs`, `Gauge`, `LineGauge`, `Scrollbar`, `Clear`) — второй задачей; О4 — отдельный крейт `crates/gterm-widgets`). **Часть 2 выполнена 2026-11-12** с отклонением, решённым владельцем (ADR-0032): `Tabs` — контрол с вводом (п. «не входит: обработка ввода внутри виджетов» к нему не применяется), `Scrollbar` — только отображение без `StatefulWidget`; пример — `Gauge` на второй вкладке, внизу `LineGauge`
- **Основа:** исследование `docs/research/2026-10-23-ratatui-backend.md` (архитектура ratatui 0.30 по исходникам: немедленный режим, `Widget::render(self, area, buf)`, `StatefulWidget`, `Layout` с ограничениями, текст `Text → Line → Span`); ТЗ §1 (библиотека для встраивания), §13 (курсор и наложения — на стороне приложения); ADR-0004 (`AppHandler`/`Ctx`), ADR-0013 (цвета с альфой, фон буфера), ADR-0014 (наложение буферов `DrawCtx::draw_buffer`), ADR-0017 (workspace), ADR-0022 (мозаики и фигуры); код `buffer.rs` (`ScreenBuffer`: `set_cell`, `write_row`, `fill_rect`, `clear_region`, `copy_region`, `transparent`, `with_default_colors`), `cell.rs` (`Cell { ch, fg, bg, flags }`, `CellFlags::{BOLD, ITALIC, UNDERLINE}`, `Color` `0xAARRGGBB`).

## 1. Цель

Дать приложениям на `gterm` библиотеку виджетов для построения интерфейсов «как в терминале, но с возможностями `gterm`»: немедленный режим, раскладка по ограничениям, стилизованный текст, рамки из процедурной псевдографики, полупрозрачные всплывающие окна через наложение. Без новых зависимостей и без роста MSRV; `gterm` не меняется, кроме явно перечисленного.

## 2. Границы

**Входит — новый крейт `crates/gterm-widgets`** (зависит только от `gterm`; `winit` не нужен):

1. **Основа.** `Rect { x, y, width, height }` с `inner`/пересечением/обрезкой; `Style { fg: Option<Color>, bg: Option<Color>, add: CellFlags, remove: CellFlags }` с `patch`; `Span`, `Line` (выравнивание), `Text` (строки) — текст в `Cow<str>`, без графем: одна кодовая точка = одна ячейка (модель `gterm`), перенос по символам и пробелам; `Buffer` — **прямо `ScreenBuffer`** с обрезкой по `Rect` (О1): `set(x, y, ch, style)`, `set_string`, `set_style(area)`, `fill(area, ch, style)`.
2. **Трейты.** `Widget { fn render(self, area: Rect, buf: &mut ScreenBuffer) }`, `StatefulWidget { type State; fn render(self, area, buf, state: &mut Self::State) }` — по форме как у ratatui, чтобы структура приложения совпадала.
3. **Раскладка.** `Layout { direction, constraints: [Constraint], spacing, margin }` → `Vec<Rect>`; `Constraint::{Length(u16), Percentage(u16), Min(u16), Max(u16), Fill(u16)}`; жадный алгоритм без солвера (О2): фиксированные → проценты (от всей длины) → `Min`/`Max` как границы → остаток между `Fill` по весам; нехватка — урезаются последние; детерминирован и целочислен.
4. **Виджеты v1** (О3): `Block` (заголовки с выравниванием, рамка `Borders` по сторонам, вид рамки `Single/Double/Heavy/Rounded/None` — процедурная псевдографика, `padding`, стиль рамки и фона); `Paragraph` (текст, перенос `Wrap { trim }`, выравнивание, прокрутка `(x, y)`); `List` + `ListState` (выделение, `offset` с автоподгоном под высоту, стиль и символ выделения); `Table` + `TableState` (ширины колонок через `Constraint`, заголовок, выделение строки, межколоночный зазор); `Tabs` (выделение, разделитель); `Gauge` (доля 0…1, подпись, цвет заливки) и `LineGauge`; `Scrollbar` + `ScrollbarState` (вертикальная/горизонтальная, стрелки, из псевдографики); `Clear`.
5. **Особенности `gterm`:** `Popup` — помощник для всплывающего окна через `DrawCtx::draw_buffer` (буфер `ScreenBuffer::transparent` с виджетом внутри, полупрозрачный фон по альфе — ADR-0014); рамки `Block` в любом из пяти видов стыкуются между соседними блоками; стили принимают цвета с альфой.
6. **Пример** `crates/gterm-widgets/examples/widgets.rs` на системном шрифте (без `assets/`): `Tabs` сверху, слева `List`, справа `Table` и `Paragraph` с переносом, снизу `Gauge`, по клавише — полупрозрачный `Popup`; клавиши `Tab`, стрелки, `Esc`.
7. **Тесты**: единичные — рендер каждого виджета в `ScreenBuffer` и сравнение с ожидаемым текстом строк (как `TestBackend` в ratatui) плюс стили в контрольных ячейках; раскладка — таблица случаев (нехватка места, `Fill` веса, `Min`/`Max`); перенос текста; `Popup` — альфа в наложении через существующий `tests/overlay.rs`-подход.
8. **Документы**: ADR на архитектуру крейта, ТЗ 1.19 (§1, §5.1, §13), `AGENTS.md`, `PROJECT_MAP.md`, `TODO.md`, отчёты.

**Не входит:**
- слой совместимости с ratatui, типы crossterm, второй поток (исследование — другой путь);
- обработка ввода внутри виджетов (как и в ratatui: состояние меняет приложение в `on_key`), фокус, формы ввода;
- `Chart`, `BarChart`, `Sparkline`, `Canvas`, `Calendar` — v2 (на мозаиках ADR-0022, отдельное ТЗ);
- графемы и двухшириные символы, перенос по Unicode-правилам, двунаправленный текст;
- изменения `gterm` (ни API, ни рендера); если в ходе работы потребуется — отдельным решением.

## 3. Контракты

- Виджет рисует только внутри `area` и только через `ScreenBuffer` — ячейки вне `area` не меняются (тест).
- Рендер не выделяет память в горячем пути отрисовки кадра `gterm` (виджеты работают до рендера, в `on_redraw`/обработчиках; их собственные выделения — обычная работа приложения, NFR-6 не про них).
- Раскладка детерминирована: одинаковые входы — одинаковые `Rect`, сумма длин ≤ доступной, без отрицательных размеров.
- Крейт не содержит `unsafe`, зависит только от `gterm`, MSRV 1.85, `default-features = false` не требуется (нет фич).
- API по форме повторяет ratatui (имена трейтов, `Layout`/`Constraint`, `Span/Line/Text`, `*State`), но не обещает совместимости типов.

## 4. Критерии приёмки

| № | Критерий | Чем подтверждается |
|---|---|---|
| К1 | `gterm` не изменён; `cargo test` в корне гоняет оба пакета и новый | `git diff crates/gterm` пуст; прогон |
| К2 | Каждый виджет v1 рендерится в ожидаемый текст и стили, не выходит за `area` | тесты по виджетам (`Block` — пять видов рамок, заголовки; `Paragraph` — перенос и прокрутка; `List`/`Table` — выделение и смещение; `Tabs`, `Gauge`, `LineGauge`, `Scrollbar`, `Clear`) |
| К3 | Раскладка: таблица случаев, в том числе нехватка места и `Fill` по весам | тесты |
| К4 | `Popup` рисует полупрозрачное окно поверх через наложение | тест с `Overlay`/`SoftBackend` по образцу `tests/overlay.rs` |
| К5 | Пример: экран из §2 п.6 на трёх бэкендах; глазами | запуск с `--backend=soft --fail-frames=2`; владелец |
| К6 | Гейты, размер примера, документы | fmt, clippy `--all-targets -D warnings`, test; размеры release; ADR, ТЗ 1.19, карта, `AGENTS.md`, `TODO.md` |

## 5. Риски

- Объём: по оценке исследования 2 500–3 500 строк с тестами — крупнейшая задача проекта; план делится на шаги по виджетам с проверкой каждого (QG-03).
- Жадная раскладка ведёт себя иначе, чем солвер ratatui на противоречивых ограничениях (например, `Percentage` сверх 100 %); правило урезания фиксируется в тестах.
- Перенос по символам без графем: комбинируемые знаки занимают ячейку — ограничение модели `gterm`, не крейта.

## 6. Открытые решения

- **О1. Буфер виджетов.** Рисовать прямо в `ScreenBuffer` (рекомендуется: нет второго буфера и копирования, dirty-строки `gterm` работают как есть) или свой `Buffer` с диффом, как у ratatui (копирование и дифф уже делает `gterm`).
- **О2. Раскладка.** Жадный алгоритм (рекомендуется: без зависимостей, детерминирован, ≈150 строк) или солвер ограничений (как `kasuari` в ratatui — новая зависимость либо ≈1 000 строк своего).
- **О3. Состав v1.** Перечень п.4 (`Block`, `Paragraph`, `List`, `Table`, `Tabs`, `Gauge`, `LineGauge`, `Scrollbar`, `Clear`, `Popup`) — либо сократить до `Block`/`Paragraph`/`List`/`Table`/`Popup` на первый шаг и остальное второй задачей.
- **О4. Имя и место.** `crates/gterm-widgets` (рекомендуется, по аналогии с `gterm-demo`), либо модуль внутри `gterm` за фичей `widgets` (растит библиотеку и её тесты; не рекомендуется).
