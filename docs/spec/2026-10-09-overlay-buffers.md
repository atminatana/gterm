# Дополнение к ТЗ: наложение клиентских буферов поверх экрана

- **Идентификатор:** `2026-10-09-overlay-buffers`
- **Дата:** 2026-10-09
- **Статус:** утверждено владельцем 2026-10-09 (Н1 — а, Н2 — отдельный бинарник `overlay`)
- **Зависит от:** `docs/spec/2026-10-09-color-alpha.md` — без альфы в ячейке клиентский буфер не может быть прозрачным. Реализация начинается после завершения задачи про альфу.
- **Основное ТЗ:** `docs/TZ_terminal_emulator.md`. После реализации меняются FR-12, FR-25, §5.2, §5.3, §7, §8.
- **Решения владельца (2026-10-09):**
  - буфер хранится у клиента;
  - отрисовку даёт контекст при `RedrawRequested`;
  - клиент рисует свой буфер в текстуру, текстура накладывается поверх основного буфера;
  - текстура очищается каждый кадр;
  - координаты в ячейках сетки, всё за пределами сетки обрезается.

## 1. Цель

Клиентская программа собирает многослойный и многоцветный символ из нескольких своих `ScreenBuffer`. Каждый кадр она рисует их поверх основного экрана. Результат GL и Software совпадает бит в бит.

## 2. Границы

**Входит:**
- новый метод `AppHandler::on_redraw` и тип `DrawCtx` с вызовом `draw_buffer`;
- текстура наложения в обоих бэкендах и её наложение на кадр;
- частичный кадр Software с учётом наложения;
- тесты, сравнение GL ↔ Software, замер `--bench`, отдельный бинарник-пример `overlay`.

**Не входит:**
- смещения в пикселях;
- наложение на поле вокруг сетки;
- наложение, которое живёт дольше одного кадра;
- масштаб и поворот клиентского буфера;
- прозрачность окна.

## 3. Контракты

### 3.1. API

```rust
pub trait AppHandler {
    // ...существующие методы...
    /// Вызывается на каждом `RedrawRequested` до отрисовки кадра. Текстура наложения уже пуста.
    fn on_redraw(&mut self, _ctx: &mut DrawCtx<'_>) {}
}

pub struct DrawCtx<'a> { /* закрыто */ }

impl DrawCtx<'_> {
    /// Нарисовать `buffer` поверх уже нарисованного в текстуре наложения; левый верхний угол —
    /// ячейка `(col, row)` основной сетки (может быть отрицательной). Обрезка — по сетке.
    pub fn draw_buffer(&mut self, buffer: &ScreenBuffer, col: i32, row: i32);
    /// Сетка основного буфера — для расчёта позиции.
    pub fn grid(&self) -> Grid;
}
```

- `DrawCtx` существует только внутри `on_redraw`, поэтому вызвать отрисовку вне кадра нельзя: это не скомпилируется.
- Порядок вызовов `draw_buffer` задаёт порядок слоёв: позже вызванный буфер лежит выше.
- Клиентский буфер может быть любого размера `cols × rows`.
- Фон клиентского буфера (`background`, задача про альфу) при наложении не учитывается.
- `draw_buffer` не возвращает ошибку. Ошибка рендера идёт общим путём: повтор кадра, затем откат (§5.3 п.5).

### 3.2. Кадр

1. Текстура наложения размером с сетку очищается до `0x00000000`.
2. Вызывается `on_redraw`. Вызовы `draw_buffer` библиотека только записывает в список.
3. Глифы основного буфера и всех записанных буферов готовятся в атласе за один проход. Если страница сбрасывается, проход повторяется для всех.
4. Рисуется основной буфер — как сейчас, с альфой по задаче про альфу.
5. Записанные буферы по порядку рисуются в текстуру наложения. Подложка — то, что в текстуре уже есть.
6. Текстура накладывается на кадр: `out = blend(кадр, T.rgb, T.a)`.

### 3.3. Формулы (целочисленные, одинаковые в GL и Software)

*(Исправлено по решению О2 — а, 2026-10-09: формат — **предумноженная** альфа, формулы — план `docs/plans/2026-10-09-overlay-buffers.md`, решение 3, и ADR-0014. Ниже — исходная редакция с прямой альфой, она не реализована.)*

Отрисовка ячейки клиентского буфера в текстуру `T` в формате «прямая альфа» (straight alpha) — порядок операций и округление фиксируются в плане:

```
// слой L = (rgb, a) поверх T = (rgb, a):
a_out   = a_L + (a_T · (255 − a_L) + 127) / 255
rgb_out = a_out == 0 ? 0 : (rgb_L · a_L · 255 + rgb_T · a_T · (255 − a_L) + …) / (a_out · 255)
```

Ячейка накладывается в два шага: сначала её фон (`bg`, `α_bg`), затем символ (`fg`, `покрытие · α_fg`); `BOLD` осветляет только RGB. Вне сетки текстура не пишется.

**Двухшаговое округление.** Результат наложения может отличаться на ±1 в канале от тех же ячеек, лежащих прямо в основном буфере. Эталон — двухшаговая формула, общая для обоих бэкендов.

### 3.4. GL

- Текстура наложения — FBO с целочисленным форматом `RGBA8UI`: значения передаются точно.
- Клиентский буфер загружается в отдельную текстуру данных. Её размер растёт по необходимости и не превышает `GL_MAX_TEXTURE_SIZE`; если буфер больше, это `RenderError`.
- *(Исправлено по решению О3 — а: отдельного прохода наложения на кадр нет — текстуру накладывает основной проход последним шагом; порядок — сначала проходы записей, затем основной.)*
- Проходы (исходная редакция):
  - основной проход;
  - по одному проходу на каждый `draw_buffer` в FBO наложения — смешивание в шейдере, ping-pong двух FBO либо `texelFetch` текущего результата из второй текстуры (выбор — в плане);
  - проход наложения на кадр.
- Аппаратное смешивание GL (`glBlendFunc`) не используется.
- Без вызовов `draw_buffer` проходов наложения нет: кадр рисуется одним draw call, как сейчас.

### 3.5. Software

- Текстура наложения — `Vec<u32>` размером с сетку в пикселях, в формате `0xAARRGGBB`. Выделяется заранее и переиспользуется (NFR-6).
- Перерисовываются строки сетки, которые:
  - dirty в основном буфере;
  - покрыты наложением в этом кадре;
  - были покрыты наложением в прошлом кадре.

  Остальные строки не перерисовываются (ADR-0010).

## 4. Требования (изменения основного ТЗ)

- **FR-12 (новая редакция).** Без наложения — один draw call. С наложением — основной проход, по проходу на каждый `draw_buffer` и проход наложения.
- **FR-25.1 (новое).** `AppHandler::on_redraw` и `DrawCtx::draw_buffer` — по §3.1.
- NFR-5 и NFR-6, бит-идентичность GL ↔ Software и инвариант «частичный кадр = кадр с нуля» сохраняются.

## 5. Критерии приёмки

1. Без вызовов `draw_buffer` кадр побайтно равен кадру без этой задачи: golden-эталоны не меняются.
2. Пиксельные тесты Software:
   - один буфер с прозрачными и полупрозрачными ячейками;
   - два буфера друг над другом;
   - отрицательная позиция;
   - буфер, выходящий за сетку (обрезка);
   - пустой буфер (кадр не меняется).
3. Частичный кадр Software:
   - наложение появилось, сдвинулось, исчезло — кадр равен кадру с нуля;
   - строки, которые наложение не задело, не перерисованы.
4. `tests/stage4_gl.rs`: сцена с двумя буферами наложения, GL ↔ Software с допуском 0 на GL 3.3 и GLES 3.0.
5. Сброс страницы атласа во время подготовки глифов основного и клиентских буферов не портит кадр.
6. Оконный тест: `on_redraw` приходит на каждом кадре, вызов `draw_buffer` попадает в кадр.
7. `--bench` Software с одним буфером наложения на весь экран — замер записан, NFR-5 проверен.
8. Гейты чистые, размер release замерен; ADR и основное ТЗ обновлены.
9. Глазами на машине владельца: `cargo run --bin overlay` — многоцветный символ, рамка, обрезка и сдвиг на GL 3.3, GLES 3.0 и Software.

## 6. Решения владельца (были открытыми)

Приняты 2026-10-09:
- **Н1 — а:** отдельный проход на каждый буфер, ping-pong двух FBO.
- **Н2 — отдельный пример:** не строка в `demo`, а свой бинарник `overlay` (`src/bin/overlay/main.rs`, `cargo run --bin overlay`). Общая обвязка — `src/bin/demo/common.rs` через `#[path]`, как у `full_table`. Пример показывает:
  - многоцветный символ из нескольких клиентских буферов: глиф, подчёркивание и подсветка разных цветов;
  - полупрозрачную рамку поверх текста;
  - буфер, выходящий за сетку (обрезка);
  - сдвиг буфера клавишами — проверка частичного кадра;
  - клавиши FR-28.
