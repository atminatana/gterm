# ТЗ: основа, тона и вывод недостающих областей темы; темы sniffnet

- **Идентификатор:** `2026-11-23-theme-roles`
- **Дата:** 2026-11-23
- **Статус:** утверждено владельцем 2026-11-23: О6 — (c), имена `ui.control*` (ответ на прямой вопрос); О1–О5 — рекомендованные варианты (a). Вторая редакция — по замечанию владельца «придумать названия элементам, создаваемым из основных цветов, чтобы была возможность корректировки или полного ручного описания темы». План — `docs/plans/2026-11-23-theme-roles.md`, решения — ADR-0038. Уточнения при планировании помечены в тексте.
- **Постановка владельца (2026-11-23):** «Формат темы helix оставить. Это база, которую может взять любое приложение и доработать до своих потребностей. Вариант 1 — да, берём из темы роли, недостающее создаётся на основе этих ролей. Добавить в проект к двум темам темы из sniffnet.»
- **Основа.**
  - ADR-0037 и поправка 2026-11-23: `Theme` — области «имя → `Style`» формата helix; области своей раскраски знает виджет; если своей области нет, виджет идёт по запасной цепочке областей helix (`ui.button` → `ui.menu` и т. п., таблица в п. 7 ADR).
  - Наблюдение на примере `theme` (`docs/done/2026-11-23-theme-viewer.md`): областей элементов форм в темах helix нет, запасные цепочки дают неразличимые и малоконтрастные состояния (выделенная строка в `gruvbox`, флажок под фокусом, кнопка в `base16_terminal`).
  - Разбор sniffnet 1.6.0 (коммит `247b75b`, лицензия `MIT OR Apache-2.0`): тема — шесть цветов (`primary`, `secondary`, `outgoing`, `text_body`, `text_headers`, `starred`); остальное выводится формулами — тёмная тема по сумме каналов фона, цвет кнопок = фон ± 0,15, состояния — смешение двух цветов и альфа (`src/gui/styles/types/palette.rs:65-106`, `button.rs`, `text_input.rs`). Файлов тем — 10 (`resources/themes/*.toml`), встроенных в код — 12 (`src/gui/styles/custom_themes/`: a11y, dracula, gruvbox, nord, solarized, yeti — тёмная и светлая).

## 1. Цель

Тема формата helix, в которой заданы только базовые цвета, даёт полный и контрастный вид всех контролов `gterm-widgets`: недостающие области виджетов выводятся из ролей темы. Область, заданная в файле явно, по-прежнему сильнее — приложение дорабатывает тему под себя точечно. В репозитории рядом с `gterm_dark` и `gterm_light` лежат темы sniffnet в формате helix.

## 2. Границы

**Входит — `crates/gterm-widgets`:**

Тема описывается на трёх уровнях, и у каждого элемента каждого уровня есть имя — область формата helix. Что задано в файле, берётся как есть; чего нет — выводится из уровня выше. Отсюда три способа работы с темой: задать только основу; поправить один тон (изменятся все виджеты, которые на него ссылаются); описать тему вручную целиком — все тона или все области виджетов.

1. **Уровень 1 — основа.** Обязательны две области; без любой из них вывода нет и тема ведёт себя как сейчас.

   | Область | Смысл | Если не задана |
   |---|---|---|
   | `ui.background` (`bg`) | фон экрана | вывода нет |
   | `ui.text` (`fg`) | текст на фоне | вывода нет |
   | `ui.accent` (`{ fg, bg }`) — новая | акцент и текст на нём | `bg` ← `fg` из `ui.text.focus` → `bg` из `ui.selection` → цвет текста; `fg` ← фон |
   | `error` (`fg`) | ошибка, тревога | `diagnostic.error` → красный по светлоте темы (как в sniffnet) |

2. **Уровень 2 — тона.** Именованные стили, которые выводятся из основы и на которые ссылаются виджеты. Имена helix использованы там, где смысл совпадает; новые — `ui.control*` (О6). Арифметика целочисленная: тема тёмная, если сумма каналов фона ≤ 382; `сдвиг` — каждый канал фона на 38 вверх для тёмной темы и вниз для светлой, с насыщением; `смесь(a, b, k/n)` — поканальная, с округлением.

   | Тон | Смысл | Вывод, если не задан |
   |---|---|---|
   | `ui.text.inactive` | приглушённый текст | `fg` из `ui.virtual`, иначе `смесь(текст, фон, 1/2)` |
   | `ui.text.focus` | текст под фокусом, акцент цветом символа | `fg` = акцент |
   | `ui.window` | рамка | `fg` = `fg` тона `ui.text.inactive` |
   | `ui.window.focus` | рамка под фокусом | `fg` = акцент |
   | `ui.popup` | фон окна, слоя | `bg` = `смесь(фон, сдвиг, 1/2)` |
   | `ui.selection` | выделенное: строка списка, таблицы | `fg` = текст, `bg` = `смесь(фон, акцент, 1/3)` |
   | `ui.control` — новый | элемент управления: кнопка, поле | `fg` = текст, `bg` = `сдвиг` |
   | `ui.control.focus` — новый | элемент под фокусом ввода | `fg` = текст, `bg` = `смесь(сдвиг, акцент, 1/4)` |
   | `ui.control.pressed` — новый | нажатый элемент | `fg` = текст, `bg` = `смесь(сдвиг, акцент, 1/2)` |
   | `ui.control.disabled` — новый | неактивный элемент | `fg` = `fg` тона `ui.text.inactive`, `bg` = `смесь(фон, сдвиг, 1/2)` |

   Коэффициенты — начальные; подбираются по снимкам примера `theme` на тёмных и светлых темах и фиксируются в ADR. Жирное начертание в выводимых стилях не используется (`BOLD` осветляет цвет, ADR-0003).
3. **Уровень 3 — области виджетов.** Формул здесь нет: недостающая область — ссылка на тон или на основу. Существующая область не трогается.

   | Область виджета | Если не задана — берётся |
   |---|---|
   | `ui.button` | `ui.control` |
   | `ui.button.focus` | `ui.accent` |
   | `ui.button.pressed` | `ui.control.pressed` |
   | `ui.button.disabled` | `ui.control.disabled` |
   | `ui.checkbox.focus`, `ui.tabs.focus` | `ui.text.focus` |
   | `ui.checkbox.pressed` | `ui.selection` |
   | `ui.input` | `ui.control` |
   | `ui.input.focus` | `ui.control.focus` |
   | `ui.input.selection` | `ui.selection` |
   | `ui.input.placeholder`, `ui.checkbox.disabled` | `ui.text.inactive` |
   | `ui.list.selected`, `ui.table.selected` | `ui.selection` |
   | `ui.combo`, `ui.combo.focus`, `ui.combo.selected` | `ui.input`, `ui.input.focus`, `ui.list.selected` — заданные или выведенные |
   | `ui.table.header`, `ui.tabs.selected` | `fg` из `ui.text.focus` |
   | `ui.scrollbar`, `ui.gauge.unfilled` | `fg` из `ui.window` |
   | `ui.scrollbar.thumb` | `fg` из `ui.text.focus` |
   | `ui.gauge.filled` | `fg` = акцент, `bg` из `ui.control` |

   *Уточнение при планировании (2026-11-23).* Пять ссылок отличаются от первой редакции таблицы: `ui.checkbox.focus` и `ui.tabs.focus` берут `ui.text.focus` целиком, `ui.input.selection` — `ui.selection`, `ui.combo*` — области поля и списка, `ui.checkbox.disabled` и `ui.input.placeholder` — `ui.text.inactive` целиком. Это действующие цепочки ADR-0037: `gterm_dark`, `gterm_light` и встроенная тема этих областей не задают, и с другими ссылками их вид изменился бы — вопреки контракту раздела 3 (О5).
   Тона `ui.control.focus`, `ui.control.pressed`, `ui.control.disabled` считаются от фона тона `ui.control` — заданного или выведенного: поправка `ui.control` в файле доходит и до его состояний.

4. **Место вывода в порядке поиска стиля** (О2): явный стиль виджета → своя область из файла → выведенная из тонов и основы → прежняя запасная цепочка helix (остаётся только для темы без основы).
5. **API** (О3): вывод выполняется при загрузке (`Theme::load`, `Theme::from_toml_str`), во встроенной теме `Theme::default()` и по вызову `Theme::derive()` для темы, собранной в коде; `Theme::is_derived(scope) -> bool` — область создана выводом, а не задана. Отдельного типа ролей нет: основа и тона — обычные области, читаются `get` / `style`. Выведенные области видны в `scopes()` и читаются `get` / `style` / `first` как обычные — приложение со своими виджетами пользуется ими так же.
6. **Темы sniffnet** (О4): файлы формата helix в `crates/gterm-widgets/examples/themes/` — палитра из шести цветов sniffnet и области основы (`ui.background`, `ui.text`, `ui.accent`), без тонов и областей виджетов: остальное выводится. Рядом — `README.md` с источником (репозиторий, коммит) и лицензией.
7. **Пример `theme`:** в списке элементов темы выведенные области помечены; в статусе — число заданных и выведенных. Пример `widget_edit` не меняется (перечень тем у него — каталог `examples/themes/`, новые темы появятся сами).
8. **Тесты без окна:** основа (запасные ступени акцента, отсутствие `ui.background` или `ui.text`); формулы тонов — значения, посчитанные вручную, для тёмной и светлой темы; заданный тон меняет все области виджетов, которые на него ссылаются; заданная область виджета сильнее тона; тема, описанная вручную целиком (все тона заданы), не получает ни одного выведенного цвета; тема без основы красится как раньше; все темы `examples/themes/` загружаются без предупреждений, у каждой выводятся все области таблицы; снимки ячеек кнопки, поля и списка на теме из одних ролей. Тест на каталоге helix (`GTERM_HELIX_THEMES`) остаётся зелёным.

**Документы:** ADR-0038 (после утверждения), ТЗ проекта (версия 1.31, §13), `AGENTS.md`, `PROJECT_MAP.md`, оба README, `TODO.md`, план и отчёты `plans` / `done` / `test` / `verify`, размеры release.

**Не входит:**

- смена формата файла темы, отказ от областей helix, роли приложения sniffnet (`outgoing`, `starred`) как роли библиотеки — они остаются цветами палитры, доступными через `Theme::color`;
- проверка и исправление контраста выведенных пар автоматически;
- отключаемое осветление `BOLD` (отдельное решение владельца, `TODO.md`);
- перевод `widget_edit` на `Theme::list`, темы helix в репозитории, слежение за файлом темы;
- градиенты, скругления, тени sniffnet — сетка ячеек их не отображает.

## 3. Контракты

- Формат файла темы не меняется: любой файл helix загружается как раньше, ошибок и предупреждений не прибавляется.
- Область, заданная в файле или через `Theme::set`, никогда не заменяется выведенной.
- Тема без `ui.background` или `ui.text` (и `Theme::new`) ведёт себя в точности как до задачи.
- `Theme::default()`, `gterm_dark`, `gterm_light` выглядят как сейчас (О5).
- Вывод детерминирован и не зависит от порядка областей в файле; арифметика целочисленная.
- Правка основы или тона через `set` после вывода выведенные области не пересчитывает — пересчёт по вызову `derive()` (как `reversed` в ADR-0037).
- `gterm` не меняется.

## 4. Критерии приёмки

| № | Критерий | Чем подтверждается |
|---|---|---|
| К1 | Основа по п. 1: запасные ступени акцента; без `ui.background` или `ui.text` вывода нет | тесты без окна |
| К2 | Тона по формулам п. 2 для тёмной и светлой темы; заданный тон не заменяется | тесты со значениями, посчитанными вручную |
| К3 | Области виджетов по ссылкам п. 3; правка одного тона в файле меняет все ссылающиеся области; заданная область виджета не заменяется; `is_derived` верен | тесты без окна |
| К3а | Ручное описание: тема со всеми тонами (или всеми областями виджетов) в файле не содержит выведенных цветов | тест без окна |
| К4 | Порядок п. 4: явный стиль → область файла → выведенная → прежняя цепочка (только без основы) | тесты по снимкам ячеек |
| К5 | Тема без основы и существующие тесты тем — без изменений поведения, кроме тестов, закреплявших запасные цепочки для тем с основой (правятся явно, перечень — в отчёте) | полный прогон |

| К7 | Пример `theme` помечает выведенные области; вид проверен по снимкам на темах sniffnet (тёмной и светлой), `gterm_dark`, двух темах helix | снимки окна |

## 5. Открытые решения

**О1. Откуда берётся акцент.** В helix нет области «акцент и текст на нём».
- (a) **рекомендуется:** новая область `ui.accent` = `{ fg, bg }`, затем `fg` из `ui.text.focus`, затем `bg` из `ui.selection`, затем цвет текста. Свои темы и темы sniffnet задают `ui.accent`; темы helix получают акцент по запасным ступеням. Известный предел: в теме helix, где `ui.text.focus` совпадает с `ui.text` (`gruvbox`), акцент равен цвету текста — состояния различимы по фону, но не цветом; лечится строкой `ui.accent` в файле темы.
- (b) роли — имена палитры (`[palette] accent = …`): файл sniffnet почти не меняется, но палитры тем helix уже используют произвольные имена (`text`, `accent`), и совпадение даст чужой цвет.

**О2. Что сильнее для темы helix: вывод из основы или прежние цепочки областей helix.**
- (a) **рекомендуется:** вывод. Кнопка в теме helix перестаёт брать `ui.menu`, а берёт тон `ui.control`, выведенный из фона и текста, — состояния становятся различимыми; вид тем helix в `widget_edit` и `theme` изменится (в этом цель задачи). Прежние цепочки остаются только для тем без основы.
- (b) прежние цепочки сильнее, вывод — последним: темы helix выглядят как сейчас, вывод работает лишь там, где цепочка пуста; найденная проблема для большинства тем helix остаётся.

**О3. Когда выполняется вывод.**
- (a) **рекомендуется:** при загрузке (и по `derive()`), выведенные области хранятся в теме с пометкой. Одна таблица в одном месте, просмотрщик показывает результат, приложение читает выведенные области по имени.
- (b) в момент обращения, внутри каждого виджета: тема не растёт, но правила расходятся по файлам виджетов, а просмотрщик и свои виджеты приложения выведенного не видят.

**О4. Какие темы sniffnet и под какими именами.**
- (a) **рекомендуется:** все 22 (10 файлов и 12 встроенных), имена с префиксом — `sniffnet_catppuccin`, `sniffnet_dracula_dark`, … Префикс нужен: `catppuccin`, `dracula`, `gruvbox`, `nord`, `solarized` есть и среди тем helix, а при двух каталогах в перечне одноимённые темы сливаются в одну.
- (b) только 10 файлов из `resources/themes/`;
- (c) без префикса.

**О5. Свои темы и встроенная.**
- (a) **рекомендуется:** `Theme::default()`, `gterm_dark`, `gterm_light` оставить как есть — образцы явных областей; `ui.accent` в них добавить, чтобы свои виджеты приложений могли читать роли.
- (b) убрать из них области виджетов и перейти на вывод: файлы короче, но вид трёх тем изменится и пропадёт образец точечной настройки.

**О6. Имена новых областей (постановка владельца 2026-11-23: у выводимых элементов должны быть имена — для корректировки и для полного ручного описания темы).**
- (a) **рекомендуется:** в пространстве `ui.`, как уже названы области виджетов (ADR-0037): `ui.accent`, `ui.control`, `ui.control.focus`, `ui.control.pressed`, `ui.control.disabled`; остальные тона — существующие имена helix (`ui.text.inactive`, `ui.text.focus`, `ui.window`, `ui.window.focus`, `ui.popup`, `ui.selection`). Автору темы helix знакома половина имён, файл остаётся однородным.
- (b) свой префикс для всего нового (`gterm.accent`, `gterm.surface.*`): исключает совпадение с будущими областями helix, но тема делится на два пространства имён, а области виджетов (`ui.button` и др.) уже лежат в `ui.`.
- (c) другое слово вместо `surface` — например `ui.control`, `ui.control.focus`, `ui.control.pressed`, `ui.control.disabled`: ближе к «элементу управления», но тон используется и не только контролами (заливка индикатора).
