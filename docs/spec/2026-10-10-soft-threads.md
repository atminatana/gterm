# ТЗ: многопоточная отрисовка Software-рендерера

- **Идентификатор:** `2026-10-10-soft-threads`
- **Дата:** 2026-10-10
- **Статус:** утверждено владельцем 2026-10-10 (О1 — `rayon`, О2 — не больше 4 потоков, О3 — делать сейчас)
- **Основа:** исследование 2026-10-10 (прототип в копии крейта): `thread::scope` 2 / 4 / 6 / 12 потоков — 143 / 231 / 262 / 293 FPS с наложением против 71 на одном потоке; `rayon` 4 потока — 243 FPS, 0 выделений памяти за 20 кадров, +25,6 КБ к `demo.exe`; `thread::scope` — 13 выделений на кадр (нарушает NFR-6).

## 1. Цель

Ускорить кадр Software на многоядерных машинах, сохранив бит-идентичность с GL и golden, NFR-6 (нет выделений в кадре) и NFR-9 (нет `unsafe` вне `gl_backend.rs`).

## 2. Границы

**Входит:**
- постоянный пул потоков `rayon` в `SoftBackend`, число потоков `min(available_parallelism, 4)`;
- параллельно по полосам строк сетки: основной слой с наложением текстуры и сборка текстуры наложения;
- малые кадры (мало строк к перерисовке) — в текущем потоке;
- одна реализация отрисовки полосы для однопоточного и многопоточного пути;
- тесты, замеры, размер бинарника, ADR-0016.

**Не входит:**
- флаг или переменная окружения для числа потоков;
- параллельная подготовка глифов (`Atlas::ensure` меняет атлас) и вывод в окно (`softbuffer`);
- GL-бэкенд.

## 3. Контракты

- Публичный API `App`/`AppHandler` не меняется. `SoftBackend::with_threads(atlas, n)` — конструктор с заданным числом потоков (тесты, замеры); `SoftBackend::new` — по умолчанию.
- Кадр при любом числе потоков бит в бит равен однопоточному.
- Не удалось создать пул — отрисовка в текущем потоке, без паники (NFR-7), причина — в stderr.
- После первого кадра выделений памяти в кадре нет (NFR-6).

## 4. Критерии приёмки

| № | Критерий | Чем подтверждается |
|---|---|---|
| К1 | Кадр не зависит от числа потоков | тест: 1 и 4 потока на сценах с наложением, частичными кадрами, окном больше сетки — кадры равны; golden, `stage4_gl`, `tests/overlay.rs` зелёные без правки эталонов |
| К2 | Нет выделений в кадре | тест со счётчиком выделений (`#[global_allocator]` в отдельном тест-бинарнике): 0 выделений за серию кадров на 1 и 4 потоках |
| К3 | Ускорение | `--bench --backend=soft` с наложением и без — замер в отчёте; на 4 потоках быстрее однопоточного |
| К4 | Малые кадры не медленнее | замер кадра с одной изменённой строкой: не хуже, чем до задачи |
| К5 | Однопоточный путь не медленнее, чем до задачи | `with_threads(…, 1)` в `--bench` (временно, в копии) или эквивалентный замер |
| К6 | Гейты, размер бинарника (NFR-1), ADR-0016, зависимость в `Cargo.lock` | fmt, clippy `--all-targets -D warnings`, test; отчёт |
