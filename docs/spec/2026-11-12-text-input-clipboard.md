## 1. Цель

В поле ввода можно выделить часть текста клавиатурой и мышью, скопировать, вырезать и вставить через системный буфер обмена стандартными сочетаниями, не зависящими от раскладки. Поле поглощает эти сочетания — до карты сочетаний и приложения они не доходят.

## 2. Границы

**Входит — `crates/gterm-widgets`:**

1. **Выделение в состоянии.** `TextInputState` получает якорь выделения (позиция в символах); выделение — промежуток между якорем и курсором, пустое — когда якоря нет или он равен курсору. Методы: `selection() -> Option<(usize, usize)>` (начало, конец), `selected_text() -> &str`, `select_all()`, `clear_selection()`, `delete_selection()`.
2. **Клавиатура:**
   - `Shift+←/→`, `Shift+Home/End` — расширяют выделение от якоря;
   - `←/→/Home/End` без `Shift` — снимают выделение; `←` ставит курсор в начало выделения, `→` — в конец;
   - `Ctrl+A` — выделить всё;
   - набор текста, вставка, `Backspace`, `Delete` при непустом выделении — заменяют или удаляют выделенное (одно событие `Changed`);
   - `Enter` выделение не трогает.
3. **Мышь:** левое нажатие ставит курсор и якорь; движение при удержанной кнопке (захват уже есть, ADR-0026) расширяет выделение, указатель левее или правее поля прокручивает текст; `Shift` + нажатие расширяет выделение от прежнего якоря.
4. **Отрисовка:** выделенные ячейки — стиль `TextInput::selection_style` (по умолчанию обмен fg/bg); выделение и курсор видны только под фокусом; при непустом выделении отдельная ячейка курсора не рисуется.
5. **Буфер обмена — трейт `Clipboard`** (`src/clipboard.rs`): `get(&mut self) -> Option<String>`, `set(&mut self, text: &str)`. `MemoryClipboard` — буфер в памяти (тесты, приложения без системного буфера). Подключение: `Ui::clipboard(&'a mut dyn Clipboard)` на корне описания; модальный слой пользуется им же.
6. **Операции — вход контрола:** `Control::clipboard(&mut self, op: ClipboardOp, clipboard: &mut dyn Clipboard, out) -> Handled` с телом по умолчанию `No`; `ClipboardOp::{Copy, Cut, Paste}`. Дерево распознаёт сочетания по **физической** клавише в `route_key_event` и вызывает метод у контрола под фокусом **до** обычной доставки клавиши; ответ `No` — клавиша идёт прежним путём (контрол → текст → карта сочетаний).
   - Сочетания: `Ctrl+C` / `Ctrl+Insert` — копировать, `Ctrl+X` / `Shift+Delete` — вырезать, `Ctrl+V` / `Shift+Insert` — вставить (О2).
   - `TextInput`: копирование и вырезание — выделенный текст (пустое выделение — буфер не трогается); вставка — в курсор с заменой выделения, событие `Changed`; все три операции поле под фокусом поглощает (`Yes`) в любом случае.
7. **Системный буфер:** `SystemClipboard` на `arboard` с `default-features = false` (только текст) за фичей крейта (О1). Ошибки доступа к буферу не паникуют: `get` → `None`, `set` — без действия, причина один раз в stderr.
8. **Пример** `widget_edit`: системный буфер подключён, подсказка дополнена.
9. **Тесты** без окна (`MemoryClipboard`, `route_key_event`): выделение клавишами и мышью, замена выделения набором, копирование/вырезание/вставка, поглощение сочетаний (привязка `Ctrl+C` в карте не срабатывает при фокусе в поле и срабатывает на кнопке), вставка многострочного текста, поле в модальном слое, отрисовка выделения.

**Документы:** ADR-0030 (после утверждения), ТЗ проекта §13 (версия 1.25), `AGENTS.md`, `PROJECT_MAP.md`, `TODO.md`, план и отчёты, размеры release.

**Не входит:**

- движение и выделение по словам (`Ctrl+←/→`), двойной клик — слово (двойной клик — отдельный пункт `TODO.md`), отмена/повтор (`Ctrl+Z`);
- многострочное поле, редактируемый `ComboBox`, копирование из `List`/`Table`/`Paragraph`;
- буфер «primary selection» X11/Wayland (вставка средней кнопкой), картинки и прочие форматы;
- изменения `gterm` (рендереры, цикл событий).

## 3. Контракты

- Позиции выделения и курсора — в символах, `0..=len`; после любой операции якорь и курсор в границах.
- Поле под фокусом поглощает сочетания буфера обмена всегда — и при пустом выделении, и без подключённого буфера (О4); привязки карты с теми же сочетаниями при фокусе в поле не срабатывают.
- Контрол без поддержки буфера (`Control::clipboard` по умолчанию) сочетания не поглощает — они идут прежним путём.
- Вставляемый текст: перевод строки и табуляция → пробел, прочие управляющие символы отбрасываются (О3).
- Без `Ui::clipboard` поведение прежних путей (`route_key`, `Ui::text`, мышь) не меняется, кроме появившегося выделения.
- Неактивное поле (`enabled == false`) не выделяется и буфер не трогает.
- Выделений памяти в кадре не добавляется сверх уже существующей сборки видимой строки.

## 4. Критерии приёмки

| № | Критерий | Чем подтверждается |
|---|---|---|
| К1 | Выделение клавиатурой: `Shift`+стрелки/`Home`/`End`, `Ctrl+A`, снятие движением, границы | тесты без окна |
| К2 | Замена выделения набором и вставкой, удаление `Backspace`/`Delete`, одно `Changed` | тесты без окна |
| К3 | Выделение мышью: нажатие, протяжка с захватом, `Shift`+нажатие, прокрутка за краем | тесты без окна |

| К5 | Поглощение: карта `Ctrl+C` молчит при фокусе в поле, срабатывает на контроле без буфера; поле в модальном слое работает с буфером | тесты без окна |

## 5. Риски

- `arboard`: состав зависимостей при `default-features = false` и поведение на Wayland (через XWayland либо протокол data-control за отдельной фичей) — `[нужны данные: cargo tree и документация arboard 3.7 — снимается на этапе плана]`; проверка на Linux — только глазами на машине владельца.
- На X11 содержимое буфера живёт, пока жив владелец: `SystemClipboard` должен храниться в состоянии приложения, а не создаваться на событие.
- Системный буфер автотестом не проверяется (общий ресурс машины, гонки между тестами) — только `MemoryClipboard`.
- Размер бинарников примеров вырастет на код `arboard` — замеряется.
- `Ctrl+A` поле поглощает — привязка `Ctrl+A` в карте экрана при фокусе в поле перестанет срабатывать (следствие правила «контрол раньше карты»).

## 6. Открытые вопросы

- **О1. Где живёт доступ к системному буферу.** (a) **Рекомендуется:** `gterm_widgets::SystemClipboard` на `arboard` за фичей `system-clipboard`, включённой по умолчанию (приложение класса «панели и диалоги» ждёт буфер из коробки; отказ — `default-features = false`); (b) библиотека даёт только трейт и `MemoryClipboard`, системную реализацию пишет приложение, пример показывает обёртку над `arboard` (dev-зависимость) — у библиотеки ноль новых зависимостей; (c) буфер в `gterm` (`Ctx`) — нарушает «библиотека ввод не интерпретирует» и тянет зависимость во все бинарники.
- **О2. Набор сочетаний.** (a) **Рекомендуется:** `Ctrl+C/X/V` и классические `Ctrl+Insert` / `Shift+Delete` / `Shift+Insert`; (b) только `Ctrl+C/X/V`.
- **О3. Вставка многострочного текста в однострочное поле.** (a) **Рекомендуется:** перевод строки и табуляция → пробел; (b) отбрасывать, как сейчас делает `insert_str` (строки склеятся); (c) вставлять только первую строку.
- **О4. Поле без подключённого буфера.** (a) **Рекомендуется:** сочетания всё равно поглощаются, операции — без действия (поведение поля не зависит от того, подключил ли приложение буфер); (b) не поглощаются и идут в карту сочетаний.
