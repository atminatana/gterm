# Дополнение к ТЗ: альфа-канал цветов ячейки и фон буфера

- **Идентификатор:** `2026-10-09-color-alpha`
- **Дата:** 2026-10-09
- **Статус:** утверждено владельцем 2026-10-09; Р1 — а, Р2 — а
- **Основное ТЗ:** `docs/TZ_terminal_emulator.md` 1.10. После утверждения и реализации изменения вносятся в основное ТЗ версией 1.11. Затрагиваются FR-2, FR-14, §5.2, §6.1, §7.2–7.3, §8 и §13.
- **Решения владельца (2026-10-09):** альфа действует у fg (вариант 1) и у bg (вариант 2); кодировка `0xAARRGGBB`, где `A = 255` — непрозрачно; фон буфера заменяет `ViewParams::border_color`; работа идёт полным циклом.

## 1. Цель

Ввести в ячейку полупрозрачные цвета символа и фона. Ввести понятие **фона буфера** — непрозрачной подложки, которая видна под ячейками и на поле вокруг сетки. Результат GL и Software по-прежнему совпадает бит в бит.

## 2. Границы

**Входит:**
- кодировка альфы в `Color`, конструкторы и константы;
- фон буфера `ScreenBuffer` — хранение, чтение и смена;
- новое смешивание в обоих рендерерах и в шейдере, передача альфы на GPU;
- `ViewParams::border_color` удаляется, поле вокруг сетки заливается фоном буфера;
- тесты, golden-сравнение, сравнение GL ↔ Software, замер `--bench` Software;
- строка демо с полупрозрачными цветами (открытое решение Р2);
- обновление основного ТЗ, ADR, `PROJECT_MAP.md`, `AGENTS.md`.

**Не входит:**
- прозрачность окна, то есть рабочий стол сквозь окно (§13 основного ТЗ). Фон буфера всегда непрозрачен, его альфа игнорируется;
- картинка или второй слой под сеткой — подложка в этой задаче только однотонная;
- альфа и цвета из SVG-файлов: цвета файла по-прежнему игнорируются (FR-8.6);
- смешивание с прошлым кадром или между ячейками.

## 3. Контракты

### 3.1. `Color`

- `Color(u32)` хранит `0xAARRGGBB`. `A = 255` — непрозрачный цвет, `A = 0` — полностью прозрачный.
- `Color::from_rgb(r, g, b)` даёт `A = 255`. `Color::from_rgba(r, g, b, a)` сохраняет `a` (сейчас альфа отбрасывается).
- Константы `BLACK`, `WHITE`, `GREEN`, `MAGENTA`, `CYAN` становятся непрозрачными (`0xFF……`).
- Добавляется аксессор `a()`. Аксессоры `r()`, `g()`, `b()` не меняются.
- `Color::default()` равен `Color(0)` — прозрачный чёрный. Следствие: пустая ячейка `Cell::default()` / `Cell::blank()` показывает фон буфера. `ScreenBuffer::new` по-прежнему заполняет пустые ячейки непрозрачными `DEFAULT_FG`/`DEFAULT_BG` (белый на чёрном).

### 3.2. Фон буфера

- `ScreenBuffer` хранит `background: Color`. Значение по умолчанию — `Color::BLACK`, то есть прежний цвет поля в демо.
- Чтение — `background()`, смена — `set_background(color)`. Хранится цвет как есть, но рендереры альфу фона не учитывают: подложка непрозрачна.
- Смена фона меняет весь кадр — и ячейки с прозрачностью, и поле вокруг сетки. Следующий кадр обоих рендереров обязан учесть её целиком, частичный кадр после смены фона недопустим. Механизм — в плане.
- Чем заполняются пустые ячейки (`with_default_colors`, `blank`), не меняется.

### 3.3. `ViewParams` и `Renderer`

- `ViewParams::border_color` удаляется. Поле вокруг сетки (FR-14) заливается фоном буфера.
- Что станет с `ViewParams` без полей, решает владелец (Р1).

### 3.4. Алгоритм ячейки (новая редакция §7.3)

Все величины — целые 0…255, смешивание `blend(x, y, a) = (x·(255 − a) + y·a + 127) / 255` по каналам, как сейчас (ADR-0002).

```
B   = RGB фона буфера                         // подложка, альфа фона буфера не учитывается
bg' = blend(B, bg.rgb, bg.a)                  // фон ячейки поверх подложки
fg' = BOLD ? min(fg.rgb + 0x55, 255) : fg.rgb // осветление — только RGB, альфа fg не меняется
cov = покрытие глифа (0…255); UNDERLINE на нижней строке ячейки → cov = 255
a   = (cov · fg.a + 127) / 255                // покрытие с учётом альфы символа
out = blend(bg', fg', a)
```

- Вне сетки результат — `B`.
- Если `bg.a = 255` и `fg.a = 255`, результат совпадает с нынешним алгоритмом бит в бит: `blend(x, y, 255) = y` и `(cov·255 + 127)/255 = cov`.

### 3.5. Данные GPU (§6.1)

- В каналах G и B текстуры данных лежит `Color` целиком, `0xAARRGGBB`; срез альфы при упаковке убирается. Канал R (слот и флаги) не меняется.
- Фон буфера идёт в шейдер uniform-переменной вместо `u_border`. Её тип и представление определяет план; требование одно — бит-идентичность с Software.

## 4. Требования

- **FR-2 (новая редакция).** Цвета символа и фона — RGBA8, `0xAARRGGBB`. Альфа fg и bg участвует в смешивании по §3.4. Прозрачность окна остаётся вне рамок (§13).
- **FR-2.1 (новое).** У буфера есть фон — непрозрачная подложка под всеми ячейками. Он же заливает поле вокруг сетки и заменяет `border_color` (FR-14).
- **FR-14 (новая редакция).** Область окна, не занятая сеткой, заливается фоном буфера.
- Бит-идентичность GL ↔ Software (§8, §11.2) и инвариант «частичный кадр = кадр с нуля» (ADR-0010) сохраняются при любых альфах.
- NFR-5 и NFR-6 сохраняются: Software не медленнее 60 FPS на сетке 120×40 при полной перерисовке, в горячем пути нет выделений памяти.

## 5. Критерии приёмки

1. Если все цвета непрозрачные, а фон буфера равен прежней `border_color`, кадр Software побайтно равен **существующим** golden-эталонам 16 и 32 px. Эталоны в этой задаче не перезаписываются.
2. Пиксельные тесты Software для формулы §3.4: `bg.a = 0` (видна подложка), `bg.a = 128` (смешивание с подложкой), `fg.a = 0` (символа нет), `fg.a = 128` (символ наполовину), `BOLD` с альфой (осветление не трогает альфу), `UNDERLINE` с альфой. Ожидаемые значения посчитаны вручную в тесте.
3. Смена фона буфера: следующий кадр Software равен кадру с нуля и перерисован полностью, включая поле вокруг сетки.
4. `tests/stage4_gl.rs`: новая сцена с полупрозрачными fg и bg и фоном не по умолчанию, GL ↔ Software с допуском 0 на GL 3.3 и GLES 3.0. Существующие сцены совпадают как раньше.
5. Упаковка `to_packed` / `from_packed` сохраняет альфу (тест «туда-обратно» с `A ≠ 255`). `from_rgb` даёт `A = 255`, `from_rgba` сохраняет `A`.
6. `--bench` на Software: не менее 60 FPS на сетке 120×40. Замер записывается в отчёт рядом с прежним (97,9 FPS).
7. Гейты: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` чистые. Размер release замерен и записан (NFR-1).
8. Основное ТЗ обновлено до 1.11; есть ADR с решением.
9. Глазами на машине владельца: строка демо с полупрозрачными цветами на GL 3.3, GLES 3.0 и Software выглядит одинаково (если Р2 принято).

## 7. Риски

- **Тонкое расхождение GL ↔ Software в двухшаговом смешивании** (округление, порядок операций). Смягчение: одна формула с целыми числами в обоих рендерерах и сцена с альфой в `stage4_gl` (критерий 4).
- **Цвета, собранные в коде напрямую как `Color(0x00RRGGBB)`**, станут прозрачными. Поиск 2026-10-09 показал: напрямую собраны только константы `cell.rs` (через `Self(…)`); альфу срезают маски `& 0x00FF_FFFF` в `encode_color` обоих рендереров и в тестовом помощнике `rgb()` (`stage3_render.rs:35`); `from_packed` передаёт значение целиком. План перепроверяет это поиском.
- **Стоимость второго смешивания в Software.** Смягчение: при `bg.a = 255` первый шаг пропускается; проверяется замером (критерий 6).
