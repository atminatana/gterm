## 1. Цель

Приложение на `gterm-widgets` описывает экран один раз — функцией `ui()`, возвращающей временное описание из контейнеров и контролов по ссылкам на состояния приложения, — и получает из него раскладку, отрисовку, обход фокуса по `Tab`, доставку клавиш контролу под фокусом, попадание мыши и сообщения своего типа. Ручной `match focus { … }` из `examples/widgets.rs` исчезает. На этом механизме дальше строятся поле ввода, выпадающий список и меню (отдельные задачи `TODO.md`).

## 2. Границы

**Входит — `crates/gterm-widgets`:**

1. **Контрол** — трейт крейта, который реализуют и состояния встроенных контролов (`ListState`, `TableState`, новый `ButtonState`), и типы приложения (своя панель). Контрол умеет: нарисовать себя в область; принять клавишу и сообщение мыши с ответом «обработано/нет»; опубликовать сообщения типа приложения `Msg` (параметр механизма); сказать, фокусируем ли он. Признаки «под фокусом» и «область последней раскладки» ведёт крейт (где они хранятся — решение плана, не ТЗ). Паттерн «состояние у приложения, виджет-значение потребляется при отрисовке» (ADR-0023) сохраняется: для встроенных контролов виджет (`List`, `Table`, `Button`) по-прежнему задаёт вид, а состояние — поведение.
2. **Описание экрана** — временная структура, которую приложение строит функцией `fn ui(&mut self) -> …` на каждое событие и на каждый кадр из `&mut` на свои состояния; состояния не пересобираются, идентификаторов нет. Элементы: контейнеры «колонки/строки» по `Layout` (ADR-0023 п. 5) с необязательной рамкой `Block`; контрол — встроенный (виджет + `&mut` состояние) или свой (`&mut` тип приложения); лист без состояния (`Paragraph`, `Block`) — рисуется, фокус и ввод не получает; **модальный слой** — второе описание поверх первого с областью на сетке (центрирование по сетке, как `Popup::centered`). Одно описание служит раскладке, отрисовке, обходу фокуса и попаданию мыши — порядок везде один, по построению.
3. **Сообщения.** Механизм параметризован типом `Msg` приложения. Встроенные контролы получают сообщения при описании: кнопка — `on_activate(Msg)`, список и таблица — `on_select(fn(usize) -> Msg)` (вызывается только при изменении выделения). Свой контрол публикует сообщения сам из обработчика клавиши или мыши: обработчик получает `&mut` очередь сообщений аргументом и кладёт в неё ноль, одно или несколько (решение О1; привязки встроенных контролов пишут в ту же очередь). Результат маршрутизации: признак «обработано/нет» плюс собранные сообщения; адрес контрола в результате не передаётся (решение владельца: задел на будущее). Порядок в приложении: `let r = self.ui().key(ev, ctx)` → описание сброшено → разбор сообщений с изменением `self` → `self.ui().render(area, screen)`.
4. **Фокус.** Кандидаты — фокусируемые контролы-листья; контейнеры прозрачны (сами фокус не берут). Порядок — порядок объявления в `ui()` в глубину, `Tab` по кольцу, `Shift+Tab` строго обратно; без кандидатов фокуса нет, `Tab` ничего не делает. При старте и при исчезновении контрола под фокусом из описания — фокус первому кандидату. Левый клик по фокусируемому контролу переводит фокус на него до доставки сообщения мыши; по нефокусируемому — не меняет. Контейнер с рамкой может задать стиль рамки «фокус внутри»; встроенные контролы — стиль «под фокусом» для своей рамки. Без фокуса картинка виджетов не меняется (тесты ADR-0023 остаются).
5. **Клавиатура.** `Tab`/`Shift+Tab` перехватываются механизмом до контролов (модификаторы — из `Ctx`, п. 8). Остальные клавиши — контролу под фокусом; ответ «не обработано» возвращается приложению как есть (контейнеры прозрачны, подъёма по родителям нет). Без фокуса все клавиши — приложению. `Esc` для механизма не особенный (ADR-0004); в модальном слое его превращает в сообщение только привязка `on_escape` (п. 7).
6. **Мышь.** Сообщение мыши строится из `PointerEvent` с ячейкой под указателем (п. 8): нажатие/отпускание кнопки, движение, колесо, уход указателя из окна. Адресат — верхний (последний в порядке объявления) контрол, чья область содержит ячейку; никого — «не обработано». Список и таблица: левое нажатие по строке — выделение этой строки (`on_select`), колесо — выделение на число строк по дельте. **Захват указателя** (решение О4): контрол, ответивший «обработано» на нажатие, получает последующие движение и отпускание той же кнопки независимо от положения указателя, пока кнопка не отпущена или указатель не покинул окно (`PointerEvent::Left` приходит контролу как отмена); захват снимается отпусканием или отменой. Кнопка: нажатие в области переводит её в «нажата», отпускание внутри области — `on_activate`, отпускание снаружи или отмена — возврат без активации. Двойного клика и перетаскивания как жеста нет (не входит), но захват и формат сообщения мыши им не мешают.
7. **Модальный слой.** Пока в описании есть модальный слой, весь ввод идёт ему: клавиши — его фокусу, мышь — его контролам в локальных ячейках слоя; основной экран не получает ничего, его фокус не меняется (хранится в его состояниях). Слой рисуется поверх экрана через наложение (`DrawCtx::draw_buffer`, ADR-0014) с фоном стиля слоя; область, буфер и вывод он берёт у `Popup`, который остаётся с тем же API в своём файле `widgets/popup.rs`, а логика слоя живёт в отдельном файле (решение О3; `tests/popup.rs` не меняется). Клик вне области слоя поглощается: слой остаётся, основной экран ничего не получает, сообщений нет (решение О2). Слой принимает необязательную привязку `on_escape(Msg)`: `Esc`, не взятый контролом под фокусом слоя, публикует это сообщение; без привязки `Esc` возвращается приложению как «не обработано», как любая клавиша (решение О5, ADR-0004). Стек из более чем одного слоя не демонстрируется (второй слой — то же описание, вложенное в первый).
8. **Изменения `gterm`** (добавления, ADR-0004 соблюдается — типы `winit` остаются): `PointerEvent::Moved`, `Input`, `Wheel` получают поле `cell: (i32, i32)` — ячейка сетки под указателем по последнему известному положению (деление с округлением вниз на размер ячейки; отрицательные и за краем сетки — вне); `Ctx` получает `modifiers: ModifiersState` (цикл событий обрабатывает `WindowEvent::ModifiersChanged`) и `cell_px: (u32, u32)` — размер ячейки в физических пикселях. `Request`, рендереры, формат кадра не меняются.
9. **Встроенные контролы первого шага:** новый `Button` (`ButtonState`: `enabled`, активация клавишами `Enter`/пробел и мышью, стили обычный/фокус/неактивный, `on_activate`); `ListState`/`TableState` реализуют трейт контрола: `↑`/`↓`/`Home`/`End`/`PgUp`/`PgDn`, клик и колесо, `on_select`; для попадания клика по строке `List::render`/`Table::render` записывают в состояние карту видимых строк (переиспользуемый вектор). `Paragraph`, `Block` — без состояния, как сейчас.
10. **Пример** `examples/widgets.rs` переводится на `ui()`: две колонки — список в рамке контейнера со стилем «фокус внутри», таблица, абзац, кнопка «Открыть окно»; `Tab` по кольцу список → таблица → кнопка; стрелки, клик и колесо — в контроле под фокусом/указателем; `Esc` на главном экране — выход (необработанное — приложению); `p` и кнопка открывают модальный слой с абзацем «Выбрано: …» и кнопкой «OK»; «OK» (клавишей или мышью с отпусканием внутри) и `Esc` через `on_escape` дают одно сообщение, которым приложение закрывает слой; клик вне окна ничего не делает. Сообщения — `enum Msg` примера, разбор в одном `match`.
11. **Тесты** без окна (`gterm-widgets/tests/`): обход фокуса (порядок, кольцо, обратный, пропуск нефокусируемых и листьев без состояния, без кандидатов, исчезновение фокуса из описания); клавиатура (доставка фокусу, «не обработано» наверх, `Tab` перехвачен, без фокуса — приложению); мышь (верхний контрол, фокус по клику до доставки, нефокусируемый не меняет фокус, вне областей; захват — движение и отпускание идут захватившему контролу вне его области, снятие отпусканием и уходом указателя); сообщения (привязка у встроенных, публикация из своего контрола-заглушки, `on_select` только при изменении); отрисовка (кадр описания совпадает с ручным рендером тех же виджетов; стиль фокуса только под фокусом); модальный слой (ввод только слою, фокус экрана не тронут, локальные ячейки, клик вне поглощается, `Esc` → `on_escape` или «не обработано»); встроенные (`Button` в состояниях обычная/фокус/нажата/неактивная, активация по отпусканию внутри и отмена снаружи; список и таблица — клавиши, клик по строке, колесо). `gterm`: `Ctx::modifiers` — сценарий в оконном `stage6_events` (один цикл событий на процесс — расширением существующего бинарника); `cell` в `PointerEvent` и `cell_px` — единичные тесты перевода.
12. **Документы:** ADR на модель (после утверждения ТЗ, AR-04), ТЗ 1.21 (§13 — ввод на стороне приложения дополняется ячейкой и модификаторами), `AGENTS.md`, `PROJECT_MAP.md`, `TODO.md` (пункты «мышь» и «комбинации клавиш» закрываются в части координат и модификаторов), отчёты `docs/done|test|verify/`; размер release-примера `widgets.exe` и `demo.exe` — замерить и записать (NFR-1).

**Не входит:**

- поле ввода (командная строка), выпадающий список, чекбокс, меню, подсказки, немодальные окна — следующие задачи на этом механизме;
- адрес контрола (ссылка, идентификатор, путь) в результате маршрутизации; карта «сочетание клавиш → сообщение»; акселераторы `Alt+буква`; кнопка по умолчанию;
- двойной клик, перетаскивание как жест, автоповтор; курсор ввода и IME (`on_text` остаётся приложению);
- стек более чем одного модального слоя, переключение между окнами по клику;
- изменение рендереров и формата кадра; новые зависимости помимо `winit` в `gterm-widgets` (с теми же фичами, что у `gterm`).

## 3. Контракты

- Одно описание `ui()` — один порядок для раскладки, отрисовки, обхода фокуса и попадания мыши. Описание временное: состояния приложения не копируются и не пересобираются; идентификаторов и диффа нет.
- Фокус — ровно у одного фокусируемого контрола-листа или ни у кого; контейнеры фокус не берут; порядок детерминирован и равен порядку объявления в глубину; `Shift+Tab` — строго обратный `Tab`.
- Клавиша доставляется ровно одному контролу — под фокусом; «не обработано» возвращается приложению без изменений состояния механизма; `Tab`/`Shift+Tab` до контролов не доходят.
- Сообщение мыши доставляется ровно одному контролу — захватившему, если захват есть, иначе верхнему под ячейкой; левый клик по фокусируемому меняет фокус до доставки; захват держит контрол, обработавший нажатие, до отпускания той же кнопки или ухода указателя из окна.
- Пока есть модальный слой: клик вне его области поглощается без сообщений; `Esc`, не взятый контролом слоя, даёт сообщение `on_escape`, если оно задано, иначе возвращается приложению.
- Сообщения приложения собираются за одну маршрутизацию и отдаются приложению вместе с признаком «обработано»; механизм их не интерпретирует.
- Пока есть модальный слой, основной экран ввода не получает и его фокус не меняется.
- Отрисовка через описание даёт те же ячейки, что ручной `render` тех же виджетов в тех же областях, плюс стили фокуса у контролов и рамок под фокусом.
- `gterm` меняется только добавлением полей (`PointerEvent::*::cell`, `Ctx::modifiers`, `Ctx::cell_px`) и обработкой `ModifiersChanged`; NFR-6 не затрагивается — описание строится в обработчиках событий и в `on_redraw`, не в кадре рендерера; `unsafe` в `gterm-widgets` нет; MSRV 1.85.

## 5. Риски

- Описание держит `&mut` на все состояния, пока живёт: приложение не может читать `self.list.selected()` «во время». Смягчение: порядок вызовов закреплён в п. 3 и показан в примере; сообщения несут нужные данные (`on_select(fn(usize) -> Msg)`).
- Параметр `Msg` проходит через трейт контрола и описание экрана — обобщения во всём крейте. Смягчение: эскиз сигнатур в плане и проверка компилируемости на минимальном примере до основной работы.
- Добавление полей в `PointerEvent` — правка публичного контракта `gterm`: демо и оконные тесты, сопоставляющие варианты по образцу, нужно поправить. Смягчение: поля добавляются, не убираются; список мест — в плане.
- Описание строится на каждое событие и кадр с выделениями в обработчиках; NFR-6 (кадр рендерера) не затронут; размеры release записать (NFR-1).
- Карта видимых строк в `ListState`/`TableState` — состояние растёт на вектор; переиспользуется, клик сопоставляется с последним кадром (как и области — осознанно).
- Два стиля в одном крейте — немедленные виджеты (ADR-0023) и контролы с состоянием-поведением; виджеты те же, описание лишь вызывает их `render`; приложение может не использовать описание вовсе.

## 6. Решения по открытым вопросам (владелец, 2026-10-30)

- **О1. Публикация сообщения из своего контрола** — обработчик получает `&mut` очередь сообщений аргументом (как `Shell::publish` в iced) и публикует ноль, одно или несколько; привязки встроенных пишут в ту же очередь. Отклонено: возврат `Option<Msg>` — одно сообщение на событие, неудобно для встроенных с привязкой.
- **О2. Клик вне модального слоя** — поглощается, слой остаётся, сообщений нет. Отклонено (пока): привязка `on_click_outside(Msg)` — добавить, когда появятся меню и выпадающий список.
- **О3. `Popup`** — остаётся низкоуровневым буфером наложения с тем же API в своём файле `widgets/popup.rs`; модальный слой использует его внутри, его логика — в отдельном файле; `tests/popup.rs` не меняется. Отклонено: упразднение или переименование — ломает API части 1 (ADR-0023).
- **О4. Активация кнопки мышью** — по отпусканию внутри области после нажатия в ней; отпускание снаружи или уход указателя — отмена. Следствие: захват указателя между нажатием и отпусканием входит в первый шаг (п. 6 §2), перетаскивание позже строится на нём. Отклонено: активация по нажатию без захвата.
- **О5. `Esc` в модальном слое** — слой принимает необязательную привязку `on_escape(Msg)`; без неё `Esc` возвращается приложению как «не обработано» (ADR-0004). Отклонено: приложение само проверяет открытый диалог на каждом необработанном `Esc`.
