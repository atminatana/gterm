# ТЗ: карта «сочетание → сообщение» в описании экрана `gterm-widgets`, событие фокуса окна в `gterm`

- **Идентификатор:** `2026-11-12-hotkey-map`
- **Дата:** 2026-11-12
- **Статус:** утверждено владельцем 2026-11-12 («ТЗ утверждаю»; О1–О3 — рекомендованные варианты (a)). План — `docs/plans/2026-11-12-hotkey-map.md`, решения — ADR-0029.
- **Постановка владельца (2026-11-12, ответы на шесть вопросов):**
  1. Привязка срабатывает **на нажатие**.
  2. Контрол под фокусом — первый: поле ввода само обрабатывает стандартные комбинации (`Ctrl+V`, `Ctrl+X`) и алфавитно-цифровые клавиши и поглощает их — дальше они не идут; при нажатом модификаторе набор текста не производится.
  3. Модальный слой забирает всё; у него может быть своя карта.
  4. Трекер живёт в состоянии приложения и передаётся в описание; `Ui::key` кормит его и отпусканиями.
  5. Запись сочетаний — всегда латиница (имена физических клавиш); акселераторов `Alt+буква` нет.
  6. Потеря фокуса окна: библиотека должна о ней сообщать («Правь»).
- **Основа:** ADR-0028 (`gterm::hotkey`: `Key`, `Hotkey`, `matches`, `HotkeyTracker`), ADR-0026 (описание `Ui`, `Routed`, модальный слой), ADR-0027 (текст — вход контрола), ADR-0004 (библиотека ввод не интерпретирует). Код: `crates/gterm-widgets/src/ui/route.rs:17` (`Ui::key` отбрасывает `Released`, `KeyMsg` — из `logical_key`), `ui/route.rs:28` (`route_key`: слой → `Tab` → контрол под фокусом → текст), `ui/modal.rs:125` (`Modal::route_key`, `on_escape`), `ui/mod.rs:1` (описание строится заново на каждое событие и кадр), `input.rs:43` (`typed_text`: при `Ctrl`/`Alt`/`Super` текста нет), `crates/gterm/src/app/events.rs:21` (`WindowEvent::Focused` не обрабатывается), `app/api.rs:135` (`AppHandler`).

## 1. Цель

Приложение объявляет в `ui()` привязки «сочетание → сообщение» (`Ctrl+S` → `Msg::Save`, `Ctrl+[K,U]` → `Msg::Chord`); дерево сопоставляет нажатия с образцами и публикует сообщение в `Routed::messages` тем же путём, что `on_activate`. Сочетания не зависят от раскладки. Разбор «необработанного деревом» в приложении для таких клавиш больше не нужен.

## 2. Границы

**Входит — `crates/gterm-widgets`:**

1. **Карта `HotkeyMap<M>`** (новый модуль `src/hotkeys.rs`): упорядоченный список пар «образец `Hotkey` → сообщение `M`». Строится один раз и хранится в состоянии приложения (описание пересобирается на каждое событие — разбирать строки при каждой сборке нельзя). `HotkeyMap::new()`, `bind(pattern: Hotkey, message: M)`, `bind_str(&str, M) -> Result<_, ParseError>` (ошибка `gterm::hotkey::ParseError` с позицией), `is_empty`, `len`. Образцы — как в ADR-0028, включая альтернативы `K|U`. `M: Clone` — сообщение публикуется копией.
2. **Подключение к описанию:** `Ui::hotkeys(self, tracker: &'a mut HotkeyTracker, map: &'a HotkeyMap<M>)` — на корне описания; `Modal::hotkeys(self, map: &'a HotkeyMap<M>)` — карта слоя. Трекер один на приложение (клавиатура одна), лежит в его состоянии. Вложенное описание с `hotkeys` при сборке контейнера поднимается к корню так же, как модальный слой (первое побеждает).
3. **Маршрутизация клавиши** (`Ui::key`):
   - событие (нажатие, отпускание, автоповтор) **сначала всегда** скармливается трекеру, если он подключён, — и при модальном слое тоже;
   - отпускание дальше не идёт (`Routed::ignored()`, как сейчас);
   - нажатие идёт прежним путём: модальный слой либо `Tab` → контрол под фокусом → текст;
   - если нажатие **не принято** (`Handled::No`) и трекер его учёл (не автоповтор, не повторное нажатие удержанной клавиши, не `Unidentified`) — сопоставление с действующей картой: при модальном слое — только карта слоя (нет карты — ничего), иначе карта экрана;
   - сопоставление: сначала полная история `tracker.full()` (аккорды: `Ctrl+[K,U]` в момент нажатия `U`), затем цепочка удержанных `tracker.current()` (простые сочетания: `Ctrl+V` после `Ctrl+C` без отпускания `Ctrl`); внутри каждого шага — первая привязка в порядке объявления; срабатывает **одна** привязка, её сообщение добавляется в `Routed::messages`, `handled = Yes`.
4. **Порядок относительно `on_escape` слоя:** `Esc`, не взятый контролом слоя, — сначала привязка `on_escape` (как сейчас), карта слоя — только если нажатие всё ещё не принято.
5. **Точка входа тестов без окна:** маршрутизация по `(Option<Key>, ElementState, repeat, KeyMsg)` — `KeyEvent` без окна не сконструировать; `Ui::key` — тонкая обёртка над ней. Прежний `route_key(&KeyMsg)` остаётся (без карты).
6. **Примеры:** `widget_edit` — `Ctrl+S` «Применить», `Ctrl+R` «Сброс» через карту экрана (работают при фокусе в поле ввода и в русской раскладке); `widgets` — открытие окна по `P` переведено на карту экрана, у модального слоя своя карта; оба сбрасывают трекер при потере фокуса окна.

**Входит — `crates/gterm`:**

7. **Событие фокуса окна:** `AppHandler::on_focus(&mut self, focused: bool, ctx: &mut Ctx<'_>)` с пустым телом по умолчанию; `events.rs` — `WindowEvent::Focused(focused)` → `notify` + `apply_request`. Библиотека ничего сама не сбрасывает (ADR-0004): приложение вызывает `HotkeyTracker::reset()` при `focused == false`. Пример `hotkeys` — сброс трекера по `on_focus(false)`.

**Документы:** ADR-0029 (после утверждения ТЗ), ТЗ проекта §13/FR-25 (версия 1.24), `AGENTS.md`, `PROJECT_MAP.md`, `TODO.md` (пункт «комбинации клавиш» закрывается; акселераторы `Alt+буква` снимаются решением владельца), план и отчёты `docs/plans|done|test|verify/`, размеры release.

**Не входит:**

- буфер обмена и выделение в `TextInput` (`Ctrl+V`/`Ctrl+X`/`Ctrl+C`) — отдельная задача из `TODO.md`; эта задача лишь гарантирует порядок «контрол раньше карты», при котором поле их поглотит;
- акселераторы `Alt+буква`, разметка буквы в подписи — сняты решением владельца (п. 5);
- срабатывание по отпусканию и по `complete`, тайм-ауты аккордов, подавление привязки-префикса;
- карты на уровне отдельного контейнера или контрола (только экран и модальный слой);
- автоматический сброс трекера библиотекой; изменения рендереров; новые зависимости.

## 3. Контракты

- Контрол под фокусом всегда раньше карты: принятое им нажатие (включая набранный текст) привязок не вызывает. Набор текста при `Ctrl`/`Alt`/`Super` не производится (`KeyMsg::typed_text`, без изменений) — такие нажатия поле не принимает, и они доходят до карты. **Допущение:** `Shift` набору не мешает (заглавные буквы) — «модификатор» в п. 2 постановки понят как `Ctrl`/`Alt`/`Super`.
- Привязка срабатывает только на нажатие, один раз на нажатие; автоповтор привязку не вызывает (О2).
- При модальном слое карта экрана не действует; действует только карта слоя.
- Нажатие, принятое контролом, остаётся в истории трекера: `Ctrl`↓ `K`↓ (принято контролом) `U`↓ даёт `full = Ctrl+[K,U]`.
- Привязка-префикс не подавляется: при `Ctrl+K` и `Ctrl+[K,U]` в одной карте первая сработает на `K`, вторая — на `U`. Избегать — дело автора карты.
- Без `Ui::hotkeys` поведение `Ui::key` не меняется.
- `on_focus` по умолчанию пуст — существующие обработчики не меняются.
- Выделений в кадре не добавляется: сопоставление — в обработчике события (NFR-6 не затронут).

## 5. Риски

- Оконные тесты ввод и фокус не инжектируют: `Ui::key` с настоящим `KeyEvent` и `on_focus` проверяются чтением кода и глазами (как отпускания в ADR-0028).
- `M: Clone` для карты — новое ограничение только у тех, кто подключает карту; сообщения примеров репозитория — проверить при планировании.
- Привязка без модификаторов (`P`) срабатывает при фокусе на любом контроле, не принимающем букву (кнопка, список); при фокусе в поле ввода — нет. Это следствие п. 2 постановки, не дефект.
- Приложение, не вызывающее `reset()` при потере фокуса, получит «зависшую» клавишу в трекере — привязки перестанут совпадать до полного отпускания.

## 6. Открытые вопросы

- **О1. Форма привязок.** (a) **Рекомендуется:** карта `HotkeyMap<M>` в состоянии приложения, `M: Clone` — образцы разбираются один раз, карту удобно читать из настроек; (b) привязки по одной в описании — `Ui::hotkey(&'a Hotkey, M)`, как `on_activate`: без `Clone`, но разобранные образцы приложение хранит отдельными полями.
- **О2. Автоповтор.** (a) **Рекомендуется:** автоповтор привязку не вызывает (одно нажатие — одно сообщение, трекер автоповтор и так игнорирует); (b) вызывает на каждый повтор (удобно для «следующий элемент», опасно для «удалить»).
- **О3. Приоритет при двух совпадениях** (в карте есть и `Ctrl+U`, и `Ctrl+[K,U]`, нажата `U` после `K`). (a) **Рекомендуется (принято в п. 3):** побеждает полная история — аккорд; (b) срабатывают обе.
