# ТЗ: двойной клик для любого контрола и ползунок `Slider`

- **Идентификатор:** `2026-11-16-double-click-slider`
- **Дата:** 2026-11-16
- **Статус:** утверждено владельцем 2026-11-16 — утверждение унаследовано от ТЗ `sfplayer` `docs/spec/2026-11-16-dialogs-and-keys.md` (разделы G-3 и G-4, утверждены 2026-11-16; решения владельца по ОР-1 и ОР-3). Этот документ пересказывает G-3 и G-4 в терминах `gterm`; при расхождении главнее G-3/G-4. План — `docs/plans/2026-11-16-double-click-slider.md`.
- **Постановка владельца (2026-11-16, проект `sfplayer`):** «двойной клик делается в gterm для любого контрола; приложение обрабатывает двойной клик контрола так же, как обычный клик у кнопки, — привязкой сообщения» (ОР-1); «уровни эффектов меняются ползунком; в библиотеке такого контрола нет — он добавляется в `gterm-widgets` как универсальный» (ОР-3).
- **Основа:** ADR-0026 (контролы, дерево `Ui`, мышь с захватом, привязки), ADR-0031 (флажок — образец контрола с событием пользователя), ADR-0032 (полоса прокрутки у списка и таблицы), ADR-0034 (дорожка индикатора). Код: `crates/gterm/src/app/events.rs` (`WindowEvent::MouseInput` → `PointerEvent::Input`), `crates/gterm/src/app/api.rs` (`PointerEvent`), `crates/gterm-widgets/src/input.rs` (`MouseMsg`), `src/ui/route.rs` (`Ui::route_mouse`), `src/ui/element.rs` (привязки), `src/widgets/checkbox.rs`.

## 1. Цель

1. Приложение получает сообщение на двойной клик по любому контролу дерева — привязкой, как `on_activate` у кнопки; часов в контролах и тестах нет.
2. В `gterm-widgets` есть универсальный контрол «ползунок» для целого значения в границах.

## 2. Границы

**Входит — двойной клик (G-4):**

1. Двойной клик — второе нажатие **левой** кнопки в **той же ячейке** не позже **500 мс** после предыдущего; интервал и допуск по месту фиксируются в ADR.
2. Нажатия считает окно `gterm`: `PointerEvent::Input` несёт число нажатий подряд; счётчик — чистая функция от кнопки, ячейки и момента времени (время — аргументом), проверяется unit-тестами без окна.
3. Третье нажатие подряд начинает счёт заново (1).
4. `gterm-widgets`: `MouseMsg` несёт число нажатий; признак двойного клика — помощником.
5. Привязку двойного клика может получить любой контрол дерева `Ui` (встроенный и свой); сообщение публикуется, когда двойной клик пришёлся на область контрола. Контрол без привязки ведёт себя как раньше.
6. Первое нажатие пары действует как обычный клик (в списке выделяет строку), второе тоже доставляется контролу — к моменту сообщения выделена строка под указателем.
7. Двойной клик по полосе прокрутки списка (и таблицы) сообщения не даёт: контрол может отклонить двойной клик по месту нажатия, по умолчанию — принимает.
8. Тесты без окна (`route_mouse`), пример `widgets`, ADR, документы.

**Входит — ползунок (G-3):**

9. `Slider` + `SliderState` в `crates/gterm-widgets/src/widgets/slider.rs`: горизонтальная дорожка шириной своей области с заполненной частью; целое значение в `min..=max`; шаг для клавиш и колеса.
10. Контрол с фокусом: `←`/`→` — на шаг, `Home`/`End` — к границам; в границе значение не меняется, события нет.
11. Мышь: левое нажатие на дорожке ставит значение по положению указателя и берёт захват; движение под захватом ведёт значение; отпускание завершает; уход указателя из окна снимает захват, достигнутое значение остаётся; колесо — на шаг.
12. Приложению — сообщение с новым значением только при изменении пользователем (новый вариант `WidgetEvent` и привязка в стиле `on_toggle`); программная установка значения события не даёт — как у флажка.
13. Виды: обычный, под фокусом, неактивный; неактивный не берёт ни фокуса, ни ввода; стили задаются как у `Checkbox`/`Meter`.
14. Тесты без окна, пример с видимым значением, ADR, документы.

**Не входит:** вертикальный ползунок, дробные значения, подпись и значение внутри виджета (приложение рисует их рядом), двойной клик правой/средней кнопкой, тройной клик, настраиваемый интервал двойного клика, двойной клик в `gterm-demo`.

## 3. Контракты

- Без привязки двойного клика маршрутизация мыши не меняется: те же вызовы контролов, тот же захват и те же сообщения.
- Публичные типы получают поля и вариант: `PointerEvent::Input` (сопоставление с `..` в репозитории уже везде), `MouseMsg` (литералы в тестах дополняются полем), `WidgetEvent` (исчерпывающий `match` в `ui/element.rs` дополняется). Внешний код, создающий `MouseMsg` литералом, перестанет собираться — для `sfplayer` это известно и указывается в отчёте.
- Ни один контрол не заводит часов; кадр отрисовки не выделяет память больше прежнего; новых зависимостей нет.

## 5. Риски

- Добавление поля в `MouseMsg` ломает литералы у потребителей (в `sfplayer` — тестовые помощники).
- Интервал 500 мс не берётся из настроек ОС (на Windows — `GetDoubleClickTime`): одинаково на всех платформах, но может не совпасть с привычкой пользователя.
- Живая проверка окна зависит от незаблокированной сессии владельца.
