# ТЗ: поле ввода текста и выпадающий список в `gterm-widgets`, пример `widget_edit`

- **Идентификатор:** `2026-10-30-widget-edit`
- **Дата:** 2026-10-30
- **Статус:** утверждено владельцем 2026-10-30 («Приступай»). План — `docs/plans/2026-10-30-widget-edit.md`, решения — ADR-0027. **Уточнение при реализации (2026-10-30, подтверждено владельцем 2026-10-30 после проверки глазами):** п. 3 — поле и слой раскрытого списка строит один вызов `Ui::combo_box(widget, &mut state, on_select)` (два `&mut` на одно состояние в приложении невозможны); закрытие по `Esc` и клику мимо список делает сам (`Modal::dismiss_on_click_outside` → `Control::dismiss`), сообщение `on_close` приложению не требуется; `Modal::below(anchor, height)` вместо ручного `Modal::at` для выпадающих списков; программные `set_value`/`clear` событий `Changed` не дают. ## 1. Цель

Формы на `gterm-widgets` получают два недостающих контрола: однострочное поле ввода с курсором и выпадающий список. Оба встраиваются в описание экрана `ui()` как встроенные контролы (`Ui::stateful` с привязками), работают с клавиатуры и мыши по механизму ADR-0026 и показаны в новом примере `widget_edit` — форме с несколькими полями, списком, кнопками и строкой статуса.

## 2. Границы

**Входит — `crates/gterm-widgets`:**

1. **Текст как третий вход дерева.** `Control<M>` получает `fn text(&mut self, text: &str, out: &mut Messages<M>) -> Handled` (по умолчанию `No`); `Ui::text(&mut self, text: &str) -> Routed<M>` доставляет текст контролу под фокусом (при модальном слое — его фокусу), «не обработано» возвращается приложению; привязок дерево не вызывает иначе, чем для клавиш (`WidgetEvents::take_event` после обработчика). Приложение вызывает `self.ui().text(text)` из `AppHandler::on_text`. В `gterm` ничего не меняется.
2. **`TextInput<'a>` / `TextInputState`.** Состояние: `value: String`, `cursor: usize` (индекс символа, 0..=len), `scroll: usize` (первый видимый символ), `node: NodeState`, `enabled: bool`. Клавиши: `←`/`→` — курсор на символ; `Home`/`End`; `Backspace` — удалить перед курсором; `Delete` — под курсором; `Enter` — событие `Submitted(value)`; остальные клавиши — «не обработано» (`Tab` берёт дерево — решение 2026-10-30). Текст из `text()` вставляется в позицию курсора целиком (многосимвольные вставки IME — одним событием), управляющие символы (`\r`, `\n`, `\t`, прочие `< 0x20`) отбрасываются; каждое изменение `value` — событие `Changed(value)`. Мышь: левое нажатие ставит курсор в ближайшую позицию (ячейка → `scroll + col - area.x`, зажим по длине), фокус — деревом как у любого контрола. Прокрутка: `scroll` подгоняется при отрисовке так, чтобы курсор был виден (как смещение списка): курсор левее — `scroll = cursor`, правее последней ячейки — `scroll = cursor - width + 1`. Виджет: `style`, `focus_style` (накладывается на всё поле под фокусом), `placeholder: Line<'a>` + `placeholder_style` (рисуется при пустом значении), `block: Option<Block<'a>>` с `focus_style` рамки, как у `List`. **Курсор** рисует виджет только под фокусом: ячейка под курсором — обмен fg/bg (ТЗ §13), за концом строки — пустая ячейка с обменом; без мигания (ADR-0012). Ввод без `node.focused` невозможен по построению (дерево доставляет только фокусу), но `TextInputState` как значение редактируется и напрямую (`insert_str`, `set_value`, `clear`) — для «Сброс» в примере. Привязки элемента дерева: `on_change(fn(String) -> M)`, `on_submit(fn(String) -> M)`.
3. **`ComboBox<'a>` / `ComboBoxState`.** Закрытое поле: текущее значение (`items[selected]`, иначе `placeholder`) и маркер `▾` справа (`▴`, пока раскрыт; малые треугольники из шрифта — полноразмерные `▼`/`▲` `gterm` рисует во всю ячейку); `style`, `focus_style`, `block`. Состояние: `selected: Option<usize>`, `open: bool`, `list: ListState` (выделение раскрытого списка), `node`, `enabled`. Закрытое поле под фокусом: `Enter`/пробел/`↓`/левый клик — `open = true` (список стартует с текущего значения), `↑`/`↓` в закрытом состоянии по решению владельца не листают (раскрытие — единственный путь выбора; иначе `↓` конфликтует с раскрытием). Раскрытый список — **слой** `Modal` в том же описании: `ComboBoxState::dropdown(&mut self, items: &'a [&'a str], height: u16) -> Modal<'a, M>` — слой с областью **под полем** (`Modal::at(area)`, новый конструктор: произвольная область на сетке; если снизу не хватает строк — над полем), с рамкой `Block::bordered()`, содержимое — внутренний контрол списка над `self.list`: `↑`/`↓`/`Home`/`End`/`PgUp`/`PgDn`, колесо; `Enter` и левое нажатие по строке — `selected = i`, `open = false`, событие `Selected(i)`; `Esc` и клик мимо — закрытие через привязки слоя (п. 4), `open = false` ставит приложение сообщением. Пока `open`, приложение вызывает `.modal(state.dropdown(items, h).on_select(..).on_close(..))` — `on_close(M)` ставит одно сообщение и в `on_escape`, и в `on_click_outside` (`M: Clone`). Привязка закрытого поля: `on_select(fn(usize) -> M)` — публикуется при выборе из списка (тем же путём, что `on_select` у `List`), событие только при изменении значения.
4. **Слой: клик мимо и произвольная область.** `Modal::at(area: Rect)` — слой в заданной области (центрирование остаётся через `centered`); `Modal::on_click_outside(M)` — сообщение при левом нажатии вне области слоя (нажатие по-прежнему поглощается; прочие виды мыши вне слоя — без сообщений); без привязки — поведение ADR-0026 (поглотить молча). `Esc` — как раньше, `on_escape`. Сообщения слоя публикуются один раз за маршрутизацию (`Option::take`).
5. **События состояний.** `WidgetEvent` дополняется `Changed(String)`, `Submitted(String)` (у `ComboBox` — `Selected(usize)` как у списка). Элемент дерева `Stateful` получает привязки `on_change`, `on_submit` (`Box<dyn Fn(String) -> M>`), остальные — как в ADR-0026.
6. **Пример `widget_edit`** (`crates/gterm-widgets/examples/widget_edit.rs`, системный моноширинный шрифт, как `widgets`): форма-диалог в рамке по центру экрана: подписи слева, справа поля «Имя», «Путь» (длинное значение — видна прокрутка), «Размер», выпадающий список «Тип» (`файл`/`каталог`/`ссылка`/`устройство`), кнопки «Применить» и «Сброс»; снизу строка статуса: последнее сообщение (`Changed`/`Submitted`/`Selected`/…) и итог последнего «Применить» (все значения одной строкой). `Tab`/`Shift+Tab` по кольцу поля → список → кнопки; `Enter` в поле — «Применить» (через `on_submit`); «Сброс» очищает поля и выбор; `Esc` — выход (необработанный деревом; при раскрытом списке — закрывает список по `on_escape`). Сообщения — `enum Msg`, разбор в `update`. Запуск: `cargo run -p gterm-widgets --example widget_edit`; `Cargo.toml` — `[[example]] name = "widget_edit"`.
7. **Тесты** без окна: `tests/text_input.rs` — вставка в позицию курсора и события `Changed`, управляющие символы отброшены, `Backspace`/`Delete` на краях, `←`/`→`/`Home`/`End` с зажимом, `Enter` → `Submitted`, прокрутка в узком поле (снимки: курсор виден слева/справа), клик ставит курсор, отрисовка с курсором (обмен fg/bg под фокусом, без фокуса курсора нет), `placeholder`, `focus_style`, неактивное поле не фокусируется и не меняется; `tests/combo_box.rs` — раскрытие клавишами и кликом, слой под полем (и над — при нехватке места), выбор `Enter`/кликом → `Selected` и `open = false`, `Esc`/клик мимо → сообщение `on_close`, `on_select` только при изменении, снимок закрытого поля с маркером; `tests/route.rs` (+) — `Ui::text` фокусу, в слое, «не обработано» без фокуса/у контрола без текста; `tests/modal.rs` (+) — `Modal::at`, `on_click_outside` (нажатие — сообщение, движение/колесо — нет, повторно за одну маршрутизацию — нет). Пример — сборка, запуск с `--backend=soft --fail-frames=2`.
8. **Документы:** ADR-0027 (решения владельца 2026-10-30: текст как вход контрола, курсор в виджете, раскрытие слоем с `on_click_outside`), ТЗ 1.22 (§13), `AGENTS.md`, `PROJECT_MAP.md`, `TODO.md` (пункт «поле ввода и выпадающий список» закрывается; «элементы форм» — чекбокс и группы остаются), отчёты `docs/done|test|verify/`; размеры release (`widget_edit.exe`, `widgets.exe`, `demo.exe`).

**Не входит:**

- выделение текста, буфер обмена, многострочное поле, маска/валидация ввода, история/автодополнение, курсор мышью с перетаскиванием (захват у поля не используется);
- `wants_tab` и перехват `Tab` полем; акселераторы и карта клавиш;
- редактируемый `ComboBox` (ввод своего значения), фильтрация списка по набору, мультивыбор;
- чекбокс, переключатели, группы форм — следующий пункт `TODO.md`;
- изменения `gterm` и рендереров; новые зависимости.

## 3. Контракты

- Текст доставляется ровно одному контролу — под фокусом (слоя, если он есть); контрол без `text()` отвечает «не обработано», и текст возвращается приложению.
- `TextInputState`: `0 ≤ cursor ≤ value.chars().count()`; после любой операции инвариант держится; `Changed` публикуется только при фактическом изменении `value`, `Submitted` — на `Enter` всегда (и при пустом значении).
- Отрисовка поля: символы с `scroll` по ширине области, курсор виден всегда под фокусом; без фокуса ячейки без обмена fg/bg; `placeholder` только при пустом значении.
- `ComboBoxState`: `open` ставится контролом (раскрытие) и его списком (выбор); закрытие по `Esc`/клику мимо — только сообщением приложения через `on_close`; `Selected` — только при изменении `selected`.
- `Modal::at(area)` не меняет поведение `centered`; `on_click_outside` срабатывает один раз за маршрутизацию и только на левое нажатие вне области; остальное поглощается как прежде.
- Тесты части 1 и ADR-0026 — без изменения ожиданий; `gterm` не меняется (`git diff --stat crates/gterm` пуст).

## 5. Риски

- Текст IME приходит отдельно от клавиш: порядок `on_key` → `on_text` за одно нажатие гарантирует `winit`; поле не должно обрабатывать символьные клавиши в `key()` (иначе двойной ввод) — закреплено в п. 2 («остальные клавиши — не обработано»).
- `WidgetEvent::Changed(String)` клонирует строку на каждое нажатие — приемлемо для однострочного поля; многострочный редактор — не в этой задаче.
- Раскрытый список — слой в описании: приложение держит `open` в состоянии контрола, но закрытие по `Esc`/клику мимо проходит через сообщение (`on_close`) — одна лишняя ветка `update` на каждый список. Смягчение: `on_close` ставит обе привязки сразу.
- Высота слоя списка ограничена сеткой: при нехватке места снизу слой уходит вверх, при нехватке и сверху — обрезается по сетке (`Rect::intersection`).
- Курсор без мигания (ADR-0012): видимость обеспечивает контраст обмена fg/bg; на полях с одинаковыми fg/bg курсор невидим — `focus_style` примера задаёт контраст.
