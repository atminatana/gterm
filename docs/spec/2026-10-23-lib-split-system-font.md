# ТЗ: библиотека `gterm` отдельно от `assets/` и бинарников; системный моноширинный шрифт по умолчанию

- **Идентификатор:** `2026-10-23-lib-split-system-font`
- **Дата:** 2026-10-23
- **Статус:** утверждено владельцем 2026-10-23 (О1-a — workspace, О2-a — шрифт тестов из `../gterm-demo/assets`, О3-a — `fontdb`, О4-a — `assets/`, иначе системный, О5 — `gterm-demo`; К13 и минимальный пример добавлены по указанию владельца)
- **Основа:** ТЗ §1 («библиотека (crate) + демонстрационный бинарник, чтобы модуль отображения можно было встроить в другие продукты»), FR-8…FR-8.6, NFR-1, NFR-3, §5.1; ADR-0003 (семейство из `assets/`), ADR-0005, ADR-0008 (SVG из `assets/svg/`); текущий код `src/font.rs`, `src/svg.rs`, `src/bin/demo/common.rs`, `tests/common/mod.rs`.

## 0. Текущее состояние (факты, по коду)

- Один крейт `gterm`: библиотека (`src/lib.rs`) + три бинарника (`demo`, `full_table`, `overlay`) + `assets/` (четыре TTF Nerd Font по ≈ 2,57 МБ — 10,3 МБ, и четыре SVG-тайла демо). `Cargo.toml`: `default-run = "demo"`, четыре `[[test]]` с `harness = false`.
- `App::new(title, screen, rasterizer, config, options)` принимает **готовый** `Rasterizer` — поиск и загрузка шрифта уже лежат на приложении (`common.rs: load_family/load_rasterizer`), библиотека шрифт сама не ищет.
- Библиотеку к `assets/` привязывают: константы `FONT_FAMILY = "RobotoMono Nerd Font Mono"`, `ASSETS_DIR_NAME`, `FONTS_DIR_NAME`; функция `find_assets_dir()` (зависимость `find_folder`) и `fonts_dir()` в `font.rs`; `svg_dir()` в `svg.rs`; `FontFamily::load(assets_dir)` читает только `assets/fonts/` и оставляет файлы, у которых `name` ID 1 равен `FONT_FAMILY`; `FontError::AssetsDirNotFound`, `NoRegularFace { family: &'static str }` с `FONT_FAMILY` внутри `from_faces`.
- `find_assets_dir()` вне библиотеки используют только бинарники (`common.rs`) и один тест (`stage2_font::find_assets_dir_locates_repo_assets_from_test_cwd`).
- Тесты (`tests/common/mod.rs`, `tests/events_common/mod.rs`, `tests/stage2_font.rs`, `tests/stage3_render.rs`) берут шрифт по `CARGO_MANIFEST_DIR/assets`. Golden-эталоны `tests/golden/soft_golden_{16,32}px.bin` — растр именно этого шрифта; системные шрифты от машины к машине разные, поэтому golden, `stage4_gl` и сцены `stage6_*` обязаны остаться на шрифте репозитория.
- Иконки Nerd Font нужны демо: `full_table` считает страницы по числу глифов этого шрифта (`src/bin/full_table/main.rs:353`), сцена `demo` показывает тайлы `assets/svg/`.
- Зависимостей для системных шрифтов в `Cargo.lock` нет (`fontdb`, `font-kit`, `fontconfig` отсутствуют); `usvg 0.48` подключён без фич `text`/`system-fonts`. В реестре: `fontdb 0.24.0`, MSRV 1.71, фичи `std`, `fs`, `memmap`, `fontconfig` (по умолчанию все четыре).

## 1. Цель

Сделать `gterm` встраиваемой библиотекой (ТЗ §1): крейт библиотеки не содержит `assets/`, демо-бинарников и кода поиска каталога ресурсов рядом с exe; шрифт задаётся приложением явно, а при отсутствии явного — библиотека находит **системный моноширинный шрифт** сама. Демо-бинарники и `assets/` живут отдельно от библиотеки и зависят от неё как обычный потребитель.

## 2. Границы

**Входит:**

1. **Разделение на крейты** (форма — О1): библиотека `gterm` (имя крейта сохраняется — `AGENTS.md`) без `assets/`, без бинарников и без `find_folder`; крейт демо (рабочее имя `gterm-demo`) с бинарниками `demo`, `full_table`, `overlay`, общей обвязкой `common.rs` (обычный модуль вместо `#[path]`), каталогом `assets/` и `find_folder`. Интеграционные тесты библиотеки остаются в крейте библиотеки (шрифт для них — О2).
2. **API шрифта без привязки к `assets/`** (`src/font.rs`):
   - семейство задаётся параметром, а не константой: `FontFamily::load(dir, family)` — все `*.ttf`/`*.otf` каталога `dir` с `name` ID 1 == `family` (правила FR-8.1/FR-8.2 без изменений, подкаталог `fonts/` каталог не подразумевает — его добавляет приложение); `FontFamily::from_faces` — как сейчас, имя семейства в ошибке `NoRegularFace` — `String`;
   - `FontFamily::from_files(paths, family)` — явный список файлов (приложение само знает, где шрифт);
   - константа `FONT_FAMILY`, `ASSETS_DIR_NAME`, `FONTS_DIR_NAME`, `find_assets_dir`, `fonts_dir`, `FontError::AssetsDirNotFound` уходят из библиотеки в крейт демо; `svg_dir` — тоже (загрузка `SvgGlyphs::load(dir)` по произвольному каталогу остаётся в библиотеке);
   - **проверка моноширинности**: загруженное начертание Regular считается моноширинным, если advance всех глифов контрольного набора (`M`, `i`, `.`, `W`, `0`, пробел) равен advance `M` (с учётом округления до пикселя при `FONT_SIZE_PX`); иначе — `FontError::NotMonospace { family, glyph, advance }`. Пропорциональный шрифт в сетке ячеек даёт обрезанные глифы (FR-9, FR-13), это не должно проходить молча.
3. **Системный моноширинный шрифт** (новый модуль библиотеки, рабочее имя `font::system`; механизм — О3):
   - `FontFamily::system(family: &str)` — семейство по имени среди установленных в системе шрифтов (те же правила отбора начертаний по `OS/2`, что для каталога);
   - `FontFamily::system_monospace()` — «моноширинный по умолчанию»: обобщённое семейство `monospace` платформы (fontconfig на Linux; на Windows — встроенный список кандидатов в порядке предпочтения: `Cascadia Mono`, `Consolas`, `Lucida Console`, `Courier New`; на Linux без fontconfig — `DejaVu Sans Mono`, `Liberation Mono`, `Noto Sans Mono`, `FreeMono`), первое семейство, у которого есть Regular и которое проходит проверку моноширинности; ни одно не нашлось — `FontError::NoSystemMonospace { tried: Vec<String> }`;
   - каталоги системных шрифтов: Windows — `%WINDIR%\Fonts` и `%LOCALAPPDATA%\Microsoft\Windows\Fonts`; Linux — каталоги fontconfig либо, без него, `/usr/share/fonts`, `/usr/local/share/fonts`, `~/.fonts`, `~/.local/share/fonts`; платформы — §4.1 ТЗ;
   - выбор детерминирован (порядок кандидатов и сортировка путей фиксированы); какой файл за какое начертание отвечает — в stderr при старте, как по FR-8.3; ошибки чтения отдельных файлов — пропуск файла, не остановка;
   - пути поиска читаются один раз при вызове; в горячий путь кадра ничего не добавляется (NFR-6).
4. **Умолчание в демо** (порядок — О4): без флагов `demo`/`full_table`/`overlay` берут шрифт по цепочке О4; флаг `--system-font` принудительно включает путь `system_monospace()` (нужен для проверки на машине, где `assets/` есть); семейство из `assets/` — по-прежнему `RobotoMono Nerd Font Mono` (константа переезжает в демо).
5. **Сборка и команды**: корневой `Cargo.toml` — `[workspace]` (О1); `cargo test` в корне гоняет все крейты; `cargo run --bin demo` (и `full_table`, `overlay`) работает из корня; четыре `[[test]] harness = false` переезжают в манифест библиотеки; `Cargo.lock` один на workspace. `AGENTS.md`, `PROJECT_MAP.md`, ТЗ (§1, FR-8, FR-8.1, FR-8.5, NFR-3, §5.1, §10.1) актуализируются до версии 1.14.
6. Размер release-бинарников замеряется до и после (NFR-1): вклад системного поиска шрифтов и разница от выноса `find_folder`.
7. Тесты по TR, ADR на принятые решения О1–О4 (один ADR на структуру крейтов, один — на источник шрифта; может быть объединён, если решения взаимосвязаны).
8. **Минимальный пример** `crates/gterm/examples/minimal.rs` — потребитель библиотеки без `assets/`: зависит только от `gterm` (и `winit` для типов событий, как любой `AppHandler`), шрифт — `FontFamily::system_monospace()`, сцена — несколько строк текста и рамка псевдографики; запуск `cargo run -p gterm --example minimal`. Пример — живое доказательство контракта §3 «библиотека без ресурсов рядом с exe».

**Не входит:**

- выбор семейства из командной строки или файла настроек (`--font=<family>`, `FONT_SCALE`) — только `--system-font`; подключение «будущего файла настроек» (FR-8) остаётся отдельной задачей;
- публикация на crates.io, `include`/`exclude` в манифесте, семантическое версионирование библиотеки;
- несколько шрифтов одновременно и подстановка глифов из другого шрифта (§13 «Несколько шрифтов»): иконки Nerd Font при системном шрифте — пустые ячейки (слот 0), это ожидаемо;
- горячая смена шрифта на лету, перечитывание системных каталогов после старта;
- изменение рендереров, атласа, растеризатора, `App`/`AppHandler`, формата golden;
- установка/копирование шрифтов, поставка `assets/` инсталлятором.

## 3. Контракты

- **Публичный API библиотеки** по шрифту меняется (несовместимо, библиотека 0.x): `FontFamily::load(dir, family)`, `from_files`, `system`, `system_monospace`; `FontError` — новые варианты `NotMonospace`, `NoSystemMonospace`, убран `AssetsDirNotFound`, `NoRegularFace.family: String`. Всё остальное (`Rasterizer`, `Atlas`, `App`, `AppOptions`, `Config`, рендереры) — без изменений сигнатур.
- Библиотека **не ищет** каталогов относительно exe или cwd и **не содержит** имени конкретного шрифта: единственное знание о «умолчании» — список обобщённых моноширинных семейств платформы в `font::system`.
- Семейство из каталога/файлов/системы, загруженное одними и теми же TTF, даёт тот же `FontFamily` (те же `faces`, `style_source`, метрики): golden и `stage4_gl` на шрифте репозитория не меняются ни байтом, эталоны не перезаписываются.
- Нет системного моноширинного шрифта, нет Regular, шрифт пропорциональный → ошибка `FontError` с понятным текстом; приложение завершается по FR-8.5 (код ≠ 0, сообщение в stderr). Паник нет (NFR-7).
- Зависимость для системных шрифтов (О3) — `default-features = false` с минимальным набором фич (§10.2); `unsafe` в коде проекта не добавляется (NFR-9 — о коде проекта; `unsafe` внутри зависимости, как у `winit`/`softbuffer`, не считается). Уточнение 2026-10-23 по исходникам `fontdb 0.24`: без фичи `memmap` он читает каждый файл системных каталогов целиком (`std::fs::read`), с `memmap` — отображает файл и разбирает только таблицы заголовка; включается `memmap` (подтверждено владельцем 2026-10-23), задержка старта замеряется (К5).
- Демо после установки **без** `assets/` рядом с exe запускается на системном шрифте (вариант О4 определяет, когда ещё).

## 5. Риски (принятые осознанно)

- Поиск системных шрифтов открывает все файлы системных каталогов при старте (сотни файлов на типичной Windows; с `memmap` читаются только таблицы заголовка): задержка старта замеряется в отчёте (К5); если больше ≈ 100 мс — отдельным решением владельца: собственный обход с разбором только `name`/`OS/2` (вариант О3-b).
- Системный шрифт не покрывает иконки Nerd Font и глифы вне BMP: `full_table` при `--system-font` показывает меньше страниц; сцена `demo` — пустые ячейки на месте иконок. Это следствие §13 «Несколько шрифтов» (не делается).
- Несовместимое изменение API `FontFamily` — библиотека 0.x, внешних потребителей пока нет.
- Тесты библиотеки читают шрифт из соседнего крейта (вариант О2-a): `cargo test` из распакованного опубликованного пакета библиотеки без репозитория не проходит — публикация не в объёме задачи.

## 6. Открытые решения (AR-04 — решает владелец; после решения — ADR, статус `Accepted`)

**О1. Форма разделения.**
- (a) **Рекомендуется:** workspace в этом же репозитории: `crates/gterm/` (библиотека + её тесты) и `crates/gterm-demo/` (бинарники, `common.rs`, `assets/`); корневой `Cargo.toml` — только `[workspace]`. История git сохраняется (`git mv`), один `Cargo.lock`, потребители подключают библиотеку через `path`/`git` и не тянут `assets/` в сборку.
- (b) Бинарники — в `examples/` того же крейта, `assets/` остаётся в корне: минимальный diff, но `assets/` и демо-код по-прежнему внутри пакета библиотеки — цель §1 достигается лишь формально.
- (c) Два репозитория: библиотека и демо. Максимальное разделение, но ломает единые гейты (`cargo test` одной командой), golden-тесты библиотеки теряют шрифт, двойная история.

**О2. Шрифт для тестов библиотеки** (golden требует именно Nerd Font).
- (a) **Рекомендуется:** тесты библиотеки берут `../gterm-demo/assets/fonts/` через единый помощник `tests/common::repo_assets_dir` (четыре места в тестах); дублирования 10 МБ нет; цена — зависимость тестов от соседнего крейта (риск §5).
- (b) Копия четырёх TTF в `crates/gterm/tests/data/fonts/` (+10,3 МБ в репозитории), тесты полностью автономны.
- (c) `assets/` остаётся в корне workspace и не принадлежит ни одному крейту: демо находит его `find_folder` от exe (как сейчас), тесты — `../../assets`; поставка демо копирует `assets/` рядом с exe по §5.1.

**О3. Механизм поиска системных шрифтов.**
- (a) **Принято:** `fontdb 0.24` с `default-features = false, features = ["fs", "memmap", "fontconfig"]` (`memmap` — чтобы не читать все системные шрифты целиком при старте; `unsafe` — внутри зависимости, NFR-9 не нарушается): каталоги Windows и Linux (§4.1), разбор fontconfig для `monospace` на Linux, запрос `Family::Monospace`; чисто Rust, MSRV 1.71 ≤ 1.85. Вклад в размер замеряется (К11) — оценка по `usvg`-соседям: порядка 100–200 КБ, подтверждается только замером.
- (b) Собственный обход: фиксированные каталоги платформ + разбор `name`/`OS/2` уже имеющимся `skrifa`; без новой зависимости и минимальный размер, но нет fontconfig (на Linux — только встроенный список кандидатов), список каталогов поддерживается вручную.
- (c) `font-kit`: обёртки DirectWrite/fontconfig/CoreText — внешние C-зависимости и `unsafe`, противоречит NFR-3/NFR-9. Не рекомендуется.

**О4. Умолчание демо-бинарников.**
- (a) **Рекомендуется:** `assets/fonts/` рядом с exe/в репозитории, если найден (иконки, SVG-тайлы, сопоставимость `--bench` с прежними замерами) → иначе системный моноширинный; `--system-font` — принудительно системный.
- (b) Системный моноширинный всегда; `assets/` — только по флагу `--assets-font`. Демо по умолчанию теряет иконки и сопоставимость `--bench`.
- (c) Только `assets/` (как сейчас); системный шрифт — только в API библиотеки для внешних потребителей, демо его не демонстрирует. Не рекомендуется: К5/К8 нечем проверить.

**О5. Имя крейта демо и бинарников.** `gterm-demo` с бинарниками `demo`, `full_table`, `overlay` (команды меняются на `cargo run --bin demo`), либо иное имя по указанию владельца. Имя библиотеки `gterm` не меняется.
