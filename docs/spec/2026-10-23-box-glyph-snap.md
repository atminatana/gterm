# ТЗ: выравнивание вписанных рамок по пиксельной сетке (вариант Г)

- **Идентификатор:** `2026-10-23-box-glyph-snap`
- **Дата:** 2026-10-23
- **Статус:** утверждено постановкой владельца 2026-10-23 («Г» — после отказа от А поверх Б)
- **Основа:** ADR-0020 (рамки из шрифта вписываются в ячейку без хинтинга), факт: без хинтинга штрихи дробной толщины лежат между пиксельными рядами — у шрифта репозитория 378 единиц краски на колонку `─` (≈ 1,5 px на две строки), линии сероватые; ADR-0002 (целые толщины процедурного пути).

## 1. Цель

После вписывания (ADR-0020) привести контур рамки к пиксельной сетке: координаты точек — целые пиксели, любой штрих — не тоньше 1 px. Линии становятся чёткими, целой толщины, при этом сохраняют рисунок шрифта: положение штрихов, зазор двойной линии, форму дуг (с огрублением).

## 2. Границы

**Входит:**
1. `snap_commands_to_cell_grid` в `rasterizer.rs`, вызывается после `fit_commands_to_cell` для тех же глифов (U+2500–U+259F в `Font`/`Combined`). По каждой оси: все различимые координаты (разница больше 1/64 px) сортируются, округляются к ближайшему целому и приводятся к строго возрастающим с шагом не меньше 1 px (штрих не схлопывается); результат зажимается в ячейку (`0…w`, `baseline − h…baseline`). Контрольные точки кривых обрабатываются так же.
2. Тест: в `Font` на шрифте репозитория `─`, `│`, `┼`, `═`, `║`, `╬`, `┏` состоят только из значений 0 и 255 (ни одного полутона), краска на колонку/строку — кратна 255 и не меньше 255; прежний тест равномерности краски остаётся зелёным.
3. ADR-0021, ТЗ 1.16 (FR-8.4 — дополнение абзаца о режимах), `AGENTS.md`, `PROJECT_MAP.md`, `TODO.md`, отчёты.

**Не входит:** хинтинг и выравнивание букв, SVG, процедурный путь; сглаживание дуг после округления (принимается огрубление); варианты А/В.

## 3. Контракты

- `Procedural` — умолчание, байт в байт прежнее; golden и прежние сцены `stage4_gl` не меняются.
- GL ↔ Software бит-идентичны; выравнивание — на промахе атласа; `unsafe` нет.
- Выравнивание монотонно: порядок координат сохраняется, две разные координаты не сливаются; при переполнении ячейки (толщины не помещаются) координаты зажимаются краями — штрих у края может потеряться только в вырожденно малой ячейке.

## 4. Критерии приёмки

| № | Критерий | Чем подтверждается |
|---|---|---|
| К1 | Умолчание не меняет вывод | `cargo test`: golden, прежние сцены `stage4_gl` |
| К2 | Прямые рамки в `Font` чёткие: только 0/255, краска кратна 255, ≥ 255 | новый тест; мутация без выравнивания падает (378 на колонку) |
| К3 | Равномерность краски по длине сохраняется | `font_box_glyphs_reach_cell_edges` |
| К4 | GL ↔ Software identical в `Font`/`Combined` | `stage4_gl` |
| К5 | Глазами: чёткость и стыки в `w`/`e` против `q` | владелец |
| К6 | Гейты, размер, документы | fmt, clippy, test; размеры; ADR-0021, ТЗ, карта, `AGENTS.md`, `TODO.md` |

## 5. Риски

- Дуги `╭╮╯╰` после округления контрольных точек теряют плавность — принято.
- Толщина после округления может отличаться от процедурной (например, 2 px против 1 px) — это рисунок шрифта, не дефект.
