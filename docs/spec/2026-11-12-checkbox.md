## 1. Цель

В формах есть флажок: контрол с подписью и состоянием «отмечен / не отмечен», который переключается клавиатурой и мышью и сообщает приложению новое значение. Группа флажков оформляется существующим `Ui::group`.

## 2. Границы

**Входит — `crates/gterm-widgets`:**

1. **`CheckboxState`** (`src/widgets/checkbox.rs`): `node`, `enabled`, `checked`, `pressed`; `new()`, `checked(bool)`, `disabled()`, `toggle()`, `set_checked(bool)` (программная смена события не даёт — как `TextInputState::set_value`).
2. **Поведение (`Control`):** фокусируется, если активен; пробел переключает (О2); мышь — как у кнопки: левое нажатие в области даёт захват, отпускание внутри переключает, отпускание снаружи или уход указателя — отмена; кликабельна вся область, включая подпись.
3. **Событие и привязка:** `WidgetEvent::Toggled(bool)` → `Ui::on_toggle(impl Fn(bool) -> M)`; у остальных узлов привязка не действует.
4. **Вид `Checkbox`:** метка и подпись в одну строку слева — `[x] подпись` / `[ ] подпись` (О3); метки настраиваются `Checkbox::marks(checked, unchecked)`; стили `style`, `focus_style`, `pressed_style`, `disabled_style` — с теми же правилами наложения, что у `Button`.
5. **Группа:** новых типов нет — `Ui::group` с рамкой и заголовком (О5); пример показывает группу флажков с подсветкой рамки под фокусом.
6. **Пример** `widget_edit`: группа «Параметры» с двумя флажками, значения — в строке статуса и в итоге «Применить».
7. **Тесты** без окна: переключение пробелом и мышью (отпускание внутри/снаружи, отмена), событие и привязка `on_toggle`, неактивный флажок, программная смена без события, отрисовка меток и стилей по состояниям, флажки в группе — обход `Tab` и подсветка рамки.

**Документы:** ADR-0031 (после утверждения), ТЗ проекта §13 (версия 1.26), `AGENTS.md`, `PROJECT_MAP.md`, `TODO.md`, план и отчёты, размеры release.

**Не входит:**

- переключатели «один из многих» (radio) и третье состояние флажка (О1, О4);
- блокировка группы целиком, сворачиваемые группы;
- изменения `gterm`.

## 3. Контракты

- `checked` меняется только действием пользователя (с событием `Toggled(новое значение)`) либо `set_checked`/`toggle` приложения (без события у `set_checked`).
- Неактивный флажок не фокусируется, не переключается и рисуется `disabled_style`.
- Одно действие пользователя — одно событие.
- Клавиши, которые флажок не принимает, идут прежним путём (карта сочетаний, приложение).
- Существующие контролы и `Ui::group` не меняются.

## 4. Критерии приёмки

| № | Критерий | Чем подтверждается |
|---|---|---|
| К1 | Переключение пробелом; прочие клавиши не принимаются | тесты без окна |
| К2 | Мышь: отпускание внутри переключает, снаружи и уход указателя — отмена, захват | тесты без окна |
| К3 | `Toggled(bool)` → сообщение по `on_toggle`; программная смена без события | тесты без окна |
| К4 | Неактивный флажок: без фокуса и реакции, свой стиль | тесты без окна |
| К5 | Отрисовка: метки, подпись, стили обычный/фокус/нажат/неактивный, свои метки | тесты по снимкам |
| К6 | Флажки в `Ui::group`: обход `Tab`, рамка под фокусом | тесты без окна |
| К7 | Пример `widget_edit` с группой флажков | сборка; запуск с инжекцией; глазами — владелец |
| К8 | Гейты, размеры release, документы | `fmt`, `clippy --all-targets -D warnings`, `cargo test`; размеры; ADR-0031, документы, отчёты |

## 5. Риски

- Новый вариант `WidgetEvent::Toggled` — перечисление публичное; внешний код с исчерпывающим `match` по нему перестанет собираться (в репозитории такой `match` один — в `ui/element.rs`).
- Метки `☑`/`☐` зависят от шрифта; `[x]`/`[ ]` рисуются любым.

## 6. Открытые вопросы

- **О1. Переключатели «один из многих» (radio).** (a) **Рекомендуется:** не в этой задаче — в постановке их нет; при необходимости отдельной задачей на том же механизме; (b) включить сейчас (`RadioGroup` с выбором одного из N).
- **О2. Клавиши переключения.** (a) **Рекомендуется:** только пробел — `Enter` остаётся свободным для «Применить» формы (карта сочетаний, приложение); (b) пробел и `Enter`, как у кнопки.
- **О3. Метки по умолчанию.** (a) **Рекомендуется:** `[x]` / `[ ]` — рисуются любым шрифтом, свои метки задаются `marks`; (b) `☑` / `☐`.
- **О4. Третье состояние** («частично отмечен»). (a) **Рекомендуется:** нет; (b) да.
- **О5. Группа.** (a) **Рекомендуется:** существующий `Ui::group` — рамка `Block` с заголовком и подсветкой под фокусом уже есть, новых типов не нужно; (b) нужно что-то сверх этого (блокировка группы целиком, общий заголовок-флажок) — что именно.
