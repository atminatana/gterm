# AGENTS.md

## Цель

`gterm` — терминальный эмулятор консоли: сетка из ячеек, отображаемая либо шейдером OpenGL, либо CPU-рендерером, с автоматическим переключением GL → GLES → Software. Основательный дизайн-спецификация `docs/TZ_terminal_emulator.md` (русский, версия 1.1; требования FR-1…FR-28, NFR-1…NFR-9, этапы в §12). **Читать соответствующую секцию перед любым проектированием** — спецификация, а не интуиция, определяет решение. Архитектурные решения — в `docs/adr/` (индекс `docs/adr/README.md`).

**Состояние** (этапы 1–7 из §12 сделаны): workspace (ADR-0017) из библиотеки `crates/gterm/`, пакета демо `crates/gterm-demo/` и крейта виджетов `crates/gterm-widgets/` (ADR-0023: немедленный режим по образцу ratatui — `Widget`/`StatefulWidget`, `Layout`/`Constraint` (жадная раскладка), `Span/Line/Text`, `Style` с альфой; рисует прямо в `ScreenBuffer` через `BufferExt`; часть 1 — `Block` (пять видов процедурных рамок), `Paragraph`, `List`, `Table`, `Popup` через наложение; часть 2 (ADR-0032) — `Clear`, `Gauge` (заливка с точностью до 1/8 ячейки процедурными блоками, включено по умолчанию), `LineGauge`, `Meter` (ADR-0034, `src/widgets/meter.rs`: индикатор уровня — зоны «порог → стиль», цвет ячейки по её месту на шкале, заполнение с точностью до половины ячейки `█`/`▌`/`░`, отметка пика целой ячейкой; виджет-значение без состояния), `Tabs`/`TabsState` — контрол (`←`/`→`/`Home`/`End`, клик по заголовку, `on_select`; число и колонки вкладок состояние узнаёт на отрисовке), `Scrollbar`/`ScrollbarState` — сам по себе только отображение (`Widget` со `state(...)`), а у списка полоса своя: `List::scrollbar(...)` — список рисует её в последней колонке с точным смещением своего кадра и сам обрабатывает мышь на ней (стрелки — на пункт, дорожка — на страницу, ползунок тянется под захватом; разметка `BarLayout` в `ListState`); прокрутка полосой выделение не меняет, смещение подгоняется под выделение только при смене выделения, высоты или числа пунктов; `ListState::scroll_by`/`scroll_to`; удержанная на стрелке или дорожке кнопка листает повторно по тактам времени: приложение зовёт `Ui::tick(Instant::now())` из `on_frame`, ответ `Yes` — перерисовать и `ctx.redraw()` (`Control::tick`; задержка `Scrollbar::REPEAT_DELAY` 400 мс, шаг `REPEAT_INTERVAL` 50 мс; таймеров у виджетов нет); контролы — ADR-0026: приложение описывает экран один раз функцией `ui()` → `Ui<'_, M>` из `&mut` на свои состояния (`Ui::split`/`group`/`control`/`stateful`/`widget`, модуль `src/ui/`), дерево раскладывает, рисует, водит фокус по `Tab`/`Shift+Tab` по кольцу листьев (контейнеры прозрачны), доставляет клавиши фокусу и мышь верхнему контролу под ячейкой с захватом до отпускания, непринятое возвращает приложению; `←`/`→` — шаг, `Home`/`End` — границы, в границе клавиша принята без события; дорожка — вся область узла, левое нажатие ставит значение по колонке и берёт захват, протяжка до отпускания, `Cancel` оставляет значение, колесо — шаг; `ListState`/`TableState` — только по строке, не по полосе прокрутки и заголовку; неактивные кнопка и флажок — нет); признак — `MouseMsg::click_count`/`is_double_click()`, часов у контролов нет, тесты подают `MouseMsg { click_count: 2, .. }`, `ListState`/`TableState` — контролы с картой строк для клика (`src/widgets/selection.rs`); ADR-0027: текст — вход `Control::text`: обычный набор дерево берёт из `KeyEvent.text` клавиши, не принятой контролом (`KeyMsg::typed_text`, без `Ctrl`/`Alt`/`Super` и управляющих символов), IME-композицию — из `on_text` через `Ui::text` (`winit` отдаёт одно из двух для одного нажатия), `TextInput`/`TextInputState` (`src/widgets/text_input.rs`: вставка в курсор, `Backspace`/`Delete`, стрелки, `Home`/`End`, `Enter` → `on_submit`, `on_change`, прокрутка держит курсор видимым, курсор обменом fg/bg только под фокусом, `placeholder`; ADR-0030 — выделение: якорь в состоянии, `Shift`+стрелки/`Home`/`End`, протяжка мышью под захватом, `Shift`+клик, набор и удаление заменяют выделенное, `selection_style`), `ComboBox`/`ComboBoxState` (`src/widgets/combo_box.rs`): поле и слой списка строит `Ui::combo_box(widget, &mut state, on_select)` — слой `Modal::below` под полем (над — при нехватке места) поднимается к корню описания, закрывается выбором, `Esc` и кликом мимо сам (`Modal::dismiss_on_click_outside` → `Control::dismiss`); слой также умеет `Modal::at`, `on_click_outside`, `on_close`; `Ui::owned` — контрол, которым владеет описание; `gterm` о крейте не знает); пути `src/…` и `tests/…` ниже — внутри `crates/gterm/`, `src/bin/…` и `assets/` — внутри `crates/gterm-demo/`. Библиотека: `src/lib.rs` + модули `cell`, `buffer`, `font` (+ `font/system.rs` — системные шрифты), `rasterizer`, `atlas`, `box_drawing`, `block_mosaic`, `shapes`, `procedural` (диспетчер процедурной псевдографики — ADR-0022), `svg`, `config`, `app`, `renderer/{soft,gl}_backend`; тесты в `tests/`, golden-эталоны `tests/golden/soft_golden_{16,32}px.bin`; примеры `examples/minimal.rs` — потребитель без `assets/` (`cargo run -p gterm --example minimal`) и `examples/pseudographica.rs` — режимы псевдографики (ADR-0018). Демо: бинарники `src/bin/demo/` (`cargo run --bin demo`; `--bench` — замер NFR-4/NFR-5), `src/bin/full_table/` (таблица всех глифов блоками 2×2 в цветах палитры — FR-27.1) и `src/bin/overlay/`; общий код — библиотечная цель `gterm_demo::{assets, common}`; каталог `assets/`; `find_folder` — только здесь. CI нет. **Комбинации клавиш** (ADR-0028): модуль `src/hotkey.rs` вне цикла событий — `Key` по `physical_key` (левый/правый модификатор — один; имена по таблице всех `KeyCode`: `A`–`Z`, `0`–`9`, `F1`–`F35`, `Up`/`Down`/`Left`/`Right`, `Esc`, знаки `Comma`/`BracketLeft`/…), дерево удержаний `Hotkey` (`Ctrl+K`, `Ctrl+[K,U]`, `Space+[Ctrl+[K,U]]`, `K,U`; образцы `K|U`; подряд удержанные модификаторы — множество в порядке `Ctrl`, `Alt`, `Shift`, `Super`), `Display`/`FromStr` с позицией ошибки, `matches`; `HotkeyTracker::feed(&KeyEvent)` — `full`/`current`, сигнал `HotkeyEvent { hotkey, complete }` на каждое отпускание (цепочка удержанных включая отпускаемую), при последнем — `full`; автоповтор и чужие отпускания игнорируются, `reset()`. **`on_key` получает и отпускания** — фильтр `Pressed` снят, состояние проверяет приложение (все обработчики репозитория проверяют; контролам `Ui::key` отпускания не доставляет). Пример — `cargo run -p gterm --example hotkeys`. **Карта сочетаний** (ADR-0029): `gterm_widgets::HotkeyMap<M>` (`src/hotkeys.rs`; `bind`/`bind_str`, `M: Clone`) и `HotkeyTracker` лежат в состоянии приложения, подключение — `Ui::hotkeys(&mut tracker, &map)` на экране и `Modal::hotkeys(&map)` у слоя; `Ui::key` кормит трекер каждым событием клавиши (обработчики примеров передают в него и отпускания), нажатие, не принятое контролом под фокусом, сопоставляется с картой — полная история `full()`, затем цепочка удержанных `current()`, срабатывает одна привязка; при модальном слое действует только его карта (после `on_escape`); автоповтор привязку не вызывает; акселераторов `Alt+буква` нет; точка входа тестов без окна — `Ui::route_key_event`. **`AppHandler::on_focus(focused, ctx)`** — из `WindowEvent::Focused`; библиотека трекер не сбрасывает — `reset()` при потере фокуса вызывает приложение. **Буфер обмена и команды правки** (ADR-0030, `gterm-widgets/src/clipboard.rs`): трейт `Clipboard` (`get`/`set`/`is_available`) — объект в состоянии приложения, подключение `Ui::clipboard(&mut …)`; `MemoryClipboard` — в памяти (тесты), `SystemClipboard` — на `arboard` за фичей `system-clipboard` (по умолчанию; ошибки не паникуют, причина один раз в stderr); `EditCommand::{Copy, Cut, Paste, SelectAll}` дерево распознаёт в `route_key_event` по физической клавише (`Ctrl+C`/`Ctrl+Insert`, `Ctrl+X`/`Shift+Delete`, `Ctrl+V`/`Shift+Insert`, `Ctrl+A`; модификаторы — ровно названные) и передаёт контролу под фокусом (`Control::edit`) **до** обычной доставки клавиши; `TextInput` команды поглощает всегда (без подключённого или при недоступном буфере вырезание текст не удаляет), остальные контролы пропускают их в карту сочетаний; вставка — перевод строки и табуляция → пробел. `Ctx` несёт `stats: FrameStats`, у `AppHandler` есть `on_frame` (ADR-0006); `Ctx::modifiers` (состояние `ModifiersChanged`) и `Ctx::cell_px`, а `PointerEvent::{Moved, Input, Wheel}` — ячейку под указателем `cell` с учётом центрирования сетки в окне (`app::pointer_cell`, ADR-0026); `PointerEvent::Input::click_count` — номер нажатия подряд, который считает окно (ADR-0035, `src/app/clicks.rs`, время аргументом, unit-тесты в модуле): 2 — второе нажатие левой кнопки в той же ячейке не позже 500 мс включительно, после двойного счёт заново, другая кнопка — 1. Флаги ячейки — только `BOLD`/`ITALIC`/`UNDERLINE` (биты 0–2, те же `F_*` в `cell.frag`); мигания и `INVERSE` в библиотеке нет (ADR-0012). **Тик приложения** (ADR-0033, частично заменяет ADR-0012): `AppOptions::tick_period` и `Request::tick_period` (`Some(None)` выключает) → `AppHandler::on_tick`; состояние — `src/app/tick.rs`, срок проверяется в `about_to_wait` (`src/app/events.rs`), ожидание — `WaitUntil` до срока, без периода — прежний `ControlFlow::Wait`; отставание не догоняется (следующий срок — от возврата из обработчика), кадр тик не запрашивает; таймеров у виджетов по-прежнему нет. `Color` — `0xAARRGGBB`: альфа fg и bg участвует в смешивании; поле вокруг сетки и подложку задаёт фон буфера (`ScreenBuffer::set_background`), `ViewParams` упразднён — `Renderer::render(screen)` (ADR-0013). Наложение клиентских буферов: `AppHandler::on_redraw` + `DrawCtx::draw_buffer` (копия, порядок вызовов = слои, обрезка по сетке), `Renderer::render_overlaid`, текстура с предумноженной альфой, в GL — проход `overlay.frag` на запись; пример — `cargo run --bin overlay` (ADR-0014). Попиксельные функции Software — `#[inline(always)]`, деление на 255 — `div255`: при `opt-level = "z"` иначе Software теряет в 2–3 раза (ADR-0014). Текстура наложения Software пересобирается только при смене записей, размера сетки или метрик ячейки; R и B (в `over` ещё A и G) считаются парой в одном умножении (`div255_pair`), равенство поканальным формулам держит `tests/soft_pixel_math.rs` (ADR-0015); арифметика — `src/renderer/pixel.rs`. Кадр и текстура рисуются полосами строк в пуле `rayon` (`min(ядра, 4)`, меньше 8 строк — в текущем потоке); отрисовка полосы — `src/renderer/soft_band.rs`, одна для 1 и N потоков; равенство кадров 1 ↔ 4 потока — `tests/soft_threads.rs`, 0 выделений в кадре — `tests/soft_threads_alloc.rs` (отдельный бинарник со счётчиком выделений) (ADR-0016). **Software-рендерер — эталонная реализация §7.3** (бит-идентичность с GL сверяется по нему); перерисовываются только dirty-строки, в окно выводятся только перерисованные полосы (ADR-0010, ADR-0012) — инвариант «частичный кадр = кадр с нуля» держат `tests/soft_partial_redraw.rs` и третий кадр `stage4_gl`. GL-бэкенд (`gl_backend.rs`, весь `unsafe`) бит-идентичен Software — проверяется `tests/stage4_gl.rs` на обоих уровнях (GL 3.3, GLES 3.0) и в том числе после смены DPI. Окно и цикл — каталог `src/app/` (ADR-0011): цепочка уровней и откат по `config.rs` — `chain.rs`, окно, сетка и DPI — `window.rs`, кадр и повтор — `frame.rs`, вывод Software в окно — `backend.rs`, события `winit` — `events.rs`, контракт для приложений — `api.rs`, параметры и ошибки — `options.rs`, сама `App` — `mod.rs`. Карта — `PROJECT_MAP.md`, артефакты задач — `docs/plans|done|test|verify/`.

**Размер и DPI (ТЗ 1.3, ADR-0005)**: целочисленного масштаба **нет** — `ViewParams.scale`, uniform `u_scale` и `fill_block` упразднены. Единственный источник геометрии — метрики растеризации: `glyph_px = clamp(round(FONT_SIZE_PX · FONT_SCALE · scale_factor), 8, 48)`, ячейка = `glyph_w × glyph_h`, сетка = окно ÷ ячейка. `FONT_SCALE = 1.0` — константа (будущий файл настроек), зума `+`/`-` нет. **Курсор убран из библиотеки** (ADR-0004) — рисует приложение (ADR-0004, ТЗ §13); мигания в `gterm` тоже нет (ADR-0012). События приложения — трейт `AppHandler` + `Ctx` (`app/api.rs`), типы `winit` не переводятся, `Esc` не перехватывается.

**Шрифт (ТЗ 1.2, ADR-0003, ADR-0017)**: ничего не вшито и не кэшируется на диске. Библиотека имени шрифта и каталогов не знает: `FontFamily::load(fonts_dir, family)` / `from_files(paths, family)` / `system(family)` / `system_monospace()` (системные шрифты — `fontdb` в `src/font/system.rs`: Windows — `Cascadia Mono`, `Consolas`, `Lucida Console`, `Courier New`; Linux — алиас fontconfig `monospace`, затем `DejaVu Sans Mono`, `Liberation Mono`, `Noto Sans Mono`, `FreeMono`); Regular проверяется на моноширинность (`FontError::NotMonospace`); среди файлов одного начертания предпочитается тот, чьи глифы несут родные инструкции хинтинга (`font::has_glyph_instructions`, ADR-0025) — у `Cascadia Mono`, установленной и как `.ttf`, и как `.otf`, берётся `.ttf`. Демо: семейство `FONT_FAMILY` из `assets/fonts/` (`gterm_demo::assets::find_assets_dir` — от exe, от cwd, затем каталог пакета), нет каталога или флаг `--system-font` — системный моноширинный (четыре начертания по `OS/2`, подстановка недостающих; источник и время выбора — в stderr). Глифы растеризуются **по требованию** (`src/rasterizer.rs`: `skrifa` + `zeno`, 8 бит покрытия; движок по шрифту — глифы с родными инструкциями → интерпретатор с целью `Mono`, без них → автохинтер с целью `Smooth/Normal`, ADR-0025: в `Mono` автохинтер даёт 2-пиксельные стойки и сжатые буквы) в **динамический атлас** (`src/atlas.rs`): одна страница `RGBA8` ≤ 2048², каналы = начертания (R/G/B/A = Regular/Bold/Italic/BoldItalic), один слот на кодовую точку, переполнение → сброс. Псевдографика — по умолчанию процедурно: рамки и блоки U+2500–U+259F (`src/box_drawing.rs`), мозаики (секстанты, октанты, «Centered», восьмушки — `src/block_mosaic.rs`) и фигуры (круги, треугольники, ромб, диагонали — `src/shapes.rs`), диапазоны и диспетчер — `src/procedural.rs` (ADR-0022; таблицы узоров сгенерированы из имён Unicode 16); режим `rasterizer::BoxDrawingMode` (ADR-0018) — `Procedural` / `Font` (глифы шрифта) / `Combined` (шрифт, иначе формула), смена на лету — `Request::box_drawing` (сброс атласа, полная перерисовка, тот же путь, что `set_size`); в `Font`/`Combined` рамки зависят от начертания и **вписываются в ячейку без хинтинга** (ADR-0020: advance → ширина, `descent…ascent` → высота; `fit_commands_to_cell` в `rasterizer.rs`), затем выравниваются по пиксельной сетке — `snap_commands_to_cell_grid` (ADR-0021: координаты монотонно в целые, штрих ≥ 1 px, линии чёткие). Вариант «подобрать размер шрифта под целую ширину ячейки» проверен и отклонён (ADR-0019 Rejected). **SVG-глифы** (ТЗ FR-8.6, ADR-0008, `src/svg.rs`): `assets/svg/<4–6 HEX>.svg` (каталог задаёт приложение — `SvgGlyphs::load(dir)`; демо — только при шрифте из `assets/`), `usvg` → контуры → `zeno`, приоритет SVG > псевдографика > шрифт, вписывание с сохранением пропорций, цвета файла игнорируются, все 4 канала атласа; тестовые SVG — `tests/data/svg/` (не в `assets/`). Логический размер шрифта приложения — `AppOptions::font_size_px` (демо 22, `--bench` 16). `Cell::ch` — кодовая точка Unicode; начертание — из флагов `BOLD`/`ITALIC` (`Cell::style()`); рендереры читают `Atlas::pixel(slot, x, y, style)`, глифы готовит `Atlas::ensure` до горячего пути. `BOLD` = жирный глиф **и** осветление цвета.

- Инструментарий: stable 1.98.1, хост `x86_64-pc-windows-msvc`. Кросс-компиляция отсутствует.
- Зависимости библиотеки: `bitflags`, `skrifa 0.47` + `zeno 0.3`, `usvg 0.48` (SVG-глифы), `fontdb 0.24` (`fs`, `memmap`, `fontconfig` — системные шрифты, ADR-0017), `winit 0.30`, `softbuffer 0.4` — все с `default-features = false` и минимальным набором фич; `glow 0.18`, `glutin 0.32`, `glutin-winit 0.5`, `raw-window-handle 0.6`; `rayon 1.12` — пул потоков Software (ADR-0016). Пакет демо: `gterm`, `find_folder`, `skrifa`, `winit`. Крейт виджетов: `gterm`, `bitflags`, `winit`, `arboard 3.7` (`default-features = false` — только текст; необязательная, за фичей `system-clipboard`, включённой по умолчанию — ADR-0030). Версии в спецификации provisional; перед добавлением перепроверять.
- `Cargo.lock` есть, но репозиторий без коммитов — закоммитить вместе с кодом.
- Лицензия — `MIT OR Apache-2.0` (`LICENSE-MIT`, `LICENSE-APACHE`; поле `license` — в `[workspace.package]` корневого `Cargo.toml`, члены наследуют). Новая зависимость обязана быть под разрешительной лицензией (без GPL/LGPL-условий) — проверять поле `license` в `cargo metadata`. Шрифт демо — сторонний, под Apache 2.0 (`crates/gterm-demo/assets/fonts/README.md`). README — `README.md` (английский) и `README.ru.md` (русский): правки вносятся в оба, пример кода в них одинаков.
- Название крейта библиотеки **`gterm`**, пакета демо — `gterm-demo`; корневой `Cargo.toml` — виртуальный workspace (`resolver = "3"`, там же `[profile.release]` — в манифестах членов Cargo его игнорирует).

## Команды

Нет CI, поэтому гейты спецификации (§4.5) выполняются вручную. Запустите три команды по очереди перед объявлением завершенности работы:

```
cargo fmt --check
cargo clippy -- -D warnings      # также служит как gate на типобезопасность; отдельного шага нет
cargo test
```

Фокусные запуски:

```
cargo test --test stage3_render golden              # golden-тест Software-рендерера
GTERM_UPDATE_GOLDEN=1 cargo test --test stage3_render golden   # перезаписать эталон (после смены шрифта/размера)
cargo test --test stage4_gl                          # GL ↔ Software (допуск 0); без GL — печатает причину и проходит
cargo run --bin demo                                 # демо-окно (Esc — выход); из корня workspace без --bin Cargo не знает пакет
cargo run --bin demo -- --system-font                # то же на системном моноширинном шрифте (без assets/ — так по умолчанию)
cargo run -p gterm --example minimal                 # минимальный потребитель библиотеки без assets/ (ADR-0017, К13)
cargo run -p gterm --example pseudographica          # режимы псевдографики (ADR-0018): 1/2/3 — бэкенд, q/w/e — процедурная/шрифт/комбинированная
cargo run -p gterm --example hotkeys                 # комбинации клавиш (ADR-0028): «сейчас»/«полная»/«последняя», журнал сигналов, образцы; Esc при пустой комбинации — выход
cargo run -p gterm-widgets --example widgets          # экран из виджетов (ADR-0023/0026/0032): сверху вкладки (←/→ под фокусом или клик; вторая — индикаторы Gauge/LineGauge/Meter (ADR-0034)), полоса прокрутки у списка, внизу LineGauge позиции и пункт, открытый двойным кликом (ADR-0035); Tab/Shift+Tab — фокус по кольцу, стрелки/клик/колесо — выделение, P или кнопка — модальное окно (Esc/P/OK закрывают; P — карты сочетаний экрана и слоя, ADR-0029), Esc — выход
cargo run -p gterm-widgets --example widget_edit      # форма (ADR-0027): три поля ввода, ползунок «Уровень» со значением справа (ADR-0036; ←/→/Home/End под фокусом, клик, протяжка, колесо), группа «Параметры» с двумя флажками (ADR-0031; пробел/Enter/клик), выпадающий список, кнопки «Применить»/«Сброс», строка статуса; текст — в поле под фокусом, Enter — применить, Ctrl+S/Ctrl+R — применить/сброс из карты сочетаний (ADR-0029), в полях Shift+стрелки/мышь/Ctrl+A — выделение, Ctrl+C/X/V — системный буфер обмена (ADR-0030; пример требует фичу `system-clipboard`, она по умолчанию), список — Enter/пробел/↓/клик, Esc — выход
cargo run --bin full_table                           # таблица всех глифов постранично, блоки 2×2 в цветах палитры (FR-27.1)
cargo run --bin overlay                              # пример наложения клиентских буферов (ADR-0014)
cargo run --release --bin demo -- --bench [--backend=gles|soft] [--overlay] # замер NFR-4/NFR-5; --overlay — наложение на весь экран, отчёт в stderr; на Windows консоль в release
                                                     # скрыта (`windows_subsystem`) — перенаправляйте: `2> bench.txt`
```

`cargo clippy --all-targets -- -D warnings` должен быть чистым (feature `gl` упразднена: GL всегда в сборке, откат — в рантайме).

## Ограничения из спецификации

Это требования, которые являются критериями приемки, нарушение которых приводит к отклонению даже при правильном коду:

- **GL и Software рендереры должны быть бит-идентичны** (§8, §11.2). Логика шейдера (§7.3) и `soft_backend.rs` — две реализации одного алгоритма. Если они расходятся, одно из них ошибочно.
- **Нет выделения памяти в горячем пути отрисовки кадра** (NFR-6) — предвыделяйте и переиспользуйте буферы.
- **`unsafe` только** при создании контекста/дисплея и вызовах `glow`, изолированные в `gl_backend.rs` (NFR-9).
- **Никогда не паниковать при ошибках графики** (NFR-7) — каждый вызов инициализации/рендеринга возвращает `Result` и запускает откат.
- **Один вызов, один fullscreen треугольник**, фильтрация `NEAREST`, **один пиксель глифа = один пиксель кадра** (FR-12, FR-13) — без увеличения блока, без интерполяции. Размер задаёт шрифт, а не масштаб (ADR-0005).
- **Размер бинарника замеряется и записывается в отчёт каждого этапа** (NFR-1; жёсткого лимита с этапа 7 нет — прежние 1,5 МБ / 2 МБ были оценкой стека на старте и сняты владельцем 2026-10-02). ## Подводные камни

- Спецификация требует `panic = "abort"` в релизном профиле (§10.2, NFR-8). Как только это будет добавлено, **`cargo test --release` не сработает** — тесты нужно запускать в debug.
- `--fail-gl`, `--backend=auto|gl|gles|soft`, `TERM_BACKEND`, `--allow-sw-gl`, `--debug` реализованы в `src/config.rs` (этап 5). Проверка отката без GL на машине с GL: `cargo run -- --fail-gl` → stderr `backend Software`.
- `--fail-frames=N` и `--lose-context` (этап 8, ADR-0007) инжектируют ошибку кадра в `App::render_frame` после настоящего рендера: `cargo run -- --fail-frames=2` → повтор кадра, затем откат на Software; `cargo run -- --lose-context` → откат сразу; `cargo run -- --backend=soft --fail-frames=2` → код возврата 1. Счётчик `--fail-frames` общий на запуск: повторы и кадры после отката считаются.
- `Cargo.lock` должен быть закоммичен после появления зависимостей (спецификация §14 указывает на риск разрыва зависимостей как высокую вероятность). Бинарник не публикуется, поэтому дрейф lockfile — основная угроза.
- Список этапов спецификации (§12) — это порядок зависимостей, а не список желаний: буфер → шрифт/атлас → Software рендерер → GL бэкенд → fallback цепочка → мигание/размер/DPI/ввод → демо/размер → тестирование. Не начинайте работу с GL бэкендом до того, как Software рендерер существует, так как он задает эталонный вывод.
- Внутри этапа 6 порядок жёсткий: сначала `font`/`rasterizer`/`atlas` (размер и пересборка), потом удаление `u_scale`/`u_cursor` из шейдера и обоих рендереров, потом `app.rs` (трейт, сетка, DPI). Менять рендереры раньше нельзя — `tests/stage4_gl.rs` перестанет собираться.
- **Пять интеграционных тестов объявлены с `harness = false`** (`stage6_events`, `stage6_events_auto`, `stage6_fallback`, `stage8_faults`, `tick_events`): `winit` требует главный поток и разрешает **один** цикл событий на процесс. Любой новый тест, открывающий `App::run`, обязан быть отдельным бинарником с общим кодом в `tests/events_common/` (запуск окна со своим обработчиком — `events_common/launch.rs`: бинарник подключает только его через `#[path]`, как `tick_events`, иначе остальное из `events_common` даст `dead_code`; оконные бинарники не подключают `tests/common/` — шрифт репозитория у `events_common` свой), иначе он молча превратится в «пропуск». Если сценариев несколько — как в `stage8_faults`: бинарник запускает сам себя по разу на сценарий (`--scenario=…`) и проверяет код возврата и stderr дочернего процесса.
- `Request::grid` действует **только** в `FixedGrid` (FR-23 с уточнением). Проверено тестом: в `AutoGrid` запрос не действует, иначе следующая же перерисовка по размеру окна вернула бы старое значение.
- Смена DPI идёт **на месте**: `Rasterizer::set_size` + `Atlas::set_size` (страница 16 МБ переиспользуется, `resets` растёт) + `GlBackend::set_size`/`SoftBackend::set_size`. Гейт после любой правки этого пути — `cargo test --test stage4_gl` и `stage6_app` (кадр после смены DPI обязан совпасть с эталоном, построенным растеризатором с нуля).
- **KWin (KDE Plasma 6.8) на Wayland читает старший байт буфера `Xrgb8888` как альфу** (ADR-0024): кадр Software — `0x00RRGGBB`, и без обхода окно «полупрозрачно», кадры складываются, картинка белеет (GL/GLES и X11 чисты). Обход — в `app/backend.rs`: на Wayland (`SoftState::is_wayland` по `RawWindowHandle`) кадр копируется в буфер окна через `pixel::copy_opaque` (`| 0xFF00_0000`); формат самого кадра не трогать — golden, GL ↔ Software и наложение считают `0x00RRGGBB`. Независимое воспроизведение без `gterm` — зонд `winit` + `softbuffer` в коммите `d17a8a2`.
- **Визуальная проверка окна.** На Windows она делается самим исполнителем: запустить собранный exe в фоне, снять окно скриптом `tools/shot.ps1`, который перед снимком умеет изменить размер окна, нажать клавиши, кликнуть и протянуть мышью (`powershell -NoProfile -ExecutionPolicy Bypass -File tools/shot.ps1 -Name widgets -Out target\shots\1.png [-Size "740x300"] [-Keys "{TAB}{END}"] [-Click "246,73"] [-Drag "246,170,246,60"] [-Hold "246,233,1000"] [-Wheel "500,150,-2"]` — точки в пикселях от левого верхнего угла окна, как на снимке; в ответе `foreground=` и `hit=` показывают, было ли окно на переднем плане и лежало ли оно под точкой — при `False` ввод не дошёл, шаг повторить; код 2 — окна ещё нет, повторять до `saved …`), посмотреть PNG, закрыть процесс (`taskkill //IM <имя>.exe //F`). Снимки — в `target/shots/` (в git не попадают). Скрипт не трогает чужое окно: клавиши и мышь шлются, только если окно примера на переднем плане; курсор возвращается на место. Не делается так: системный буфер обмена (чтобы не затирать буфер владельца). На Linux-машине владельца прежние попытки не удались: `xdotool` не видел клиентских окон, `ffmpeg -f x11grab` давал чёрный root — причина не выяснялась (оба инструмента работают только с X11; под Wayland-сессией так и должно быть — это предположение, не проверено), другие средства (`spectacle`, `grim`, портал снимков) не пробовались; там окно проверяется через stderr, код возврата и содержимое кадров, а глазами — владельцем (§11.3). По бэкендам виджеты и контролы не проверяются: они пишут только в `ScreenBuffer`, равенство бэкендов держит `tests/stage4_gl.rs` (решение владельца 2026-11-12).
